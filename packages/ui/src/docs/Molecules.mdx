# Molecules

`CMP-040..069` in `docs/plan/15-component-catalogue.md`: form fields, menus, tabs, dialogs, toasts,
tables and cards. A component's stories live under `Molecules/<Component>` and ship with the
component (E05-S01..S04).

## RbacGate (CMP-079)

RbacGate is a UI affordance, not an authorisation control: the server enforces RBAC (C-12.4).

It wraps one atom. Allowed renders the atom unchanged. Denied takes a key of the E09-D09 §3.1
vocabulary (`RBAC_REASONS`, with `{verb}` or `{user}` fills where the string has them) and passes
the sentence to the atom's own `disabledReason`, so the atom stays focusable with
`aria-disabled="true"` and its reason as the accessible description. It has no keys of its own:
Enter, Space and a click on a denied control do nothing. Only the inline form ships; the tooltip and
notice forms follow CMP-016 Tooltip.

## Keyboard

Each component's keyboard table lives here (the WAI-ARIA pattern it follows, then keys and actions),
with its accessible name and role table.

### FormField (CMP-040, no widget pattern: a labelled-field wrapper)

| Keys                      | Action                                                                                                |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| Tab / Shift+Tab           | The child's Tab order; the field adds no stop of its own.                                             |
| Any key in the control    | The child's own keys (CMP-007, CMP-008, CMP-009); the field handles none.                             |
| Pointer press (the label) | Focuses the control: natively through `<label for>`, and by a handler for an `aria-labelledby` child. |

| Element      | Role                                                   | Name                         | ARIA                                                                                                  |
| ------------ | ------------------------------------------------------ | ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| label        | `<label for>`; without `for` for a non-labelable child | —                            | `id` = `labelId`, the `aria-labelledby` target of a radiogroup, slider, grid or div combobox          |
| control      | its own                                                | the label, with "(optional)" | `aria-describedby`: the error id, then the help id (the reason id alone while T2); `aria-required`    |
| error node   | none                                                   | —                            | `aria-live="polite"`, `aria-atomic="true"`, in the DOM at mount, empty while valid; never shown in T2 |
| help, reason | text                                                   | —                            | referenced, not live; while T2 the help line stays visible but leaves the description                 |
| lock glyph   | img (the child's, in its well)                         | "Not available"              | CMP-019 `decorative=false`                                                                            |
| error glyph  | none                                                   | —                            | `aria-hidden="true"`                                                                                  |

Inside a FormField, TextInput, Select and NumericStepperInput draw no error or reason line of their
own: the field draws each once. A stepper's own parse message ("Maximum 100") shows in the field's
error line. Outside a FormField the atoms keep their own lines.

The field owns the control's id: a field atom takes the field's `htmlFor` (or a generated id) over
any id of its own, so set a control's id on the field. RadioGroup, Slider, SegmentedControl and
Checkbox do not read the field yet; name them with `aria-labelledby` set to the field's `labelId`
until a later E05-S03 (#266) slice wires them.

### FormSection (CMP-065, collapsible: the WAI-ARIA APG Disclosure pattern)

| Keys                       | Action                                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------- |
| Tab / Shift+Tab            | The disclosure button (collapsible only), then the fields; a collapsed section's fields are skipped. |
| Enter / Space (the button) | Shows or hides the fields; focus stays on the button.                                                |
| Submit (the host's form)   | A collapsed section around an invalid field opens, and focus reaches the field.                      |

| Element           | Role                           | Name                      | ARIA                                                                                     |
| ----------------- | ------------------------------ | ------------------------- | ---------------------------------------------------------------------------------------- |
| section           | group (`<fieldset>`)           | the legend's heading text | `aria-labelledby` → the heading; `aria-describedby` → the description                    |
| heading           | heading, `h{headingLevel}` (3) | `title`                   | inside the `<legend>`                                                                    |
| disclosure button | button                         | `title`                   | `aria-expanded`, `aria-controls` → the body; `aria-describedby` → the errors-within line |
| errors within     | text                           | —                         | "2 problems" with the `danger` glyph (`aria-hidden`), shown only while collapsed         |
| T2 notice         | text                           | —                         | the `aria-describedby` target of every gated field inside (one notice, many pointers)    |

The count is `errorCount`, else the FormFields inside that show an error. A native constraint
failure (`required`) opens the section before the browser moves focus; a host-validated error opens
it in the render after the submit, and focus moves to the first invalid control unless it is
already on one. Plain disabled is `<fieldset disabled>`; the disclosure button, inside the legend,
stays usable. The T2 gate reaches FormFields only: a bare control inside the section is not wired.

### SearchBox (CMP-054, no widget pattern: a native search field)

| Keys                   | Action                                                                  |
| ---------------------- | ----------------------------------------------------------------------- |
| Tab / Shift+Tab        | The field, then the clear button when it shows.                         |
| Typing                 | Changes the query; the host filters after its debounce or on Enter.     |
| Esc                    | Clears a non-empty query and keeps focus; on an empty query it bubbles. |
| Enter / Space on Clear | Clears; focus returns to the field.                                     |

| Element      | Role                                       | Name                         | ARIA                                                        |
| ------------ | ------------------------------------------ | ---------------------------- | ----------------------------------------------------------- |
| field        | searchbox (native `<input type="search">`) | `label` through `aria-label` | the placeholder is never the name; `disabled` when disabled |
| search glyph | none                                       | —                            | `aria-hidden="true"`                                        |
| clear button | button                                     | "Clear search"               | rendered only with a value                                  |

The host announces its result count, politely, once per settled query. A search is a read and is
never gated, so SearchBox has no `disabledReason`.
