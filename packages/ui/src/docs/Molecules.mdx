# Molecules

`CMP-040..069` in `docs/plan/15-component-catalogue.md`: form fields, menus, tabs, dialogs, toasts,
tables and cards. A component's stories live under `Molecules/<Component>` and ship with the
component (E05-S01..S04).

## RbacGate (CMP-079)

RbacGate is a UI affordance, not an authorisation control: the server enforces RBAC (C-12.4).

It wraps one atom. Allowed renders the atom unchanged. Denied takes a key of the E09-D09 §3.1
vocabulary (`RBAC_REASONS`, with `{verb}` or `{user}` fills where the string has them) and passes
the sentence to the atom's own `disabledReason`, so the atom stays focusable with
`aria-disabled="true"` and its reason as the accessible description. It has no keys of its own:
Enter, Space and a click on a denied control do nothing. Only the inline form ships; the tooltip and
notice forms follow CMP-016 Tooltip.

| ------------ | ------------------------------------------------------ | ---------------------------- | ----------------------------------------------------------------------------------------------------- |

| control      | its own                                                | the label, with "(optional)" | `aria-describedby`: the error id, then the help id (the reason id alone while T2); `aria-required`    |

| help, reason | text                                                   | —                            | referenced, not live; while T2 the help line stays visible but leaves the description                 |
| lock glyph   | img (the child's, in its well)                         | "Not available"              | CMP-019 `decorative=false`                                                                            |

Inside a FormField, TextInput, Select and NumericStepperInput draw no error or reason line of their
own: the field draws each once. A stepper's own parse message ("Maximum 100") shows in the field's
error line. Outside a FormField the atoms keep their own lines.

The field owns the control's id: a field atom takes the field's `htmlFor` (or a generated id) over
any id of its own, so set a control's id on the field. RadioGroup, Slider, SegmentedControl and
Checkbox do not read the field yet; name them with `aria-labelledby` set to the field's `labelId`
until a later E05-S03 (#266) slice wires them.

### Combobox (CMP-048, APG Combobox: editable, list autocomplete)

| Keys              | Action                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Typing            | Edits the query; once it settles (`settleMs`, 500 ms by default) the list opens: local matches, or "Searching…".          |
| ↓ / ↑             | Open at once if closed; next / previous option: ↓ from the text reaches the first, ↑ on the first returns to it.          |
| Alt+↓ / Alt+↑     | Open at once without moving / close.                                                                                      |
| PageDown / PageUp | On an open list, move the active option by the visible rows (10 if unmeasured): no wrap; PageUp stops at the first.       |
| Enter             | Chooses the active option (its label fills the input); a T2 option says its reason instead; none: the host's.             |
| Esc               | Closes the list and keeps the text (in a CMP-043 Dialog, only the list); a second Esc, or one before the settle, bubbles. |
| ← / →, Home / End | Move the caret. Tab leaves, closing the list without choosing.                                                            |
| Any key while T2  | Changes nothing; the first refused key of a focus visit says the reason once.                                             |

The input is `role="combobox"` with `aria-autocomplete="list"`, named by CMP-040's label or, outside a field,
`aria-label` / `aria-labelledby`; `prefix` leads the well as CMP-007's, after a T2 lock, and a press on the well
focuses the input. `aria-activedescendant` names the active option, which takes `aria-selected`. The listbox, named
like the input and `aria-busy` while searching, portals as CMP-017 does; inside a Dialog it portals into the
dialog's layer, where the overlay stack gives the list the first Esc. Status rows (searching, no results, a failed
search) are not options. One polite status says the count ("8 results") or the host's sentence once per settled
query; "Searching…" is shown, never said. `asyncSearch` gets an `AbortSignal`; an older answer never overwrites a
newer query's. A local source without `noResultsText` keeps the list closed when nothing matches; the count
("0 results") is still said, so give a host sentence where an empty answer needs one. `animated={false}` opens the
popup at once, without its fade. `onKeyDown(event, active)` runs first on every key outside an IME composition, with
the active option; its `preventDefault()` leaves that key to the host (`Shift+Enter`, `Shift+F10`, the Menu key, its
own Esc) and the combobox skips it.

### CommandPalette (CMP-059, APG Combobox with a grouped listbox popup, inside the APG Dialog (Modal))

| Keys                    | Action                                                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------------------------------ |
| Typing                  | Filters (fuzzy, ranked, grouped); the first result becomes active; the count is said once the query settles. |
| ↓ / ↑                   | Next / previous option, skipping group headers and wrapping; focus stays in the input.                       |
| Home / End              | First / last option.                                                                                         |
| PageDown / PageUp       | Ten options on, or back; no wrap.                                                                            |
| Enter                   | Runs the active command and closes; a destructive one asks the host's confirm; a gated one says its reason.  |
| Ctrl+Enter              | The group run (`onRunGroup`), gated and confirmed as Enter; without `onRunGroup`, nothing.                   |
| Esc                     | Closes; focus returns to the opener (CMP-043).                                                               |
| Tab                     | Stays in the dialog: the input and CMP-043's close button.                                                   |
| A held Enter (repeated) | Nothing more: a command runs once, a reason is said once per press.                                          |

The input is `role="combobox"` (`aria-autocomplete="list"`, `aria-controls`, `aria-activedescendant`); the listbox
holds one `role="group"` per section, named by its header. An option's name is its label, then "confirms" on a
destructive row; a gated option is `aria-disabled` and described by its reason; the CMP-022 hint is `aria-hidden` and
its keys are the option's `aria-keyshortcuts`. One polite status says the count (or the no-results sentence) once per
settled query and a re-shown reason once per press. Every string is a prop (E15's SCR-012 keys); `Ctrl+K` is the
host's binding (#305).

### Tabs (CMP-042, APG Tabs)

| Keys                                    | Action                                                                                                                                 |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| Tab                                     | Into the tablist onto the selected tab (roving `tabindex`); the next Tab goes into the panel.                                          |
| → / ← (↓ / ↑ when vertical)             | Next / previous tab, wrapping; the other axis is not handled. Automatic: selects it. Manual (`activation="manual"`): moves focus only. |
| Home / End                              | First / last tab, as the arrows.                                                                                                       |

| An arrow, Home or End onto a gated tab  | Focus lands on it and nothing is selected, silently: the name, "unavailable" and the reason are its description.                       |
| Enter / Space or a press on a gated tab | Nothing is selected; the reason is announced once, politely, per press.                                                                |
| Alt / Ctrl / Meta chords                | Not handled, on a gated tab too: the browser's and the host's.                                                                         |

| Element | Role     | Name                                                    | Notes                                                                                                             |
| ------- | -------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| tablist | tablist  | the host's `aria-label` or `aria-labelledby` (required) | `aria-orientation="vertical"` when vertical.                                                                      |
| tab     | tab      | its visible label                                       | `aria-selected`, `aria-controls` its panel; gated: `aria-disabled="true"` and `aria-describedby` the reason line. |
| panel   | tabpanel | its tab (`aria-labelledby`)                             | Only the selected panel is mounted; `tabindex="0"` while it holds nothing focusable (J10).                        |
| reason  | none     | —                                                       | One caption line under the strip per distinct reason; tabs gated for the same sentence point at one line.         |
| status  | status   | —                                                       | Visually hidden; filled only when a gated tab is pressed, cleared when focus moves on.                            |

A switch never moves focus off the tab, and a panel that takes focus as it mounts (an `autoFocus` or an effect)
gives it back to the tab. Selection and the panel swap are cuts. The strip scrolls in one row; it never wraps or hides
a tab.

### Dialog (CMP-043, APG Dialog (Modal); Alert Dialog for `role="alertdialog"`)

| Keys                 | Action                                                                                                                                        |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| On open              | Focus to `initialFocusRef` (or the first tab stop inside it), else the first field, else the heading. An alertdialog passes its Cancel (H32). |
| Tab / Shift+Tab      | Cycle inside the card, in DOM order; the page under it is inert.                                                                              |
| Esc                  | Closes the topmost layer only: a tooltip, then a popover or menu, then the dialog. Focus returns to the opener, else `fallbackFocusRef`.      |
| A press on the scrim | Cancel for a `dialog`; nothing for an `alertdialog`.                                                                                          |
| Enter / Space        | The focused control's own; the dialog adds none.                                                                                              |

| Element | Role                   | Name                                           | ARIA                                                                                                   |
| ------- | ---------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| card    | dialog or alertdialog  | the title (`aria-labelledby`), or `aria-label` | `aria-modal="true"`; `aria-describedby` → the description, then the host's ids; `aria-busy` while busy |
| title   | heading, `h2`          | its text                                       | `tabindex="-1"`: the fallback focus target                                                             |
| close   | button (`dialog` only) | "Close {title}"                                | CMP-002 `ghost`                                                                                        |
| body    | none, or group         | the title, when it is a Tab stop               | a body that scrolls with no control in it takes `tabindex="0"` so the keyboard can scroll it           |
| scrim   | none                   | —                                              | `aria-hidden="true"`; the page under it `inert` (`aria-hidden` where the engine has no `inert`)        |

`onOpenChange(false, reason)` reports `escape`, `scrim` or `close`; the host decides. A lock ignores
`Esc` by keeping `open`; a form with unsaved changes opens its own stacked CMP-044 alertdialog
("Discard unsaved changes?", H36), whose `Esc` returns to the form as it was. While open, every
subtree outside the dialog's layer is inert except elements marked `data-cv-inert-exempt` (the
shell's TopBar, env band, StatusBar and announcer regions, H23); the shell can inset the scrim with
`--cv-scrim-inset-top` and `--cv-scrim-inset-bottom`. The page does not scroll, and the scrollbar's
width is given back as padding (`--cv-scroll-lock-gutter` for fixed bars), so nothing shifts. A
Popover, Tooltip or nested Dialog rendered inside portals into the dialog's layer. There is no
NoEscClose: `Esc` always cancels before a send, and closes the view after one (H22). `busy` sets only
`aria-busy` on the card; the dialog does not drive its footer, so the host sets its primary
action's `loading` itself.

### ConfirmDialog (CMP-044, APG Alert Dialog; APG Dialog (Modal) for an order confirm)

| Keys                               | Action                                                                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| On open                            | Focus on Cancel (H32); nothing is sent until Confirm.                                                                                 |
| Tab / Shift+Tab                    | The trap in DOM order from Cancel: Confirm, the close button (an order confirm), the body's controls, back to Cancel.                 |
| Enter / Space / a press on Confirm | Confirms once, unless the press began in the first `confirmDelayMs` (at least 400 ms) of the guard; repeats never count.              |
| Typing in the typed field          | Confirm enables when the text matches the token exactly (paste allowed); Enter in the field never confirms.                           |
| Hold, pointer                      | Press and hold Confirm for `holdDurationMs` (800 ms, 300–2,000); an early release resets the ring and fires nothing.                  |
| Hold, keyboard                     | Hold Enter as long, or two non-repeat Enter / Space presses 250 ms – 5 s apart, a keyup between; the first arms ("Press again to …"). |
| Second press under 250 ms          | A bounce: ignored, and the window keeps the first press's start; so is a press whose keydown follows a keyup within 50 ms.            |
| Armed window runs out (5 s)        | Disarms; Confirm takes its own name back and "Disarmed — {effect}" is spoken politely once.                                           |
| Space on a hold Confirm            | One press on its keyup, never a hold; a click or a pointer press never arms.                                                          |
| Esc or blur on a hold Confirm      | Disarms and drops the hold, silently; Esc then cancels the dialog (`onCancel("escape")`, once).                                       |
| Title or effect changes while open | Drops a hold under way and an armed press; the guard restarts, so the next press only arms (or starts a new hold).                    |
| Any key or pointer input           | Restarts an `autoCancelMs` count (key repeats do not); at 0:00 the dialog cancels (`"timeout"`), never confirms.                      |
| Esc                                | Cancels (`onCancel("escape")`); focus returns to the opener, else `fallbackFocusRef`.                                                 |
| Enter / Space on a T2 Confirm      | Nothing; the reason is re-shown with one polite announcement.                                                                         |
| A press on the scrim               | Nothing for an `alertdialog`; Cancel (`"scrim"`) for an order `dialog`.                                                               |

| Element     | Role                                             | Name                                                   | ARIA                                                                                                                                               |
| ----------- | ------------------------------------------------ | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| card        | alertdialog, or dialog for an order confirm      | the title, or the host's `aria-label`                  | `aria-modal="true"`; `aria-describedby` → the message, then the restatement; `aria-busy` while busy                                                |
| restatement | group (or plain text with `restatementLabel=""`) | "What this does"                                       | —                                                                                                                                                  |
| typed field | textbox                                          | the instruction ("Type FLATTEN to confirm"), its label | —                                                                                                                                                  |
| Confirm     | button                                           | the effect, never "Confirm"                            | native `disabled` until the summary loads and the token matches (validity); `aria-describedby` → the instruction; T2: `aria-disabled` + the reason |
| status      | status, alert                                    | —                                                      | visually hidden: a T2 re-show (polite); a Confirm gated while it held focus (assertive, once)                                                      |
| hold ring   | progressbar                                      | "Hold to {effect}", stable while armed (E39-D03 §5)    | `aria-valuenow` 0–100 and its text twin at up to 2 updates a second; the arc at up to 10, hidden under reduced motion                              |
| armed count | text (CMP-035)                                   | the 5 s window, beside the ring while armed            | `aria-live="off"`, no thresholds: silent (a visible reading of the catalogue's "visible countdown"); the lapse is spoken once by the status        |
| countdown   | text (CMP-035)                                   | "Cancels in 20 seconds unless you act"                 | `aria-live="off"`; polite at 0:10 and 0:00 only                                                                                                    |

`onConfirm(meta)` reports `{ variant, gate, elapsedMs }` for the host's audit event, the gate being
`click`, `typed`, `pointer-hold`, `key-hold` or `double-press`; `onCancel(reason)` reports `cancel`,
`escape`, `close`, `scrim` or `timeout`. A hold that also asked for a `typedConfirmValue` reports its
hold gate only: the meta does not say the token was matched too, which the host knows from its own
props. Events are not filtered on `isTrusted`: the gate guards against accidental and browser-made
activations, not in-page script, which could call the host directly. The accepted boundary is that a
lone untrusted `pointerdown` that never gets its `up` satisfies a hold after `holdDurationMs`; that is
a hold, not a single click. The guard runs from the moment the dialog opens and applies to pointer, Enter and Space
alike. A typed mismatch, a loading summary and a sent confirm (`busy`) are not T2; only a reason
given while open (H30) is, and focus stays on Confirm. A partial failure is CMP-027's inline error
with its Retry, above the footer.

The guard is a safety control. `confirmDelayMs` below 400 (or not a finite number) is raised to 400
with a dev warning. The window restarts when Confirm becomes available (a typed match, the summary
loaded, a T2 reason cleared) and when the title or Confirm's label changes while open. A press that
began inside the window is rejected even when it ends after it, across a blur or a pointercancel;
the click that ends it clears the mark. `onConfirm` fires at most once per opening: a new `failure`
message or `busy` going false allows one more. The clock is `performance.now` (monotonic). A `Space`
released on Cancel or Confirm activates only when its own press began there.

A hold Confirm never reads a click, so a synthetic `click()` confirms nothing. The guard applies to the moment
each hold or press begins. Completion is read from the clock: it fires at the duration, never
before. A `typedConfirmValue` on a hold gates it too: no press starts until the field matches. The
`autoCancelMs` count stops once Confirm has fired and stays off for the rest of the opening, a
failed send's retry included, so a sent confirm is never cancelled by it. A `busy` that ends without a
send shows the count again from the full time. The count listens on the document, not the dialog
surface: the dialog is modal, so a press on a toast action outside it also restarts the count.

With `summaryLoading` set while
Confirm holds focus, Confirm becomes natively disabled and focus is lost; that inherited spec gap is
open for the host or the spec to decide.

### Toast and the toast region (CMP-045, no widget pattern; messages follow the APG Alert pattern through the shell's announcer)

| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| On arrival                                    | Nothing: a toast never takes focus. Its sentence is written once through `announce`.                                                           |
| Tab / Shift+Tab                               | Through each toast's actions and dismiss button, in stack order; while a modal is open the stack is inert.                                     |

| Element      | Role                     | Name                          | ARIA                                                                                                     |
| ------------ | ------------------------ | ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| region       | region (`<section>`)     | `label` ("Notifications")     | portalled to `body`; rendered only while it holds a toast; its list is an `<ol>`                         |
| toast        | group                    | its title (`aria-labelledby`) | never a live region itself (H28)                                                                         |
| announcement | —                        | —                             | `announce(politeness, sentence, id)`: polite, assertive for `danger` or an error; `politeness` overrides |
| glyph        | none                     | —                             | `aria-hidden="true"`                                                                                     |
| dismiss      | button                   | "Dismiss {title}"             | CMP-002 `ghost`; never gated                                                                             |
| gated action | button                   | its full label                | `aria-disabled="true"`, `aria-describedby` → the one reason line every gated action shares               |

Timing (H26): a toast with an action, an error or `danger` persists; any other closes after the region's
`durationMs` (5 s by default; `null` is "until dismissed"), or its own. There is no countdown bar. An
Undo window follows the same duration, then the outcome line stays (H27); an order cancel offers no Undo.
The shell passes its one announcer as `announce`, so the region renders no live region of its own; the
stories use a local pair. The count, the storm summary and "Focus toasts" are CMP-212's.

The width is host data (`width`, in px; 480 by default); at a viewport of 720 CSS px or less the
drawer takes the full width. A modal drawer is CMP-043's contract: the page inert (the
`data-cv-inert-exempt` regions spared), no page scroll, the shell's scrim insets. A non-modal one
sits at `elevation.popover` with no scrim and the page live, and does not close when focus leaves
it. With neither the opener nor `fallbackFocusRef` reachable, its Tab path has no anchor and keeps the
browser's order: the drawer is last in `body`, so Tab past its last control leaves the page. It
slides in opaque from the first frame and out over `fast`; reduced motion is a cut. `busy`
sets only `aria-busy` on the body: the host renders its CMP-015 rows. A docked inspector that
reflows its host is the host's layout, not this overlay.

| drawer       | dialog  | the title            | a non-modal CMP-046 (no `aria-modal`)                                                                                                                                                   |
| inline panel | region  | its heading          | `section` with `aria-labelledby` → the heading                                                                                                                                          |
| heading      | heading | the detector's name  | `tabindex="-1"`: focus on open                                                                                                                                                          |
| body         | —       | —                    | `aria-busy="true"` while the values load (the drawer's body; inline, the values part only, so the heading and the static text stay readable); a load failure is CMP-027's polite region |

The trigger is the host's (the CMP-227 chip): `trigger` renders it from the props to spread on a
button. The static methodology (`content`) shows at once; the current values (`values`) load under
it as CMP-015 rows, or fail as a CMP-027 inline error with Retry (`error`, `onRetry`).

### Table (CMP-049, table mode: the WAI-ARIA APG Table pattern)

| Keys                                             | Action                                                                                                                     |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| Tab / Shift+Tab                                  | The scroll region when it scrolls (named by the caption), then the sortable header buttons in order; the body has no stop. |
| Arrows, Page Up / Down, Home / End on the region | Scroll it (native).                                                                                                        |
| Enter / Space on a header button                 | Sorts ascending, then descending; while that column is `sortPending` the press changes nothing.                            |

| Element     | Role                            | Name             | ARIA                                                                                            |
| ----------- | ------------------------------- | ---------------- | ----------------------------------------------------------------------------------------------- |
| table       | table (native `<table>`)        | the caption      | `aria-rowcount` (rows and the header; -1 while loading); `aria-busy="true"` while loading       |
| region      | region, only while it scrolls   | the caption      | `tabindex="0"`; no role and no stop when everything fits                                        |
| header cell | columnheader (`th scope="col"`) | its label        | `aria-sort` on the sorted column, `none` on the other sortable ones, none on plain headers      |
| sort button | button                          | the header label | `aria-busy="true"` while `sortPending`; a CMP-014 spinner replaces the glyph                    |
| row         | row                             | —                | `aria-rowindex` (absolute: the header row is 1)                                                 |
| live region | status, one per table           | —                | polite: a settled sort ("Sorted by Size, ascending"), a finished load ("3 rows"), an error once |

The consumer sorts the rows: `onSortChange` asks for the next sort and the host passes the sorted
`rows` and `sort` back. Numeric columns (`numeric`, a NumericText format) are end-aligned and never
truncate; text cells truncate with an ellipsis and keep the full text in the DOM. Loading keeps the
header row under CMP-015 skeleton rows and shows the caption's loading words; empty and
filtered-empty render the host's CMP-026 (`emptyState`) across every column; an error renders CMP-027
with Retry, spoken once by the table's region (the panel itself is not live). v0 renders every row
and is not virtualised: above 200 rows it warns in development (#266).

Below the sum of its columns' `minWidthEm` (default 8 each, in the table's own `em`, so 200 % zoom
counts) the table stacks, one block per row, read in order: the header buttons (wrapped, still
sorting), then each row with its first cell as the heading line and every other cell as its header
label then its value. The label is visible but hidden from assistive technology, which takes the
header from the cell's `columnheader` (the explicit table roles stay while stacked). In table
navigation a screen reader says the header once, then the value; reading linearly in browse mode it
reads the values without their headers. Not yet confirmed with NVDA or VoiceOver: an E05-D05 check.

The polite line clears as a load, a pending sort or a Retry starts, so a result identical to the
last one (the same row count after a reload, the same failure after a Retry) is said again. The
default empty title "No rows to show" is PROPOSED copy, pending E05-D05 review.

### Table, grid mode (CMP-049, the WAI-ARIA APG Grid pattern)

Any interactive column makes the table a grid: `onRowSelect`'s select column, `rowActions`' actions
column, or a column marked `interactive`; `grid` forces it on a static table.

| Keys                    | Action                                                                                                             |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Tab / Shift+Tab         | One stop: into the grid on the last focused cell, else the first body cell; the next Tab leaves.                   |
| ↑ / ↓                   | Previous / next row, the header row included; stops at the edges.                                                  |
| ← / →                   | Previous / next cell; stops at the edges.                                                                          |
| Home / End              | First / last cell of the row.                                                                                      |
| Ctrl+Home / Ctrl+End    | The grid's first cell (the header row) / its last cell (the last row).                                             |
| Page Up / Page Down     | By the rows that fit the visible region, less the header; stops at the first / last row.                           |
| Enter / Space           | On a header button, sorts; on the select box, toggles it; on the actions button, opens the row menu.               |
| Space                   | On any other body cell, toggles the row's selection (with a select column).                                        |
| Enter / F2              | On an `interactive` cell, moves focus to its first control (which owns its keys from then on).                     |
| Esc                     | In an `interactive` cell's control, back to the cell; in the row menu, closes it, focus back where it opened from. |
| Shift+F10, the Menu key | On a focused body cell, opens the row's menu at the row; T2 items stay arrow-reachable and are never activated.    |

| Element      | Role                                  | Name                              | ARIA                                                                                                            |
| ------------ | ------------------------------------- | --------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| table        | grid                                  | the caption                       | `aria-rowcount`, `aria-colcount`; `aria-multiselectable` with a select column                                   |
| cell         | gridcell (header cells: columnheader) | its content                       | the roving `tabindex` (0 on the remembered cell); a control takes it in its place                               |
| row          | row                                   | —                                 | `aria-rowindex`; `aria-selected` with a select column                                                           |
| select boxes | checkbox (CMP-005)                    | "Select all rows"; "Select {row}" | select-all mixed when some rows are selected                                                                    |
| actions      | button (CMP-002, `more-horizontal`)   | "Actions for {row}"               | `aria-haspopup="menu"`; opens CMP-041                                                                           |
| live region  | status, the table's one               | —                                 | adds the selection count ("2 selected", rows only), once per change, and a row menu's T2 reason, once per press |

`{row}` is `rowLabel(row)`, by default the first column's value when it is text or a number, else
the row's key. A focused cell scrolls into view below the sticky header (`scroll-margin-top` is the
header's height), so focus is never hidden under it; in grid mode a scrolling region stays a named
landmark but takes no Tab stop of its own. Selected rows take `color.action.selected` (Highlight in
forced colours).

A press on a cell makes it the remembered cell, so a right-click opens the pressed row's menu; a
press beside a built-in control (the select or actions cell's padding) focuses that control. Row
menus pass CMP-041's `announceReason`, so they render no live region of their own: the table keeps
one. A row's items (`rowActions`) are asked for only while its menu is open.

Stacked (the reflow above), a grid degrades to a table: arrow navigation needs rows and columns
laid out, so the explicit table roles return and every control (the select boxes, the actions
buttons, an `interactive` cell's controls) is its own Tab stop, in reading order; the row menu
still opens with `Shift+F10`, and `aria-selected` stays on the rows.

### Menu (CMP-041, APG Menu Button and Menu)

| Keys                                         | Action                                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Enter / Space / ↓ on the trigger             | Opens on the first item; a menu whose items all pick one value (radio) opens on its checked item.             |
| ↑ on the trigger                             | Opens on the last item.                                                                                       |
| ↓ / ↑, Home / End                            | Next / previous item, wrapping; first / last. Separators and group captions are skipped.                      |
| A printable character                        | Type-ahead: the next item whose label starts with the typed text (a 500 ms window; one letter cycles).        |
| Enter                                        | Activates the item and closes; focus returns to the trigger before the item runs (or a dialog takes it).      |
| Space                                        | Activates an action item and closes; toggles a checkbox or radio item and keeps the menu open.                |
| Enter / Space on a disabled, busy or T2 item | Nothing runs; a T2 item's reason is announced once, politely, per press.                                      |
| → / Enter / Space on a submenu item          | Opens its submenu beside the row, on its first item.                                                          |
| ← in a submenu                               | Closes that submenu alone; focus back on its item.                                                            |
| Esc                                          | Closes the topmost level only (a submenu, then the menu); focus returns to its item, then the trigger.        |
| Tab / Shift+Tab                              | Closes every level and moves on from the trigger (it stays on the trigger with no earlier stop).              |
| A pointer click on an item                   | Like Enter: activates and closes, a checkbox or radio item too (only Space keeps the menu open).              |
| Pointer hover on an item                     | Moves focus to it, a disabled, busy or T2 item too; nothing runs.                                             |
| A press outside                              | Closes the menu; focus goes where the press lands.                                                            |
| Pointer on another item of the parent        | Closes the open submenu; the pointer crossing the submenu's own row leaves focus inside it.                   |
| Shift+F10, the Menu key (context menu)       | Opens it below the focused element in its target, on its first item; focus returns there.                     |
| A right-click (context menu)                 | Opens it at the pointer instead of the browser's menu; focus returns to the pressed control, else the target. |
| The host's `open` (host-opened menu)         | Opens it below the `anchor`'s start, on its first item; focus returns to the element that held it.            |

| Element       | Role                                        | Name                                             | ARIA                                                                                                        |
| ------------- | ------------------------------------------- | ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| trigger       | button (the host's CMP-001 or CMP-002)      | its label                                        | `aria-haspopup="menu"`, `aria-expanded`, `aria-controls` → the menu                                         |
| menu          | menu                                        | the trigger (`aria-labelledby`), or `aria-label` | `hidden` while closed, so `aria-controls` stays valid; a context or host-opened menu requires `aria-label`  |
| group         | group, a `separator` between groups         | its caption, when it has one                     | danger items always form the last group (H16)                                                               |
| item          | menuitem, menuitemcheckbox or menuitemradio | its visible label                                | `aria-checked` on checkable items; `aria-keyshortcuts` for a shortcut; glyphs and key caps `aria-hidden`    |
| submenu item  | menuitem                                    | its visible label                                | `aria-haspopup="menu"`, `aria-expanded`, `aria-controls` → the open submenu; the chevron `aria-hidden`      |
| submenu       | menu                                        | its item (`aria-labelledby`)                     | rendered only while open                                                                                    |
| T2 item       | its kind                                    | its full label                                   | `aria-disabled="true"`, `aria-describedby` → its reason line, in the DOM at mount; the lock leads the label |
| disabled item | its kind                                    | its label                                        | `aria-disabled="true"`: reached, never activated                                                            |
| busy item     | its kind                                    | its label                                        | `aria-busy="true"`, `aria-describedby` → its description line; CMP-014 leads the label, `aria-hidden`       |
| danger item   | its kind                                    | its label, with "…" when it opens CMP-044        | `aria-describedby` → a visually hidden "Destructive action"                                                 |

Each item is a row (`role="none"`, the hit target and the look) around the `menuitem`, which holds the label
alone, so the name is the visible label; the second line and the shortcut are its description and
`aria-keyshortcuts`. The host owns `checked`: an item's `onSelect` toggles it. The menu is anchored below its
trigger (above when there is no room), at least as wide as the trigger, its height capped to the room and
scrolling. It opens at once and fades out over `fast` (a cut under reduced motion). Focus leaving the menu closes it, unless it moves into a layer opened above it (a dialog a checkable item opens). Inside a CMP-043 Dialog it
portals into the dialog's layer. An item with `items` opens a submenu: the same surface beside its row
(`right-start`, flipped to the left at the edge), each submenu its own layer, so Esc closes it alone. With
`contextTarget` (a ref) instead of `trigger`, the menu is a context menu: no trigger renders, a right-click opens it at
the pointer through a zero-size virtual reference (positioning only) and `Shift+F10` or the Menu key below the focused
element; the target should be focusable, as a grid row is. The target should mount with the menu: one swapped or
mounted later is bound on the menu's next render. With `anchor` and a controlled `open` instead (E08-D05 A-D05-13),
the host opens the menu from its own keys or a right-click: no trigger renders, the menu opens below the anchor's
start (an element such as the active option of a list whose focus stays in its input, or a viewport rect, read as
it opens; keep an element mounted while open), focus returns to the element that held it when it opened, and its T2
items behave as in any menu.

Submenu decisions (E05-S03):

- Hover does not open a submenu; only `→`, Enter, Space or a click does.
- There is no safe triangle: the pointer on another item of the parent closes the open submenu.
- A gated (T2) submenu item never opens; a press (Enter, Space or a click) re-shows its reason, `→` does not.
- A submenu always opens on its first item; a checked radio item in it does not choose where it starts.
- No RTL mirroring yet: `→` opens and `←` closes in every direction, and a submenu opens `right-start`
  (a known deferral, to be tracked in its own issue).

A re-shown T2 reason is said by the menu's own polite `role="status"`, rendered only while some item
has a reason. A host that owns its surface's one live region (CMP-049's line) passes
`announceReason` instead: the menu then renders no region and hands each re-shown reason to the
host.

### DatePicker (CMP-047, APG Date Picker Dialog; the dialog is modal)

| Keys                                            | Action                                                                                                              |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Tab / Shift+Tab (field)                         | The date field, the time field (`withTime`), then the calendar button.                                              |
| Typing                                          | `YYYY-MM-DD`, parsed on blur or Enter; never clamped. Unparsable or out-of-range text keeps its words and no value. |
| Alt+↓ in the field; Enter / Space on the button | Opens the dialog; focus on the selected day, else today, else the nearest allowed day.                              |
| ← / →                                           | Previous / next day, across month and year edges.                                                                   |
| ↑ / ↓                                           | The same weekday, previous / next week.                                                                             |
| Home / End                                      | Monday / Sunday of the week.                                                                                        |
| Page Up / Page Down                             | Previous / next month: the same day number, clamped to the month's last.                                            |
| Shift+Page Up / Shift+Page Down                 | Previous / next year (29 February clamps to 28).                                                                    |
| Enter / Space on a day                          | Picks it and closes.                                                                                                |
| Enter / Space on an out-of-range day            | Nothing changes; the caption is spoken on every such press.                                                         |
| Tab / Shift+Tab (dialog)                        | Cycles the month buttons and the grid's one tab stop; focus stays in the dialog.                                    |
| Esc                                             | Closes without a change. Every close returns focus to the calendar button.                                          |
| Any key while T2                                | The field is read-only, the button `aria-disabled`: the dialog never opens; the reason is spoken once per visit.    |

| Element         | Role                        | Name                               | ARIA                                                                                            |
| --------------- | --------------------------- | ---------------------------------- | ----------------------------------------------------------------------------------------------- |
| date field      | textbox                     | CMP-040's label (or `aria-label`)  | `aria-describedby`: the error, the format hint, then the "UTC" suffix; T2 the reason alone      |
| calendar button | button                      | "Choose date"                      | `aria-haspopup="dialog"`, `aria-expanded`; T2 `aria-disabled="true"` with the reason            |
| dialog          | dialog, `aria-modal="true"` | the month heading ("October 2026") | a modal CMP-017 Popover                                                                         |
| grid            | grid                        | the month heading                  | Monday-first `columnheader`s, each an `abbr` with the full weekday name                         |
| day             | gridcell holding a button   | "23 October 2026", with ", today"  | `aria-selected` on the selected cell; `aria-disabled` out of range; `aria-current="date"` today |
| month buttons   | button                      | "Previous month" / "Next month"    | CMP-002 `ghost`; focus stays on the button                                                      |
| caption status  | status                      | —                                  | empty until an out-of-range day is chosen                                                       |

The value is an ISO `YYYY-MM-DD` string in UTC, never a `Date`; today comes from an injectable
`now` clock. The date math is in-house: no date library. `withTime` adds an `HH:MM` well after the
date (24-hour UTC, typed only, parsed on blur or Enter as `H:MM` or `HH:MM`) with its own `time` and
`onTimeChange`, and the calendar button moves to the end of the time well, so the Tab order is the
date, the time, then the button. The range form is its own export, `DateRangePicker`, so
`DatePickerProps` keeps `value: string | null`.

A press inside the open calendar stays the calendar's: React bubbles it through the portal to the
well, which forwards only presses on its own padding and suffix to the field. A read-only field
keeps its value selectable, and its calendar button is natively disabled, so it leaves the Tab
order (T2's `aria-disabled` is for a gated field only). Empty cells before the 1st and after the
last day are empty `gridcell`s, as in the APG example.
