# Trading

`CMP-100..139` in `docs/plan/15-component-catalogue.md`: trading-specific molecules and organisms:
the order ticket, DOM row, footprint cell and positions grid. A component's stories live under
`Trading/<Component>` and ship with the component (E05-S01..S04).

## Keyboard

Each component's keyboard table lives here, with its accessible name and role table.

### PnLBadge (CMP-116, no widget pattern: text)

Not interactive: no Tab stop, no keys. One visually hidden sentence is what assistive technology reads, the sign in
words with the magnitude and its unit: "profit 8.00 USDT", "loss 121.50 USDT", "profit 0.32 R"; a null R reads
"R unavailable: no stop price". The visible digits and the accent bar are `aria-hidden`, and nothing carries an
`aria-label` (E29-D04 §2.3). The value is the server's decimal string, rounded half away from zero for display and
never parsed into a JavaScript number.

Text resize (`05` §5 item 7: 200 % zoom and the in-app text scale): the digits grow and the badge widens on one line,
never truncating or wrapping a value (E29-D02 D-8); its column widens with it (E29-D02 §11.5).

### PositionModeToggle (CMP-129, `display`: text)

The mode as the word "One-way" or "Hedge": no Tab stop, no control role, no reason and no live region. The `toggle`
variant ships with the ticket that hosts it.

### AccountMultiSelect (CMP-105, the account filter use: an APG Listbox, multi-select, in a CMP-017 popover)

| Keys                  | Action                                                                                 |
| --------------------- | -------------------------------------------------------------------------------------- |
| Enter / Space / Alt+↓ | On the trigger: opens the popover, focus on the list, the first chosen account active. |
| ↑ / ↓, Home / End     | Move the active option (`aria-activedescendant`); no wrap.                             |
| Space                 | Includes or drops the active account.                                                  |
| Enter                 | Closes; the choices are already applied. Focus returns to the trigger.                 |
| Tab / Shift+Tab       | "Select all", then out of the popover (it closes); Shift+Tab back to the trigger.      |
| Esc                   | Closes and returns focus to the trigger.                                               |

| Element      | Role    | Name                                     | ARIA                                                        |
| ------------ | ------- | ---------------------------------------- | ----------------------------------------------------------- |
| trigger      | button  | its label: "Filter"                      | `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`. |
| panel        | dialog  | the trigger                              | CMP-017, non-modal.                                         |
| list         | listbox | the host's `listLabel`, else the trigger | `aria-multiselectable="true"`, `aria-activedescendant`.     |
| account      | option  | its label: "Sub-1"                       | `aria-selected`; the drawn check box is `aria-hidden`.      |
| "Select all" | button  | "Select all"                             | A distinct labelled control (`15` CMP-105 A11y).            |

The list is the server's scope: a Manager's assigned accounts only. A filter is a view choice, never T2. `listLabel`
names the list when the trigger's words don't name the choice, as when a "+ Filter" menu's Account item opens the
picker; its words are the copy owner's (E29-D03).

Text resize (`05` §5 item 7: 200 % zoom and the in-app text scale): the panel is CMP-017's capped surface, so at 200 %
the list scrolls under the pinned "Select all" footer, and a long account label wraps rather than truncate.

### CellNumberEditor (the cell use of CMP-100 and CMP-101: an APG Spin Button in a grid cell)

| Keys                      | Action                                                                                                         |
| ------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Enter / F2 / double-click | At rest: opens the editor, a fresh field holding the live value, selected. `Space` is left to the grid.        |
| ↑ / ↓                     | One tick (a price, a trigger) or one lot (a quantity); `Shift` ten. An off-step value lands on the next step.  |
| ← / → / Home / End        | Open: move the caret, and never reach the grid.                                                                |
| Enter                     | Commits a valid value that differs from the live one; focus returns to the cell's value. Gated: sends nothing. |
| Esc                       | Restores the live value at once and returns focus; the grid's own `Esc` waits for the next press.              |
| Tab / a click elsewhere   | Restores the live value; focus stays where it went.                                                            |

| Element | Role       | Name                                              | ARIA                                                                                                           |
| ------- | ---------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| at rest | spinbutton | the host's `label`: "Price, ETHUSDT Buy on Sub-2" | `readonly`, `aria-valuetext` the shown value; T2: `aria-disabled`, described by the reason or the host's node. |
| editing | spinbutton | the same label                                    | `aria-valuetext` the typed text; described by the host's sentence, the step hint, a refusal or a gated commit. |
| lock    | img        | "Not available"                                   | Leads a T2 reason re-shown 2a under the cell or the editor; never among the numerals (E29-D02 D-8).            |

The value is the wire's decimal string and never becomes a JavaScript number: a step moves a scaled BigInt by the
tick or the lot, and a typed value off the step is refused with its reason, never rounded (E29-D02 §7: "without its
blur auto-round"). Well-formed thousands grouping is accepted and dropped ("2,495.00"); "2,5" is no number. `Enter`
alone commits; the host keeps the live value on the row until the exchange confirms (D02 D-10). The refusals are
E30's merged words where E30 has them (E30-D06 `ticket.order.v.price.tick`, "Price must be a multiple of 0.01.", and
`ticket.order.v.qty.lot`, "Minimum 0.001, step 0.001."); a price at zero or below and a trigger off its tick
(`CELL_TRIGGER_OFF_TICK`) are PROPOSED to E30-D02 §14's owner with E29-D03 informed.

While the editor is open the host suspends its grid keys and its trading hotkeys, from `onEditingChange(true)` until
`onEditingChange(false)` (E29-D01 D12): the editor stops only the keys it uses (`Enter`, `Esc`, `↑`, `↓`) and the
caret's (`←`, `→`, `Home`, `End`), so a chord or `PageDown` still reaches the host, which must send nothing for it.

T2 (E09-D09 §2.2; E29-D04 §4.1): a gated cell keeps its value's own look, with no glyph among the numerals and no
echo, and its Tab stop; `aria-disabled` and its description carry the state. The description is the editor's own
hidden reason node, or the host's notice through `disabledReasonId` (one notice, many pointers: a Viewer's or a
view-as panel-header line). `Enter`, `F2` or a double-click opens nothing: the reason is re-shown 2a under the cell,
the lock in `color.text.tertiary` leading it in `color.text.secondary`, and said once, politely; it goes when focus
leaves the cell. `commitGate` gates an open editor's commit the same way, under the editor, without `aria-invalid`,
and `Esc` restores. A gate that comes or goes never remounts the focused value. Plain `disabled` has no use on
SCR-063 (#912 BQ-9 makes a state that cannot be amended T2): it dims the value and takes the cell out of the grid's
focus order.

The step hint is not a CMP-016 tooltip, because an open tooltip takes the first `Esc` as its layer. It shares a note
with the live value, a refusal and a re-shown reason: CMP-016's surface, anchored under the cell, out of the flow and
with no pointer events, so the row keeps CMP-049's one row height (D01 D13 b holds the rows still while an editor is
open). The live value keeps `type.num.sm`'s tabular figures, so its digits line up with the cell's. A host whose rows
are separate stacking contexts raises the edited row above the rows its note covers.

Text resize (`05` §5 item 7: 200 % zoom and the in-app text scale): the field grows with its text (`size` follows the
value), so the cell widens rather than truncate a digit (E29-D02 D-8), and the well keeps at least the density's
control height. The note's words wrap inside its 20rem cap and grow over the rows below; the row itself never grows.
The grid's scroll region (CMP-049, `overflow: auto`) would clip the note in two places: under the last visible rows,
and past the region's inline end when the cell is at the right edge, where 200 % leaves 640 × 400 CSS px at the
1280 × 800 frame. So the editor brings the note into view whenever it shows (when the editor opens, when a refusal or
a gated commit's reason joins it, and when a refused press re-shows a reason) with
`scrollIntoView({ block: "nearest", inline: "nearest" })`: the region scrolls on the block and the inline axis only as
far as the note needs, and not at all when it fits. The call gives no `behavior`, so it is an instant jump, never
smooth (the theme sets `scroll-behavior: auto` under reduced motion); the host's region needs no code for it.
