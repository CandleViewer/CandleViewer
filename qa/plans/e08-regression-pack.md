# E08 regression pack (market data and ingestion)

Ticket: E08-Q06 (#283). Source plan: `qa/plans/e08-market-data-test-plan.md` (E08-Q01, #278). Case register of the contract pack: `services/api/tests/contract/bybit/E08_Q02_COVERAGE.md` (E08-Q02, #279). Same design as the E09 pack (`qa/plans/e09-regression-pack.md`, #297). All paths below are relative to `services/api/` unless they start with `apps/`, `docs/`, `packages/` or `qa/`.

## How to run

Automated backend subset (single command, no network, no docker):

```
cd services/api
uv run pytest -p no:randomly --no-cov -m e08_regression
```

`e08_regression` is a pytest marker registered in `services/api/pyproject.toml`. `services/api/tests/conftest.py` applies it at collection to the paths listed under "Marker coverage" below, so a new test in one of them joins the pack. A bare `-m` replaces the repo's default `-m` expression, so the marker is never put on `perf`, `fuzz`, `harness` or `flaky` (C-9.3 quarantine) items; those run in their own lanes. The run collects the whole tree first (about 1 min on the author's laptop).

Expected result: no failure and five strict `xfail`s, each pinning an open defect (section C). A fix flips its `xfail` to a failure, so the fixing PR removes the marker. Any other failure blocks the E08 sign-off. Counts and the dated record are in section D.

Editing this document? Run its guard before you push: `cd services/api && uv run pytest -p no:randomly --no-cov tests/qa/test_e08_regression_pack.py` (about 3 min: two whole-tree collections). CI runs the guard in the `py` lane, which does not start on a change to `qa/` alone (section C), so a docs-only edit is not checked there.

## C. Gaps and deviations (each cites an open issue unless marked untracked)

- **Nightly schedule (deviation).** No CI job selects `-m e08_regression` on its own, the same position as the E09 pack (#2716, labelled `post-ga`). A lane edits `.github/workflows`, which `.github/CODEOWNERS` routes to devsecops and security and `AGENTS.md` section 8 gates behind the `security-review` label, so this pack does not add one. The tests already run in CI: `py` on every Python change (chaos and abuse suites included), `integration` for the QuestDB round trips, `py-perf`, `fuzz-nightly` and `perf-ingestion-nightly` for the items the marker withholds. A lane, when added, runs the command under "How to run"; it must also add `qa/plans/e08-regression-pack.md` to the `py` path filter in `.github/workflows/pr.yml`, which has no `qa/` entry today.
- **Strict `xfail`s in the pack (open defects):** `tests/security/ingestion/test_fuzz_parsers.py::test_instrument_regression_launchtime_inf` and `tests/security/ingestion/test_market_integrity.py::test_malformed_instrument_row_cannot_fail_catalogue` (two parameters) pin #1896 (P2); `tests/security/ingestion/test_fuzz_parsers.py::test_checked_in_regressions_never_crash` (`book_ts_infinity.frame`) pins #1900 (P2, residual of #1889); `tests/security/ingestion/test_resource_exhaustion.py::test_never_idle_stream_does_not_starve_loop` pins #1893 (P2).
- **Order dependence:** `tests/contract/bybit/test_contract_trades.py::test_reconnect_replay_duplicates_are_published_once` fails in some full-gate orders and passes alone (#1899, open, no priority). The pack runs with `-p no:randomly`; it passed in the runs of section D.
- **Not automated anywhere yet:** the E08-Q05 browser, axe and screen-reader cases (#282 has not run); the WS gateway halves of C07, D02, E05, E07, E08 and F02 (#1878).
- **Not in this pack by design:** performance budgets (E08-Q04, `perf-ingestion-nightly`), the 24 h soak (#2825), and the docker-backed integration tests (CI `integration`).
