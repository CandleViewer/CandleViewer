# E47 accessibility black-box test plan

Ticket: E47-Q01 (#1314). Owner: QA with the Accessibility role. Status: **draft; group 4 is partly pending E47-D03 (and the E47-D01 baseline) and group 6 is partly pending E47-D02 (marked `pending`); the dry run (section 11) has not been executed.**

This plan is written against what a person can observe: screen ids (`docs/plan/14-screens-catalogue.md`), keystrokes, announced text and rendered colour. It never refers to component internals, so remediation can move code without rewriting it. The normative source for every case is `docs/plan/05-accessibility-standard.md` (the standard); severity follows `docs/plan/03-testing-strategy.md` section 11.3.

## 0. How to use this plan

- **Audience:** a QA engineer new to CandleViewer with a staging build and the fixture appendix (section 9). No author context is needed.
- **Environment:** the demo environment only. Never use live keys, real account identifiers or real P&L. Review every screenshot and speech transcript for sensitive strings before attaching it.
- **Case ids:** `E47-TC-<group><nn>`, for example `E47-TC-302` is group 3 case 02. Each case has a surface (screen id), the WCAG 2.2 success criterion (SC) it verifies, steps as keystrokes, an expected result and an automation status.
- **Verdicts:** write `pass`, `fail`, `blocked` or `not run` as words. Never record a verdict by cell colour. A mismatch of announced text is judged on the quoted facts and their order; punctuation and the screen reader's own role prefix (for example `table`, `link`, `button`) are tolerated variance. NVDA may say `minus` where the text shows `-`.
- **Automation column:** `Q03` keyboard e2e and tree snapshot, `Q04` axe and Lighthouse gates, `Q05` flash and performance, `T03` contrast linter, `T01` sweep register, `Q02` manual screen-reader pass, `X02` abuse cases; `S01`..`S08` the remediation story the case covers. **This column is a proposal until agreed with E47-Q03** (the Definition of Done item); `manual` means no automation is planned.
- **Observability tags:** record each result in the QA result store tagged `epic:E47` and `criterion:<wcag-id>`, for example `criterion:2.1.1`, using the SC column. File defects with the `a11y` label and the screen id.
- **Severity:** a task of the standard's section 8.2 script that cannot be completed keyboard and screen reader only is `priority/p0` and a release blocker. An awkward but completable flow is P1 or P2. Cases marked P0 in the first step are P0 on failure by this plan.
- **Jargon:** SC = success criterion; AT = assistive technology; SR = screen reader; DOM mirror = the hidden, focusable page structure that stands in for the WebGL canvas (standard section 6.1); live region = a page area whose text changes are spoken (6.2); CVD = colour-vision deficiency; G005 = the CI flash-rate gate.
