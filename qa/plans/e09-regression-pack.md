# E09 regression pack (auth, session, RBAC)

Ticket: E09-Q06 (#297). Source plan: `qa/plans/e09-auth-rbac-test-plan.md`. Automation status: `qa/plans/e09-q02-automation-status.md`.

## How to run

Automated backend subset (single command, about 1 min locally, no network, no docker):

```
cd services/api
uv run pytest -p no:randomly --no-cov -m e09_regression
```

`e09_regression` is a pytest marker registered in `services/api/pyproject.toml`. `services/api/tests/conftest.py` applies it at collection to the paths listed under "Marker coverage" below, so a new test in one of them joins the pack. A bare `-m` replaces the repo's default `-m` expression, so the marker is never put on `perf`, `fuzz`, `harness` or `flaky` (C-9.3 quarantine) items. The run collects the whole tree first (about 15 s).

Expected result: no failure; the chaos S1b test skips without docker. Any failure is a release-gate blocker. Counts and the dated record are in section D2.

Editing this document? Run its guard before you push: `cd services/api && uv run pytest -p no:randomly --no-cov tests/qa/test_e09_regression_pack.py` (about 20 s). CI runs the guard in the `py` lane, which does not start on a change to this file alone (section C, the #2716 item), so a docs-only edit is not checked there.

Frontend E2E (needs Playwright browsers; **not run by the pack author**): `apps/web/e2e/auth/*.spec.ts`.

Time budget: automated about 10 min including setup (about 1 min 20 s wall measured, section D2); manual items below about 2 h. The manual half has not been executed by anyone yet (#2491).

## CSRF position

CSRF protection currently relies on SameSite=Strict cookies, the Origin allow-list on cookie refresh, and bearer-header auth on state-changing routes (`test_ac_csrf_01`, `_02`, `_04`). There is **no double-submit CSRF token**; that is deferred to #2090 and the SR-152 "CSRF token absent/invalid" negative test is blocked by it.
