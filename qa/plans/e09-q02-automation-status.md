# E09-Q02 (#293) automation status

As built after PR 3 of 3 (the stub level, and the real-backend lane with its cold start and its server-clock specs; no product code). Case ids and plan rows are `qa/plans/e09-auth-rbac-test-plan.md` (E09-Q01).

- **Specs:** `apps/web/e2e/auth/` (repo convention; the ticket text says `tests/e2e/auth/`). Stub lane (`*.spec.ts`, the `e2e-web` job): 46 tests. Real lane (`*.real.ts`): 15 tests, 8 in `cold-start.real.ts` (project `real`) and 7 that move the server clock (project `real-clock`): `idle-lock.real.ts` 3, `step-up-expiry.real.ts` 1, `sign-out-everywhere.real.ts` 2, `lockout.real.ts` 1.
- **Support:** `apps/web/e2e/support/`: `api.ts` (stubs; `watchForLeaks` reads response bodies only and fails closed on one it cannot read), `wsHarness.ts` (a fake 23 gateway), `contexts.ts` (one user's sessions on a stubbed server, shared by several browser contexts, each with its own harness), `serverClock.ts` (the server test clock), `axe.ts`, `totp.ts`; for the real lane `real/stack.ts` (the fixture users, one per test, and the password, from the lane's environment), `real/signIn.ts` (the password through SCR-001, then MFA by in-page `fetch` at the server's time), `real/cookies.ts` (the jar's names and flags; values compared, never printed), `real/wsTap.ts` (a passthrough tap on the shared worker's socket, from `wsHarness.ts`'s bridge) and `real/failureArtefacts.ts` (the `lane` fixture: failure artefacts, a second browser, the audit rows, the refresh budget). Unit tests: `apps/web/test/e2e-server-clock.test.ts`, `e2e-real-lane.test.ts`, `e2e-leak-guard.test.ts`.
- **Stub level:** the API is stubbed at the network layer; the browser clock is `page.clock`, the stubbed server's is `SessionStore.advance` (no sleeps). C-13.4 puts login with 2FA end to end against a seeded stack, so the stub level is not the end state: the real lane is.
- **Real lane:** `.github/workflows/e2e-auth-real.yml`, nightly at 03:51 UTC and on dispatch, non-required (#2490). A throwaway stack on the runner: Postgres and QuestDB from compose, the API on testnet with the real storage backend, the synthetic feed and the server test clock (`CV_TEST_CLOCK`), 24 seeded fixture users each with a TOTP method; every password, key and seed is generated per run, masked and never committed. The built SPA is served by `vite preview` with `e2e/vite.real.config.ts`, which proxies `/api/v1` and its WebSocket to the API, so the browser sees one origin (`http://127.0.0.1`, where Chromium keeps `Secure` and `__Host-` cookies). `e2e/playwright.real.config.ts`: project `real` (2 workers) and `real-clock` (`@clock` specs, 1 worker, after `real`). No trace, video or screenshot is kept; a failed test attaches its `X-Correlation-Id` values and a read-only `audit_log` slice, uploaded for 14 days only if no password, key or TOTP seed of the run reached them.
- **Contract figures (`22-api-openapi.yaml` "Idle lock", `session_service.py`):** the idle lock is 15 min by default (5 to 60 min per user); the absolute lifetime is 12 h; the only activity is `POST /auth/session/extend` and a successful `POST /auth/unlock`. SCR-112 (not "SCR-111", the profile screen, which is not built) is the sessions list. Plan rows C02, C03 and C04 follow these figures (they said 8 h, 7 days and "13 h ago").
