# E02-Q02 — Charter Session 1: "From zero to green gate"

Format per `docs/plan/03-testing-strategy.md` §11.2. Executed as a non-author,
clean-clone simulation: a fresh git worktree from `origin/main`, a fresh
`pnpm install` / `uv sync`, no reuse of any pre-warmed cache belonging to the
scaffold's authors, on the pinned toolchain versions from `/README.md`.

## Charter

**Mission:** starting from only the committed docs (`/README.md`,
`/AGENTS.md`), go from a clean clone to a green `pnpm verify` and a green
Python gate (`ruff`, `ruff format --check`, `mypy --strict`, `pytest`) without
asking the scaffold's author anything, or file every point that required a
guess as a documentation defect.

**Areas to probe:**

- Prerequisite versions as pinned in `/README.md` §"Prerequisites".
- `pnpm install` from cold cache (timing, warnings, errors).
- `uv sync --frozen --project services/api` from cold cache.
- `pnpm verify` (lint/typecheck/test/build/size across every workspace
  package) run start-to-finish, uncached.
- The Python unit gate as documented in `AGENTS.md`'s command table
  (`pytest -m "not integration" --cov=. --cov-fail-under=85`, run from
  `services/api/`).
- CRLF/LF integrity of shell scripts and hooks after checkout on Windows
  (closest available proxy for `/mnt/c` semantics — see Coverage assessment).

**Oracles (what "looks wrong"):**

- Any step in the documented Clone → install → verify path that fails,
  hangs, or produces an error a new joiner could not self-diagnose from the
  README's Troubleshooting section.
- A gate presented as "green" in docs that is not actually green on a clean
  checkout.
- Any prerequisite version drift between what's pinned and what's actually
  required to succeed.

## Coverage assessment

This session's environment is **native Windows** (Git Bash), not WSL Ubuntu —
the target environment per `20-architecture.md` §5 — because the available
non-author machine for this charter run had no WSL distro provisioned and no
Docker Desktop installed (see Session 2 note on Docker). Per the ticket's
"Out of scope" note ("a finding that something _only_ works on one host OS is
still reportable"), this session is reported as a **best-effort substitute**
for the WSL-Ubuntu session-1 charter, not a replacement for it: findings that
are OS-agnostic (pnpm/uv install behaviour, `pnpm verify` flake, the
hypothesis deadline flake, CRLF integrity, doc accuracy of the Prerequisites
table) are reported with full confidence; the `/mnt/c`-vs-WSL-filesystem
warning itself could only be verified as _present and worded correctly_, not
empirically reproduced (no WSL available on this machine to time the 9p
filesystem penalty first-hand). **Recommendation:** re-run this specific
sub-check (empirical timing of `/mnt/c` vs WSL-native clone) on an actual WSL
Ubuntu machine before E02 is marked Done, to fully close AC2's "or they pass"
branch — filed as a follow-up note under Bugs filed (P3, tracking only).
