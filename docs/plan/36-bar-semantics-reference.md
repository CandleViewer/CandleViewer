# 36. Bar semantics reference (E12-K02)

> **Normative reference** for what a bar _means_, written for the epics that consume bars: indicators
> (E13), footprint (E18), profiles (E19), CVD and delta panes (E23), replay (E26) and the rule
> node-graph editor (E37). It is producer-side and backend-facing. `25-market-data-trust-contract.md`
> stays the short consumer checklist, and `26-chart-engine-design.md` stays the client-side view; neither
> restates this file, and this file links to them rather than restating their rules (C-16.5).
>
> **As built at `main` commit `c6b53ad9d`** (2026-11-04). Items that change when open work merges are
> marked _pending #N_; rows marked _pending #N_ are refreshed when #N merges (guidance, not a rule of
> this file). Statements that are planned but not built are never written here as behaviour.

## 0. Scope, classification and how to read this file

- **Classification.** Bars are **public market data**: a deterministic, lossless transform of the
  exchange's public trade prints (`25` §1, "measured"). They carry no account, order, key or user
  field. That does **not** make them low-stakes: rules (E37) may place live orders on bar closes, so the
  integrity statement of §8 binds every consumer. Do not weaken bar handling on the assumption that it
  is "just chart data".
- **Families.** Six server-built families (`time`, `tick`, `volume`, `range`, `delta`, `renko`) and one
  client-side transform (Heikin-Ashi, §3). `pnf` is not built.
- **Evidence.** Every normative row names its evidence: a QA case id from
  `qa/plans/e12-bars-and-series-test-plan.md` (`E12-TC-…`), a golden conformance pair from
  `packages/fixtures/golden/bars/conformance/MANIFEST.toml` written `golden:<tape>/<pair>`, or a test
  written `test:<path>::<name>` (paths under `services/api/tests/` unless they start with `packages/`).
  A claim with no backing test is removed or turned into a test. The one exception is the claims
  #2200 tracks (a range case with no golden yet), labelled **convention, no golden (#2200)**. The
  unit test `test_bar_semantics_trace.py` fails when a cited id does not exist, when an evidence cell
  is empty or missing, when the label names another issue, when a §9 signal is not registered or
  a §9 metric is not in `20` §12.1 with its labels, when a table loses its Evidence column, or when
  `pr.yml`'s `py` filter misses a file the test reads. The golden
  tapes are synthetic, generated from documented message shapes (exception #1778 A), not recorder
  captures.
- **Names and units.** The domain model (`24` §3.1) names times `open_time`/`close_time`: integer
  microseconds since the Unix epoch, UTC. The wire renames them and changes the unit, and this file uses
  the wire names where a consumer sees them:

| Domain (`24` §3.1) | Store (`21` §4.8)               | REST `Bar` (`22`)               | WS item (`23` §14.3)                             | Meaning                                  |
| ------------------ | ------------------------------- | ------------------------------- | ------------------------------------------------ | ---------------------------------------- |
| `open_time`        | `ts`                            | `t`                             | `t_ms`                                           | Bar open time (per family, §2)           |
| `close_time`       | `close_ts`                      | `close_time`                    | `close_t_ms`                                     | Bar close time (per family, §2)          |
| (unit)             | µs, UTC (QuestDB timestamp)     | ISO-8601 string, UTC, to the µs | integer ms since the Unix epoch, floored from µs | WS time bars send no `close_t_ms` (§2.1) |
| `closed`           | `is_closed`                     | `confirm`                       | `confirm`                                        | Final, subject to §4                     |
| `index`            | `index`                         | `index`                         | `index`                                          | Position inside a generation             |
| (series epoch)     | `generation`                    | `generation`                    | `generation`                                     | §1                                       |
| `trade_count`      | `trade_count`                   | `trades`                        | `trades`                                         | Prints folded in (§2.3 for splits)       |
| (not on the bar)   | `open_source_ts` (range, renko) | not served                      | not served                                       | §2.4, §2.6, divergence V-2               |

The ticket's working names map as follows: `t_ms` and `close_t_ms` are the WS names above;
`open_source_ts` is the range and renko column; `no_data_recorded` is the 422 problem code of §6.

## 1. Common model

| Concept             | Rule                                                                                                                                                                                                                                                                                                                          | Evidence                                                                                                                                                                                                                                                         |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Input               | Every builder consumes normalised trade prints only, never exchange klines. | Determinism (BI-4)  | The same ordered, deduplicated tape and the same `build_version` produce identical closed bars, `spec_hash` included.                                                                                                                                                                                                         | `golden:btcusdt-2026-09-01/time:1`, `test:unit/bars/test_conformance_behaviour.py::test_rebuild_twice_identical_and_build_version_bump_keeps_bars`                                                                                                               |
| Conservation (BI-1) | The volume of all bars of a series, the open bar included, equals the volume of the prints applied. A time-bar print the builder drops (§2.1) is not applied.                                                                                                                                                                 | E12-TC-X02, `test:unit/bars/test_conformance_behaviour.py::test_exact_fill_closes_without_empty_successor_and_overshoot_conserves_volume`                                                                                                                        |
| Delta (BI-2, BI-3)  | `delta = buy_volume - sell_volume`; `min_delta <= delta <= max_delta`, the extremes of the running intra-bar cumulative delta in **arrival** order (not endpoint values).                                                                                                                                                     | E12-TC-X05                                                                                                                                                                                                                                                       |
| VWAP (BI-6)         | `vwap = turnover / volume`, half-even to 8 dp; `open` when `volume = 0`.                                                                                                                                                                                                                                                      | `test:unit/bars/test_determinism_harness.py::test_bi_invariants_hold_on_pr_gate_tape`                                                                                                                                                                            |

| `spec_hash`         | sha256 over the canonical JSON of the full `BarSpec`, defaults included (`24` §3.1). One hash per series; the wire pair `(bar_type, param)` maps 1:1 to it.                                                                                                                                                                   | `test:unit/bars/test_bar_spec.py::test_canonical_json_includes_every_field_sorted_without_whitespace`                                                                                                                                                            |
| Identity            | A bar is identified by `(series, generation, index)`. `t`/`t_ms` is **not** unique for non-time bars: one print can yield several volume bars or renko bricks with one open time. Key bars by `(generation, index)`, never by time.                                                                                           | `test:unit/bars/test_bars_key_by_index.py::test_three_volume_bars_from_one_print_survive_write_read_round_trip`, E12-TC-D11                                                                                                                                      |
| `index`             | Strictly increasing inside a generation, starting at 0 in a fresh generation; never renumbered.                                                                                                                                                                                                                               | `test:unit/bars/test_same_ts_bars_property.py::test_same_open_time_bars_round_trip_storage_and_page_by_key`                                                                                                                                                      |
| `generation`        | An opaque epoch id. A builder cold start begins a new one (normally higher, `24` §3.5); an ADR-0033 rebuild swap would too (§5). A window may hold bars of several generations.                                              | `test:unit/bars/test_builder_set_generation.py::test_crash_after_a_cold_start_restarts_in_a_new_generation`                                                                                                                                                      |
| `build_version`     | An integer per family, bumped by a builder-algorithm change. All six are `1` today. Each stored row records the version that built it.                                                                                                                                                                                        | `test:unit/bars/test_conformance_behaviour.py::test_rebuild_twice_identical_and_build_version_bump_keeps_bars`                                                                                                                                                   |
| Duplicates          | Builders do **not** suppress duplicate prints. Duplicate trade frames are dropped upstream, at ingestion, by trade id within a bounded per-symbol window. A duplicate that escapes that window is folded twice.                                                                                                               | `test:unit/bars/test_conformance_behaviour.py::test_duplicate_trade_id_is_not_suppressed_by_builders_but_by_the_upstream_ring`                                                                                                                                   |
| Sources             | A stored row is `tape`, `parquet` (restored tape) or `kline` (exchange kline backfill, time bars only). | First bar           | The first bar a fresh builder forms is `partial: true`: prints before the builder started are not in it.                                                                                                                                                                                                                      | `test:unit/bars/test_time_builder.py::test_on_trade_only_first_bar_is_partial`, `test:unit/bars/test_activity_builders.py::test_first_bar_partial_marks_where_tape_begins`                                                                                       |
| Tape gap            | After an unrecovered gap in the trade tape, the bar of every builder that takes the first print after the hole carries `gap_before: true`. A pre-hole straggler never takes the flag. The pending flag is in memory only and is not carried across a restart.                                                                 | `test:unit/bars/test_builder_set_gap_marking.py::test_unrecovered_gap_flags_every_builder_type_in_one_set`, `golden:btcusdt-2026-09-02-gap/tick:100`                                                                                                             |

## 2. Per-family semantics

Notation: `W` is the bar's width in price units (`param × tick_size`, exact `Decimal`). "Arrival order"
is the order the builder receives prints. "Event order" is `(ts_event, seq)`.

### 2.1 Time bars (`time`)

| Aspect                     | Rule                                                                                                                                                                                                                                                                                 | Evidence                                                                                                                                                                                          |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Param                      | A catalogue interval code: `1 3 5 15 30 60 120 240 360 720 D` (minutes, day) is built from the tape. `M` is refused (calendar-variable).                                                                                                                                             | `test:unit/bars/test_bar_spec.py::test_check_param_bounds_accepts_the_floor_and_the_ceiling`                                                                                                      |
| Weekly (`W`)               | The spec parser accepts `W`, but the time builder refuses any interval above one day, so `W` is **never built from the tape**. Weekly rows exist only as exchange-kline rows (`source: kline`, §6), whose weeks open on **Monday** 00:00 UTC, not on the 00:00 UTC epoch grid below. | `test:unit/bars/test_time_builder.py::test_validate_time_spec_rejects_out_of_range_or_fractional_seconds`, `test:unit/exchange/bybit/test_klines.py::test_parse_kline_page_weekly_grid_is_monday` |
| Grid                       | `open = floor((ts - anchor) / step) × step + anchor`, anchor `00:00 UTC` (the only wire-representable anchor).                                                                                                                                                                       | `test:unit/bars/test_time_builder.py::test_bucket_bounds_session_anchor_480_shifts_hour_grid_and_hash`                                                                                            |
| Close (boundaries)         | Half-open `[open, close)`: a print at exactly the boundary opens the next bar. Each bar closes exactly once.                                                                                                                                                                         | E12-TC-A02, `test:unit/bars/test_time_builder.py::test_on_trade_exact_boundary_timestamp_opens_next_bar`                                                                                          |
| Times                      | `t` and `close_time` are the bucket boundaries, not trade times: `close_time = open_time + step` exactly, the next bar's open (exclusive end, never `open + step - 1`). A kline row stores the same value. WS time-bar items send no `close_t_ms`: derive it as `t_ms + step`.       | `test:unit/bars/test_time_builder.py::test_bucket_bounds_session_anchor_480_shifts_hour_grid_and_hash`, `test:unit/ws/test_bars_wire.py::test_bar_item_sends_close_t_ms_for_non_time_bars`        |
| OHLC order                 | `open`/`close` follow event order, so a reordered print lands in the right place; equal timestamps order by `seq`.                                                                                                                                                                   | `test:unit/bars/test_time_builder.py::test_on_trade_equal_timestamps_order_by_seq`                                                                                                                |
| Clock close                | The open bar closes when the builder's clock reaches its close time, even with no print (dead market).                                                                                                                                                                               | `test:unit/bars/test_time_builder.py::test_on_clock_dead_market_closes_open_bar_on_its_boundary_and_emits_nothing_else`                                                                           |
| Empty interval             | No bar is emitted for an interval with no print (no phantom zero-volume bar). The next real bar has `gap_before: true`. `BarSeries.densify()` fillers are view-only, never stored or sent.                                                                                           | E12-TC-A03, `golden:ethusdt-2026-09-03-thin/time:1`                                                                                                                                               |
| Late print, ≤ 60 s         | A print whose bucket is a bar that closed no more than 60 s before the builder's watermark (the highest print or clock time seen) is applied to that bar, which is re-emitted as a close with `amended: true` and the same `(generation, index)`. Later bars are untouched.          | E12-TC-A05, `test:unit/bars/test_conformance_behaviour.py::test_late_print_after_close_within_window_amends_the_closed_bar`                                                                       |
| Late print, > 60 s         | Dropped and counted (`bars_late_trade_dropped_total{reason="late_window"}`).                                                                                                                                                                                                         | `test:unit/bars/test_conformance_behaviour.py::test_late_print_beyond_60s_window_is_dropped_and_counted_late_window`, `golden:btcusdt-2026-09-02-gap/time:1`                                      |
| Late print, empty interval | Dropped and counted (`reason="empty_interval"`): creating a bar there would break the increasing `index`.                                                                                                                                                                            | `test:unit/bars/test_conformance_behaviour.py::test_late_print_into_empty_interval_is_dropped_and_counted_empty_interval`                                                                         |
| Out of order, open bar     | Applied to the open bar.                                                                                                                                                                                                                                                             | `test:unit/bars/test_time_builder.py::test_on_trade_out_of_order_inside_open_bar_is_applied`                                                                                                      |
| Wall-clock comparable      | Yes: time bars of one interval align across symbols.                                                                                                                                                                                                                                 | `golden:btcusdt-2026-09-01/time:5`                                                                                                                                                                |

### 2.2 Tick bars (`tick`)

| Aspect                | Rule                                                                                                                                          | Evidence                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Param                 | Prints per bar, 100 to 1 000 000 for a served series (SR-E12-03); refused outside, never clamped.                                             | E12-TC-D12, `test:unit/bars/test_activity_builders.py::test_subscribable_tick_floor_matches_sr_e12_03`        |
| Close                 | After exactly `tick_count` prints, however the prints were batched on the wire. A block trade counts as one print and its full volume counts. | E12-TC-C01, E12-TC-C05, E12-TC-C06                                                                            |
| Times                 | `t` = event time of the first print, `close_time` = event time of the last (event order).                                                     | E12-TC-X04                                                                                                    |
| Empty interval        | Not applicable: tick bars never close on the clock.                                                                                           | `test:unit/bars/test_activity_builders.py::test_on_clock_is_noop`                                             |
| Late / out of order   | A closed bar is final; a late or out-of-order print joins the **open** bar, with OHLC in event order. Ratification pending #2013.             | `test:unit/bars/test_conformance_behaviour.py::test_timestamp_regression_in_activity_bars_joins_the_open_bar` |

### 2.3 Volume bars (`volume`)

| Aspect                    | Rule                                                                                                                                                                                                                     | Evidence                                                                                                                |

### 2.4 Range bars (`range`)

| Aspect                | Rule                                                                                                                                                                                                                                                            | Evidence                                                                                                                                         |

## 3. Heikin-Ashi (client-side transform)

Heikin-Ashi is **not** a server bar family. REST and WS refuse `bar_type=heikin_ashi` (422 /
`invalid_topic_format`), naming `time` as the alternative: the conformance manifest's `rejected_pair` `heikin_ashi:5`,
REST `test:contract/test_market_bars_contract.py::test_unbuildable_type_is_422_naming_alternatives` (422) and
`test:contract/ws/test_ws_bars_e12_q04_contract.py::test_contract_bars_unbuilt_bar_types_are_invalid_topic_format`
(`invalid_topic_format`). The chart engine transforms the time bars it already holds:

## 8. Integrity

- Each stored row carries an **unkeyed** checksum over its value columns, verified on read; a failing
  row is withheld and counted (`bars_checksum_mismatch_total{table,reason}`)
  (`test:unit/bars/test_bars_persistence.py::test_checksum_mismatch_and_missing_are_integrity_events`).
  The one exception is a legacy row with neither `source` nor checksum that opens before the
  provenance cutover (2026-10-07, QuestDB migration 0003): it is served trusted. A row like that from
  the cutover on is withheld and counted as `reason="missing"`
  (`test:unit/bars/test_bars_provenance_cutover.py::test_read_bars_withholds_and_counts_a_post_cutover_row_without_provenance`).
  The checksum detects naive edits only: anyone with write access to the store can recompute it. It is
  not a security boundary.
- One production writer writes bar rows: `bars/writer.py`
  (`test:unit/bars/test_bars_single_writer_guard.py::test_only_the_bar_writer_writes_bars_rows`).
- The exchange provides no checksum for trades or klines (ADR-0005), so nothing upstream of the tape
  can be verified cryptographically either.
- The integrity statement of E12-X04 (#538; the as-built review merged in #5583, the sign-off is _pending_): **served bars match the recorded tape or are marked**
  (`tape_gap` per bar, `meta.coverage_holes` per range). The "or are marked" half is **partly served**:
  REST and WS snapshots list the ranges of closed bars built but not stored (G8). The per-bar flags
  (N1, N7) and a marker for a row withheld by its checksum (F9, raised on #452, owned by #5581) are not served, so a withheld row
  still leaves a silent gap; that is why order-placing paths gate as §7 says.
- A consumer that needs stronger assurance (an audit export, a dispute) re-derives bars from the
  recorded tape with the same `build_version` and compares (G1); it never trusts a stored bar alone.
