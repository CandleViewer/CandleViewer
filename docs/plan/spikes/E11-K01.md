# E11-K01 — Spike: the SDF glyph set and atlas size for the design font (O2)

- Ticket: E11-K01 (#332). Branch `spike/e11-k01-sdf-atlas`. The harness is **throwaway**
  (`E11-K01-harness/`, BQ-182); this PR carries the findings and the doc amendments. Owner approval pending.
- Decision records: ADR-0002 "O2 atlas configuration, re-confirmed with real font rasterisation — 2026-10-31";
  `26-chart-engine-design.md` §3.7 and §16 O2; `05-accessibility-standard.md` §6.6; E11-S11's Scope
  (`backlog/E11.json`).
- Figures: `E11-K01-results.json` (generated, every number below comes from it); images `E11-K01/img/`.

## Read first: what this run is and is not

- **The font is a stand-in.** The design fonts (JetBrains Mono 400 for cells and axis, Inter 600 for the
  watermark; `16` §2, E11-D02 §6 and D13) are not vendored (G-42) and are not installed on this host. They
  were not downloaded. The run used **Liberation Mono 2.1.5 Regular** for JetBrains Mono and **Liberation
  Sans 2.1.5 Bold** for Inter 600 (the nearest installed weight); their SHA-256 values are in the results
  file. The stand-ins are fonts of the same kind (a 0.6 em monospace and a bold grotesque), so the counts,
  fill and timings transfer in kind; the legibility figures and the ink heights are font-specific and are **re-read
  with the shipped fonts**. The font **choice** is final: `16` §2.2 records Inter and JetBrains Mono as locked
  by owner decision on 2026-09-25. Only the **files** are missing: `packages/ui/src/fonts/` does not exist,
  and no backlog ticket vendors it today (G-42, routed to the orchestrator). The harness reads the shipped
  variable WOFF2 files as they ship (`cmap.mjs` decodes WOFF2; Chromium's `FontFace` loads it), so once they
  are vendored the rerun is one command on the bytes the cache key hashes (`E11-K01-harness/README.md`).
  Before then a rerun on the VR image's TTF builds is valid only if their version string equals the shipped
  files'; their SHA-256 differs from the WOFF2's by construction. The harness gained the `fonts[].version`
  field after the recorded run, so `E11-K01-results.json` does not carry it; the next run records it.
- **The host is below class and contended.** An 8-vCPU VPS (Xeon Gold 6252) shared with two other agents
  and the `cv-bench-01` runner; the run started once the 1-minute load average fell to 11.9 and ended at 17.3.
  Chromium 156 headless shell; WebGL2 is SwiftShader. Under the #220 evidence rule a gate **met** here is
  conservative evidence; a gate **missed** here is inconclusive and is re-measured (ADR-0002 "Evidence
  class"). The configurations ran **one after another, not interleaved**, while the load rose, so
  comparisons **between** configurations (the floor set's saving, `mono24-full` against `full`, 2048² faster
  than 512² and 1024²) are confounded by that drift and are indicative only.
- **Method.** Playwright drives Chromium on a `127.0.0.1` page. Cold generation runs in a **fresh module
  worker per sample** (n = 20): `FontFace` from the font bytes, OffscreenCanvas `fillText` per glyph, a tight
  ink box padded by the spread, the unchanged two-pass EDT of `bench/scenes/edt.mjs`, and a shelf pack into
  one R8 texture. A second build in the same worker gives the JIT-warm cost. Warm load is the real
  IndexedDB (n = 50). Legibility renders every mono glyph with WebGL2 beside native `fillText` at the same
  device size. Coverage is decided from the font's `cmap`, never from what Chromium draws.
- **What the timing columns mean.** The percentile is nearest-rank with a floor, so at n = 20 the cold
  "p95" index is 19: **every cold p95 below is the maximum** of 20 samples, and the tables label it
  "max". The warm p95 (n = 50) is a true p95. The cold figures below are generation only; font load (its own
  column, about 38 ms p50) and the worker spawn are reported beside them, not inside them. Whether the 60 ms
  gate excludes them is an **open interpretation for the architect and the orchestrator**, not a finding. On
  a cache hit the render worker draws SDF quads with the record's metrics and needs no `FontFace`, so the
  cache does avoid the bytes-to-`FontFace` load; it does not avoid fetching the font bytes and hashing them
  for the cache key. E11-S11 K2 measures and reports the cold figure both ways.

- **Coverage passes at every size.** No glyph was missing from a stand-in font and none overflowed, so no row
  is rejected. The harness writes `REJECTED (coverage …)` instead of dropping a row, and `cmap.mjs` reports
  any codepoint the font lacks.
- **Cold generation misses the 60 ms gate on this host, at every size and for every set.** The cost does not
  depend on the atlas size: it is the raster stage (`fillText` and one `getImageData` per family) and the
  Float64 EDT, about evenly. A fresh worker pays JIT warm-up on top; the same build run a second time in the
  same worker (the "JIT-warm" column) costs about 40 % of the cold figure. A cold generation happens once
  per font file and generator version, on first launch; every later launch reads the cache. The fresh
  workers run in one renderer and may share V8's code cache, so these cold figures may understate a true
  first launch.

  `engine.text.atlas_generate_ms` and re-measures with the shipped fonts on the reference class. Its levers,
  measured here (indicative, as the rows ran one after another): generate the mono family first and the
  Inter watermark after the first frame (the `mono24-full` row, under half the cold p50 of `full`); then a
  Float32 EDT (not measured); the floor set saves least. E11-S11's pass/fail rule is in "Requirements".

- **`fwidth` beats the fixed band** on median SSIM and on the worst cell glyph in all nine cases. On the
  closest pair it does not: the fixed band separates it better at 10 px dpr 2 (0.804 against 0.775), 11 px

- **The computed gates are not met at dpr 1 and 1.25** (`gates.ssimMinAt10pxDpr1` = 0.9 on the cell-glyph
  SSIM minimum, `gates.pairRatioMin` = 0.8). The median glyph is near native (0.85–0.95), but thin
  horizontal glyphs (`_`, `` ` ``, `-`, `=`, `~`) lose their one-pixel hinting, and the 5/6 and 6/8 pairs
  come out closer together than native draws them. At dpr 2 the cell glyphs reach 0.79–0.84 and the pairs
  0.78–1.01.
- These are computed proxies, not the ticket's test. The ticket escalates to MSDF only if a blind A/B fails
  at 11 px. Under the agent-delivery adaptation that A/B is the owner's walkthrough of the images in
  `E11-K01/img/` (each image stacks, per size, native, then `fwidth`, then the fixed band). Every finding
  here is `(heuristic)`. MSDF was **not evaluated**: its trigger moves to E11-S11's K3 A/B, and 11 px dpr 1
  does fail the proxies (cell-glyph SSIM min 0.262, pair ratio 0.596). MSDF keeps corners sharp when a glyph
  is **magnified**; the loss measured here is most likely hinting under **minification** (24 px drawn at
  10 px), which MSDF does not restore — so it is not the next step. That is argued, not measured:
  `(heuristic)`.
- **Biases of the proxy.** SSIM is computed once over the whole glyph cell, not windowed, and the black
  padding around the ink inflates it. The SDF quads land at fractional offsets while native `fillText` sits
  on a whole-pixel baseline, so a one-pixel feature (`_`, `-`, `=`) can score near 0 from sub-pixel
  registration alone. The run does not separate registration from the loss of hinting, so "hinting" above
  is the likelier cause, not a measured one. "Native" is headless Chromium's Linux `fillText` with
  SwiftShader as the GPU, not DirectWrite on a hardware GPU as the product ships on Windows, so the reference
  itself may differ from what a user sees.

## LOD floor (BQ-185)

Ink height of the cell glyphs (`0–9 . , - + % × K M B ▲ ▼ ( )`) at dpr 1, from `measureText` ink extents,
and the smallest one-row cell that holds it with a 1 px outline above and below (`legibility.ink` in the
results). This is a **geometric fit check, not a legibility test**, and it rests on two assumptions: the
1 px outline width is E06-D01 §5's resolution text (no token freezes it), and the outline lying inside the
cell is this spike's assumption, frozen nowhere.

| Class | Cell-glyph ink | Digits-only ink | Smallest cell with outline |
| ----- | -------------- | --------------- | -------------------------- |
| 10 px | 9 px           | 9 px            | 11 px                      |
| 11 px | 10 px          | 9 px            | 12 px                      |
| 13 px | 13 px          | 11 px           | 15 px                      |

`LOD_PROFILE_M0` (E06-D01 §2) puts L0 (two numbers) at 12 px and L1 (one number) at 10 px for the 10 px
class, and E06-D01 §2 validated L1 = 10 px with readers. With the stand-in font, the 10 px class fits L0
with its outline, but **the ink plus a 1 px outline does not fit a 10 px cell** (geometric check, stand-in
font; 11 px needed). That is not a legibility result and does not by itself contradict L1. Ink height depends
on the font's ascent and descent, so no change request is raised on a stand-in; `05` §6.6 quotes the frozen
floors and records the geometric minimum cell heights (11 / 12 / 15 px). A change request goes to E06-D01
only on the shipped font and with a legibility check (never a silent edit, never on geometry alone).

## Requirements recorded for E11-S11 (and E14-T03)

1. Load the font from bytes with a worker `FontFace`; never let a fallback face fill the atlas (G-42).
2. An out-of-set character draws `?` from the same family and trips a dev assertion; `glyph-runs.mjs`'s
   silent skip is not carried over (G-43, BQ-181). The atlas never grows at runtime (E14 DR8).
3. Cache key and packed-rows record as in "Answers"; a checksum mismatch regenerates (E11-S11 AC).
4. `sizeClass` leaves the cache key; a DPR change never regenerates (BQ-175, and #5206's `onDprChange`
   seam becomes a no-op for the atlas).
5. **K1, shipped fonts.** Rerun the harness on the vendored WOFF2 files (or, before they are vendored, on
   TTF builds whose version string matches them). Pass: 0 missing and 0 dropped at the chosen size. Fail:
   a further ADR-0002 amendment before any atlas code merges.
6. **K2, cold generation and warm load** on the reference class, with n ≥ 40 so the p95 is not the
   maximum. Pass: cold generation p95 ≤ 60 ms, reported both with and without the bytes-to-`FontFace` load
   and the worker spawn (which reading gates is open for the architect and the orchestrator, "Read first"),
   and the packed-rows open + get p95 ≤ 5 ms (B9), reported also with the `texSubImage2D` upload and the
   font-bytes fetch plus SHA-256 that the key needs (not measured here). On a cold miss apply, in order, and re-measure after each: the
