## Product (from research, docs/research/00-README.md + 24-owner-decisions.md)
Private, self-hosted trading terminal for one owner + a few account managers: TradingView-grade charting UX + DeepCharts-grade order-flow visibility (footprint, volume/delta profiles, Deep-Stats rows, big trades, CVD, DOM liquidity heatmap, speed of tape, imbalance tracker, iceberg/stop-run *estimated* detectors, market regime, tick replay) + full execution loop (fast order ticket, chart/DOM trading, brackets, scaled orders, emulated OCO/iceberg/TWAP/chase, rule-based stops via a rule engine with BOTH a form editor and a node-graph editor) + paper trading (Bybit demo) + multi-account trade-group fan-out + journal/analytics + admin.

## Locked decisions
- Exchange: Bybit v5, **USDT linear perpetuals only** in v1; exchange adapter abstraction for future exchanges. Environments: live + demo (testnet smoke-tests only). WebSockets everywhere available; demo has no WS order entry (REST).
- Frontend web: React + TypeScript, **fully custom WebGL chart engine** (own package), Electron desktop shell primary (Tauri measured in spike). Owner/admin functions (users & roles, Bybit accounts & API keys, per-account profiles, audit log, recorder/storage, system health, feature flags) are RBAC-gated screens **inside the web app** — there is NO separate admin app.
- **Android: OUT OF SCOPE for the current plan** (owner decision 2026-09-14). Backend API/WS protocol must remain client-agnostic so a mobile client can be added later; no Android tickets, designs or architecture docs are to be produced now.
- Backend: Python (3.12+), FastAPI/Starlette, asyncio; monolith with modular internals (ingestion, book engine, bar builders, order-flow engines, OMS, rule engine, paper matcher, recorder, replay, auth/RBAC, admin). Runs in WSL Ubuntu via docker compose, later a VPS.
- Storage: QuestDB (hot ticks/L2/bars) + Parquet/DuckDB (cold/replay/analytics) + Postgres (relational: users, accounts, keys, profiles, rules, OMS state, journal, audit).
- Recording: user-managed recorded-symbol list (empty by default) + auto-record symbols with open chart/position; retention default 30 d, pin to keep.
- Accounts: main + sub-accounts; per-account profiles (leverage, sizing rule, SL/TP offsets, risk caps, allowed symbols); one ticket → fan-out to N accounts as a "trade group". Withdrawal permission always OFF; IP whitelist; keys envelope-encrypted; RBAC Owner/Manager/Viewer; append-only audit log. Every fanned-out order carries a native exchange-side SL.
- Remote access: Tailscale only. Heatmap colours: green=bid, red=ask, configurable. Options/GEX: out of scope.
- **Statechart runtime: `xstate-statemachine==0.9.1` ADOPTED** (owner decision, 2026-09-24, after 14 verification
  rounds; `ADR-0016` Accepted). Pin: tag `v0.9.1` = `45bb7f3`, wheel-equals-tag 42/42, sha256
  `d832d4d9a17b7b8003f61fa0714a8e57eaff316bcd5dd699d81d410362687162`, PEP 740 attested. Every long-lived
  lifecycle in `28-statechart-catalogue.md` (B1–B20) is executed **exclusively** through `cv.statechart.factory`
  — no in-house shim, no dual-runtime harness, no phased retirement. Hot paths (book deltas, bar builders,
  footprint aggregation, per-tick rule evaluation, paper matcher, rate-limit admission) remain plain code
