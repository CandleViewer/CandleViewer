**Two scales share the letter T.** The tiers above are test tiers. The design's gating treatments T1 to T4
(`docs/design/E09/E09-D09.md` §2.2: enabled, disabled with a visible reason, hidden, server-denied) are another scale,

**Selection rule.** Each state runs at least once on the cheapest tier that can force it (C-13.1) and gets an E2E case
only where a user can see it (C-13.4). A state where the role matters (scope-sensitive or mutating) runs against every
role; any other state runs as Owner plus one Viewer read where a case lists roles (a case's Preconditions name the roles
it runs). The trading environment is demo only (live is forbidden by the ticket); one server serves one environment
(C-2.11), so a mixed-environment row cannot occur (S-23 stays `register`).

### 1.4 Determinism

- **Time** is a fake clock everywhere: `page.clock` and `captureTwice` in the browser
  (`packages/fixtures/src/e2e/capture.ts`), a `VirtualTimeLoop` and injected clocks in the backend. HARN counts server
  times from the fixture's epoch and the test sends every frame (`apps/web/e2e/support/wsHarness.ts:5`). No sleep; a
  wait is an event, a condition or `expect.poll` (C-13.7).
- **Order of delivery** is part of a fixture: frames carry their `ts` and `seq`, and a scenario lists them in the order
  the case needs (a gap, a reversal, a duplicate are separate scenarios, never random).
- **Randomness** is seeded; suites run in randomised order and must pass in any (C-13.7). A flaky case is quarantined
  with `@flaky` within 24 h (C-9.3), never deleted.
- **The ticket's determinism criterion** ("replayed twice, the same OMS state") is proved at the parse level by this
  ticket: a scenario replayed twice through the adapter's own parsers (REST through `httpx.MockTransport`, the stream
  through `FakeTradingPort`) yields identical normalised events. E29-Q02's conformance test proves it at the OMS-state
  level (ruling, BQ-6). The "mock exchange" is `FakeTradingPort` plus those parsers; no stateful mock exists.

## 3. The matrix: states × roles × environments

The matrix is a coverage map: one row per state, with the roles that see it, the tier and lever that force it, the oracle,
the transition rules, the cases that carry its steps, who runs it and what exists today. Its columns are the case
columns of §1.6, with the steps left to the cases and the source and the case ids in one column. A state with no lever
and no case is stated, never hidden: `register` means no open ticket builds it, `gap` means no channel shows it (part 2
records each gap).

**Roles.** Owner (all accounts, diagnostics). Manager(T): assigned accounts only, with a trading grant. Manager(R): a
read-only grant on an account (`rbac.account_read_only`). Viewer: reads, and every write is refused `403` and shown as
T2 (disabled with a visible reason: the design's treatment, §1.3). Manager(W): a Manager whose grant is withdrawn mid-view (S-08, AC-06). "All" is
D06 §3's audience, every role that sees the state, and no run per role: the runs follow the selection rule (§1.3), so a
state that is not role-sensitive runs as Owner plus one Viewer read where a case lists roles, and S-07 is role-sensitive, since a Viewer's controls
are T2 for the role before the feed (E09-D09 §2.1, step 3 before step 4). View-as is not a role (`docs/design/E29/E29-D02.md:96`): the Owner sees the viewed user's scope, and every write is T2
(`rbac.view_as`) except the C-2.6 carve-out. A command's source is a role too (S9): a user may command an order, while a
rule, an algo or a group may never command an `untracked` one (`docs/plan/24-internal-schemas.md` §8.2, "Who sends a
command").

**Environments.** Axis 1 is the trading environment: demo only for every row. Axis 2 is the tier (§1.3) where the state
can be forced; the Tier column names the cheapest and any higher tier the case also needs.

**Handles.** The cases name roles, not users. A seed, the session factories of E29-Q02 or the seeded stack's script,
creates one synthetic session per handle and never a real credential (C-12.2). Accounts A, B and C are the positions
goldens' Main, Sub-1 and Sub-2 (`docs/design/E29/E29-D02.md` §5.2; Sub-2 is the cross-margin, hedge-mode account); the
five-account cancel-all adds two more (`packages/fixtures/golden/orders/README.md`).
