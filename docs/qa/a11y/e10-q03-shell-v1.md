It is a navigation on purpose: the app's strict CSP refuses a renderer `fetch` or image to another host before the request leaves, so the guard never sees one (observed on Electron: `Failed to fetch`, image error, nothing at the route). It is not a violation and is not counted as a pass: it is human-owed (OR-5, FU-4). Each `incomplete` entry in `axe-web.json.gz` and `axe-electron.json.gz` records the rule id, the node count and the first five node targets (as `violations` does), so FU-4's reviewer can find the nodes.
- **LIVE announce:** in all 12 `chrome-live` cells the route change wrote the single polite message "Trading environment: Live" and the banner badge is named "Trading environment: Live".
- **Electron deviation (BQ-5):** `@axe-core/playwright` cannot analyse an Electron window (`browserContext.newPage: Protocol error (Target.createTarget): Not supported`), and `page.addScriptTag` is refused by the app's strict CSP (`script-src 'self'`), which is the CSP working as intended. ### 3.3 Deviation D-1: two landmarks E10-D02 :255 does not list

It is kept because axe's `region` rule flags the rows' label and message text as content outside every landmark in 24 of 24 cells of the two states, and the text carries the notice. **Designer remedy note:** the alternative that stays inside the five-landmark model is to nest the banner slot in the existing `banner` landmark (the TopBar's `<header>`) or the `complementary` one, so the rows sit inside a landmark that already exists; that moves the banner slot in the DOM and needs E10-D02 section 13 and D04 to agree on the order. Until the designer chooses, the two regions stay. The PR body lists this under Deviations (FU-1).
