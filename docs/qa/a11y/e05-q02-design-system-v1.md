**Hold-to-confirm, honest limit.** The hold stories run on a story clock (`now={storyNow}`), which the page cannot drive, so a wall-clock discrete two-press path cannot be timed from outside. What is asserted: the stories `hold`, `hold-keyboard` and `hold-released-early` reach phase "finished", which means their play functions passed in the real browser (`hold-keyboard` is the discrete path: a Space press, then Enter 250 ms to 5 s later, with real key events on the story clock, confirming with gate `double-press`); a bare Enter on the hold Confirm never confirms (the dialog stays open); the hold ring is a named `progressbar` with its text twin. Per story and mode: every header and cell text of the 1280 px render is still present (a stacked cell keeps its text and gains its column label), the page has no horizontal scroll, no element is hard-clipped (a text-overflow ellipsis keeps the full text in the DOM and is counted separately; there were none after unpinning), and for `reflow` at 200 % the table stacks with no sideways overflow in its region. 93 checks, all pass. A real 200 % text-only resize (browser text zoom with layout unscaled) was not run and is owner-run (OR-6).

**Reduced motion (SC 2.3.3, 1.3.1, 4.1.3):** per theme, every non-perf story rendered with the motion override off and on (`motion:off` / `motion:on`, plus the matching OS preference). 795 stories were probed (asserted); 47 pin their own motion state (the matrices and the `reduced-motion` / `motion-safe` variants) and are recorded with status `skip` (not applicable, not counted as asserted) in each theme. In the 795: no element keeps a CSS animation under reduce (the two recipe demo stories draw the safe value beside the reduce value on purpose; the check there is that the reduce half stops, 22 animated elements fall to 11). 92 stories (2,077 elements) had an animation that reduce removes: confirm dialog, toast, skeleton and skeleton chart, dialog, drawer, inline spinner and spinner, command palette, info panel, button busy, menu, preview tile, table sort pending, fuzzy list, symbol search. Every such element is in its end state (displayed, visible, opaque), and the change keeps a non-motion cue (its own text, name or value, or a dialog, status or progress role on the page; a scrim fading in is decorative and the dialog role plus the focus move convey the open). The cue check is a page-level DOM signal: an element passes if it has its own text, name or value, or if any dialog, alertdialog, status, progressbar or alert role exists anywhere on the page, so it can pass because of an unrelated such element. It is not a judgement that a sighted user perceives the change.

## 7. Reproduce

1. Build tokens and Storybook: `node packages/ui/scripts/build-tokens.mjs`, then `pnpm --filter @candleviewer/ui run storybook:build` (the config serves `storybook-static` on loopback).
2. Axe sweep, from `apps/web`: `A11Y_SHA=$(git rev-parse HEAD) A11Y_WORKERS=8 A11Y_OUT=<dir> npx playwright test -c ../../docs/plan/a11y/_tools/e05-q02-ds.config.ts` (add `--shard n/m` to split, one `A11Y_OUT` per shard), then `node ../../docs/plan/a11y/_tools/e05-q02-merge.mjs --strict <dir>`.
3. Manual passes, from `apps/web`: `A11Y_SHA=$(git rev-parse HEAD) A11Y_OUT=<dir> npx playwright test -c ../../docs/plan/a11y/_tools/e05-q02-manual.config.ts` (writes `<dir>/manual/*.json`; `-g "keyboard:|zoom:|tab walk|motion probe|negative controls"` selects a group).
4. `pnpm --filter @candleviewer/ui exec vitest run --project unit test/a11y-names.test.ts` for the name check.
