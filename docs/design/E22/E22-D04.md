## 3. The do-not-animate list

**T's two clauses, quoted byte for byte from `E22.json`:134 (Technical notes; Scope, first bullet).** A37 makes the
second, T's reduce clause, the rule in both modes.

- DNA-1: "Do not animate row insertion by translating the list — at 2 000 prints/s the list is virtualised and coalesced per frame, so any per-row transform is both invisible and expensive." — S01-u-04: no row or list element carries a `transform` or a `translate` at any print rate.
- DNA-2: "(static insert, no pulse, no decay animation — value snaps)" — S01-u-05: every owned row of §2 renders the same frames with reduced motion on and off.

**The additions, each from a parent.** The tool pins the bold sentence of each.

- **DNA-3. Nothing on the tape or the bubble overlay flashes.** At 2 000 prints/s a per-row arrival flash would be 33
  luminance events a frame (`memo`:91); M-12 sets the overlay's at 0 (`D03`:349); `05` §7 item 3 audits big-trade
  bubble bursts by name (`05`:208). — Q04-03: an automated flash scan of a 2 000 prints/s run finds no element
  changing luminance twice in any 1 000 ms window.
- **DNA-4. A resume inserts the buffered prints; it never replays them.** P12 (`D02`:182). — Q02-09: after a resume
  the inserted rows are present at once, in time order, with no row added after the resume frame from the buffer.
- **DNA-5. The viewport never scrolls smoothly.** Jump to live, `Ctrl+Home` and `Ctrl+End`, a located row and a
  resume move it in one frame (E14-D09 DNA-6's form; `05` §7 item 2 keeps such a user-led scroll functional,
  `05`:207). — Q02-10: the list's computed `scroll-behavior` is `auto` and every jump lands in one frame.
- **DNA-6. No bubble scales, pops or eases its radius or position.** `05` §7 item 2 names "big-trade-bubble
  pop/scale-in" for removal (`05`:206); M-1 makes the appear a flip (`D03`:338). — S03-u-06: a mark's radius and
  position change only between frames, never across them.
- **DNA-7. A counter never counts up; it swaps its text at ≤ 2 Hz.** The readout, the Paused count and the buffered
  count (`D02`:370; `memo`:260). — S01-u-06: a counter's text never shows a value the store did not hold.

## 4. Canvas and DOM: engine state changes

E05-D03 leaves the engine to E11 (`E05-D03`:247-251). The canvas rows here are **engine state changes, not recipes**
(R577 BQ-07):

- **One attribute, one call.** Each owned canvas row writes one per-instance attribute, the alpha band or the cap-ring
  flag, in the one instanced SDF-disc call (`D03`:253; `26`:326, "Radius by notional, alpha by age"): **+0 draw
  calls**, the bubbles layer only, one float (4 B) per changed instance.
- **Scheduled, never polled.** The band flip is scheduled on the next boundary time among the visible marks, and
  that time is a data-clock time: the flip is applied in the first frame whose data clock has reached it. The data
  clock advances only when a print arrives (the replay clock in replay), so no wall-clock timer runs, nothing is
  polled per frame, a quiet chart draws no frames and the loop parks between flips. On a quiet symbol the marks stay
  fresh until the next print moves the clock (D4-12).
- **The data clock (R577 BQ-06).** A mark turns aged 60 s after `ts_event` on the engine's data clock: the latest
  print time on the stream, and the replay clock in replay; never wall time. A frozen or stale feed does not age the
  marks it is not updating, and a replay at 20× ages at 20×. The value is one boundary, written
  `ageBands: { freshMs: 60000 }`, PROPOSED as CR-5's field (`D03`:331) and routed with D03-G1 (G-1). The alternative,
  one bar of the active interval, is recorded and rejected: it changes with the timeframe and is unpredictable on
  1 s charts.
- **Reduce changes nothing here.** `RenderFlags.animate = false` changes no owned canvas row, because every one is
  already a cut and identical in both modes. The stale dim (D4-15) snaps to rest as shipped (`flags.ts`:34); that
  differs from E05-D03 §6.4's "a running transition completes on its clock" (`E05-D03`:227), the difference E14-D09
  C-1 accepted, and D4-15 is E11-D06's row.
- **The 30 Hz rung.** Under `06` §4.4 item 3, bubble redraws coalesce to every 2nd frame (`06`:91). An appear or a
  band flip then lands at most one 30 Hz frame (33.3 ms) late (§6) and loses no state, because the state is per instance and the
  draw reads it whenever it runs.
- **No per-message state on the tape (R577 BQ-08 (a)).** Prints reach the tape through the coalesced path: transport,
  observable, one rAF and one fragment write, never a React state set per print (`AGENTS.md`:454-455). The tape is
  not a statechart (`CONSTITUTION.md`:207). The DOM rows change classes, attributes and text inside the tape panel
  only, never the chart container's layout.

## 5. Reduced motion and flashes

- **Every owned row has its static alternative (T AC 1).** D4-01 to D4-14 are identical under
  `prefers-reduced-motion: reduce`; D4-15 to D4-18 keep their owners' reduce variants (a cut in each case). Nothing is
  left to the implementer.
- **The carriers (MR-3).** Every row of §2 names one, present in both modes.
- **The tier-2 fills, classified (R577 BQ-08 (c)).** A tier-2 row scrolling past swaps `color.surface.raised` for
  `color.buy.subtle` or `color.sell.subtle` in the frame it lands. WCAG 2.3.1's general-flash test, as E05-D03 applies
  it, needs a relative-luminance change of at least 0.1 with the darker state below 0.80 (`E05-D03`:168). The tool
  computes it from D03 §8.2's resolved values (`D03`:315) with `contrast_check.py`'s luminance:

No pair is a transition in any theme, so HS-1b's area bound is not engaged and the tier-2 fill stays in every theme.

- **MR-1 and HS-1 apply to nothing owned here (DNA-3).** A mark changes twice in its life on screen: it appears, and
  60 000 ms later it turns aged. In any half-open 1 000 ms window it changes at most once, so it makes no flash; a
  synthetic burst of 5 000 marks appearing in one frame is 5 000 single changes in that frame and 0 flashes, under
  MR-1's 3 (R577 BQ-08 (d)).
- **MR-2 and WCAG 2.2.2 (R577 BQ-08 (e)).** The tape advances by itself for longer than 5 s, and it has its pause
  control: `P`, the pause button and the soft pause (`05`:207). Recorded as compliant, not redesigned. A drawn mark
  does not move; the chart's own auto-follow is the chart's.
- **Announcements and focus never wait on motion.** There is no motion to wait on; each is applied in the frame its
  state is.

## 6. The frame budget: evidence

T's Performance note asks motion to fit the frame budget (`06`:25, ≤ 16.6 ms p95) and the appear to tolerate the
30 Hz rung. The evidence is R353 BQ-11's three layers. **The prototype is not the engine**: no figure here comes from a
prototype, and any later one says so.

**Layer 1, arithmetic (a tool gate).** At 60 Hz one frame is 16.6 ms. 2 000 prints/s is 33 prints a frame. Every

`VISIBLE_BUBBLES_MAX` marks change in one frame, so a frame writes at most 20 000 B. Under the 30 Hz rung a change
lands at most 33.3 ms late. The tape's per-frame cost is not changed by this spec: its classes are set at insert.

**The throttle (A38).** One window, half-open, from t up to but not including t + 5 000 ms: throttle 5 s, half-open,
leading + trailing. The first whale after a quiet of at least 5 s is spoken at once and opens a window; whales inside
the window are summed and spoken once at its close, and that close opens the next window; a window that closes with no
whale ends the run, and the next whale is a leading one again. The latest window replaces, nothing queues: a write
replaces the node's text and a summary never waits behind another. Whale-class writes are therefore at least 5 000 ms
apart; the user-action and feed sentences (AN-03 to AN-06) share the node, keep their own once-per rates and are not
spaced by the whale window.

- **Suppressed while a tape row holds focus and while `verbosity` is `low`.** A user on a row is reading rows, and the
  resume count covers the gap; the shipped `shouldAnnounce` treats `low` as quiet (`model.ts`:93). A whale seen while
  suppressed is dropped, not held. When suppression begins, the open window's pending sum is dropped and the window
  keeps its clock: it closes at its end with only the whales counted after suppression ended, and a close with none
  ends the run, so the next whale is a leading one. A suppression therefore never speaks a whale that arrived while it
  held and never brings two whale-class writes closer than 5 000 ms (AN-08). `announce_prices` does not gate whales: a
  whale print is not a price update.
- **Numbers.** The spoken notional expands per CMP-020, as the mirror names do (`15`:1290).
- **AC 2's scope (C-11).** "Only whale prints qualify" binds the ambient print class; user-action confirmations
  (AN-03 to AN-05) and feed episodes (AN-06) keep D02 Table 3's and E17-D01 §7's routing, once per action or episode.
- **The simulation (the tool).** 60 s at 2 000 prints/s, 120 000 prints with a seeded whale share of 0.16 % (seed
  577, L577 BQ-09), the opt-in on and no row focused: 188 whales, 12 announcements, every one whale-class, the closest
  two 5 000 ms apart. A second run with the same prints and a row focused from 20 000 ms up to 30 000 ms (`verbosity`
  `low` is the same input): 34 whales seen while suppressed and dropped, 10 announcements, none inside the focused span,
  the closest two 5 000 ms apart. AC 2's bound, at most one announcement per 5 s window, holds in both.

**The opt-in (R577 BQ-10).** Off by default. Its home is SCR-117 Accessibility, which already lists "screen-reader
verbosity for the tape" (`14`:2410), as "Announce whale prints (tape)". Its echo is a `menuitemcheckbox` in SCR-053's
panel menu (`Shift+F10`, K9, `D02`:295), bound to the same setting; D02 D27's five stops stay, with no sixth header
button. The key is PROPOSED `accessibility.announce_whale_prints: boolean`, which fits `st_key_fmt` (`21`:3606); the
closed `accessibility` object has no such field (`22`:22233-22244), so it is G-2, contract-first, for E22-S01 (#714)
and `22`'s owner. The anonymous counter T's Observability asks for is G-3.

and the mode. Pass: the print named after the resume is the one focused before it.
