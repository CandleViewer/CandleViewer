## 4. The filter bar, the range editor and validation (RULED BQ-9, AC3)

### 4.1 Anatomy

- **Chips** (CMP-011 in CMP-055) read in plain language, W-5, the symbols visible only: each chip's accessible name is W-5's spoken form, the caption's clause (W-21). A chip is two sibling buttons, never nested: its label opens the popover, and its remove button, CMP-011's labelled IconButton (`15`:152, :155), is named by W-6 and removes the filter; focus then moves to the next chip, else the previous one, else Add filter (`15`:155). `15`:584 has no range editor and binds the unshipped `space.filterbar.*` (`15`:587; D08-C8).
- **Add filter** opens a CMP-041 menu of the 8<!--=COUNT:criteria--> criteria (§3.1) with the estimated options of §3.3. Choosing one, or a chip, opens a CMP-017 popover with Min and Max CMP-008 fields, each with its unit suffix, and "Apply" (W-6). The popover is a dialog named by its criterion and the fields by the criterion and their bound (W-6). **Regime** instead takes a CMP-005 checkbox per class the descriptor lists (D08-G9), in a group named by W-6, and Apply; with no class checked Apply is disabled, so an empty set is never a filter; its chip and its caption clause read W-5's Regime form.
- **On selecting an estimated criterion** a one-line note sits under its chip: W-3 for Regime (E25-D05:127's sentence verbatim, a PROPOSED placeholder there that `DetectorMethodology.assumption` replaces, E25-D05:118) and W-4 for the z-score (PROPOSED), each ending with the link "How is this derived?", a CMP-069 `inline` disclosure (`15`:714).
- Values are decimal strings end to end (R-2); CMP-008's `value: number` (`15`:122) is D08-C8. An empty field means "no bound"; typed text is parsed and checked when the field commits, on blur or Apply, never mid-keystroke (`15`:124), and non-numeric text is refused then; the fields set no `min` or `max`, so `Home` and `End` do nothing (D08-C8); filter text is never interpreted (T Sec).

### 4.2 The rule and the error

- **Strict min < max**, so `14`'s copy stays verbatim (`14`:2273); min == max is refused. T09 refuses only `min > max` (T09 Scope): D08-G6.
- **The error** is inline in the popover and names the filter: W-7, the `14` text prefixed with the criterion, with `aria-invalid` and one polite announcement. Its text is `color.text.primary`; `color.status.danger.strong` marks only the ✕ glyph and the invalid boundary (as E12-D05:344, merged at `d6597cbcf7`). The chip keeps its last valid range.
- **The previous results stay**, and polling continues on the last valid filter set, with the footer line W-8, "Showing results for the previous filters.", linked to the grid by `aria-describedby` (T AC3).

## 5. Rank by, the cap and sorting (RULED BQ-11, BQ-12, AC2)

### 5.1 Rank by and the column sort

- **Rank by** is the server `sort` (`22`:13035–13048), a CMP-009 select in the filter bar, default Turnover 24 h (D08-G3): it picks which 200<!--=CITE:cap--> rows come back. Its options are §3.1's criteria except Regime, a class, and each ranks highest first: `sort` has no order parameter (`22`:13035–13048), so the direction is fixed until D08-G3 lands, and no direction control is drawn.
- **Column headers sort those 200<!--=CITE:cap--> rows on the client** and never send a request. The cap note says both (§5.2); AC2's "sorting" is read as this pair (D08-C3). Rows open in the Rank by order with no header marked; a header cycles descending, ascending, then back to the Rank by order, and only the sorted header carries `aria-sort`; a Rank by, filter or preset change clears the header sort. W-15's slot names the header sort, or the Rank by criterion while none is set.
- **The hold:** D07 D5's hold applies: a re-rank at most every 2<!--=CITE:resort--> s, held while the pointer or focus is in the grid, with "paused" and "Re-sort" in the footer (D07:90). A focused symbol keeps focus across refreshes; if it leaves the set, one polite line says W-20 first, "BTCUSDT no longer matches.", and focus then moves to the row now at its index (`05`:96). The hold covers order, not membership: a row that stops matching leaves at the next refresh.

## 7. Cadence, staleness and pausing (RULED BQ-10, AC4)

### 7.1 Cadence

One `GET /scanner` every 5<!--=CITE:cadence--> s (0.2<!--=CITE:poll-hz--> Hz, `14`:2272, :2277) while the pane and the document are visible, never overlapping; a filter, preset or Rank by change polls at once. A hidden pane polls nothing.

### 7.2 Age

The footer reads "Updated 3 s ago" (W-13) on D07 D22's shared 1<!--=CITE:clock-hz--> Hz clock (D07:107), never announced.

### 7.3 The stale scan

No successful scan for 15<!--=CITE:t2--> s (D07's T2, D07:86) puts D04's `stale` on the whole result set, chip "Stale 15s" (W-14; D04:42), values kept and demoted. ### 7.5 Pause

A "Pause updates" toggle in the footer (`05`:207; `16`:177), `aria-pressed`. While paused the age keeps counting and the footer says "Paused". A refresh swaps text: no row animation, no flash (`16`:175–177).

### 15.2 Performance

### 15.3 Security

- Public market metadata only. An account-scoped column (positions, PnL) needs a separate RBAC review (T Sec; R-5).
- Filter values and preset names render as text, never markup or a query; the caption is built from the parsed filter, not the raw input (T Sec). `filters` is bounded at 4000<!--=CITE:filters.max--> characters (`22`:13034).
- Presets are user-scoped, with no cross-user visibility. Preset writes are audited server-side as `scanner_preset.*` (T09 Scope), PROPOSED in `24` (D08-G7); scans write no audit record, being reads (`14`:88 covers state-changing actions).
