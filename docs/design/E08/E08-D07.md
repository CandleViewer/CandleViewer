## 1. Locked, not relitigated

- **The 40-symbol cap is a security control.** `23` §16.2: 200 subscriptions, 50 topics per `sub`, 40 distinct
  symbols per connection, 8 connections per user (L4578-4584); a `sub` past 40 symbols is refused per topic with
  `subscription_limit` (L398, L709). Threat WS-D04 "Subscription / symbol exhaustion", requirement SR-073
  (`docs/security/threat-models/E17-ws-gateway.md` L186). They are floors: "a later release may raise them and may
  not lower them" (`23` L389). This design fits inside them and asks for no change.
- **RBAC is server-side.** C-2.12 (C L164-166) and C-12.4 (C L769-773): hiding or disabling a control is cosmetic; the
  server returns 403 and audits regardless (`14` L85).
- **Interfaces #175 forbids breaking:** `23-ws-protocol.md` (batching, throttling, coalescing) and
  `06-performance-and-load-standard.md`. No new topic, option or frame; nothing implies a per-row connection.
- **The 200-symbol list cap** (`14` L2048; `WatchlistInput.symbols` `maxItems: 200`, `22` L19316) and its copy
  "Watching 200 symbols — remove some to add more" (`14` L2037).
- **One state per surface, from a closed set of eight.** Precedence per D01 §2, never stacked (D02 L22-27); a new
  state is a design-system change request (D04 §6, `15` L2318).
- **No per-tick logic in a statechart** (#175 "Do NOT"; `28` §1.2): staleness, coalescing and the countdown clock are
  plain client code.

### 4.4 Import and export format (D14)

- **Accepted:** `.txt` or `.csv` (`text/plain`, `text/csv`), UTF-8, at most 64 KB; parsed in the client, never
  uploaded. Split on newlines, commas, semicolons, spaces and tabs; drop empty tokens and lines starting with `#`;
  trim and upper-case each token; collapse duplicates.
- **Valid** means: matches `^[A-Z0-9]{2,20}USDT$` (`22` L14517) and is in `GET /instruments` with `delisted: false`.
- **Preview groups** (each lists its symbols as plain text, never markup): to add · "Already on Majors" · "Not found
  on Bybit USDT perps" (after `17` L336) · "Delisted by the exchange" (`14` L2037) · "Not a USDT perpetual symbol"
  (the raw token, escaped, cut at 24 characters) · "12 symbols not added: a watchlist holds at most 200." (proposed).
- **Rejected before parsing** (proposed): "This file is 2.1 MB. A watchlist file can be at most 64 KB." · "This file
  isn't plain text." · "This file has no symbols."
- **Export:** `<list name>.txt`, characters outside letters, digits, space, `_` and `-` replaced by `-`. Content: one
  header line `# CandleViewer watchlist "Majors", 12 symbols, exported 2026-10-21 10:31 UTC`, then one symbol per line
  in list order. Never account, key, user or position data (#175 Security notes).

### 4.5 Announcements and analytics

- **Live regions (D17).** An episode is a period with at least one stale row or column. On entry one polite message:
  "3 watchlist symbols stale: SOLUSDT, DOGEUSDT, PEPEUSDT." (up to three names, then "and N more"); on exit:
  "Watchlist prices live again." (proposed). Flapping within 5 s collapses (`15` L2315). Never announced: ticks, ages,
  countdowns, live-window changes, initialising rows. Once each, polite: moves, removals ("Removed SOLUSDT. Undo is in
  the footer.", proposed), failed saves, import results, the "Live prices paused" notice (§4.6). With SCR-117's price
  announcements on (`14` L2187), only the focused row's Last is spoken, at most once per 2 s (`05` L147).
- **Analytics.** Kept: `watchlist.symbol_added`, `.symbol_removed`, `.reordered`, `.column_changed`,
  `.symbol_activated`, `.created`, `.renamed`, `.deleted`, `.duplicated`, `.imported` (`14` L2042, L2053). Added (§10):
  `watchlist.exported`, `watchlist.bulk_added {count}` and `data_confidence.state_entered {surface: "SCR-100", state}`
  (#175 Observability; not registered in `14` today). Payloads carry ids, counts, column ids and public symbols.
- **Audit (server-side, C-2.9).** Record and unrecord are `recording.started` / `recording.stopped` (`24` L4309). No
  watchlist key exists in the closed vocabulary although `14` L88 audits every state-changing action (C-7).

### 4.6 Live window (D6, D7)

Worked example (boards 18 and 24): Alts holds 120 symbols, 15 rows are in view, and the other panes hold one symbol
that is not on the list, so the budget is 39.

- **Budget and window.** The budget is 40 distinct symbols per connection minus those the other panes hold (`23`
  L398, L4581); a list within it is wholly subscribed. On a longer list the window is the focused row plus a block of
  rows around the rows in view, as many as the budget allows (rows 1–39 at the top of Alts). It moves only when a row
  in view falls outside it, 300 ms after scrolling settles, and re-centres on the view (DJ). A budget smaller than
  the rows in view takes the focused row, then the rows in view from the top.
- **Client limit (DJ).** `symbols` is not a `ctl` key (`23` L703), so a move is an `unsub` and a `sub` of `ticker`,
  and that `sub` draws one unit of the topic's rebuild share: 5 per sliding 60 s, resyncs included (L1180, L4601).
  The client counts every draw on the connection's `ticker` subscription, whichever pane makes it. It starts a move,
  a list switch or a re-open after a collapse (L1348) only while fewer than 4 draws fall in the last 60 s, so one
  unit stays free for a resync, which is never held; moves are at least 2 000 ms apart. Past the limit, a move,
  switch or re-open waits, then subscribes the window wanted when it may go. Meanwhile rows in view outside the window
  read "Not live", with the tooltip "This row goes live in 23 s; the live rows change at most 4 times a minute."
- **Refused anyway.** A `sub` refused with `resync_rate_limited` subscribes nothing (`23` L587): every row reads "Not
  live" and the panel status (D4) shows the inline pane notice of `23` §10.3 (L1610), "Live prices paused — retrying
  in 5 s". The client keeps to §8.5 (L1352): it waits 5 s, twice as long after each further refusal up to 60 s, then
  subscribes the window wanted then, never in a loop. Disconnected replaces the notice.
- **Footer.** "Live prices: 39 of 120 symbols" while the window is smaller than the list (0 after a refused `sub`);
  from 180 symbols it adds the count: "Live prices: 39 of 187 symbols · 187 / 200" (D10).
- **Short budget (board 18 inset).** Other panes hold 30 symbols that are not on the list, so the budget is 10: the
  focused row and the first 9 other rows in view are live; the last 5 read "Not live", with the tooltip "At most 40
  symbols are live on one connection; other panels use 30."
- **Rec column.** One `recorder` subscription without `symbols`, held for the panel's life, never moved; the recorder
  records at most `policy.max_symbols` symbols (20 by default; `23` L3981, `20` L872); C-10 routes `23`'s gaps.

## 6. Keyboard model and focus

### 6.1 A grid, not a table (the divergence, D16)

`15` L442 makes CMP-049 a semantic `<table>` and `14` L2038 says "table with sortable headers"; US-MKT-003 asks for "a
proper ARIA grid" (`11` L653), #175 for an "ARIA grid with sortable headers and a caption", and `05` L95 for roving
tabindex in "watchlist rows" per the APG grid pattern. SCR-100 is a `<table role="grid">` with a visually hidden
`<caption>`, `gridcell` cells, the Symbol cell as `rowheader`, and one tab stop. A grid because the rows act
(activate, menu, move, remove): a table with focusable rows would put up to 200 stops in the Tab order. SCR-101's
symbol list uses the same mode. §5 (CMP-049) and §10 (`14` L2038) record the divergence.

### 6.3 Panel focus order

List tabs (one stop; arrows move, `Enter` or `Space` switches) → "+" new list → panel menu ⋮ → the grid → footer
("+ Add symbol", "Columns", "Sort: Manual ▾", then "Undo" when present). The panel status has no control: Retry lives
in the SCR-152 banner. The panel is a labelled region (`05` L94; `14` L503), named "Watchlist Majors" (proposed).
Live updates never move focus (`05` L96); a re-rank keeps focus on the same symbol; removing the focused row moves
focus to the next row, or to the previous one at the end of the list.

### 6.4 Reorder without a pointer (#175 AC4)

- **SCR-100:** `Alt+↑`/`Alt+↓`, or "Move up"/"Move down" in the row menu, in manual order.
- **SCR-101:** "Move BTCUSDT up" and "Move BTCUSDT down" buttons on every row beside the drag handle (the handle is
  `aria-hidden`; the buttons are the accessible path). After a move, focus stays on the same button of the moved row,
  so repeated presses keep moving it, and one polite message gives the new position: "BTCUSDT moved to position 2 of
  12." At the ends the button is `aria-disabled` with "Already first" or "Already last". `Alt+↑/↓` does the same on a
  focused row. Lists reorder the same way once the contract stores a list position (C-3).
- **Columns:** the same buttons in SCR-101's Columns tab, plus `Alt+↑/↓` (`15` L498).

## 8. Motion constraints

E08-D11 #179 owns the motion; this spec only constrains it (D18).

- Nothing animates on a cell or row that is stale, disconnected, delisted, initialising or not live: "a stale cell
  never animates" (E08-D11 scope).
- A state change is one flip (D01 L49; `15` L2313). A panel-wide change is one class on the grid container, never an
  animation per row (D02 L142-143; #175 Performance notes).
- Tick emphasis, if E08-D11 adds it: at most 3 flashes per second per cell (`16` L172; `05` L208), background only,
  no layout change; reduced motion gives no flash (`16` L176); SCR-117's "disable flash-on-update" turns it off
  (`14` L2190). This is how the SCR-100 checklist item "flash-on-update respects reduced motion" is met.
- Sort and reorder move rows without animation under reduced motion; otherwise transform only, within
  `motion.duration.fast` (100 ms) (DJ, for E08-D11 to confirm).
- Age text and countdowns change text at ≤1 Hz with no motion (E17-D01 L231); skeletons are static under reduced
  motion (`15` L165); the panel status appears and clears with one flip, in a row that already exists.
