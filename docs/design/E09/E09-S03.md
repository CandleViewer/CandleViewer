## 3. A11y notes

Standard: WCAG 2.2 AA (C-14.1); sources E09-D06 section 6 and `05-accessibility-standard.md`.

**Alertdialog semantics.** Every lock surface (warning, locked card, sign-out confirm, expiry card) is
`role="alertdialog"` with `aria-modal="true"`, named by its heading (`aria-labelledby`) and described by a body
(`aria-describedby`). While a call is on the wire the dialog carries `aria-busy`. The sessions confirms on R-201 use the
same pattern.

**Focus rules.**

- Locked card: focus on the password field. Warning: focus on Stay signed in. Sign-out confirm and sessions confirms:
  focus on the safe action (Back to unlock, Cancel). While both actions wait, focus rests on the dialog, never on a
  disabled button. Expiry card: focus on Sign in.
- Tab is trapped inside the dialog. Esc does nothing on the locked and expiry cards (E09-D06 section 5); it dismisses the
  warning without extending, and goes back on the two confirms (section 5).
- **Focus guard:** on the SCR-005 cards and the SCR-112 sessions confirms, any focus that lands outside the dialog is pulled back to its first control, and a mousedown on the scrim is refused. Only the SCR-005 cards set the `Locked` keymap context.
- **Scrim:** a flat overlay with no blur. A press on the scrim takes no focus.
- **Hotkey suppression while locked:** every SCR-005 card sets `data-keymap-context="Locked"`; the keymap host runs no
  command while that marker is in the document (no command lists "Locked"), so a shortcut such as Ctrl+K does nothing.
  The warning is deliberately not a lock and sets no marker.
- On unlock, focus returns to the element that had it when the dialog opened. The guard is removed before focus returns.
- Sessions confirm: Esc cancels and returns focus to the row's Revoke. If that row went away in a re-read, focus goes to the
  section heading. After a revoke, the heading takes focus and a polite status says "Session revoked."

**Live regions.** The lock is announced once, assertively, by the alertdialog description (E09-D06 section 6): "Screen
locked after N minutes idle. Market data continues. Order entry is disabled. Enter your password to resume."; expiry
likewise. The countdown on CMP-098 is shown but never announced per tick. "Verifying..." is a polite status. A refused
password is a `role="alert"` linked to the field. The sessions section has one polite status (loading, then the result of
a revoke) and `role="alert"` for failures.

**320 px reflow (SC 1.4.10).** Dialog cards are fluid (`max-inline-size: 100%`). The sessions table scrolls inside its own
labelled region ("Signed-in sessions", `overflow-x: auto`), so the page itself never scrolls sideways. The row header
(device) and the visually hidden target in each Revoke name (device, "(this session)" or last-seen time) keep a destructive
control self-describing.

**axe coverage.** `apps/web/test/features/session/session.test.tsx` runs axe on every dialog state (warning, locked,
verifying, wrong-password, sign-out confirm, expiry), with the contrast rule off because jsdom has no layout; contrast is held by the token audit (E09-D06 section 9). `apps/web/test/features/session/sessions.test.tsx` covers the
sessions states by role and label queries, runs axe, and covers the keyboard paths. `apps/web/e2e/e09-auth-a11y.spec.ts` lists SCR-112 as
shipped on `/settings/profile`, with the "Signed-in sessions" marker, and runs the 320 px reflow check on it. SCR-005 is
still listed there as not shipped (its route `/locked` is an alias with no page); the cards are covered by the component
tests above and by the Playwright paths below.

**Playwright paths** (`apps/web/e2e/auth/session.spec.ts`):

1. A reload into an idle-locked session shows SCR-005 and does not route to `/login`; Esc does not dismiss it; the password
   is sent once, in the unlock body only; the app boots on a bearer and the URL is kept.
2. SCR-112 Sign out everywhere: logout with `all_sessions`, SCR-001, the `4401` close honoured.

## 5. Deviations and gaps

| Item                                   | What the build does, and why                                                                                                                                                                                                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No password field on the expiry card   | The `absolute-expiry-signed-out` frame draws a password field above Sign in. The session is already revoked, so a password has no call to go to; the card has one action, Sign in, which goes to SCR-001. The frame and the build differ here; the frame needs a correction or the owner's waiver |
| Locked reload shows over an empty page | A reload into a locked session mounts SCR-005 alone: no route, no claims, no private data. The scrim therefore sits over an empty page, not over the live workspace the frames draw. Nothing private may mount before unlock, so this stays until a masked workspace exists                       |
| Panel masking                          | No private-data panels exist yet (E12 and E15 are stubs), so the scrim is flat over everything. A masking hook is needed when they exist                                                                                                                                                          |
| Esc on the confirms                    | E09-D06 section 5 says Esc does not dismiss SCR-005. On the sign-out confirm (and on the sessions confirms) Esc goes back, a safe no-op, except while the call is on the wire. The locked and expiry cards ignore Esc                                                                             |
| No location column                     | `14` SCR-112 lists "device, IP, location". `UserSession` has no location field, so the IP address stands in                                                                                                                                                                                       |
| No "Lock now"                          | CMP-098 draws "Lock now" beside Stay signed in. No lock call exists, and a client-only lock would make the later unlock answer `409`. Not drawn until `POST /auth/lock` lands (#4743, PROPOSED)                                                                                                   |
| Revoke from another device             | Revoking this device's session elsewhere closes its WS with `4401`; the client has no `bye` reason until G12, so the connection region shows "Offline — retry stopped" instead of routing to SCR-001. Own-device revoke and Sign out everywhere end at SCR-001 through `endSession`               |
| View-as                                | The server scopes the list to the viewed user and the actions to the caller's own sessions. The section hides nothing under view-as, and no view-as UI exists yet; revisit when it does                                                                                                           |
| Session read errors                    | A read with no usable answer retries after 30, 60, then every 120 s, never a tight loop; a session past its deadline but not yet locked is asked again later, not at once                                                                                                                         |
| No step-up on the sessions routes      | Neither sessions route declares step-up in `22`. A Sign out everywhere from a locked or cookie-only caller is refused server-side, and the section shows its fixed refusal copy (`sessions.refused`)                                                                                              |
| List endpoint name                     | `22` declares both `GET /auth/sessions` (`authListSessions`, paged) and `GET /me/sessions` (`listMySessions`, unpaged `items`). The build calls the paged `/auth/sessions`; `14` SCR-112 names the unpaged `/api/v1/me/sessions`. The screen text should name the route the build uses            |
| Revoke target id (carried hardening)   | The Sign out everywhere confirm and a per-session revoke share one dialog state; a server row without a string `id` must never reach the everywhere path. The hardening carried from the #4762 review: branch on the dialog kind and require a non-empty string id                                |
| Keymap host                            | `KeymapHost.tsx` reads the `Locked` context marker; it was touched outside the ticket's write set at the security review's request                                                                                                                                                                |
| Code-less 401                          | `sessions.py::_unauthorized()` serves a 401 without `code`; the client accepts both shapes meanwhile (#4751)                                                                                                                                                                                      |
