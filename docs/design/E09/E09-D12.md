### 4.2 The fallbacks (the only 4<!--=COUNT:fallbacks-->; each justified)

- **F-1** disabled and locked read as invalid credentials: `22`:1144–1145 makes every credential failure one uniform `401`, and SR-014 (`04`:831) forbids any distinguishable answer; a distinct state would be an account-state oracle. Every credential failure renders `error-generic` with the one string; the countdown only from `429` (G-10).
- **F-2** a replayed TOTP or recovery code reads as an invalid one: the server answers `mfa_invalid` for both (SR-014); a "replayed" string would confirm a code was once valid.
- **F-3** an exhausted set reads as an invalid code: `22` declares no exhausted answer (G-3); until `22` declares a `code`, exhausted reads as invalid, and #229's Gherkin (E09J:187) is met by `enrol.exhausted` when G-3 lands.
- **F-4** every `503` code (incl. `auth_unavailable`) reads as one recoverable state with Retry: the server's `detail` is never rendered (S03:67).
