## 1. Purpose
The only E09 surfaces that sit on top of a live trading workspace. Chassis designed once (alertdialog, flat
60% scrim, no blur, focus trap) and reused for SCR-149.

## 2. Interruption policy
Ruling: https://github.com/basiltt/CandleViewer/pull/2290#issuecomment-6139341861 (architect, owner-delegated per #1778). Gap issues: #2300-#2305.
1. **Frozen = UI-level.** Private-data panels (positions, orders, balances, account labels, PnL) are masked under the scrim; public market data (chart, ladder, tape) keeps streaming visibly, so "locked" is distinguishable from "hung". Nothing is unsubscribed or re-snapshotted (no reconnect storm).
2. **Order entry.** One-click is disarmed **server-side** at lock and never restored (#2305). Idle lock: half-typed ticket retained in memory, disarmed, flagged stale, with a read-only echo (symbol, side, size, price). Absolute expiry, sign out instead, logout, revocation: "Not sent. Discarded. One-click disarmed." The first submit after unlock always goes through SCR-076 with the draft re-validated.
3. **Alerts while locked.** Class A (kill switch, connectivity/degraded, missing native SL, liquidation risk, risk lockout, unwind incomplete) shows as a status strip on the lock card: icon, class label, count, since-time, DEMO/LIVE badge only; never account, symbol, qty, price, PnL, username or free text. Class B (user alerts, rule fires, fills, recorder, info) queues to SCR-014 and shows one polite unlock summary. Sound: Class A only. No ack/snooze/mute from the lock card.
4. **In-flight order.** Lock or expiry never cancels or amends anything; native SL untouched. Server completes accepted requests; the client never resubmits an unknown-outcome request. On resume: `GET /auth/session`, then `GET /orders?open_only=true`, resolve by Idempotency-Key / `orderLinkId` (#2303; until then "outcome pending, see Orders").
5. **Actions while locked: none that change state.** Allowed: unlock (password), Sign out instead, and **Emergency stop**, a routed path (shown only with `killswitch:write`): focuses the password in emergency mode and on unlock opens SCR-072 (typed FREEZE + reason, nothing pre-sent). Not allowed: engage/release kill switch, flatten-all, cancel-all, arming, env switch, step-up, any write.
6. **On return.** Polite "Unlocked. N notifications, M critical." Focus returns to the prior element unless it is a trading action control (submit, flatten, cancel-all, arm, kill, env switch); then it goes to that panel's region heading and the stale-draft marker is announced.
7. **Step-up interrupting an action.** On `403 step_up_required` the exact request is held in memory; on success the identical request is re-sent with the same Idempotency-Key. Esc, expiry, the 3rd failure, idle lock or absolute expiry discard it (nothing sent, toast "Not sent", draft stays unarmed).
8. **Precedence.** If the idle lock fires while SCR-006 is open, SCR-006 closes and SCR-005 takes over. A read-only downgrade survives the lock; step-up elevation does not (#2301). Native exchange stop-losses are unaffected (C-2.6).

## 4. Data
- `POST /auth/step-up` `{password, code, action_class?}` -> `{elevated_until, action_class, single_use, step_up_expires_at}`. No token; elevation is server-side session state. Challenge fields `challenge_id`, `challenge_expires_at`, `action_summary` from #2304.
- `POST /auth/unlock` (password), `GET /auth/session` (`idle_deadline`, `expires_at`), `POST /auth/session/extend`, and `401 session_idle_locked` (#2300).
- Admin token 15 min (SCR-149). All remaining-validity values come from server expiry, never a client clock.
- Audit: `auth.idle_locked`, `auth.session_unlocked`, `auth.step_up_granted|failed|required`, `auth.session_readonly_downgrade`, `auth.session.expired`, `admin.session_elevated`.
- WS Class A summary frames: #2302.

## 5. Interactions and hotkeys
Enter submits. Esc does not dismiss SCR-005; Esc cancels SCR-006/SCR-149 to a safe no-op (SCR-149 returns to the non-admin app). Tab cycles inside the dialog. **Emergency stop:** the kill-switch hotkey (#1012) pressed while locked behaves like the Emergency-stop control (password, then SCR-072). CMP-098: Extend is an explicit server call (`POST /auth/session/extend`); typing or WS traffic never extends; Esc dismisses without extending.

## 6. A11y
- Lock: one assertive announcement ("Screen locked after N minutes idle. Market data continues. Order entry is disabled. Enter your password to resume."; expiry: "Session expired. Signed out. Sign in again."), then focus to the password field. `role="alertdialog"`, trapped, Esc does not dismiss. Open SCR-076/SCR-006 close first and that is announced. Scrim appears instantly under reduced motion; no blur.
- Class A raised/cleared on the card: assertive once each; counts polite.
- Unlock: polite summary, then any active Class A announced once; focus rule per section 2.6.
- SCR-006: `role="alertdialog"`, accessible description = the held action verbatim; focus starts on the **password** field; failures assertive; downgrade banner `role="alert"` once; grace/challenge time polite at 60 s and 10 s only.
- **CMP-098 stays `role="alertdialog"`** (component catalogue owns it): announced once with remaining time and Extend; focus moves to Extend after the announcement; never covers the submit control; countdown not announced per tick.
