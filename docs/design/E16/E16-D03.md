## 1. Purpose, locked inputs, the rules stated once, the classification

### 1.1 Purpose

SCR-141 is the one screen that can destroy recorded history by configuration (ticket Context): shortening a stream's **total horizon** — a `drop` row's days, or `archive_parquet` → `drop` (`21` :3003) — makes data eligible for deletion at the next sweep (`22` :5090 "Changes apply at the next nightly sweep"), and the owner cannot get it back. The design therefore makes every reduction pass through a preview and a typed confirmation whose consequence sentence names what, how much, which dates, when, that it cannot be undone and what replay and the journal lose (`14` :2756, :2759; `11` :4895; E16-D02 §8.4 :506), keeps every write Owner-only in practice (§1.4), and shows the sweep as a job with the contract's words.

### 1.3 The rules, stated once (every later section with a gated control cites "§1.3")

**T2 — disabled with a visible reason** (E09-D09 §2.2 :49, §3.1 :85–95, §9.1 :224, §9.3 :238; CMP-079 RbacGate `15` :799; CMP-019 Icon `lock`). A control gated by a role, grant, environment, session or **registered state** keeps its native role and its full label; `aria-disabled="true"`, never the `disabled` attribute, so it stays a Tab stop; a CMP-019 `lock` glyph (`decorative=false`, name "Not available") leads the label in the same colour; the reason sits under it (2a inline), in the DOM at mount and linked by `aria-describedby`; on SCR-141 every gated control points at the one panel notice and carries no reason line of its own (the grid included — D03-D11; E16-D02 D-15 :777's 2b question does not arise); role legs are wrapped in CMP-079. Hi-fi: label `color.text.tertiary`, reason `color.text.secondary`, fill `color.surface.raised` with a `color.border.default` hairline; never `color.text.disabled`, never `opacity.disabled`. Keys: `Enter` / `Space` / `↑` / `↓` on a T2 field change nothing (a press stages nothing) and re-show the reason once, politely. Reasons are `rbac.*` keys or registered state keys; a screen never writes its own string; a reason never names data, ≤ 60 <!-- audit:layout.reason_max=60 --> characters, one sentence, full stop. A read-only panel carries **one** notice every gated control points at. **The view-as leg comes first** on every write (`rbac.view_as` "Read-only while viewing as {user}."), one notice per frame; `22` refuses every write while viewing as (`view_as_read_only`), the C-2.6 carve-out does not touch this screen. ## 5. Preview and the destructive confirmation (board 03; 5 frames)

**The pattern (reusable, D03-A4 to `15` CMP-044's Purpose line).** A destructive configuration change is confirmed in three steps inside one dialog flow: (1) the **preview** renders what the change makes eligible — grouped by symbol, then range and size (`11` :4146) — and Apply keeps the validity look until it has rendered for the current diff (`retention.apply.preview_first`); (2) the **typed confirm** (CMP-044 `variant="typed"`) carries the consequence sentence **in the confirm itself** (BQ-10 RULED): the stream, the scope, the date range, the size, and either "eligible for deletion at the next retention run (daily, 03:00 UTC)" or "a retention sweep starts now", then "It cannot be undone." and the effect line; the typed value is the stream word (the `22` kind, `trades`) for a global or per-stream reduction, the symbol for a per-symbol one, `all streams` when several streams shrink — matched exactly after trimming, case-sensitive, the value set in the mono face inside the instruction (D03-D14); the title names the kind (the reduction-kinds table below); the destructive button names its object (E30-D03 N7 :102); (3) the **step-up** runs on submit when the server answers `403 step_up_required` (E16-D02 §6.4 :380: the request is held and re-sent once, unchanged, with the same `Idempotency-Key`; Esc, expiry or the third failure → "Not sent", the dialog keeps its inputs, focus returns to its primary; before the audit line the dialog says "You'll confirm with your password and a code." or "Still trusted for recorder changes · {mm:ss}" inside a grace window). The consequence paragraph is a real `<p>`, the Apply control's `aria-describedby`; the typed input's label is the instruction. Sizes come from the PROPOSED preview when it exists (D03-G1), else the client-side fallback, worded as what it is: `StorageUsage.symbols[].used_bytes` is one figure per symbol **across all its streams**, so the fallback says "about {size} across {symbol}'s recorded streams" (a per-stream figure needs D03-G5); its range is clamped to the recorded history — recording start = `generated_at − used_bytes ÷ daily_growth_bytes` — and the size is the growth over the days between that start and the cut-off; when nothing predates the cut-off it says so: "Nothing recorded before {to} exists yet (about 0 GB now; recording started about {since}), so the first run deletes nothing." (the fixture's case: ETHUSDT holds about 2.3 days); "about" on every figure, and the caption "Estimated from the storage report, per symbol across its recorded streams; the retention run's audit record carries the exact figures." (C-2.13, C-2.14). The tool derives the start, the clamp and the sentence and gates them.

**The per-frame gate (the orchestrator's ruling).** Every reduction frame — `SCR-141/editing-dirty-reduce`, `SCR-141/preview`, `SCR-141/confirm-reduce`, `SCR-141/confirm-reduce-now`, `SCR-141/confirm-kinds` — carries its consequence sentence (the kinds frame: every kind's title); every destructive frame also carries the typed instruction, a timing clause ("at the next retention run (daily, 03:00 UTC)" or "a retention sweep starts now") and "It cannot be undone.
