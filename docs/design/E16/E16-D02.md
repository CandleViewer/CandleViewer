## 2. Data bindings

Every element binds to an existing contract field, or to a field of the recording-status amendment (owner decision 5;
the amendment, #3951, merged 2026-10-20), marked **amendment**. The names are that PR's final names as the
orchestrator confirmed them on 2026-10-20: `lingering` is a boolean beside `state: recording` (the `state` enum stays
closed); `linger_until` (REST) / `linger_until_ms` (WS); `refusal` per symbol; the disk fields `level`, `write_gate`,
`write_gate_reason` and `cap_bytes` are volume-wide, on `StorageUsage` and the WS `storage` object, never on rows;
`role_restricted` is collection-level; `policy` carries the configured values. Three more items came in #3955 (merged
2026-10-20; 24 §19.18; orchestrator ruling, 2026-10-20): `accelerate_retention` on `StorageUsage` and WS
`storage`; `DataCoverage.gaps[].reason` declared open-ended for readers, with `backpressure_drop` and `seq_jump` added
(an unknown reason reads as "gap"); and the rule that `addRecordedSymbol` on an already-listed symbol adds the `manual`
reason.
What the contract still lacks is in §15 (C-5, C-6) and is never drawn as if it existed.

## 3. Screen states

One board per drawn state (`SCR-140/<state>`; the cap draws five of the eight, §"Penpot boards"; `starting`, `purge-in-progress` and `empty` are not drawn — the text binds), all on the same sample set (§1), so the states compare like for like. The
boards use an illustrative 200 GB recording budget; `CV_DISK_CAP_GB` defaults to 600 (20 §7.2). The
disk ladder has hysteresis (24 §13.4.1: a level engages at its trigger and releases 5 points lower), so every disk
headline and banner is keyed on **`level`**, never on the percentage, and names the **release point** as the way back.
Levels 1 and 2 speak in the disk card (warning icon + words, polite); only level 3 and an incident raise a CMP-028
danger banner (`role="alert"`, announced once). Every disk figure carries a number with units **and** a state word
(AC2).

### 6.4 Retention and Keep forever (security note: confirmation + audit + step-up)

its inputs, and focus returns to its primary. Before the audit line, each dialog here and in §6.5 says whether a code

02:14" inside a live grace window.

  Retention is removed and nothing is deleted automatically. Type BTCUSDT to confirm." · CMP-093 "This action is

## 9. Motion and live updates

### 9.1 1 Hz updates never move the layout

- The `recorder` topic updates at 1 Hz. Values change **in place**: no row animation, no flash, no colour pulse, no
  re-sort while the page is open (a sort applies on the next explicit sort or reload).
- Numbers use tabular figures (`type.num.sm`) in fixed-width, right-aligned columns (§1), so "9.9 GB" → "10.0 GB" never
  shifts a neighbour. The State cell is one line with an ellipsis, so a longer state never changes the row height.
- A row entering or leaving appears or disappears without a transition; if the focused row leaves, focus moves to the
  next row and the live region names the symbol that left. A focused action that changes in place (Stop ↔ Keep
  recording, T2 ↔ T1) keeps focus: the element updates and is never re-mounted (E09-D09 §9.2, §9.4).

**Findings, to apply in the boards:**

1. **State words are never drawn in a status colour.** `color.status.*.strong` as text reaches only 3.39–4.11:1 on
   `color.surface.raised` in the light theme, so every state word uses `color.text.primary` and the tone moves to the
   icon, which needs only 3:1.
2. **Danger uses `color.status.danger.default`, not `.strong`.** `color.status.danger.strong` resolves to an amber in
   every theme (`palette.amber.400` in dark and high contrast; the same value as `warning.strong` in light), so a
   "danger" icon or fill in `.strong` would be indistinguishable from warning (1.00–1.18:1). `danger.default` is red
   and passes 3:1 on both surfaces in all themes since #3925 (merged 2026-10-20) retuned light `danger.default` from
   the warning amber to a dark red (8.95 and 7.35:1 on raised and sunken); the words and the icon shapes carry the
   warning/critical distinction as well. The `danger.strong` value is reported to the design-system owner as a token
   finding (§15, D-9).
3. **The bar's track is not a contrast carrier.** The CMP-023 track against the card is 1.21–1.22:1, so the bar's
   value is always stated in text beside it ("61.4 GB of 200 GB (31 %)"), and the threshold scale is text.
4. **A blocked control is T2 (§10.5), never dimmed.** `color.text.disabled` measures 2.86 / 3.74 / 2.86:1 on
   `color.surface.raised` and is never used (E09-D09 §11, DS-1). The label and lock take `color.text.tertiary`, and the
   reason `color.text.secondary` (rows above).
5. **Stale rows swap the recording icon to `color.status.success.default`.** On `color.surface.sunken`,
   `success.strong` is 2.78:1 in the light theme; `success.default` reads 3.84:1. The other icons pass as they are. The
   icon is also redundant to the state words and the "stale" tag.

CVD: no meaning depends on hue alone (word + icon shape for every state), so the dichromacy simulation of the running
and disk-critical boards will be attached as a legibility check, not a hue-coding one (§"Penpot boards").

  `policy` object (`autostart_delay_s`, `autostop_grace_s`, `max_symbols`, `warn_pct`, `autostop_pct`, `halt_pct`,

  `addRecordedSymbol` on an already-listed symbol adds the `manual` reason ("Keep recording");
  `DataCoverage.gaps[].reason` is open-ended for readers, with `backpressure_drop` and `seq_jump` (the gap table
  names gate drops); `accelerate_retention` on `StorageUsage` and WS `storage`, with the 24 §13.4.1 hysteresis in the

**Deviations and decisions:**

- **D-2 (CMP-177 contract):** `recording: boolean` and `onToggleRecording` are replaced by `state` and explicit actions

  purge is `retention.purge` in the contract. The server's audit catalogue decides; the design depends on none.
