## 2. Data bindings

Every element binds to an existing contract field, or to a field of the recording-status amendment (owner decision 5;
the amendment PR, `Refs #323`, `Refs #492`), marked **amendment**. The names are that PR's final names as the
orchestrator confirmed them on 2026-10-20: `lingering` is a boolean beside `state: recording` (the `state` enum stays
closed); `linger_until` (REST) / `linger_until_ms` (WS); `refusal` per symbol; the disk fields `level`, `write_gate`,
`write_gate_reason` and `cap_bytes` are volume-wide, on `StorageUsage` and the WS `storage` object, never on rows;
`role_restricted` is collection-level; `policy` carries the configured values. Three more items follow in a small
contract PR right after it (orchestrator ruling, 2026-10-20): `accelerate_retention` on `StorageUsage` and WS
`storage`; `DataCoverage.gaps[].reason` declared open-ended for readers, with `backpressure_drop` and `seq_jump` added
(an unknown reason reads as "gap"); and the rule that `addRecordedSymbol` on an already-listed symbol adds the `manual`
reason.
What the contract still lacks is in §15 (C-5, C-6) and is never drawn as if it existed.

### 3.1 Page states: loading, unavailable, stale (14 §0.5 rule 4)

A screen whose job is to catch silent failure must never look healthy when it is not current.

### 3.2 Job terminal states (purge and compact)

`Job.status` can end `succeeded`, `failed` or `cancelled`, and a job can be lost when the API restarts (`GET /admin/jobs/{jobId}` → 404 `job_unknown`). Each terminal state clears "A purge is running" / "Compacting":

- **Purge failed:** CMP-028 danger, `role="alert"` once: "Purge of ADAUSDT failed (`<code>`). Some data may already be deleted: check ADAUSDT's size and gaps." Action "Open ADAUSDT".
- **Purge cancelled:** info, polite: "Purge of ADAUSDT was cancelled. Data deleted before the cancel is gone."
- **Purge status unknown:** info, polite: "The purge's status was lost when the server restarted. Check ADAUSDT's size and gaps."
- **Compact failed / cancelled / unknown:** the card's compact line, polite, with no banner: "Compaction failed (`<code>`); nothing was deleted." / "…cancelled." / "Compaction status unknown after a restart."
- **Succeeded:** the card states the result from `Job.result` ("Purged 5.5 GB of ADAUSDT data", "Compacted at 10:42 UTC").

`CMP-177/states` (§4.2), `REC-chip/states` (§5.4), `SCR-140/motion` (§9) and `SCR-140/redlines` (§11).

## 5. Auto-record disclosure and review (decision 2: A′, silent)

Auto-record stays silent: no toast, no prompt. Four elements carry discoverability instead.

### 5.1 The reason tag and its "Why?" popover

Every row shows its reason as a CMP-011 Tag. Auto tags are followed by a CMP-002 IconButton "Why is SOLUSDT recorded?"
(info glyph) that opens a CMP-017 Popover:

> **Recorded automatically**
> SOLUSDT's chart has been open since 10:13 UTC; recording started 60 s later, at 10:14. It stops 30 min after the last
> SOLUSDT chart closes. Data is kept for 30 days.
> [ Keep recording ] (adds the symbol to your list, so closing the chart no longer stops it)

The position variant: "XRPUSDT has an open position (since 09:02 UTC); recording started then and continues until the
position closes. An open position never stops recording." The rule and alert variants name the rule or alert.

### 5.2 Reviewing what auto-record added

- The summary line counts them ("Recording 4 symbols · 2 auto-recorded"), and "2 auto-recorded" is a link that applies
  the FilterBar chip "Reason: Auto", so the list shows exactly what auto-record added.
- Each auto row's Since is the moment the trigger started it, and its Size and rate say what it costs.
- Analytics: `recorder.auto_review_opened` when the chip is applied from the summary or a "Why?" popover opens (§12).

### 5.3 One-click stop, within today's limits (decision 3)

AC3 asks for a one-click stop on a `chart_open` row (E16-D01). Today's backend cannot honour it while the chart is
open: `DELETE` is refused with 409 while a trigger is active, and a forced stop re-arms within a tick (E16-D01 §2). So
the row's Stop is a **disabled-with-reason** control: one click (or focus) shows the reason, which names the trigger and
how to stop ("Close the chart; recording stops 30 min later"). Once the chart closes, the row is lingering and offers
"Keep recording". Nothing promises an undo or a suppression; a suppress primitive is a `post-ga` candidate (decision 3).

### 5.4 REC chip state sheet (cross-screen)

draws its states so the copy has one source; the chip itself belongs to those screens' tickets. The chip always carries

### 6.4 Retention and Keep forever (security note: confirmation + audit + step-up)

The ticket's security note routes retention changes through CMP-044 with typed confirmation and CMP-093, and RBAC row 9
requires step-up for pin and retention. The design draws that path for **every** change. Step-up is SCR-006 (the
step-up modal), run **on submit**, after the typed confirmation, when the server answers 403 `step_up_required`; focus
then returns to the dialog's primary button.

- **Keep forever on** (CMP-004 switch "Keep BTCUSDT data forever") → CMP-044: "Keep BTCUSDT data forever?
  Retention is removed and nothing is deleted automatically. Type BTCUSDT to confirm." · CMP-093 "This action is
  audited."
- **Keep forever off** → CMP-044 (destructive): "Stop keeping BTCUSDT forever? Retention returns to 30 days,

- **Retention** (CMP-009 select in the row detail: 7 · 30 · 90 · 365 days, "Custom…" opens SCR-141, E16-D03):

Owner decision D-8 (§15) proposes exempting the two non-destructive changes (Keep forever on, lengthening) from the

### 6.5 Purge data (per symbol; Owner + step-up + typed symbol + reason)

`purgeRecordedData` deletes one symbol's data recorded before a date, irreversibly. The card's "Purge data…" (and the
row detail's "Purge…") opens one CMP-043 Dialog form (CMP-040 fields) using CMP-044's typed-confirmation pattern,

the server answers 403 `step_up_required`:

> **Purge ADAUSDT data?**
> Symbol: [ ADAUSDT ▾ ] · Delete data recorded before: [ 2026-10-01 ] (default: the retention cut-off)
> This deletes **about 5.5 GB** recorded from 2026-09-20 to 2026-10-01 from QuestDB and Parquet. **It cannot be
> undone**, and replay, footprint history and the journal lose this range. Shared QuestDB day partitions are freed by
> the nightly roll-off.
> Reason (required, 3–280 characters): [ …………………… ]
> [ ] Include pinned data (shown only for a pinned symbol; adds "Pinned data is deleted too.")
> Type the symbol to confirm: [ ADAUSDT ]
> This action is audited (high severity). (Dialog copy; CMP-093 records the action.)
> [ Cancel ] [ Purge ADAUSDT data ] (enabled only when the reason is valid and the typed symbol matches)

The size is an estimate from the storage report and the coverage intervals ("about"); the audit record carries the
exact window, partitions, rows and bytes. While a purge job runs, "Purge data…" is disabled ("A purge is running";

### 6.6 Compact now

`compactRecorder`, non-destructive, no confirmation. The button shows the job ("Compacting · 42 %"); the card states

## 9. Motion and live updates

### 9.1 1 Hz updates never move the layout

- The `recorder` topic updates at 1 Hz. Values change **in place**: no row animation, no flash, no colour pulse, no
  re-sort while the page is open (a sort applies on the next explicit sort or reload).
- Numbers use tabular figures (`type.num.sm`) in fixed-width, right-aligned columns (§1), so "9.9 GB" → "10.0 GB" never
  shifts a neighbour. The State cell is one line with an ellipsis, so a longer state never changes the row height.
- A row entering or leaving appears or disappears without a transition; if the focused row leaves, focus moves to the
  next row and the live region names the symbol that left.

### 9.2 Animated elements

| Element                      | motion-safe                                                                               | `prefers-reduced-motion: reduce`                                       |
| ---------------------------- | ----------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Disk bar fill (CMP-023)      | tween to the new value over `motion.duration.normal` (200 ms), `motion.easing.decelerate` | jumps to the new value                                                 |
| Purge / compact progress bar | same tween                                                                                | jumps                                                                  |
| Starting spinner (CMP-014)   | CMP-014's rotation                                                                        | CMP-014's opacity pulse (16 §7); the word "Starting" carries the state |
| Everything else              | none animated                                                                             | none animated                                                          |

### 9.3 Live region

One polite live region (`role="status"`) holds the summary line, without its timestamp. It announces **changes of
state only, at most once every 10 s**. Changes in the same window are announced as one batch, so none is lost:
"ETHUSDT degraded; SOLUSDT stopped recording", "Auto-record paused". Ticking numbers (rates, sizes, lag, percentages) are never announced. The level-3 and
incident banners are announced once as `role="alert"` and never repeat while their condition holds.

### 10.3 Contrast and colour

Every state is a word plus an icon of a distinct shape (dot, triangle, octagon, info circle); tone is a third signal,
never the only one. Contrast is computed from the resolved tokens with the WCAG 2.x formula.

### 10.4 Computed contrast (WCAG 2.x, resolved tokens)

Method: `packages/ui/tokens` (themes as in `themes.json`: dark = primitives + semantic-dark; light adds
semantic-light; high contrast adds semantic-hc), the formula of `docs/design/_tools/contrast_check.py`. Text needs
4.5:1; icons, the bar and its ticks, and the focus ring need 3:1. The danger rows use the token values of PR #3925
(#3896), which this design depends on (finding 2).

| Use                                 | Foreground                           | Background                         | Dark          | Light       | High contrast | Need |
| ----------------------------------- | ------------------------------------ | ---------------------------------- | ------------- | ----------- | ------------- | ---- |
| Cell text, state words, banner text | `color.text.primary`                 | `color.surface.raised`             | 14.35         | 15.62       | 16.25         | 4.5  |
| Since, rate, legend, formula        | `color.text.secondary`               | `color.surface.raised`             | 8.81          | 8.98        | 14.35         | 4.5  |
| Updated time                        | `color.text.tertiary`                | `color.surface.canvas`             | 5.96          | 6.36        | 11.87         | 4.5  |
| Header cells                        | `color.text.primary`                 | `color.surface.sunken`             | 17.42         | 12.82       | 19.73         | 4.5  |
| Danger banner                       | `color.text.primary`                 | `color.status.danger.subtle`       | 12.06         | 14.64       | 13.66         | 4.5  |
| Info banner (purge)                 | `color.text.primary`                 | `color.status.info.subtle`         | 10.74         | 15.44       | 12.16         | 4.5  |
| Warning icons, level 1–2 bar fill   | `color.status.warning.strong`        | `color.surface.raised` / `.sunken` | 11.00 / 13.36 | 4.11 / 3.37 | 11.00 / 13.36 | 3.0  |

**Findings, to apply in the boards:**

1. **State words are never drawn in a status colour.** `color.status.*.strong` as text reaches only 3.39–4.11:1 on
   `color.surface.raised` in the light theme, so every state word uses `color.text.primary` and the tone moves to the
   icon, which needs only 3:1.
2. **Danger uses `color.status.danger.default`, not `.strong`.** `color.status.danger.strong` resolves to an amber in
   every theme (`palette.amber.400` in dark and high contrast; the same value as `warning.strong` in light), so a
   "danger" icon or fill in `.strong` would be indistinguishable from warning (1.00–1.18:1). `danger.default` is red and
   passes 3:1 on both surfaces in all themes **once PR #3925 lands** (it retunes light `danger.default` away from the
   warning amber; on today's `main` light danger and warning are the same colour). Until then the warning/critical
   distinction in the light theme rests on the words and the icon shapes alone, which the design already guarantees.
   The `danger.strong` value is reported to the design-system owner as a token finding (§15, D-9).
3. **The bar's track is not a contrast carrier.** The CMP-023 track against the card is 1.21–1.22:1, so the bar's
   value is always stated in text beside it ("61.4 GB of 200 GB (31 %)"), and the threshold scale is text.
4. A disabled Stop uses `color.text.disabled` (2.86–3.74:1): exempt as a disabled control, and its reason is available
   as text (tooltip and `aria-describedby`).

CVD: no meaning depends on hue alone (word + icon shape for every state), so the dichromacy simulation of the running
and disk-critical boards will be attached as a legibility check, not a hue-coding one (§"Penpot boards").

  2026-10-20): `addRecordedSymbol` on an already-listed symbol adds the `manual` reason ("Keep recording");
  `DataCoverage.gaps[].reason` becomes open-ended for readers, with `backpressure_drop` and `seq_jump` (the gap table

  the audit record carries the exact figures.
- **C-6:** "Restart a feed" (US-REC-008) has no REST operation, so it is not drawn.

**Deviations and decisions:**

- **D-2 (CMP-177 contract):** `recording: boolean` and `onToggleRecording` are replaced by `state` and explicit actions
  (§4.2); the catalogue entry is updated here and the handoff checklist covers the change.
- **D-3 (audit vocabulary):** the catalogue says `recorder.started|stopped|…`, the ticket `recorder.start|stop|…`; the
  purge is `retention.purge` in the contract. The server's audit catalogue decides; the design depends on none.
- **D-4 (themes):** the boards are dark (the default). Light and high contrast are covered by §10.4's computed contrast,
  not duplicate boards: switching the token theme in the shared Penpot file changes every agent's view at once.
- **D-5 (roles):** SCR-140 is owner-only, so no Manager or Viewer variant of the page exists (decision 4 lives in the REC
  chip and CMP-177 `ReadOnly`).
- **D-6 (backfilling):** the catalogue checklist's per-symbol "backfilling" state is not drawn: an `archive_import` job
  does not name its symbol in `Job`, so the import's progress belongs to E16-T10's surface.
- **D-7 (projection):** the catalogue wireframe's "projection 60 d: 118 GB" is replaced by the state-first headline (E16-D01
  §3); ADR-0015 §6's "projected 30-day footprint" stays as "In 30 days: about {used30}" in the formula line.
- **D-8 (owner decision):** the security note routes every retention change through typed confirmation. Proposed: exempt
  the two changes that delete nothing (Keep forever on, lengthening retention) from the typed symbol, keeping step-up and
  the audit. The boards draw the compliant path until the owner decides.
- **D-9 (token finding for the design-system owner):** `color.status.danger.strong` resolves to an amber in every theme,
  and light `danger.default` equals the warning amber on today's `main` (PR #3925 retunes the latter). This design uses
  `danger.default` for danger and depends on #3925 for the light theme.
- **D-10 (auto-record switch):** the sitemap lists an auto-record toggle on `/admin/recorder` (R-340). No API changes it
  (`CV_RECORDER_AUTORECORD_ENABLED` is a server setting), so SCR-140 states it as text (§8.1).
- **D-11 (Silent):** derived client-side from `last_event_at` (US-REC-008); an explicit server state would replace it.
- **D-13 (SCR-141/142):** the decision comment on #323 mentions SCR-141/142; the ticket's out-of-scope list wins, and
  E16-D03/D04 are `blocked_by` this ticket. SCR-140 draws only their entry points ("Retention policy", "Storage
  details").
- **D-12 (shell):** CMP-087 names `color.surface.admin-tint`, which no token set defines; the boards use
  `color.surface.canvas`. The nav width (240 px) is assumed; CMP-087 names none.
