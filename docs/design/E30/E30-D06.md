### 6.1 The key scheme and the `errors.ts` map (BQ-12)

- **Stable key** `ticket.<surface>.<code>`, generated mechanically from the first merged key: `<code>` is the merged key with a leading segment equal to the surface dropped (`confirm.timeout.status` → `ticket.confirm.timeout.status`; `v.sl.required` → `ticket.order.v.sl.required`). A star family takes its suffix from its own words (the first three, or the row's named classes: D02 §10's for `rejected.class.*`, D03 §5's Reason column for `reason.*`). The owning surface of a shared string is where its owner spec first draws it.
- **Exactly once:** a string reused across surfaces is one entry with every key in `alias` and every place in `where`; the tool fails a string under two keys and a key with two strings (G-ONCE).
- **Templates** (BQ-13): a fixture value becomes a parameter (`{account}`, `{symbol}`, `{qty}`, …), the fixture rendering kept in `examples`; no word changes. A digit outside a parameter is allowed only where the entry's `fixed` lists it (a product constant: the 2 % fallback, the 10–60 s range, 00:00 UTC). No account, symbol or decimal from the boards survives in a string (G-FIXTURE).
- **The backend map:** every string that renders a server refusal carries `codes` — `problem:` a `22` x-error-code slug (a `:reason` suffix for `trading_disabled`'s `24` §8.10 reasons), `rule:` a `validation_failed` rule, `preview:` a `TradeGroupPreview` `rejection.code`, `oms:` a `24` §8.6 `OmsErrorCode`, `sizing:` a `24` §9.3 `LegSizing` reason — never a Bybit `retCode` (D03:730). The inverse `by_code` table resolves each code to one key per surface (37<!--=COUNT:deck.codes--> codes); a refusal string without a registered code names its open row in `codes_pending` (G-1, G-4).
- **`errors.ts` is E30-T01's** (#984): the deck fixes keys, strings, parameters, politeness and the code map; the module's form is the build's. A key is never renamed or reused; a string changes only by a versioned delta (§14.1).
