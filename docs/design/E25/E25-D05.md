## 3. Why one badge

**The invariant chain.** C-2.13 (estimated-signal honesty) → `11` global AC 6 ("renders a visible (estimated) badge with an explanation popover") → `30` §6.3 criterion 4 ("A missing badge is a P1 bug, not cosmetic") → `14` §0.5 item 2 (every heuristic value "renders an `(estimated)` chip with a tooltip linking the methodology drawer (SCR-058)"; `30` §6.3's criterion is the release exit criterion) → CMP-227's catalogue-level test (every screen in `14` §12.3's "(estimated) labelling" row renders this component). One component carries the whole chain; if six surfaces each drew their own chip, one would get it wrong (the ticket's R2 argument).

**The structural guarantee.** CMP-227's API is `({ detector, variant, size, confidence? })` — there is no `onOpenMethodology` prop and no decorative mode. The drawer binding comes from a required provider, **`EstimatedMethodologyProvider`** (name PROPOSED), which supplies `openMethodology(detector)` (opens SCR-058 at the detector's section) and emits `methodology.opened{detector}`. Rendering a badge outside the provider is a **development-time error** (the hook throws `EstimatedBadgeOutsideProviderError`; the component never falls back to a `<span>`), so a consumer cannot produce a non-actionable chip (the ticket's technical note) — which is what makes E25-S04's "opens from any estimated badge" structurally true. Tiers (`15`): CMP-227 Atom (honesty affordance, cross-cutting), CMP-131 Molecule (trading, chart-adjacent), CMP-187 Chart-primitive, CMP-132 Chart-primitive (trading), CMP-133 Atom (trading), CMP-134 Molecule (trading). The same hook drives the one host that embeds the badge's look inside its own button — CMP-133 (§7.4), **the only host today**: a host is a native `<button>` (or `role="button"`) whose activation calls `openMethodology(detector)`; the `EstimatedBadgeHost` context carries that binding and throws otherwise, so wrapping the context around a `<span>` cannot produce the look (PROPOSED; the unit test of §13).

**Surfaces today and PROPOSED additions (cited, not re-proposed).** `14` §12.3 lists SCR-030, 050, 056, 057, 058, 059 and 081; E25-D01 §9.5 proposes SCR-053, 054, 014, 090, 091 and 092 (E22-D01 G9 and E24-D01 G8 point at that proposal; E40-D01 K3 / NC-10 put the qualifier in alert titles). CMP-227's catalogue-level test asserts the row as `14` has it on the day it runs.

**The pattern rule — lineage, not a second proposal.** "Hollow, dashed or hatched = estimated or absent, never a side or direction" is PROPOSED for `16` §6 **in E25-D01 §9.5 only** (orchestrator ruling LANE-32, 2026-10-21); E22-D01 C19, E24-D01 F22 and E40-D01 NC-10 carry rows pointing at it. **Here the rule lands in the design system at component level**: CMP-227's `marker` variant is hollow / dashed with the visible word in the pane's legend row (or beside the mark) and in the mirror; CMP-132's `status` is carried by pattern and word, its `direction` by the ▲/▼ glyph, the word BUY/SELL and the buy/sell hue — a pattern never carries the side; CMP-134's marker glyphs are hollow; CMP-133's low-confidence strip segments are dashed. Each `15` entry says so. If the owner rejects §9.5, the component rule still stands on `16` §6 rules 1 and 5 and `25` §3, which are binding now; C-2.13 is binding regardless.

### 7.2 Anatomy (L3, E25-D01 §3.3)

The chip **is** the badge's look — CMP-227's pill (fill `color.status.info.subtle`, outline `color.status.info.default`, glyph, `color.text.primary`) carrying **"Trending up (estimated) · medium"** (32 characters; the rule ≤40 on one line, no wrap; the label and "(estimated)" are never truncated — a long-label guard story proves it). Beneath it, **rendered by CMP-133 itself** (the ticket's scope gives the component the numeric confidence; SCR-057 A11y: "the confidence value is always numeric"), the labelled line **"Confidence 0.71 (sub-signal agreement)"** as a CMP-036 row with CMP-032's dots after the number (filled count by G5's bands), then the optional `signals` text "ADX 31 · Hurst 0.61 · ATR 1.2 %" (D03's) — the number only where its label says what it is, never a bare 0.71 beside the direction word. A standalone chip (SCR-104's scanner row, SCR-030's header) therefore always shows the number too; a surface that already renders the labelled number adjacent passes `confidenceLabelId` and the component omits its own line and points `aria-describedby` at it. Test: the number renders whenever `confidence` is non-null. **Never `color.buy.*` / `color.sell.*`**, no direction arrow in a side hue, no imperative verb (R3's lint); the forbidden reading (E25-D01 F21, L1′): the direction glyph in buy-green is a buy signal by colour and a bare 0.71 beside the direction word reads as 71 % chance up. **Confidence absent:** chip "Trending up (estimated)", cell "Confidence — not supplied". **Insufficient data:** chip **"Insufficient data (estimated)"** and the cell "210 of 512 bars (hurst window in force) · Confidence — not computed" (R3's single string "Insufficient data — N of M bars" split across the chip and the cell so that the chip keeps the mandatory word within 40 characters; PROPOSED). The regime transition strip is SCR-057's (D03); its low-confidence segments are dashed (`16` §6 rule 5; the family rule).

### 7.3 Budget

≤1 Hz, rendered only on change, ≤1 ms (SCR-057); every change a single flip; the regime change is announced politely once per change and at most once per 5 s: "Regime changed — ranging, estimated, medium confidence".

### 7.4 The badge's host — one button, one Tab stop (PROPOSED; §17 Q5)

CMP-133 is the host `<button>`: it consumes the same `useEstimatedMethodology()` hook, its accessible name starts with the visible text (WCAG 2.2 SC 2.5.3 Label in Name — a speech-input user says what is shown): **"Trending up (estimated) · medium — market regime, medium confidence"**; confidence absent: "Trending up (estimated) — market regime, confidence not supplied"; insufficient data: "Insufficient data (estimated) — market regime, 210 of 512 bars"; and `Enter` / `Space` open SCR-058 at the regime section. CMP-227 renders inside it in **presentational mode** (`host` mode exists only inside the `EstimatedBadgeHost` context CMP-133 provides; outside a host the development-time error of §3 fires). **The host contract (PROPOSED):** a host is a native `<button>` (or `role="button"`) whose activation calls `openMethodology(detector)`; `EstimatedBadgeHost` carries that binding and throws when its element is not such a button or the activation is not bound, so a `<span>` wrapped in the context cannot render the look; a unit test asserts that no `host`-mode badge renders outside such an element (§13). CMP-133 is the only host today (§3). Consequence: one Tab stop per regime panel, not two; the confidence line is static text (`aria-live="off"`). The alternative — the chip beside a separate badge — costs a second stop on a 1 Hz panel whose only action is the drawer, and is recorded as the owner's choice. A panel whose CMP-133 chip is the host therefore carries no `section` pill: its heading is the plain word "Regime" and the chip carries "(estimated)"; §4.1's `section` example "Regime (estimated)" — `14` SCR-057's wireframe title — is a heading without a host chip and is never reused inside the host panel (board 07 draws the panel so from r6).

### 8.3 Hover / focus parity and keyboard (`05` §3.4 item 2; E11-D02 D18)

Nothing is hover-only: the full parameter snapshot and the observed / inferred copy are always rendered, so parity holds by construction. In a list the cards follow the **WAI-ARIA APG Feed pattern** (a streaming list that loads as it is read): the container is `role="feed"` (`aria-busy="true"` only during a batch insert, cleared when the DOM is stable), each card an `article` with `tabindex="0"`, `aria-labelledby` → its header sentence, `aria-describedby` → the chip, the freshness marker and the observed / inferred lines, `aria-posinset` / `aria-setsize` (the loaded count of the bounded ring buffer). `↑` / `↓` and `Page Up` / `Page Down` move between cards, `Home` / `End` to the first / last loaded card, `Ctrl+Home` / `Ctrl+End` to the element before / after the feed (APG), `Enter` opens the detail (the SCR-056 row detail or the journal context), **`Tab` from a focused card enters its inner stops — the chip first, then `actions`** (conformant for a feed, whose articles are in the Tab sequence; the arrows and `Page Down` are the fast path), `Esc` returns focus to the card (innermost-cancel), `Shift+F10` opens the row menu where one exists. New cards never move focus and arrive without an announcement per card: the panel's `role="status"` summarises at most once per 5 s ("2 new detector events — iceberg 63,118, absorption 63,090"; the zone list's own summary is the SCR-056 table's, C19). The cross-highlighted card carries `aria-current="true"` — never `aria-selected`, which neither `article` nor `button` allows (axe `aria-allowed-attr`); an `article` as a direct child of `role="list"` would fail axe `aria-required-children`, so `list` is not used. The card's accessible name starts with its visible header text (SC 2.5.3): "Iceberg, 13:58:02, 63,118.0, BUY, estimated" — the word "estimated" closes the name, the deliberate exception of §4.4 — and its description opens with the two composition names "Estimated, Iceberg. Stale, 12 seconds." when stale.

### 8.4 Card states (C17, G6)

**Detector off, two states with a precedence:** the platform flag wins — "Not available on this server — the stop-run detector is behind a feature flag" (`24` §16 `metrics.stop_run_detector` default `false`; a flag never gates the badge — the state is a card, not a missing chip); beneath it the user's switch — "Off — turn on in Detector settings" (`DetectorConfig.*.enabled`, default `true` in `22`); the two defaults contradict (C7). **Error:** "Detector error — last value 13:58:02" (no health field exists, G6). **Loading / empty** are list states: "Loading…" and "No events above 300 % × 3 levels in the last 50 bars" with a link to the thresholds (US-DET-004). **Stale:** the CMP-239 composition in the header.

### 8.5 Data contract

**Backend-side** detector events on `metrics.{symbol}` (event-like items: `v` the confidence, `unit: "confidence"`, `estimated: true`, `meta {price, side, reloads}` — `22` `/market/metrics` example; `23` §14.7) and `/market/metrics` for history; `params` is the series echo (G7); the detector is never run client-side. `detectorType` aligns with `DetectorMethodology.detector` (+ `unfinished_auction`, G2); the journal auto-tag reuses the same card.
