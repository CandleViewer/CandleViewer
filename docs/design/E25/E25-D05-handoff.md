## B. Accessibility acceptance criteria (`05` §10) — the six components

```gherkin
Feature: E25-D05 detector components and the estimated badge — accessibility acceptance criteria

  Scenario: Keyboard-only operation
    Given the user has not used a pointing device
    When the user reaches an estimated badge, changes the tape window, selects an imbalance zone,
      reads the regime chip and opens a detector card using only the keyboard
    Then every control involved is reachable via Tab or arrow-key navigation (Table 2)
    And every action has a documented non-drag keyboard equivalent (no drag exists here)
    And focus is never silently moved by a background data update (a push, a re-rank, a new card)
    And a visible focus indicator meeting >=3:1 contrast is present at every step (6.66 / 5.86 / 17.30 on raised)

  Scenario: Screen-reader operation
    Given the user is using NVDA with the keyboard
    When the user performs the same tasks
    Then all labels, roles and current values are announced correctly (Table 3)
    And live data is announced per 05 §6.2: readouts aria-live="off", band and regime changes polite
      at most once per 5 s, new cards summarised, never per tick
    And the canvas-rendered zone marks and the tape pane have a working DOM mirror and a
      "View as table" equivalent (Alt+T) with full data parity

  Scenario: Colour-independence
    Given the components display buy/sell direction, estimated status, tape bands and zone status
    When the state is rendered
    Then the state is also conveyed via glyph, pattern and text, not colour alone
      (the word "(estimated)", BUY/SELL with triangles, band words, solid / dashed / hatched status)
    And the components pass the deuteranopia simulation review run on the exports (2026-10-22, E25-D05 §12.3),
      protanopia and tritanopia being covered by the same non-colour channels per hue pair (not simulated)

  Scenario: Contrast
    Given the components are rendered in the dark theme and the high-contrast theme
    Then all text meets >=4.5:1 and all meaningful non-text elements meet >=3:1 per the token
      contrast matrix (E25-D05 §12.1: 29 gated rows, 0 FAIL)

  Scenario: Reduced motion
    Given the user has prefers-reduced-motion enabled
    When a value changes
    Then nothing animates beyond the pane's stale dim, which becomes instant; no flash exceeds 3 per second
      and nothing moves for more than 5 s

  Scenario: Automated gates
    Given the implementation PR is opened
    Then axe-core reports zero new serious or critical violations
    And the keyboard-only E2E smoke test covering the badge → drawer path passes
    And the catalogue-level test asserts CMP-227 on every 14 §12.3 "(estimated)" screen
    And every pane that draws a marker badge shows a visible (estimated) word (the pane-level assertion)
    And the card feed passes axe (no aria-required-children or aria-allowed-attr finding)
```
