## 3. Step 1 — the form comparison (RULED BQ-08)

**Rule.** One row per D01 §4 field and per built field, once each. The tool computes every row from the form YAML and from D01 §4 at the base and the gate compares cell by cell (G06): the built line is the line of the field's own `label:` key; the Label cell is `same`, `same (spacing)` (equal once spaces, hyphens and slashes are ignored) or the built label in quotes; Required reads `D01 / built`; Options lists the options when there are at most five short ones, else the count. A row with no difference reads `match`. A row with a difference starts with its `FM` id, then `drift` (a bare dropdown option, D01 §7), `spec-update` (a required flag or an added field), `defect` (a label the repository lacks) or `fixed-at-source` (a label the repository lacked at the read and that has been created since), then a register row. A field label (the heading the defect-triage DoR and the guards parse) and a required flag are never changed in place: such a row stays a `spec-update` row (RULED BQ-08). Help text and order are compared over the whole form: the count of help texts that differ from D01's summaries, and of fields in another order, stands in each form's note. (RULED BQ-08) A later edit to these files shows up as a difference against D01 and is read as `drift`. (RULED BQ-05)
