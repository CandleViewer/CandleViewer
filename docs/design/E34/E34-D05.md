## 1. Rules stated once (every later row cites "rule n")

1. **The server derives every status** (E34-T01; `T` Technical notes). The client renders `TradeGroupStatus`, `LegStatus` and the preview's leg `status` as served and computes no group status, no count and no aggregate. A figure not served reads `e34.shared.not_served` ("not served yet").
2. **The native stop is a statement, never a control** (C-2.6). Every leg row's protection word comes from `native_sl_confirmed` (`22`:21754); no control on either screen removes, loosens or skips a stop, and a filled leg whose stop is not confirmed reads "stop pending" in danger, never neutral.
3. **One served operation, two labels.** Unwind and Close group are both `cancelTradeGroup` with `flatten_filled: true` (`22`:7896); Cancel working orders is the same operation without it. The client never loops over legs (`14`:1523).
4. **Protective actions are never armed and never hidden.** Unwind, Retry unwind, Close group and Cancel working orders need no arm, and a lockout, view-as, a pending stop, an unknown leg or a lost connection never gates them (D02 §4.2; D03 §3.5). Only the permission leg or a read-only account gates them, as T2.
5. **Words carry every state.** Colour and glyph reinforce; every status has a word, every glyph is `aria-hidden` (D03 §5.3; D04 §10).
6. **Every client guard is a UX affordance, re-enforced server-side** (`T` Security notes). The arm state (`session_not_armed`, `22`:638), the SL presence (C-2.6), the override limits (refused whole, never clamped, C-12.5) and the account scope (C-12.4) are each checked by the server on the request. The UI hides nothing for safety and enforces nothing; an engineer who implements a guard as the control has built a defect.
7. **Copy is the deck's, byte for byte.** A builder renders a deck row's text exactly and fills only its `{slots}`; `{reason}` is always the served `error.message`, the OMS's own text (`22`:21783), never the exchange's.
