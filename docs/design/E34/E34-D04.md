## 3. Table semantics (T §Scope)

- **SCR-061 preview and outcome.** RQ-1 §7 names a `<table>` with the account as row header and, in the same paragraph, a grid with one Tab stop and arrows by cell. A body row holds controls (the include box, the row menu, "Why this size", the override fields), so the table is CMP-049's grid mode (`15`:584), `role="grid"`, the account `th scope="row"` and each column a `columnheader`. **Verdict:** compliant once read as the grid; RQ-1's "`<table>`" is the static case CMP-049 reserves for rows without controls (C-1).
- **SCR-062 treegrid.** CMP-049 `treegrid` (RQ-2 §2.1): one header row for both levels, so every leg cell has its column header and its row header (the account), `aria-level`, `aria-expanded`, `aria-posinset` / `aria-setsize` from the model. **Verdict:** compliant. **Sort:** `aria-sort` sits on the `columnheader`, the sort button inside it; RQ-2 §2.1 puts it on the button (F-11), and a sort must keep each group's legs under it (F-11).
- **Nested leg tables in confirms** (CMP-044 `legs`): a static table, `th scope="row"` the account, read in the dialog's scroll region (`15`:521). **Verdict:** compliant.
