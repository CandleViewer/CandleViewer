## 1. Locked inputs (built on, never re-decided)

1. **The native stop (C-2.6).** Every position-opening order, every leg of a fan-out included, carries a native exchange stop; no flag, environment or mode disables it (`CON`:128–134). A leg whose resolved parameters would have no stop is rejected at validation, never sent (`22`:7489). A filled leg whose stop the exchange has not acknowledged within 3 s is closed reduce-only by the OMS with a critical alert (`ADR8`:45). The stop is the native one, "held by Bybit (exchange)" (`E32D06`:143), never an app-side stop. **No control on SCR-061 turns the native stop off, and no frame shows a way to omit it.**
2. **Server-side fan-out** (`ADR8`:44). The client sends one intent; partial failure is an expected, first-class state (`ADR8`:18), and the system never resends a leg that might have executed (`ADR8`:48).
3. **The policy.** `atomicity` is `best_effort` (the default) or `all_or_none` (`22`:7481–7484). Under `best_effort` failed legs are reported and the others stay open; under `all_or_none` the opened legs are unwound and the group ends `failed` (`24`:2932–2933). `abort_on_first` is the rule-originated default (`24`:2934) and never reaches this ticket, whose request enum has two values. `all_or_none` never rests in `partially_open` (`28`:2442).
4. **Caps reject, never clamp (C-12.5).** A request that would widen any leg past its bound profile is refused whole, never a partial group (`22`:7452); an account-state cap rejects only its leg.
5. **RBAC is server-side** (C-12.4). The preview takes the submit's permission, so a Viewer has nothing to preview (`22`:14790). A Manager is scoped to the assigned accounts; a group definition is offered only when every member is granted (`E30D03`:349), and a read-only member is the one narrowable case (`E30D03`:364).
6. **The arm** (`DS`:74–78). `createTradeGroup` needs the arm on a live account (`22`:16748); a Retry is a new submit and needs it too. Unwind, Retry unwind and Cancel working orders are reduce-only closes and a cancel: **never asked for the arm**, and never gated by a lockout, view-as, a pending stop, an unknown leg or a lost connection; under the kill switch Cancel working orders passes and the closes follow OD-11 (§4.2).
7. **T2** (`E09D09`:85; `14`:85). A control the session may not use is disabled with a visible reason, programmatically associated (CMP-079, `15`:893). Reasons are E09-D09 §3.1's keys, verbatim, or a registered state string (E30-D02 §14's `lockout` and `frozen`, `E30D02`:421–422); a new reason is a PROPOSED key with its owner named. Each T2 control keeps its native role and full label, and its state row names its rendering (G-T2.1c): 2a, the reason inline, the label led by the CMP-019 `lock` glyph ("Not available"; G-T2.1d; `15`:238); 2b, the CMP-016 Tooltip echo, for icon-only controls, the `lock` the badge on the icon; or the sentence form, CMP-026 with `cta` omitted, where there is no control and no `lock`. G-T2.1b, verbatim (`DS`:28–29): `aria-disabled="true"`, never the `disabled` attribute — it stays in the Tab order and a menu item stays arrow-reachable. G-T2.2, verbatim (`DS`:40–42): hi-fi label `color.text.tertiary`, reason `color.text.secondary`; for primary / buy / sell actions the fill becomes `color.surface.raised` with a `color.border.default` hairline; never `color.text.disabled`, never `opacity.disabled` on the label, glyph or reason (the label pair is §8.1 P-08). G-T2.3, verbatim (`DS`:47–48): `Enter`, `Space` or a bound hotkey on a T2 control changes nothing and re-shows the reason inline with one polite announcement.
8. **The preview half is built on, not redrawn.** The columns `acct · profile · qty · lev · SL · ok`, the reason row (DS-F), the override marker (DS-C) and the S61-1 … S61-9 states are E28-D03 §8's (`E28D03`:333, :353–360); the selector and the pre-confirm leg table are E30-D03 §8's; the aggregate restatement is SCR-076's fan-out confirm (`E30D03`:179–180). This spec adds the send, the outcome, recovery, the T2 and blocked states and the gestures `E28D02`:442 leaves to it.
9. **The vocabulary** is E34-D01 §7's (a request row, R-1; V-1 … V-7 are ruled, BQ-4): Retry, Unwind, Retry unwind, Leave as is, Close group, Cancel working orders; Flatten reserved for CMP-123 and the kill switch; these are `24`'s words (`24`:3015, `24`:3048), and the wire name `flatten_filled` stays. Only these words appear on SCR-061, and their labels, confirms and tone are one table, §4.2, the same as E34-D03 §3.5 (a request row, R-7).
10. **No safety count is computed here.** An "N of M accepted / protected / unknown" figure is drawn only when served; `totals` serves requested, submitted and rejected legs only (`22`:21588–21592), so the rest is G-7 and every row says its own words. The count in a recovery label is a scope: the legs its confirm lists one per row, re-read on Confirm.

### 2.3 Per-account rate budget before Send

A row whose account has no request budget reads **"held"**, E30-D03's preview word for a leg with `rate_budget_exhausted` (`E30D03`:358; `E30D02`:444), with the CMP-232 `budget` pill and its CMP-035 countdown to the refill (E34-D03 §5.2, a request row, R-7). **When a rate limit holds the group, Send's T2 reason is `ratelimit.held` verbatim**, "Rate limited — your request is held." (`E30D03`:509; S061-40), never a coined string (G-T2.4). A whole refusal across accounts is SCR-158's `fanout-budget` state, "Not sent — the group would exceed the request budget on sub_002 …" (`E30D03`:266, :274), never redrawn here; the backoff frame names the starved account and its refill ETA (`20`:635). **While the budget holds, a row shows nothing about it; during backoff the waiting row shows its account's per-UID budget** (`14`:1504, `14`:1512; E34-D01 §6 Q3, ruled in BQ-5, a request row, R-3), not only a countdown. The spreading is explained in these words, not a checkbox (`14`:1509): the server sends each account's leg within its own budget. The checklist's "per-account rate-limit budget indicator" is therefore CMP-232's `budget` pill when a budget binds, before Send (here) and during it (S061-13); the figure in the pill is the served per-UID budget, "not served yet" (DS-G, `E28D03`:449) until G-2 serves it; an always-on figure is OQ-3.

### 2.4 The override: visibly exceptional (sign-off item)

- **The gesture.** A row's quantity, leverage, stop and take-profit cells are read-only text. The per-row include checkbox stays (`14`:1503); unchecking it excludes the row, the primary per-row control (E34-D01 §6 Q2, a request row, R-3), and "skipped" is the row word for a server skip. **Override…** is in the row menu (`Shift+F10`, or the row's overflow button, `size.target.min`). Choosing Override… turns that row's cells into fields, frames the row with a `border.hairline` `color.status.warning.strong` border on `color.status.warning.subtle`, and adds the override marker, CMP-256 OverrideMarker (PROPOSED; a request row, R-8), after the account. A footer line reads "1 override — audited" in `type.ui.caption`.
- **Narrowing only.** A value above the bound profile is refused whole, never clamped (`22`:7452). The row states it before Send: "Above the profile's cap, the whole group is refused." in `color.text.secondary` under the field.
- **The stop field.** Under Override… the stop cell is a field that is never empty: clearing it restores the profile's stop, and a stop looser than the profile allows refuses the whole group (C-2.6; `22`:7452). No gesture leaves a leg without its stop.
- **"Capped by profile."** Where the profile caps a field at its current value (leverage at 5x on sub_001), the increase stepper is natively disabled and the field's description is "Capped by profile: 5x" (E28-D03's words, `E28D03`:345). This is form validity (E09-D09 §9.1), **not T2**: no `lock` glyph, no CMP-079.
- **Names.** The field's accessible name is "Override quantity for sub_001"; its description "Override. Capped by profile: 5x" (E28-D03 DS-C). Clearing the field returns the profile's value and removes the pill.
