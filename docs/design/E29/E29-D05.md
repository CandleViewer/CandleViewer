### 1.4 Rules stated once (every later row cites "R-n")

- **R-1 Severity.** **Blocking:** a clause or a WCAG 2.2 A / AA criterion non-compliant with no compliant path in the merged designs, a state carried by colour alone, or an announcement with no string or politeness. **Major:** an at-risk clause, a key collision without a declared shadow, a T2 over- or under-conversion. **Minor:** wording, cadence or order, or an at-risk clause whose interim path the merged designs already give. **Info:** recorded for a consumer's charter (E11-D07:62; E13-D05:89). `05`:238's P0/P1 defect bar is E29-Q05's and is not used for design findings.
- **R-2 Findings and their closing (RULED BQ-8, confirmed).** An F row is a defect in a merged design against `05` or WCAG 2.2; it names the spec and its area, never an agent, plus the sentence, the replacement, one owner and one target. A finding closes when it is routed (owner and target named, the consumer's acknowledgement at merge) or accepted with a written rationale, both under the owner's `approved`; "fixed in the design file" is read as "fixed in the pack E29-D06 lifts" (C-19).
- **R-3 Verdicts.** `compliant` · `at risk` · `non-compliant` · `out of scope — <owner>` · `not yet decidable — routed to E29-Q05`. A `non-compliant` clause carries a Blocking F row; an `at risk` clause carries a Major F row or names its interim path.
- **R-4 Focus follows the row (AC1).** Stated once in §5.4; every other section cites it.
- **R-5 Never colour alone.** Every colour-carrying signal has a word, glyph, sign or `aria-*` state recorded in §9 (T AC2; `05`:107).
- **R-6 One motion definition.** D04 §3 is the blotters' motion owner (RULED BQ-26, confirmed); every transition cites its Mo row (§12).

## 5. Grid semantics, sorting, virtualisation and the focus rule

### 5.1 Semantics (RULED BQ-5, BQ-10)

`05` names no "data grid" pattern; `T Tech` is read as §3.4 item 2's APG grid / treegrid (`05`:95) and §6.5 (`05`:200); §6.1 is the canvas mirror and does not apply (C-01, C-02). The blotters hold to D02 D-1, D03 §8.2 and D04 A-6: `role="treegrid"` with `aria-level` per grouping layer, `aria-multiselectable`, `aria-rowcount` and absolute `aria-rowindex` across the window, the Symbol cell the `rowheader`, the totals in a trailing `rowgroup` led by a `rowheader` ("LIVE total"), Closed today its own `role="table"` (D02:142, :244); SCR-078 a treegrid of levels 1 to 3 (D03:477), its drawer `complementary` named by its heading (D03:89, :459). The panel is a labelled region, "Positions and orders — LIVE and DEMO" in a mixed view (D02:441). `aria-current` on the active row, which CMP-049 binds (`15`:530), carries into the treegrid variant.

### 5.2 Sorting (RULED BQ-11)

The header row is reached by `↑` from the first data row (`15`:530); `Enter` or `Space` activates a header button with `aria-sort` on its `columnheader` (D02:142; D03:470), and the result is announced once in the table's one polite region, as `15`:530 and D04:273 bind. **The cycle (PROPOSED; F-04):** ascending, descending, then the default order, `05` §6.3's tri-state (`05`:187) read as guidance, because D02 and D03 are silent. A sort pending on reading rows keeps its header busy and focusable, never T2 (`15`:530). SCR-078 sorts by Time only (D03:127). A sort by uPnL, liquidation distance or mark is a snapshot (D02:239); opted-in live sort waits while a row is focused or selected (D01:406).

### 5.3 Virtualisation and roving focus (T Perf; RULED BQ-12)

Rows have one fixed height per density and text scale, so the window places rows by index with no measurement (D02:115; D03:91, :477). One roving stop returns to the last focused cell (D02:447). **The focused row stays mounted (PROPOSED; G-01):** scrolled out of the window it stays in the DOM as the one row outside it, with its absolute `aria-rowindex`; no other off-screen row is rendered. `PageUp` / `PageDown` move by the window's row count; `Home` / `End` render only the target window; `Ctrl+A` selects without rendering, and a selected row scrolled out still counts (D02:144). The row-fixture tests stay the tests (D04H:215, :222; D04:269). **Set position (PROPOSED; F-03):** every row carries `aria-posinset` and `aria-setsize` within its group, from the data model's count, never the DOM's.

### 5.4 The focus rule (AC1; RULED BQ-13, confirmed)

- **Identity.** Focus is bound to the row's id and its column, never to an index: a re-sort, an insert above, a held change applied by the "Updates paused" chip and a recomputed `aria-rowindex` all leave focus on the same row and cell (D01:406; D04:320).
- **No live re-sort under focus.** Opted-in live sort waits while a row is focused or selected (D01:406); only an explicit header press re-sorts under focus, and the focused row keeps focus, is scrolled into view and is announced once by its name and position.
- **Leaving rows.** A focused row never leaves while it is focused (D01:408; D02:461); a terminal order or a closed position lingers and leaves once focus moves off (D02:465).
- **Revocation (PROPOSED; F-02).** When the focused row's account is revoked, its rows leave at once, because the security rule wins over the linger (D03:173), and focus moves to that account's "No longer shown — access to Sub-2 was withdrawn." line (D02:400), which is focusable; the focus move speaks the line once and RT-15's polite "revoked" stays silent for that account, so the line is heard once; focus never moves to `body`. `05`:96 lets only a user action or a modal alert move focus: C-22.
- **Row actions.** A SplitButton half keeps focus through value and state swaps, which are cuts (D04:344); a control that turns T2 keeps focus, because it stays focusable (D02:429); a busy Close keeps focus (D02:341).
- **Dialogs and menus** return focus to their opener; if the opener's row has gone, to the grid's roving stop (D03:459; D02:447).
