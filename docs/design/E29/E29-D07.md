## 1. Method and evidence

### 1.1 What can be observed, and by what

**Verify by:** **(a)** static, in code or CSS; **(b)** CI Storybook and VR (the `vr` check; committed baselines, six cells per story); **(c)** CI Playwright e2e capture (the `e2e-web` check; PNGs uploaded as `e2e-web-corpus-shard-<n>`, 7 days); **(c')** the same e2e, a computed style or a box measure and no image; **(d)** a human reviewer only; **OR** owner-run (§10). This lane reads PNGs, so a pair is judged here from a committed PNG or a downloaded CI artifact; it has **no browser and no design tool**: every render comes from CI, and a frame that is not exported as a PNG goes back to the orchestrator. Nothing here reaches an exchange or any external host (C-13.5); every value is a recorded, redacted fixture or a constant. e2e captures carry no Inter or JetBrains Mono (the `vr` job installs them, `_job-a11y.yml`:371–444), so they judge state, colour, copy and layout, and the **type ramp and digit alignment come from (a) and (b)**.

### 1.2 The pair (BQ-5)

A pair is one board PNG and one capture of the **same** state, theme, density, fixture and panel width, named `<S>/<theme>/<density>`. Panel widths of the boards: 1680 px (D02:11), 1920 px for board 06, 360 px for board 19, and 816 px for the state panels of board 13 (D01 D1's drop order, read on the board), so a capture takes the board's width or the pair is void. A **matching** row records the CI run id and the artifact (or VR baseline) name and commits nothing. A **discrepancy** row commits `docs/design/E29/img/E29-D07-<row>-<theme>-<density>-spec.png` and `-built.png` beside it (README:44–59), is a DF row, and cites both names. No baseline is committed and no pixel diff is made against Penpot.

## 7. The defect register (BQ-4, BQ-9; PROPOSED mapping)
