## 1. Purpose and scope
Decide the cost and shape of the DOM-mirror layer: nodes, update rate, screen-reader (SR) behaviour, structure, roles, live-region policy, keyboard model, and the engine-side contract that E06-T02 and E11 (M8) consume. Out of scope: the production layer, hi-fi SCR-045, per-cell footprint surrogates beyond affordability (ticket "Out of scope").

## 2. Method (honest)
- **Desk research** of the cited plan docs.
- **Measured microbenchmark, not the ticket's prototype scene.** The E06-K04 findings (`docs/plan/spikes/E06-K04.md`, "Honest limits") state no browser/Electron/GPU exists in the environment; there is no mirror stub in the K04 prototype. I wrote a standalone throwaway page that builds a 200-row × 7-column hidden table, patches it per `requestAnimationFrame`, and forces style/layout (`offsetHeight`) inside the measured span. Headless Chromium 156 shell on WSL2 Linux, 16 cores, software rendering, no worker/GL running concurrently. 20 s per run, 3 reps, 100k synthetic bars. Scenarios: static, pan at 30 bars/s, update storm at 20 msg/s.
- **Not done, and not claimed:** Electron and the other two runtimes, the reference machine, measurement alongside a rendering worker, NVDA/VoiceOver walkthrough, axe-core run. No SR testing was done by anyone. Cadence results in §5 are a design proposal, not validated. See §8.

## 4. Decisions
**D1 Window and nodes.** Cap stays 200 rows (26 §12) as the *maximum*; the default window is **60 rows centred on the cursor**, grown to 200 only when the table (SCR-045) is open. Hard cap 1,800 mirror nodes per chart pane (200 × 8 + ~40 detail + ~30 chrome), CI-asserted. *(F1, F2, F10, F11)*
**D2 Update policy.** Cursor row and any row receiving a live update: every frame. Other rows: diff-patched (write only changed strings), spread over ≥8 frames while the viewport moves (time-slicing), zero writes when nothing changed. Mirror is declared *eventually consistent within 8 frames (~133 ms) during pan and exact on pan end*; this is the reading of "never desync" that this review proposes (**needs owner/a11y sign-off**, see §8), because strict same-frame parity for 200 rows measured at 7-8 ms. *(F1, F10, F11)*
**D3 Budget status.** 1 ms p95 is **met only for static/storm**; **not met during pan with 200 rows** (8.5 ms). With D1+D2 the measured p95 is 0.8 ms (60 rows, time-sliced). Production verdict is deferred to E06-T02 on real Electron + reference machine. *(F10, F11)*
**D4 Structure and roles.** As `E06-D03-mirror-structure.png`: wrapper `role="application"` + `aria-roledescription="trading chart"` + static aria-label (symbol, interval, range, last) + `aria-describedby` hint including "Tab leaves the chart"; canvas `role="img"` and not a tab stop; ONE pre-rendered `role="status" aria-live="polite" aria-atomic="true"` region; hidden table with `th scope=col`, `aria-rowcount`/`aria-rowindex`, focused bar marked `aria-current="true"`; one tab stop for the whole chart (roving cursor, not `tabindex` per row). *(F2, F3, F4, F8)*
**D5 Live-region policy.** Keyboard cursor announcements: 1 region, last-write-wins, coalesce to **one announcement per 500 ms while keys auto-repeat, 250 ms leading-edge for the first press, trailing edge always flushed ≤250 ms after the last key** (final state never lost). This yields ≤2/s while a key is held, satisfying US-CHART-008's NFR, and is stricter than 26's 4/s; 26 §12 and US-CHART-008 should be reconciled to this (proposal, **unvalidated by SR users**). Discrete jumps (Home/End, Alt+T, Enter) announce immediately and never coalesce. Ambient market values (bid/ask, mark, PnL) keep 05 §6.2's 1/2 s. Assertive is reserved per 05 §6.2 and is never used by the chart cursor. Under `prefers-reduced-motion` nothing changes for announcements; momentum is off and cursor snaps (26 §12, 05 §7). *(F4, F5, F6)*
**D6 Keyboard model.** As `E06-D03-keyboard-model.png`. ←/→ bar, ↑/↓ level, Home/End, Enter expand, Alt+T table, Esc back (reserved, 05 §3.3). PgUp/PgDn ±10 bars and a visible-range summary key are proposals needing hotkey-map entries (05 §3.2). Application-role escape path: Tab always leaves; stated in the describedby hint. Bidirectional sync: the engine owns a single cursor bar index; origin-tagged changes (pointer|keyboard|table) prevent double announcements (US-CHART-014 "Sync"). *(F2, F5, F8)*
**D7 Mirror under LOD.** Rule: **the mirror exposes the data the user can reach, not what the pixels show, but it must never expose less than the canvas and must state the degradation in text.** Concretely: L0/L1/L2/L3 all keep the bar rows (OHLCV, delta) in the mirror; L2/L3 cell values are available **only for the cursor bar via Enter** (not as 1,000s of nodes), and the cursor announcement appends "footprint at low detail" so the user knows it is richer than the canvas. This makes the mirror deliberately *more informative* than the canvas at L2/L3 (equal-status principle, 11 US-CHART-014), with the "never desync" rule of 06 §4.4 applying to values, not to glyph visibility. Consistent with CMP-182 "keep cell + DOM-mirror value". *(F1, F7)*
**D8 degraded-2d.** Mirror content and behaviour are a function of bars + LOD tier only, never of `RenderProfile`; a contract test runs the same mirror snapshot under full/reduced/degraded-2d. *(F7, ticket AC4)*
**D9 Engine contract (consumed by E06-T02, E11 M8; CMP-180 ChartApi).**
```ts
interface A11yWindow { firstBar:number; lastBar:number; cursorBar:number; lodTier:'L0'|'L1'|'L2'|'L3'; }
interface ChartApi { // additions
  getA11yWindow(): A11yWindow;                          // 05 §6.1 query surface
  onA11yWindowChange(cb:(w:A11yWindow, origin:'pointer'|'keyboard'|'table'|'data')=>void): ()=>void;
  setCursor(barIndex:number, origin:'keyboard'|'table'): void;
  getBarSummary(barIndex:number): string;                // text for the live region, one source
  getDomMirrorRoot(): HTMLElement;                       // already in CMP-180
}
```
Mirror sync is a named Performance.measure stage `domMirrorSync` (exists in the E06-D02 harness JSON, `docs/design/E06/E06-D02.md` perStageMs). Mirror values carry the chart's data classification (F9). *(F1, F9)*

## 5. Live-region throttling timeline (text form of the pending frame)
| t (ms) | Event | Announced |
|---|---|---|
| 0 | Right-arrow press #1 | immediate (leading edge): "14:05, close …" |
| 60, 120, 180, … | auto-repeat presses #2…n | cursor moves, announcement withheld |
| 500 | window elapses | latest state announced |
| 1000 | next window | latest state announced |
| last key + 250 | key released | trailing flush of final state |
| any | Home / End / Alt+T / Enter | immediate, resets window |
