## 1. Locked inputs (built on, never re-decided)

1. **Server truth (C-2.12, C-12.4).** Every value drawn is the server's: each discrepancy, its kind, both values, the account's standing and every drill verdict. The UI computes no delta, no kind and no verdict. RBAC is enforced server-side; the screen presents. Contract first (C-6.1): data no route serves yet is drawn as a target and named on a G-row, never given a shape here (§11).
2. **Statecharts record; synchronous code enforces (C-2.21).** B19's `stale_lockout` records the lock and the order-entry gate's synchronous check refuses (`24`:2172). No copy on these surfaces says the screen locks or unlocks anything: it reports the standing and sends the Owner's request.
3. **Protective paths never wait (C-2.6).** Cancel at exchange and Attach protective stop now never consult the stale standing (`24`:2174), so they stay enabled on a stale account. No frame gates them on the stale state, on an arm or on a missing step-up.
4. **Owner only (BQ-05).** Every `/admin/*` route requires the Owner (`14`:2531). The Discrepancies view and both tiles are T3 for any other role: absent, never drawn disabled, as anti-enumeration needs. E45-S01's Manager read-only list is C-1.
5. **Step-up per action (D8, ruled; R-1).** A confirm that spends a step-up asks for the code inside its own dialog, every time, and holds no grace for a second action. There is no entry gate, no admin window and no countdown on these surfaces. Copy says "Confirm it's you", never "step-up" or "re-authentication".
6. **The ladder.** AD-11 (`E42D02`:56) and D3's one anatomy per rung (`E42D02`:129). §4 places each confirm on one rung. Every confirm starts with focus on Cancel. The step-up line of every `accounts` confirm is the no-grace K-17 (BQ-04), never "Still trusted for …", which belongs to the graced classes (`E42D02`:158).
7. **T2** (`E09D09`:49). A control the session may not use is disabled with a visible reason. Each T2 control keeps its native role and its full label, led by the CMP-019 `lock` glyph ("Not available"), and its row names its rendering (G-T2.1c). G-T2.1b, verbatim (`DS`:28–29): `aria-disabled="true"`, never the `disabled` attribute — it stays in the Tab order and a menu item stays arrow-reachable. G-T2.3, verbatim (`DS`:47–48): `Enter`, `Space` or a bound hotkey on a T2 control changes nothing and re-shows the reason inline with one polite announcement. In greyscale (G-T2.2's wireframe clause) the T2 label is drawn in a grey that is not the placeholder grey. The stale reason is a state string: `recon.stale_locked` "Locked until the account is resolved." is a PROPOSED key for E29-D03's account-state vocabulary (OQ-1).
8. **No secret material (C-2.7, C-12.6).** No frame shows an API key, a signature, a session token or a credential. The raw-payload inset (DV-13) shows a redacted placeholder in every credential-bearing field, so redaction is visible in the design rather than remembered later. Account names and order ids are the only identifiers drawn.
9. **Reassurance only where true (BQ-08).** SCR-152's line (`14`:3114) is said for an account only while that account has no `missing_native_sl` row. Otherwise that account leads with K-12.

## 8. Accessibility annotations (WCAG 2.2 AA, `05`)

### 8.1 Structure and reading order

- `h1` "Discrepancies"; the table is CMP-049's `treegrid` (`15`:593) with a caption and column headers: the account ("sub_001 · LIVE") is the level-1 row, each discrepancy a level-2 row with the Kind cell as row header.
- Reading order per group: the safety line, then the rows, then "Re-run reconciliation". Status is always text (the Kind word, "stale", "DRILL"), never colour alone.

### 8.2 Keyboard and focus (R3)

- Initial focus on the `h1`. Tab order: the summary's filters, then the table as one Tab stop; inside it CMP-049's treegrid keys move by row and cell, `→` and `←` open and close an account row, and each row's actions are its cells.
- A confirm opens with focus on Cancel, traps focus, and returns it to the row's action on close; if the row has left, to the next row's first action, else the account row.
- `Enter` in the reason field (CF-06) does not submit; the confirm button does.

### 8.3 Live regions

One polite region per view. It speaks once per settled report, "{n} discrepancies resolved; {m} open", never per tick or per row. A stale lock is announced once, assertive, by the shell (E29-D03's policy), not by this view.

### 8.4 Text resize (R1) and forced colours (R2)

At 200 % zoom and the in-app text scale at 1280 × 800 the table's Local, Bybit and Delta columns stack under Kind in each row; the dialogs scroll their body and keep the buttons in view. In `forced-colors: active` every state is already a word; the DRILL badge and the Kind word keep a `CanvasText` border.
