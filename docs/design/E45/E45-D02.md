## 1. Locked inputs (built on, never re-decided)

1. **Server truth (C-2.12).** Every value drawn is served: the kind, both values, the delta, the account's standing and every drill verdict. The UI computes nothing (D01 §1 item 1, R-1). A datum not served yet is a target on a G-row (§13.1), never a shape.
2. **Statecharts record; synchronous code enforces (C-2.21).** No string or frame says this screen locks, unlocks or blocks anything. It reports the server's standing and sends the Owner's request; the server's answer decides.
3. **Protective actions are never gated (C-2.6).** "attaching a missing native SL, tightening a stop or re-arming a protective trigger is never refused" (`22`:17468). Cancel at Bybit and Attach stop stay enabled on a stale account, behind an open-dialog change (§5.3) and in every theme and width; no frame draws either as T2. The server decides and its refusal shows at the point of action (`24`:2174, `22`:16427).
4. **Owner only.** The view and both tiles are T3 for any other role (D01 §1 item 4, R-1).
5. **Step-up per action.** A code is asked inside the confirm, every time; the line is K-17 "This always needs a fresh code." (`E42D02`:171) and the heading "Confirm it's you" (`E42D02`:58). No grace, no window, no countdown.
6. **T2.** G-T2.1b, verbatim (`DS`:28–29): `aria-disabled="true"`, never the `disabled` attribute — it stays in the Tab order and a menu item stays arrow-reachable. G-T2.3, verbatim (`DS`:47–48): `Enter`, `Space` or a bound hotkey on a T2 control changes nothing and re-shows the reason inline with one polite announcement. G-T2.2 (`DS`:40): the label `color.text.tertiary`, the reason `color.text.secondary`, never the disabled text token and never the disabled opacity. The CMP-019 `lock` glyph leads the label, named "Not available" (`DS`:38).
7. **No secret material (C-2.7, C-12.6).** No frame shows a key, signature, session token or credential; the raw-payload inset shows `[redacted]` in every credential-bearing field in both themes.
8. **Motion.** A status change is applied in the frame it is known and never animated (`16`:259); only `opacity` and `transform` move (§7).
9. **Reassurance only where true (C-2.6).** SCR-152's line "Your exchange-side stop-losses are unaffected." (`14`:3115; deck `e45.s143.disc.reassure`) is said for an account only while that account has no `missing_native_sl` row. Otherwise that account leads with its no-stop line (`e45.s143.disc.no_stop.one` / `.other`, K-12 split) and the reassurance is not shown (D01 §1 item 9, R-1). The condition rides on the deck row's `source`.
