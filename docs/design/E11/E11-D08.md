## 1. Method

**Order of work** (`T Tech`): themes first, then densities, then states, then motion. Static first: a token or a constant compared from the code is exact, and a later render is then only checked for what the code cannot show (layout, rasterisation, focus over canvas).

**Observed by** (as `QA12`:70): `source` (the code at the base, read by the tool), `stub-run` (the built components rendered on loopback in headless Chromium, fixture data only, §1.1) and `owner-run` (needs the physical reference machine or the Electron shell). This pre-stage records `source` rows only; every `stub-run` row is an executable step (§8) run at its re-run trigger.

**Row status:** `compared`, `compared-in-part` (fewer than the five checks of §2.1 are measurable), `deferred-owned` (an open story builds it), `deferred-unowned` (no open story; a plan-gap G-row for the orchestrator), `out-of-scope (other epic's design QA)`.

**Severity** (RULED BQ-2; `QA12`:73): **Blocking** — a WCAG A or AA failure with no compliant path, a state carried by colour alone; **Major** — a spec line violated with a workable path; **Minor** — a tolerance-edge or wording drift; **Info** — a note. A severity word never decides filing. **Class** (RULED BQ-1): implementation defect · specification gap · accepted divergence.

**Out of scope** (`T`): functional testing (E11-Q01, Q02, Q06), the full accessibility audit (E11-Q05 #517), performance (E11-Q03 #445), and surfaces owned by other epics (their rows are G-12 … G-15).

### 1.1 The capture run (stub-run; executable at each trigger)

The collector is scratch code, never committed; this subsection is enough to rebuild it, and the run record of each re-run states the versions it used (as `QA12` §1.1).

- **Page.** A harness page under `apps/web` for the run, removed after. It imports the five style entries `apps/web/src/main.tsx` imports (the three token CSS files, `theme.css`, `components.css`), sets `data-theme` (dark, light, high-contrast) and `data-density` (comfortable, compact, dense) on the root, and mounts the built component the row names: `<Chart>` from `apps/web/src/chart/Chart.tsx` with bars from the `packages/fixtures/golden/bars/conformance/` bank, `ChartTablePanel` over the same bars, `ChartErrorSurface` with `getContext("webgl2")` returning null or a forced context loss.
- **Driver.** Playwright on the app's own Vite server at 127.0.0.1; one browser context per surface, theme, density and DPR (viewport 2560x1440; DPR 1, 1.25 and 2; reduced motion on and off); every non-loopback request aborted and listed (the list must be empty, C-13.5); the box screenshotted; computed styles, the accessibility tree, tab order and the canvas read by the collector; axe at DPR 1.
- **Evidence.** PNGs of fixture data only, checked by eye for any non-fixture value, embedded in the re-run PR body; no board and no Penpot page (RULED BQ-6, BQ-9). Each visual row names its golden case `e11-d08-<row>-<cell>` (G-09).
- **Owner-run.** RUN-9 (D06 §11 feel trials) and any row on the physical monitor or the Electron shell.
