## 1. Purpose, scope and method

### 1.1 What this spec fixes

The three surfaces a trader meets when the canvas is not enough: **SCR-045**, the data-table alternative, as the **normative accessible equivalent of SCR-030** (US-CHART-014 NFR; `05` §6.3; `14` §0.5.6) — its equal-status entry point in the chassis's panel header, where it opens, its columns and the 200 % rule, the expandable per-bar footprint sub-row (mechanism and column contract only; E18 owns the cell semantics), sort, filter and their announcements, selection and TSV copy, the row-action menu (flows E40 / E26 / E41 / E14), the stale banner, the table's own loading, empty and filtered-to-zero states, and the analytics payloads; **SCR-047**, the empty / no-data state with its three reasons drawn separately, the permitted-role CTA to SCR-140 and the explanatory variant, rendered without a GL context; **SCR-048**, the error state with three distinct errors (engine / WebGL, data feed, backend), the context-loss recovery treatment, a copyable correlation id, retry and "open diagnostics" — all in dark, light and high-contrast, with measured contrast and a CVD check. Out of scope, per #329: footprint sub-row content semantics (E18), the profile and DOM-ladder table variants of `05` §6.3 (E19, E21 — they reuse this shell), SCR-140 (E16), the alert / replay / note flows behind the row actions (E40 / E26 / E41), SCR-044's "before recorded history" error (E11-D03), the non-time bar-mode column sets (E12-D07 #242), the final empty-state copy (E16-D05 #373), the motion spec proper (E11-D06).

### 1.2 Method (honest)

Desk design and heuristic evaluation under the agent-delivery adaptation (owner decision 2026-09-25): no participants, no sessions, no prototype — nothing of SCR-045/047/048 is built (no chart UI is shipped; `packages/chart-engine/src` is scaffold), so the ticket's zoom review, screen-reader review and copy review are written as a protocol for the owner (§21.2) and a walkthrough (§21.3), not claimed as done. Contrast and CVD are computed programmatically over the token JSON (§18), never eyeballed; the column widths are computed from the `font.size.*` and `space.*` tokens (§5). Frame: Nielsen's ten heuristics plus the trading heuristics of `05` (keyboard-first as speed §1; one hotkey layer §3.1 / §3.3; no hover-only or drag-only interaction §3.1 item 6; colour never alone §4; equal-status canvas alternatives §6; reduced motion §7). Reference products are cited only where E11-D01 or E17-D01 verified them; nothing new was read from the web for this spec.

## 4. The entry point and where the table opens (D1, D2)

### 4.1 Equal status is a layout decision (D1)

The ticket's own test is structural: "reachable from the chart panel header, not hidden in settings — equal status verified" (SCR-045 sign-off). E11-D02 §2 reserved the slot (the toolbar's `Alt+T Table` placeholder at the right end; A-8 hands CMP-221's entry to this ticket). This spec fixes the control:

- **What it is.** A CMP-003 SegmentedControl with two options, `Chart` and `Table`, each a word plus a glyph (`icon/chart-candles`, `icon/table` — CR-D04-3), `role="radiogroup"` / `role="radio"` + `aria-checked`, arrow keys between the two, `Home` / `End`. Its accessible name is "Chart view" (the group), its options are named by their visible words (SC 2.5.3). The pressed option uses the pattern E11-D02 D8 fixed for the time-axis cluster — `color.surface.selected` fill, a check glyph in `color.text.primary`, `color.border.strong` 1 px (reinforcement) — so the two header controls that switch state read alike (Nielsen #4).
- **Where it sits.** In the CMP-221 toolbar immediately right of the chart-type control `[Candle ▾]` and left of `[FP]`, `[Ind]`, `[Draw]`: the three controls that choose _what the panel shows_ are adjacent, and the table is one of them. It has the same height (`size.control.height`), the same type (`type.ui.label`), the same weight (`font.weight.medium`) and the same horizontal padding (`space.button.paddingX`) as its neighbours; nothing about it is secondary — no ghost variant, no smaller type, no `color.text.secondary` label (the chassis board's placeholder text moves into this control; E11-D02's board 01 is updated in its r4, §27).
- **It never collapses away.** CMP-221 overflows into a `⋯` menu at narrow widths (CMP-221 A11y). The view switch is in the toolbar's **never-overflow set** with the symbol and interval pickers: at the 1280 px minimum viewport the toolbar holds symbol · interval · chart type · view switch · `⋯` at compact density (measured in §5.3's arithmetic: 5 controls ≈ 420 CSS px). `[FP]`, `[Ind]`, `[Draw]` overflow first.
- **Every chart panel has it**, including each SCR-049 grid cell (the cell header is a CMP-221, E11-D02 §8), floating windows (CMP-215) and the replay chart (SCR-097); a Viewer sees the same control (reading is not gated).
- **`Alt+T`** (`05` §3.2 "Toggle data-table alternative view", kept by E11-D01 Q4-f and E06-D03 D6 as the global handler that the chart root does not consume) toggles the switch. The Kbd `Alt+T` (CMP-022) is in the control's tooltip ("Table view — Alt+T"), in the `Ctrl+/` cheat-sheet (SCR-013) and in the row-action menu footer. The shipped keymap has no entry for it yet (§23 G-4): E11-S13 / E11-S14 register `chart.toggle_table` with this default.
- **Why a view switch and not a button or a menu item (heuristic).** A toggle button named "Table" says the table is an accessory of the chart; a radiogroup says the panel has two equal views and one is selected — which is the model US-CHART-014's NFR demands and what E11-D01 D5 found ("a working surface, not a read-only copy"). A menu item (the ticket's counter-example, "a view-as-table item buried in an overflow menu") fails the test by construction. The cost is one more control in the toolbar at the minimum viewport; the never-overflow set above pays it. Comparable (heuristic, low — plan sources only): the DOM / heatmap panel's own view choice (SCR-050) and the chart-type toggle (CMP-222) are also segmented controls in a panel header; the terminal already speaks this grammar.

1. **Comfortable → compact metrics** when the container is narrower than the comfortable fit width (720 CSS px at 100 %): row height, padding and type take the compact tokens; the rest of the panel keeps its density (`16` §3 rule 1 — spacing only, no structural change; the user's chosen density is unchanged elsewhere).

4. The user may still hide a primary column in CMP-056; the picker shows the measured width next to each column ("delta · 61 px") so the trade is visible.

### 5.4 Number formatting (D4)

- Every number is CMP-020 `NumericText` in `font.family.mono` with `font.feature.tabularNums`, right-aligned (`15` §0.3 rule 6).
- Prices: `priceDecimals` from the instrument via `A11yRows` (E06-D03 D9) — the table shows the digits the canvas's axis labels and pills show; it never re-quantises floats. Quantities: `qty_step` precision; abbreviation only above seven digits with the full value in `aria-label`.
- Signs: `+` / `−` (U+2212 in the cell, ASCII `-` in TSV, D9); `signDisplay: "always"` on delta, CVD and level delta; the sign is the meaning carrier (`05` §4 item 3), colour reinforces: `color.text.buy` / `color.text.sell` (E11-D02 CR-5, still unregistered — §16; measured 5.08–10.51:1 across the five row surfaces, §18); on the focused row the pair measures 6.66 / 5.96 / 6.66 :1 (positive) and 5.08 / 6.15 / 5.08 :1 (negative), so no fallback to `color.text.primary` is needed.
- `(estimated)`: CMP-227 — the literal word in the accessible name, `color.text.primary` on `color.status.info.subtle` with a `color.status.info.strong` glyph (the `info.strong`-as-text pair measures 4.38:1 in light and is rejected, §18); the flags column spells it `Est.` beside the other words (`25` §1's label; the two spellings are one DS question for E11-D05, §23).

- Zero and missing: `0` is a number; `—` means "not available" (footprint off, column not applicable) and is announced "not available".

## 6. Rows: the footprint sub-row, forming bars, aggregation and live sync (D5, D6)

### 6.1 The expandable per-bar footprint sub-row (D5)

**Mechanism (this spec's).** The bar row is a treegrid parent: `aria-expanded="false|true"`, `aria-level="1"`; the expander button in the first cell is named "Expand 38 levels" (the count comes with the row payload, so the name is honest before anything is fetched) and "Collapse 38 levels" when open; `Enter` on the row, `Enter` / `Space` on the button, or `→` on the time cell expands; `Esc`, `←` on the time cell or `Enter` again collapses. ### 6.2 Forming bar, aggregation and the caption (D6)

- **Forming bar** (`confirm: false`): the latest row while the bar is open; numbers in `color.text.secondary`, `forming` in the flags column, `aria-describedby` "forming bar, values change until close"; it is never sorted into the closed bars' order by a value sort — it stays pinned after the closed rows ("forming" is a row state, E12-D07), so a delta-sorted table does not hop every tick.
- **Aggregation (candle L2).** When the canvas merges bars into columns (E11-D01 D6's chip "Zoomed out · 1 column = 12 bars"), the table **keeps source bars** (E11-D01 Q6-c, O6 pending with E12-D07) and the caption adds "chart shows 1 column = 12 bars"; the extended column `bars per row` reads `×1` for every row (it exists for E12-D07's aggregated-row variant, where it carries the ratio). The chip's exit clause "Alt+T for every bar" therefore holds.
- **The caption is the summary.** `<caption>` = `summariseRange()` (US-CHART-014 "Summary announcement"), computed from the loaded rows in memory, never a query: "BTCUSDT 1 m — 61 bars visible on the chart (13:10–14:10 UTC) of 4,321 loaded · open 63,980.0 · close 64,011.0 (+0.05 %) · high 64,120.5 · low 63,901.0 · volume 71,204 · delta +1,208 · CVD +12,344 · 7 bars flagged · prices in USDT, volume in BTC". It updates with the chart's visible range at the live-sync cadence and is **not** a live region (it would flood); a "Read summary" key is proposed for the hotkey-map owner (the CMP-225 / E06-D03 H5 "read current bar's stats" lineage, §27). There is **no full-series aggregate footer**: a sum over 100k loaded rows is not a canvas value and would be an extra computation per tick; the visible-range summary is bounded by the viewport.

### 6.3 Live sync, cadence and the one model (D6)

- **Rows = the loaded series** the canvas draws (the `A11yRows` payload for the window plus the series store, E06-D03 D9), virtualised (CMP-049 `virtualized`, bar-keyed rows with identity preserved — E06-D03 D2's pool), `aria-rowcount` = loaded bars + 1, absolute `aria-rowindex` (E06-D03 D4), so a screen reader hears "row 2,912 of 4,321".
- **Cadence.** Values patch in place at `05` §6.3's cadence — default 1 update / 2 s, the Settings → Accessibility ambient control (SCR-117) — never destroyed; the forming row and the focused row patch at the same cadence (the table is DOM; `06` §4.4's never-desync rule binds the _mirror_, which E06-D03 D2 patches every frame; the table shows the bar's exact values at its own cadence and the caption states that cadence: "updates every 2 s").
- **Cursor.** The focused row is the selected cursor's bar (E06-D03 D6): a keyboard step in the table sets the cursor with origin `table` (announced once by the table's own grid navigation, not by the chart's region); a click on a row does the same with origin `pointer`; hover never moves anything; a `data` move (a new bar under follow, a history page) re-indexes silently and keeps the focused bar. On return to the chart the D10 column is on that bar (§4.2).
- **Following.** While the chart follows live (the cluster's `auto` on, E11-D01 Q2-c) the latest row is pinned at the bottom of the viewport and new bars push the view; when follow is off, or the user has scrolled the table away from the bottom, new bars append **without moving the view** and a neutral pill "3 new bars ↓" (CMP-011, with `End` as its shortcut) appears above the footer; `End` or the pill scrolls to the latest row and, as on the chart, re-enables follow (`05` §3.2 "Jump to latest bar (resume live)"); `Home` goes to the oldest loaded row and, at the loaded edge, raises one history page exactly as the chart's `Home` does (E11-D01 Q1-i). The pill is silent for a screen reader; the row count change is in the caption.
- **Feed state.** The status row's chips stay in view (D2), so Stale / Reduced rate / Reconnecting read as on the chart; the table adds nothing but a caption clause under Stale ≥ T1 or Disconnected — "values as of 13:42:05" (the last-good time, `14` §0.5.4) — so no row is presented as current when the feed is not (E17-D01 D6). Under Resyncing the table is untouched (bars are not book-derived).

## 7. The stale banner (D7)

`05` §6.3's rule, made precise for this table:

- **Condition.** The table's focused row's bar is outside the chart's visible range (`viewFirstBar`…`viewLastBar` from the `viewport` message, E06-D03 D9) **because the chart moved** (a pan, a zoom, follow-live advancing, a go-to-date in a linked chart) — not because the user scrolled the table (the table's own scrolling never raises it; the chart's visible range is the reference, and the user leaving it on purpose is not staleness). It also appears when the table is opened on a cursor bar that is already outside the visible range.
- **Where.** A CMP-028 banner (`tone: "warning"`, `role="status"`) between the filter toolbar and the header, full width, `color.status.warning.subtle` fill, `color.status.warning.strong` icon, `color.text.primary` text; two lines allowed at 200 %; appears instantly in both motion modes.
- **Copy (verbatim, the ticket's).** "Data is for bar 13:42, no longer in view — press Alt+T to refresh to current" with the Kbd `Alt+T` (CMP-022) and a button **Refresh to current**.
- **What refresh does.** Scrolls the table so the chart's visible range is in view, moves the selected cursor to the latest visible bar (origin `table`, so the chart's D10 column follows), focuses that row, dismisses the banner and announces "Refreshed to current: row k of N". While the banner shows, **`Alt+T` performs the refresh** (the mandated copy says so) and does **not** close the table; with no banner up, `Alt+T` toggles the view as D1 says. This is the one place `Alt+T` has two meanings; the banner names it, the Kbd is beside the button, and O-3 asks the owner to confirm or to make the banner's button the only refresh and keep `Alt+T` a pure toggle.
- **Never stale as current.** The rows the banner refers to are real bars whose closed values do not change; what is stale is the _context_. Row values keep patching; the focused row keeps `aria-current`; the caption still names the chart's current range. Under the feed's Stale / Disconnected the caption clause of §6.3 applies in addition, with no second banner (one feed state per surface, E17-D01 D1).
- **Announcement.** Polite, once on appearance: "Table is on bar 13:42, which is no longer in view on the chart." Never re-announced while the chart keeps moving; dismissed silently on refresh (the refresh announces itself).

## 8. Sort, filter, announcements, selection and copy (D8, D9)

### 8.1 Sort (D8)

- Every sortable header is a `<button>` inside the `<th>` named by the column and its state ("delta, sorted descending"); `Enter` / `Space` / click cycles **ascending → descending → time order** (`05` §6.3's tri-state; the natural order of this surface is time ascending), `aria-sort` on the `<th>` = `ascending` / `descending` / `none`; the glyph is `↑` / `↓` / none in `color.text.secondary`, with the word in the accessible name (never glyph-only).
- A **sort-status chip** (CMP-011 neutral, `color.text.primary` on `color.surface.raised`) in the filter toolbar reads "Sorted by delta ↓ — not in time order" with a **Reset** action (E12-D07's "arbitrary sorting is misleading", E11-D01 Q5-c): a value-sorted table of bars never pretends to be a time series. It persists while the table is open and is absent in time order.
- The sort **does not reset on a cursor move** (E11-D01 Q5-d: the `05` §6.3 reset would fire on every crosshair step under the sync); it resets on a symbol or interval change (a new series) and is remembered per panel while the workspace is open. The level table resets as §6.1 says.
- Announcement (polite, once per change): "Sorted by delta, descending" / "Sorted by time" — the `aria-sort` change alone is not announced by every screen reader, so the live region repeats it.
- Under a value sort the forming bar stays last (§6.2) and the selected cursor's row still scrolls into view on a cursor move (the order is the sorted order; the row is wherever the sort put it).

### 8.2 Filters (D8)

- A **CMP-055 FilterBar** above the table: active filters as removable CMP-011 chips (`Bid-stacked ×`, `Estimated ×`), an **Add filter** CMP-041 menu with checkbox items, and the **Columns** button (CMP-056). Filter-only predicates (they narrow rows, never columns — `05` §6.3): Flagged rows only → `Bid-stacked` / `Ask-stacked` / `any flag`; `Estimated rows only`; `Delta positive` / `Delta negative`; `Hide forming bar`. E12-D07 may add bar-mode predicates in the same menu.
- **Announcement** (polite, once per filter change): "Showing 6 of 40 rows, filtered by: Bid-stacked" — the ticket's wording; with two filters "…filtered by: Bid-stacked, Delta negative"; on clearing "Showing 40 of 40 rows". The count also sits as text beside the chips ("Showing 6 of 40 rows") and updates silently when live data changes it — a changed count is not a user action and would flood (`05` §6.2).
- **Filtered to zero**: the table body shows the CMP-026 `filtered-empty` block "No rows match: Bid-stacked, Delta negative" with **Clear filters**; the header row stays, so the columns remain visible and the user can see what was filtered; announced once ("No rows match the filters").
- Filters narrow the **table**; they never change the chart (the canvas keeps every bar) — the caption says "filters apply to the table only".

### 8.3 Selection and TSV copy (D9)

- **Selection model**: a row is selected with `Space` (toggles, `aria-selected`), `Shift+↑/↓` extends a contiguous range, `Shift+click` likewise, `Ctrl+A` selects every loaded row up to the copy cap, `Esc` clears the selection before it collapses or closes; selected rows get `color.surface.selected` with the time cell's check mark (the focused row's ring is distinct: the ring is focus, the fill is selection, and a row can be both).
- **`Ctrl+C`** copies the selection, or the focused row when nothing is selected, as **TSV**: a header row with the visible column names, one line per row, ISO-8601 UTC time (`2026-10-20T13:58:00Z`), numbers with the displayed precision, ASCII `-` for minus, no thousands separators (a spreadsheet parses them), the expanded level rows beneath their bar indented by one empty first column, `Est.` as text; the forming bar's line carries `forming` in the flags column. **Cap: 10,000 rows per copy** (≈ 1 MB) — above it the first 10,000 are copied and the announcement says so (O-4). Nothing leaves the machine; the clipboard write is the OS's. It is the browser's `Ctrl+C` — no keymap entry, so a text selection inside a cell copies that text as usual.
- **Announcement** (polite, once): "Copied 12 rows, 8 columns as TSV" / "Copied the first 10,000 of 12,420 selected rows as TSV"; a transient CMP-011 "Copied" chip for 2 s beside the caption (CMP-033's pattern).
- **CSV export**: the CMP-099 PrintExportBar button "Export CSV" in the footer is **designed and shipped disabled** with the reason "Export arrives with E15" (CMP-079 disabled-with-reason, `14` §0.5.5) until E11-S14's deferral target lands (E11-D01 Q5-f); it exports the same columns and rows as the TSV with `,` separators and a UTC header comment, and announces "Exported 4,321 rows as CSV" when enabled. `chart.data_table_exported` fires for both TSV and CSV (D14).

## 11. SCR-047 — the empty / no-data state (D12)

### 12.3 The correlation id and what the card never shows

- **The id.** For every REST failure the `Problem.instance` value (`urn:cv:req:{uuid}`, `22` `Problem` — "matches the `X-Request-Id` header and the audit entry"); for a WS `err` frame its `request_id` (`23` §10.2); shown as "ref urn:cv:req:0193f2bb-5031" in `font.family.mono`, `color.text.primary` on a `color.surface.sunken` chip, **selectable text** (never an image, never truncated with an ellipsis — it wraps), with CMP-033 **Copy reference** ("Copied" announced once). For an **engine-local** error no backend id exists: the client mints an opaque `urn:cv:ui:{uuid4}` and records it in the diagnostics snapshot so "Open diagnostics" and the reference join (§23 G-1 — the snapshot's closed `errors[]` entries need a `ref` field; E11-D02 D15 / E11-T07 concur before it is built).
- **Never on the card** (the ticket's security note; this screen is screenshotted into issues by design): exception text, stack traces, hostnames, IPs, URLs or query strings, `Problem.detail` or `Problem.errors[]` verbatim, Bybit's `exchange.ret_msg`, account ids or names, balances, positions, orders, user identity, workspace names. The card's words are **this spec's copy keyed by `code`** (§19), the id is opaque by construction, and the code is the `x-error-codes` slug (the closed registry, `22`) — "plain-language copy plus an opaque id is the whole contract". The CMP-027 `details` affordance is **not used** here (no technical detail is appropriate on a chart error); SCR-156's expandable stack trace belongs to the crash boundary, not to SCR-048.
- **Open diagnostics** opens SCR-046 as E11-D02 D15 fixed it; the snapshot's closed field list already carries `errors[] {code, atMs, recoverable}` and `renderProfile`, so the engine kind is reproducible from the paste.

### 12.4 The rest of the workspace stays usable

- The card lives inside the pane-stack region of **one** chart panel; the toolbar (symbol, interval, view switch) and the status row keep working — a symbol change clears the error and reloads; the view switch opens the table whenever rows exist.
- Other panels, the order ticket, positions and the kill switch are untouched (SCR-156's per-panel boundary; `06` §4.4 "trading-critical data is never sacrificed"); the body says "Other panels are unaffected." and, for the backend kind, where positions and orders live. The card never claims anything about stop-losses (the chart cannot know; SCR-156's native-SL reassurance belongs to the crash boundary where it is true).
- **Focus** is never stolen by the alert (`05` §3.4 item 3): `role="alert"` announces; the card's `Retry` is the first stop of the pane region's Tab order in place of the plot stop, `Esc` from the card goes to the toolbar's view switch. CMP-091 (which moves focus to its heading on mount) is the **crash** boundary's fallback and wraps the panel so a render crash inside the chart also stays inside the panel; SCR-048 itself is CMP-027.
- Failures never spin the render loop (SCR-048 Performance): under the card the loop is idle; under the strip it waits for `webglcontextrestored`.
- `chart.error_shown` fires once per episode (D14), not per retry.

Real `<table>` semantics throughout: `<caption>`, `<thead>` with `<th scope="col">` (sortable ones hold a `<button>`), `<tbody>`, the time cell as `<th scope="row">`, `aria-rowcount` = loaded bars + 1 and absolute `aria-rowindex` on every row (E06-D03 D4's pattern), `aria-colindex` on cells inside the virtualised window, `aria-current="true"` on the cursor row, `aria-sort` on headers, `aria-expanded` + `aria-level` on expandable rows, `aria-selected` on selected rows, `aria-busy` while loading. The table is a **grid composite** (one roving tab stop: APG grid; `05` §3.4 item 2) inside the chart panel's `role="region"`, in the panel's Tab order where the pane stack was (E11-D02 D18: toolbar → status chips → **table** → … the time axis and cluster are hidden with the pane stack); `Ctrl+\` leaves the region from any cell.

### 17.2 Focus placement and restoration

§4.2's table. In addition: the banner's **Refresh to current** and the SCR-048 card's **Retry** are reachable by `Tab` from the grid; a focused row that leaves the virtualised window (the user scrolled with the wheel) keeps DOM focus — the row node is kept alive while it is the cursor row (E06-D03 D2's identity rule) so focus is never lost to `body`; after a sort or filter the focused row stays the cursor's row if it is still shown, else the first shown row (announced "Filtered; row 1 of 6").

### 17.3 Live regions

One `role="status"` (polite, `aria-atomic`) region owned by the table for: sort, filter counts, copy, expand, page loads, the banner's appearance, refresh, follow-live; it writes **once per user action** and never per data tick (`05` §6.2) — the caption's live numbers, the "Showing n of m" count under live data, the "3 new bars" pill and the countdowns are text, not announcements. The SCR-048 card is the only `role="alert"` (assertive, once per episode); the restoring strip is `role="status"`. The chart's cursor region (E06-D03 D5) is **not** written by table navigation — the table's own grid semantics announce the cell — so a screen reader hears one voice. Re-triggers of identical text use E06-D03 D5's zero-width-space alternation.

### 17.4 Zoom, reflow and targets

- 200 % (SC 1.4.4 / 1.4.10): the primary set fits the 1280 px minimum viewport at compact density (§5.2, measured); no horizontal scroll of the primary columns ever; the stacked reflow at 320 CSS px keeps every cell and every key.
- Text scale 112 / 125 / 150 (`16` §4) composes: at 125 %+ with 640 CSS px the table reflows (§5.2) — the chosen text scale is never fought.
- Targets (SC 2.5.8, `05` §3.4 item 7): the expander, the actions button, every header button, chip, pill, Kbd and the segment ≥ 24 × 24 CSS px (chips get 2 px invisible padding above and below their 20 px pill, as E11-D02 D18 does); level rows and bar rows are 24 px tall — the row is the target. No essential exception is needed.
- Focus visible (SC 2.4.11): the focused row and cell carry the CMP-039 ring (2 px, 2 px offset, ≥ 4.72:1 on every row surface, §18); the sticky header never covers the focused row (a focused row scrolls below the header, `scroll-margin-top`).

### 17.5 Reduced motion (defaults; the motion spec is E11-D06's)

Expand / collapse: `motion.duration.fast` height animation → instant; scroll-into-view on cursor moves: smooth → instant (`scroll-behavior: auto`); skeleton shimmer → static two-tone (`16` §7); banner, pill, chip and card appearance: `fast` fade → instant; sort re-order: no animation in either mode (rows re-render in place — a FLIP animation would move 60 rows); the view switch: no transition in either mode (a view change is instant, like E11-D02's env and replay rule); the "Copied" chip's 2 s hold is a timer, not motion. Nothing flashes; nothing loops (no spinner without a count, and the one CMP-014 spinner inside CMP-038 uses `motion.spin`'s reduce variant).
