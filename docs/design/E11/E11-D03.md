## 1. Purpose, scope and method

### 1.1 What this spec fixes

The three small surfaces through which US-CHART-006 (autoscale and the manual lock), US-CHART-007 (log / linear / percent scales, the disabled-log rule) and US-CHART-010 (history depth, the recording boundary) reach the trader: the SCR-043 price-scale and time-scale context menus, the SCR-031 **Scales** tab of the chart settings dialog with its CMP-228 live preview and its scope control, the SCR-044 go-to-date dialog with its quick jumps and its failure states, and the scale-lock badge's states on CMP-188. Everything is specified in text — groups, semantics, copy, tokens, keyboard, announcements, measured contrast, CVD — so that E11-S05 / S06 / S15 can build without a verbal clarification. Out of scope, per #309: the General, Appearance, Trading and Performance tabs (E15), footprint settings SCR-032 (E18), the scale projection maths (E11-S05), session / day-boundary semantics (E12 — this spec designs only the toggles that show the markers).

### 1.2 Method (honest)

Desk design and heuristic evaluation under the agent-delivery adaptation (owner decision 2026-09-25): no participants, no sessions, no prototype. Contrast and CVD are computed programmatically over the real token JSON (§14–§15), never eyeballed. Frame: Nielsen's ten heuristics plus the trading heuristics of `05` (keyboard-first as speed §1; one hotkey layer §3.1 / §3.3; no hover-only or drag-only interaction §3.1 item 6; colour never alone §4; equal-status canvas alternatives §6; reduced motion §7). Where this spec names a reference product it relies on what E11-D01 verified (TradingView's price-scale menu and `Alt+G`, its "Reset price scale" shown only in a non-default state, Lightweight Charts issue #1759 on silent autoscale disengagement, Bookmap's documented controls); nothing new was read from the web. The owner's session protocol and walkthrough are in §17.

### 3.2 Semantics and invocation (D1)

- `role="menu"`, `aria-label="Price scale menu"`; groups `role="group"` + `aria-label` ("Scale mode", "Scale"); `role="separator"` between groups; items `menuitemradio` (mode), `menuitemcheckbox` (Lock, Invert, Merge), `menuitem` (Reset) — the WAI-ARIA APG menu pattern CMP-041 already names, extended with the checkable kinds (D03-CR-1).
- **Opened by** right-click anywhere on the gutter (the drag zone, E11-D02 D7), `Shift+F10` or the context-menu key while the price-axis stop has focus (E11-D02 D7's table row), and — for pointer-less discovery — the toolbar overflow `⋯ → Price scale…` (CMP-221; the same menu). On a pane with two gutters each gutter opens its own menu for its own scale (E11-D02 ORCH-7).
- **Focus:** the first enabled item on open (APG); `↑/↓` wrap; `Home/End` first / last item; typeahead by first letter cycles between "Linear" and "Logarithmic" (both L — allowed by APG, and the disabled item is still a typeahead target so the user lands on its reason); `Enter` / `Space` activate; `Esc` closes and returns focus to the stop that opened it (the price-axis surrogate, or the toolbar button); clicking outside closes and focus stays where the click landed.
- **Close on activation, announce once (heuristic — Nielsen #4; TradingView and native menus close on a checkable item):** every activation closes the menu; the state change is announced politely, latest-state, in E11-S06's grammar — "Price scale: logarithmic", "Price scale: percent", "Price scale: indexed to 100", "Price scale: linear", "Price scale locked" / "Price scale: auto", "Price scale inverted" / "Price scale upright", "Indicator scales merged" / "Indicator scales separate". Reopening the menu shows the new `aria-checked` states, which is how a screen-reader user verifies them.
- **Nothing here is hover-only or drag-only** (`05` §3.1 item 6): every item is reachable by keyboard from the axis stop, and the whole menu is reachable without a pointer through the toolbar.

### 3.3 Scale modes (D2)

| Item               | Meaning (projection only — `26` §3.5)           | Mode tag (E11-D02 D7) | Notes                                                                                                                                                                                          |
| ------------------ | ----------------------------------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Linear**         | `sy = (p − priceOrigin) × ky + by`              | (none)                | default; the word "Auto" is never a mode (§19 X-3)                                                                                                                                             |
| **Logarithmic**    | `sy` on `log(p)`                                | `log`                 | disabled with the D4 reason whenever any series bound to this scale holds a value ≤ 0 in the **loaded** range (not only the visible range, so panning cannot flip it); US-CHART-007 scenario 3 |
| **Percent**        | `sy` as % change from the reference bar's close | `%`                   | reference = the **leftmost visible bar** (US-CHART-007 "left edge as reference"), re-anchored on pan / zoom; the axis surrogate's name states it ("percent from 14 Oct 07:30")                 |
| **Indexed to 100** | `sy` as `100 × p / p_ref`                       | `idx`                 | same reference rule; the `idx` tag is new text in the E11-D02 D7 family (same token, `color.text.tertiary`) — an amendment to its tag list (§23 A-3)                                           |

Choosing a mode never changes the lock: a locked scale stays locked in the new projection (its manual range re-projected), an auto scale stays auto. Inversion is orthogonal and composes (`log inv`). Per-pane: each pane's own scale has its own mode; a merged indicator scale (left gutter) has its own menu and mode.

### 3.4 Lock, Invert, Merge, Reset (D3)

- **Lock scale** (`menuitemcheckbox`): checked ⇔ autoscale off ⇔ the badge "Price scale locked" is on the gutter (E11-D01 D2); its description (`aria-describedby`, visible as a second line only while the menu is at comfortable density) reads "Unchecked: auto-scale fits the visible bars". Checking it from the menu with no manual range yet freezes the current range (so the trader can pin a range before dragging); unchecking restores auto-fit, exactly as `Home`, the badge and double-click do. Session state: never persisted, never in the Scales tab, never synced (E11-D01 Q1-h).
- **Invert scale**: flips the projection; the mode tag gains `inv`; the lock is unaffected; persisted per panel (a Scales-tab field too).
- **Merge indicator scales**: when the pane carries indicators with their own scales (E13-S01 "own scale"), checking merges them into one secondary scale drawn in the **left gutter** (E11-D02 ORCH-7); unchecking returns each indicator to its own treatment (E13-S01 offers merge-into-left or "no scale"). Disabled with the reason "No indicator scales on this pane" when there is nothing to merge.
- **Reset scale** (`menuitem`): clears the manual range and restores auto-fit, keeping mode and inversion — the menu twin of double-clicking the gutter, of `Home` on the axis and of `Enter` on the badge (E11-D02 D7); disabled with the reason "Already auto-scaled" when the scale is auto (TradingView's "Reset price scale" appears only in a non-default state — E11-D01; here it stays visible and explains itself, because a disappearing item teaches nothing, Nielsen #6). Hint column: `Home · double-click`.

### 3.5 The disabled Logarithmic item (D4) and the fallback (D5)

**Why it gets its own treatment (ticket Technical note).** A silently grey item is tried three times and then filed as a bug; a tooltip on a disabled control is unreliable across platforms and assistive technology. So the reason is **part of the item**: a second line, wrapped, in `color.text.secondary` (8.14 / 8.26 / 13.27:1 on `color.surface.overlay` — measured, §14), preceded by an ⓘ glyph in the same token (≥3:1 as non-text). The label itself is `color.text.disabled` (2.64 / 3.44 / 2.64:1 — exempt as an inactive control, WCAG 1.4.3, reported not gated). ARIA: `role="menuitemradio" aria-checked="false" aria-disabled="true" aria-describedby="<reason id>"`; the item **stays in the arrow and typeahead order** (APG allows focusable disabled items, and here focus is how the explanation is heard), `Enter` / `Space` do nothing and announce nothing beyond the name + description already read on focus. The exact string, from #309: **"Log scale needs all-positive values; this series contains a value <= 0"**.

**When the condition arrives later (D5).** The rule is evaluated per scale over every series bound to it, over the **loaded** range, on every data append and on every page splice — never per frame on the visible range. If Logarithmic is active and a value ≤ 0 appears (a CVD or delta series merged onto the scale, an indicator crossing zero, a corrupt print), then in the same frame: the projection switches to **Linear** (the scale cannot render a non-positive value in log space; the engine never emits NaN, clips a bar or leaves a blank — `26` §3.5 projection function, E11-S05 unit test), the mode tag disappears, and one polite announcement reads "Log scale unavailable — switched to linear: this series now contains a value <= 0"; the menu's Logarithmic item and the Scales tab's radio become the disabled-with-reason state; the panel's **saved preference stays "logarithmic"**, shown in the Scales tab as "Logarithmic (unavailable)" with the same reason, so the user can see what they asked for. When the series is all-positive again (e.g. the offending indicator is removed) the item **re-enables but the scale stays linear** until the user chooses Logarithmic again — a scale that flips by itself every time a series crosses zero would be motion without intent and a Nielsen #5 hazard on the axis the trader reads prices from. Analytics: `chart.price_scale_changed` with `source: "fallback"` (§9).

### 6.3 Scope control (D10) and Reset (D11)

### 6.4 CMP-228 PreviewTile (D12)

- **Live, not sample:** `kind: "candles"`, `source: "live"` (D03-CR-3): the tile renders **this chart's** bound series over its current visible range, through the **pending** (unsaved) Scales values, on `color.surface.sunken` (CMP-228 token), 1 px `color.border.default`, `radius.md`; miniature axis labels in `color.text.tertiary` (6.83 / 4.86 / 13.61:1) so precision and mode are visible in the preview itself (log compresses the top, invert flips, percent relabels). It is a second, lightweight engine view of the same data (a `Chart` instance over the same `BarStore` with `setDensity("dense")`) and re-projects in ≤1 frame per change; it never fetches.
- **A11y:** `role="img"` with a name that states the configuration in words — "Preview: BTCUSDT 1 minute, logarithmic scale, 1 decimal, inverted, 12 pixels per bar, UTC" — updated with the fields; `aria-live` off (the fields announce themselves). The settings remain the primary disclosure (CMP-228 A11y line).
- **Empty** (the chart has no bars — SCR-047, a fresh symbol, or history not yet loaded): the tile keeps its frame and shows the CMP-029 silhouette at `opacity.muted` with the text **"Preview unavailable — no bars loaded"** in `color.text.secondary` (10.69 / 7.37 / 17.42:1 on the sunken fill); the fields stay enabled and apply to the chart as it fills.
- **Errored** (the chart is in SCR-048 or `degraded-2d` cannot host a second view): **"Preview unavailable — chart error; settings still apply"** with a `color.status.danger.strong` glyph (11.31 / 3.37 / 11.31:1 — non-text ≥3:1 in every theme); the fields stay enabled; the preview's name says "Preview unavailable".
- **Never a spinner:** there is no loading state — the preview either has the bars (it draws them in one frame) or shows one of the two text states; a settings dialog that spins for a projection change would teach the user the app is slower than it is (#309 Performance notes).

### 7.2 Entry (D13)

- **Two inputs, one instant.** Date (`YYYY-MM-DD`) and Time (`HH:MM`, 24-hour, seconds not offered — a bar is the unit of navigation) are interpreted in the **active zone**: the "Enter in:" segmented control defaults to the panel's time-zone setting (D6) and the active zone's abbreviation is printed after the Time field ("UTC" or "UTC+2"); the **twin line** restates the entered instant in the other zone and updates on every valid keystroke ("= 15:42 Europe/Berlin (UTC+2)" ↔ "= 13:42 UTC"), so both clocks are visible at entry time (#309 AC 3) without two editable fields that could disagree. Switching the zone re-labels; it never silently converts the typed digits (the digits stay, the twin line changes — Nielsen #3).
- **Canonical value is UTC** (CMP-047 `timezone: "UTC"`, `15`): the dialog converts local entry to UTC before anything leaves it; the local zone is the browser's (`Intl.DateTimeFormat().resolvedOptions().timeZone`), named with its IANA id and current offset, DST-correct; no third zone exists (§20 CG-2). CMP-047 gains `inputTimezone: "UTC" | "local"` and a `secondaryDisplay` (D03-CR-2).
- **Format hint** "YYYY-MM-DD HH:MM, 24-hour" is visible under the fields and is the `aria-describedby` of both inputs; the inputs are `font.family.mono`, `inputmode="numeric"`, with a lenient parser (`2026-9-15 1342`, `15.09.2026 13:42` in local-date mode are accepted and echoed back normalised on blur) but one canonical display.
- **Calendar:** the "Open calendar" button (CMP-002 IconButton, `icon/calendar` D03-CR-6) opens CMP-047's single-date grid (arrows by day, `PageUp/PageDown` by month, `Enter` picks, `Esc` closes back to the button); days before the recording start and after today are `aria-disabled` (2.64 / 3.44 / 2.64:1 — exempt) with the range stated in the grid's caption ("Recorded history: 1 Sep 2026 – today"); picking a day keeps the typed time.
- **Prefill:** on open the fields hold the **data cursor's bar** (E06-D03 D4 — what the user is looking at), or the latest bar when the cursor is unplaced, so `Alt+G`, `Enter` is a no-op jump that re-centres rather than an error.

### 7.5 Focus, closing and landing (D17)

- **On open:** focus lands on the Date input (CMP-043 `initialFocusRef`); the dialog is `role="dialog" aria-modal="true"`, `aria-labelledby` the title, `aria-describedby` the format hint; the focus trap cycles Enter-in → Date → Open calendar → Time → Quick jumps (one `role="group"`, each button a Tab stop — five stops, so a disabled one is still reachable and its reason read) → Cancel → Jump → back to Enter-in; `Enter` in either input = Jump.
- **`Esc` and Cancel** close the dialog **without moving the chart or the cursor** (#309 AC 2) — the dialog never applies anything before Jump; focus returns to the **invoking control**: the time-axis stop (`Alt+G` with the axis focused, the context menu's "Go to date…"), the toolbar's overflow button, or the plot stop when `Alt+G` was pressed with the plot focused; the live region says nothing (nothing changed).
- **On Jump:** the dialog closes **first** (no spinner inside it), focus returns to the invoking control, and the chart performs E11-D01 Q2-f: the target bar is placed at the **horizontal centre** of the plot at the **current** bar spacing (zoom unchanged), the dashed `color.action.primary.default` marker with its time pill appears (E11-D02 D8/D9) and stays until the next navigation input, follow pauses so the cluster reads "Paused at 15 Sep 13:42" (E11-D01 Q2-c, with the date when not today), and `End` / `›` / the `auto` toggle / double-click on the plot return to live at the default right offset. A target outside the loaded pages shows the E11-D02 loading band around the target while E11-S15 pages the range (≤800 ms, SCR-044 Performance); the marker is drawn as soon as the first page lands.
- **The E06-D03 cursor lands on the target bar** (E11-D01 Q2-f): the data cursor (= the crosshair's `position`, two drivers, last input wins — E11-D01 Q4-i) moves to the target so the readout shows it and `←/→` continue from there; because the cursor column (E06-D03 D10, `color.focus.ring`) and the marker share the bar, **the marker's pill yields** — the cursor's time pill is drawn, the marker's pill reappears when the cursor leaves the bar; in high-contrast the two are one hue (`palette.blue.300`, §15 collapse) and are told apart by shape — a solid ≥2 px column with a halo against a 1 px dashed line.
- **One announcement, polite, combining landing and pause** (two back-to-back announcements would interrupt each other — `05` §6.2): `"Jumped to " + target (short date, HH:MM, zone) + " — " + getBarSummary(targetBar, "full") + ". Following paused."` → "Jumped to 15 Sep 13:42 UTC — close 64,210, delta −128. Following paused."; a gap landing says "No data at 02:12 — landed on 02:15, close …". The chart root's `aria-label` (E06-D03 D4) is not changed by a jump.
- **While a jump is pending** (paging), another `Alt+G` opens the dialog again normally; `Esc` on the chart does not cancel the paging (there is nothing to cancel that would move the chart back — the view only changes when the page lands).

### 7.6 Degraded feed (D18) and the chord (D19)

- **Stale / Delayed** (E17-D01 D2): history is REST-served and already recorded, so the dialog is fully available; the header repeats the feed chip so the trader knows the "latest bar" is the stale one; a jump pauses follow anyway.
- **Disconnected:** the dialog opens (the user may want to look back while waiting); typed targets inside the loaded range jump from memory; a target that needs paging is refused inline (§7.4); the three record-backed quick jumps are disabled with "Unavailable while disconnected"; the derived two work when inside the loaded range. Nothing in the dialog implies a reconnect is being attempted — that is the chip's job (E17-D01 D13: inline text at the point of action plus one polite announcement).
- **Chord (D19):** `chart.go_to_date` = **`Alt+G`** in the Chart focus context (TradingView's habit; `rules.graph_mode` = `Alt+G` lives in the Rules context — the registry's set-intersection rule makes them disjoint, `05` §3.3, and the SCR-013 cheat-sheet shows both), **conditional on E11-D01 O13**: the shell must remove Electron's application menu so a bare `Alt` release cannot steal focus; if O13 is unmet when E11-S15 starts, the default binding is `Ctrl+Shift+G` (unbound in `keymap.json` and `reserved-keys.json` today) and the menu hint follows the registry. Bare `G` is not used (E14-D01 #204 probes the drawing letters). The user may remap either (`05` §3.1 item 3).

### 12.3 Error association and live regions

- Every error of §7.4 sets `aria-invalid="true"` on the field it concerns (Date for history / future errors, the malformed field for format errors) and `aria-describedby` = the hint id **plus** the error id (both are read; the hint is never replaced by the error, so the format stays available while the error is shown — SC 3.3.1 / 3.3.3).
- **Politeness:** before-history, after-latest, after-replay-clock, needs-paging and couldn't-check / couldn't-load are `severity="error"` → CMP-027 `role="alert"`, announced **once per submit** (discrete, user-initiated — `05` §6.2's assertive class is for low-frequency, high-importance events; a submit is one); invalid format and no-data-at-target are `severity="warning"` → `role="status"` (polite); nothing is announced per keystroke; the twin-zone line is **not** live (it changes with every keystroke) — it is read when the Time field is focused via `aria-describedby`.
- The landing announcement (§7.5) and every menu state change go to the chart's existing polite region (E11-D02 §10 ambient policy), latest-state, ≤2/s; the D5 fallback announcement goes to the same region once.
- Quick-jump reasons are each button's `aria-describedby`; a disabled button is `aria-disabled`, never `disabled`, so it stays in the Tab order and its reason is read (CMP-001 A11y; `14` §0.5.5).

## 17. Session protocol (owner-runnable) and owner walkthrough checklist

### 17.1 Session protocol (`05` §8.2 adaptation; run later, nothing here was run)

- **Participants:** S1 the owner (self-administered, never counts toward a finding); S2 one or two account managers (P2); S3 one screen-reader user (NVDA + the Electron shell, `05` §8.1 row 1; P3-type); S4 one low-vision user at 200 % (P3-type). Recruitment is E11-D01 O1 / O11's.
- **Setup:** the E11-S05 / S06 / S15 build or a keyboard HTML mock of the three surfaces (E11-D01 O2b lineage) on BTCUSDT 1 m with recorded history starting 2026-09-01 08:00 UTC and one coverage gap on 2026-09-04 02:11–02:14; a second pane with a CVD indicator merged onto the price scale (so Logarithmic is disabled); a viewer account without a journal grant for T6.
- **Tasks (think-aloud; success = task done without the moderator; record time-on-task and every utterance verbatim; nothing is scripted as "expected"):** **T1** switch the price scale to logarithmic from the keyboard, then back; note what the participant says when the item is disabled and whether they find the reason without being told. **T2** lock the scale by dragging, then restore it three different ways; ask what "Lock scale" means before and after. **T3** go to 2026-08-15 10:00 local time; observe how the before-history error is read and what they do next. **T4** go to "yesterday" with a quick jump, then return to live; ask where they expected to land and whether the marker helped. **T5** change precision to 2 decimals for all panels, then reset; note whether the scope helper was read. **T6** (viewer account) open the dialog and describe the quick jumps; ask what the disabled journal button means. **T7** (S3 only) walk the price menu with arrows and typeahead; walk the dialog's Tab order; report what was announced on landing. **T8** (S4 only) at 200 % read every error block and the badge; report any truncation.
- **Measures:** success / assisted / fail per task; time-on-task; the words used for the lock state (free recall); whether the inline reason was read aloud unprompted (T1); whether `Esc` was tried before Cancel (T3); landing expectation (T4); announcement completeness (T7).
- **Analysis:** two independent coders tag utterances against H1–H14; a finding needs two participants or one AT participant; results append to §16 as "(observed)" rows and may overturn D2–D5, D14, D17; the owner decides on #309.
