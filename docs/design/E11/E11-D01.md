## 1. Purpose and scope

E11-D02 (chart chassis, #308) wireframes from this document. It fixes: navigation gestures and keyboard
equivalents (Q1), the autoscale-on-axis-drag behaviour (Q2), the crosshair magnet default (Q3), the
keyboard-first vocabulary and focus model (Q4), the data-table role (Q5) and the "aggregated" disclosure (Q6).
Out of scope (ticket): hi-fi visuals (D02–D04), order-flow surfaces, A/B testing, usability tests of the built product.

## 2. Method (honest statement)

**Desk research only. No participants were recruited, no sessions were run, no one was interviewed.** The ticket's
planned method (owner + 2–3 managers, a screen-reader user and a low-vision user, think-aloud on the E06 build)
needs humans an agent cannot supply. Evidence used:

- repo research corpus (`docs/research/01-tradingview-charting.md` and its digest, `04-deepcharts-deepchart.digest.md`, `07-crypto-orderflow-competitors.digest.md`, `09-execution-risk-tools.md`, `20-feature-matrix.md`);
- personas `10-personas.md` (Pavel, Marta, Viewer, and the §keyboard-model for the rule canvas);
- stories `11-user-stories.md` US-CHART-006/007/008/010/014; screens `14-screens-catalogue.md` SCR-030/043/044/045;
- `05-accessibility-standard.md` §3.1–3.4, §6; `26-chart-engine-design.md` §3.5; `docs/design/E06/E06-D02.md`.

All findings are labelled **(heuristic)**: reasoned from documents, not observed. **Coverage gaps:** ATAS and
Sierra Chart appear in the corpus only as feature/pricing entries (`07-…digest` §competitors); no document records their
pan/zoom or scale-menu behaviour, so **no claim about their gesture behaviour is made**. Sierra's and Bookmap's
only cited relevance is configurable hotkeys (`09-execution-risk-tools.md` table, "Hotkeys" row). TradingView hotkeys
come from `01-…digest` line "Hotkeys: … zoom scroll up/down, arrows pan (Ctrl+arrow = bigger jump), Alt+G go to date".
The DeepCharts digest §19 states it has *no* enumerated default keys (user-assignable only). Gesture "feel" cannot be
judged from documents at all; it is deferred to §9.

### 4.1 Q1 — Navigation gestures and keyboard equivalents (→ E11-S04)

| ID | Gesture | Default | Keyboard equivalent | Trace |
|---|---|---|---|---|
| N1 | Wheel | **Zoom time**, anchored at the cursor | `+` / `−` (zoom about the crosshair, or about the right edge if no crosshair) | F1, F2, F6 |
| N2 | Shift+wheel | Zoom price (disengages autoscale) | `Shift+` `+`/`−` | F1 |
| N3 | Drag in plot | Pan time and price (price pan disengages autoscale) | `Shift+←/→` pan time by 1/4 viewport... see N3a | F1, F6 |
| N3a | Pan step | Shift+←/→ = 10 bars; Ctrl+Shift+←/→ = one page (viewport width); Shift+↑/↓ = nudge price window 10 ticks and locks scale | — | F6, F7 |
| N4 | Wheel over a price/time axis | zoom that axis only | `Shift+` `+`/`−` when axis focused | F1 |
| N5 | Double-click axis | auto-fit (restores autoscale) | `Home` is NOT fit; use `Ctrl+0` = fit & unlock, `0`-less to avoid size presets | F3, F8 |
| N6 | Double-click plot | none (reserved) | — | — |
| N7 | Inertia | On by default after drag; off when reduced motion | n/a (key repeat is not inertial) | F2, a11y §7 |
| N8 | Go to date | `Alt+G` (matches TV) opens SCR-044 | same | F1 |
| N9 | Jump | `End` = latest bar and resume live; `Home` = oldest loaded bar | same | F6 |

Wheel = zoom time is kept (not scroll time) because the catalogue, TradingView and the owner's history all point that way
(F1); a modifier-free scroll-time mode is offered as a setting `Settings → Chart → Wheel action` (zoom | scroll) — this
is the single highest-cost default so it is flagged for owner validation in §9.

### 4.2 Q2 — Autoscale on axis drag (→ E11-S05, US-CHART-006)

- **K-S1 Disengage with a persistent badge** (not silent, not a prompt). A prompt would block a drag gesture; silence hides why the chart stopped fitting. Badge: text "LOCK" with a padlock icon (never colour-only), placed in the price-axis header, focusable, announced "Price scale locked".
- **K-S2** Restore: double-click axis, `Ctrl+0`, badge Enter/Space, or menu item "Auto". Reset restores autoscale **and** linear mode? No: reset restores autoscale only; scale *mode* is separate (log/percent persist).
- **K-S3** Axis drag has a keyboard equivalent: focus axis (Tab to "Price axis" control), `↑/↓` shifts window 10 ticks, `+/−` stretches, `Enter` leaves it locked, `Esc` reverts to the pre-gesture window (WCAG 2.5.7).

### 4.3 Scale modes and controls (→ E11-S05, SCR-043)

| Mode | Where | Constraint | Shortcut |
|---|---|---|---|
| Auto | price-axis menu, checkable | default on | `Ctrl+0` |
| Linear / Log / Percent / Indexed-100 | price-axis menu radio group | Log disabled with reason when any value ≤ 0 (US-CHART-007); Percent reference = left edge visible bar | `Alt+L` log toggle (new, unbound in a11y §3.2/SCR-030) |
| Invert | checkable | — | menu only |
| Lock | checkable, mirrors badge | — | menu only |
| Time scale: auto-fit, go to date, spacing presets, sessions | time-axis menu | — | `Alt+G` |

Menus open with right-click and `Shift+F10`/context-menu key when the axis has focus (SCR-043 A11y). A scale change is a
projection change only and renders in one frame (F4).

### 4.4 Q3 — Crosshair magnet (→ E11-S07)

- **K-M1** Readout crosshair is **free (no snap) in the price direction and snaps to the bar in the time direction**. Time snapping is implied by bar-space panning (`26` §3.5) and by US-CHART-008 readout of one bar; price-axis snapping to O/H/L/C would hide the true cursor price needed for order placement.
- **K-M2** A drawing magnet (weak/strong, TV-style, F5) is a separate setting for drawing tools only, default **weak**, toggled by `Ctrl+M` (SCR-0xx). It snaps to OHLC. It never affects the order-entry price.
- **K-M3** Order-entry price from the crosshair always shows the raw, tick-rounded price with the instrument tick (`22-exchange-adapter` rule: round to tick size).
- Low confidence: no source speaks of magnet default for the readout crosshair; flagged in §9.

### 4.5 Q4 — Keyboard-first model (→ E11-S13, E11-D02)

Priority of keyboard tasks (heuristic from personas/stories): 1 read the bar under cursor, 2 move through time, 3 move through price, 4 jump to extremes/dates, 5 rescale, 6 create a drawing/alert at a level, 7 open table. Minimum cursor vocabulary: **bar, price level, page, extreme** (as the ticket asks).

| Key (chart focused) | Action | Notes |
|---|---|---|
| `←` / `→` | crosshair ±1 bar | F7 resolves in favour of §3.1.7; §3.2 row is to be corrected (hand-off) |
| `↑` / `↓` | crosshair ±1 price level (1 tick; ±10 with `Alt`) | |
| `PageUp` / `PageDown` | crosshair ±1 page of bars | |
| `Ctrl+←/→` | crosshair to previous/next swing bar? **rejected** — not in sources; omitted | |
| `Home` / `End` | oldest loaded bar / latest bar (resume live) | End re-engages live follow |
| `Shift+←/→` | pan viewport 10 bars | |
| `+` / `−` | zoom time | |
| `Ctrl+0` | auto-fit and unlock | |
| `Alt+G` | go to date | |
| `Alt+T` | data table (SCR-045) | equal status |
| `Enter` on crosshair | opens the create-at-price menu: alert here, horizontal line, replay from here (no order) | orders never from a bare Enter |
| `Esc` | leave chart context / cancel gesture | reserved key |
| `?` | hotkey cheat-sheet | global |

**Focus order (Tab):** skip links → chart toolbar (symbol, interval, chart type, indicators, table button) → price-axis control → time-axis control → **plot (single tab stop, arrow-key composite)** → pane legends → table toggle → next landmark. The plot is one tab stop; inside it arrows work (roving model, a11y §3.4.2). `Ctrl+\` / `F6` jump between landmarks. Focus is never stolen by live data (F11).

**Announcements:** a polite live region updated ≤2/s with latest value only (US-CHART-008); format "13:58, O 64000 H 64020 L 63990 C 64010, volume 120, delta +30". Stepping faster than 2/s announces the latest settled bar only.

### 4.6 Conflicts with order-ticket hotkeys (→ E11-D02, E11 hotkey registry)

| # | Conflict | Decision |
|---|---|---|
| C1 | `1`..`5` size presets vs `1..9` interval presets (F8) | Intervals keep `1..9` **only when no order ticket/trading context is active**; when chart-trading context is armed digits are size presets. A persistent context chip ("NAV" / "TRADE") shows which, text + icon. Remap UI blocks both on the same context. |
| C2 | Bare `B`/`S` market (F8) vs a11y §3.3.2 | Raise to the owner as a standards defect (O3): either `B`/`S` only *stage* the ticket (no submit) or they need a modifier. Chart navigation never uses `B`/`S`. |
| C3 | Arrow keys: crosshair vs DOM ladder vs replay step (`←/→`) | Context-scoped by focus (F10). Replay mode: `←/→` step a bar, crosshair follows the replay cursor. |
| C4 | `+`/`−` chart vs ladder | Allowed (mutually exclusive focus contexts). |
| C5 | `Ctrl+Enter` submit order vs anything on the chart | No navigation binding may use `Ctrl+Enter`, `Ctrl+Shift+F`, `Ctrl+Shift+1`. |
| C6 | `Alt+T` table vs trendline, `Alt+F` fib/profile vs `F` footprint (F9) | Table keeps `Alt+T` (a11y escape hatch, always available). Drawing tools move to `Alt+1..4` per a11y §3.2; SCR drawings screen to be corrected. `Alt+F` is freed. |
| C7 | `Ctrl+drag` axis = limit order; `Alt+click` = market (F14) | Navigation never uses Ctrl/Alt with the pointer in the plot; both order gestures stay arm-gated and have a keyboard path (crosshair → menu → confirm). |
| C8 | Viewer role | Order hotkeys inert with a toast (F16); navigation unaffected. |

### 4.7 Q5 — Data table (→ E11-S14)

Position: **working surface**, reachable from the chart header (a button, not only `Alt+T`), same fidelity as the canvas (F12). Default columns: time, O, H, L, C, volume, delta, CVD (SCR-045 wireframe); expandable footprint cells; row actions: create alert here, replay from here, add note, create horizontal line at price. `Ctrl+C` copies TSV. Whether users *read*, *verify* or *work* in it is unknown (§9).

### 4.8 Q6 — "Aggregated" disclosure (→ E11-S12)

Not researchable from desk sources (no document defines the wording). Provisional proposal for validation: a text chip in the chart header "Aggregated: 1 candle = 5 bars · lossless OHLC/volume" that appears whenever LOD merges bars, with the table (`Alt+T`) staying at source resolution. Marked **unresolved → escalated to the owner, validation by the date in §9**.

## 6. Accessibility notes

- Keyboard path exists for every pointer gesture (N1–N9, K-S3), satisfying a11y §3.1.6 and WCAG 2.5.7.
- NAV/TRADE context chip and LOCK badge use text + icon, never colour alone.
- One tab stop for the plot; roving focus inside; focus ring ≥2 px, ≥3:1 (a11y §3.4.6).
- Live region ≤2 announcements/s; reduced motion turns inertia off (a11y §7).
- Screen-reader behaviour of the semantic output is **unverified** (no NVDA run): open item O1.
