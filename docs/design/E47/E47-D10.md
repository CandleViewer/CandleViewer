### 1.4 Rules stated once (every later row cites "R-n")

- **R-1 One primitive per concern.** A focus indicator is CMP-039, an announcement is CMP-245 `LiveRegion`, an off-screen surrogate is CMP-246 `VisuallyHidden`, a motion read is CMP-247 `MotionVariant`, a non-colour state is CMP-248 `NonColorState`; a component names the one it consumes in its contract and never reimplements it (T AC2; D04 R-9).
- **R-2 Restrictive by construction.** No primitive exposes raw `aria-live`, a raw politeness, a raw media query or a raw colour; each takes a value from a closed set owned upstream (D07 §3.1's classes, D08's tiers, ENC's encodings) (T Tech).
- **R-3 One app-level instance.** One reduced-motion resolver, one throttled live-region scheduler, one shared focus-ring stylesheet; no per-instance observer or media-query listener (T Perf; `06`).
- **R-4 Hidden is not absent.** Visually hidden content is in the DOM, the accessibility tree and any DOM dump; it never holds what the visual layer withholds — a masked key, another account's order, a T3 affordance (T Sec; D04 R-10).
- **R-5 `silent` accepts nothing.** A value D07 classes `silent` cannot be passed to `LiveRegion`; a secret-bearing or masked field is `silent` (T Sec; D07 §3.1).
- **R-6 One source of truth.** Contracts live in `15`'s existing fields; this file decides and the hand-off's §C carries the copy-ready rows; no parallel document, and no owner document is edited in PR 1 (T Tech).
- **R-7 T2 is the owner's grammar.** A gated control keeps its role and full label, takes `aria-disabled="true"` and never `disabled`, stays in the Tab order and a menu item stays arrow-reachable; CMP-079 RbacGate wraps it with the CMP-019 `lock` glyph (`decorative=false`, "Not available") in rendering 2a, or the badge in 2b; `Enter`, `Space` or a bound key changes nothing and re-shows the reason with one polite announcement (R32 G-T2.1b, G-T2.1d, G-T2.3; D09E09 §9).
- **R-8 Protective actions never wait.** A cancel, a close, a quantity-reducing amend or attaching or tightening a stop is never gated on the arm; no pattern here routes such an action behind CMP-229 (R32 R5; C-2.6).
- **R-9 Every decision PROPOSED.** Ids, names, tokens and A-rows stay PROPOSED until their owner stamps them; every finding is `(heuristic)` (BQ-0).
- **R-10 Focus is never obscured (WCAG 2.4.11).** A focused element is never wholly hidden by a sticky header, a docked footer, a scrim or a toast: scrolling containers set `scroll-padding` to their sticky heights (as CMP-049's `scroll-margin-top`, `15`:584), and a toast never covers the focused element. The `FocusVisible` story asserts it (§7.1).
- **R-11 Target size (WCAG 2.5.8).** Every interactive primitive's pointer target is at least 24 × 24 CSS px, or meets 2.5.8's spacing exception; 44 × 44 under `larger_hit_targets` (§4.4). The axe run enables its `target-size` rule (§7.1). Dragging (2.5.7), content on hover or focus (1.4.13) and accessible authentication (3.3.8) are entry-level: each dragging, tooltip or auth entry states its own, and PR 2's band slices check it entry by entry.
- **R-12 Loops stop (WCAG 2.2.2).** A decorative loop (a skeleton shimmer) is static under reduced and stops after 5 s otherwise; a busy indicator is the essential exception and is static under reduced (D08's `none` recipe).

### 3.1 CMP-245 `LiveRegion` — the contract of the shell pair (BQ-5)

- **What it is.** Not a second region: the host is the shell pair, mounted once by `ShellLayout` (ANN:4, :80–91), two visually hidden containers, polite and assertive, `aria-atomic="true"`, empty from first paint, exempt from modal inertness (D07:124). `LiveRegion` is the typed writer over it.
- **API sketch.** `announce({ class, text, key })` where `class` is one of D07 §3.1's five: `significant-assertive`, `status-polite`, `ambient-polite`, `echo-polite`, `silent`. The class picks the region and the schedule (D07:132–140); the caller never names a politeness. `silent` has no writer: the type admits no text for it (R-5).
- **`LocalStatus` (a PROPOSED form, not a fifth primitive).** For D07 R-1's four local kinds (D07:128) — the reply at the control that took the user's action, a panel's own status, a countdown's status at its field, the echo of the user's keys — `LocalStatus` renders the container pre-rendered empty beside its control and swaps only its text; it takes `status-polite` or `echo-polite` only, never a taxonomy event the pair already speaks (D07 R-6).
- **Writes.** Only the text changes: neither container is re-mounted or re-created after first paint, and the scheduler makes an identical repeat audible by clearing the container and writing on the next frame (PROPOSED). Under a modal the pair stays outside the inert tree (D07:124); a dialog closing on a failure writes it before focus moves (P-5).
- **Scheduler.** One app-level throttle owns every class's schedule (T Perf; R-3): the assertive queue by rank, the 5 s status floor, the ambient cadence (D07:136–138).
- **Deprecated.** The raw `announce(politeness, text, key)` (ANN:38) and every hand-rolled region of §6 (DP-1 … DP-5).

### 3.2 CMP-246 `VisuallyHidden` — the surrogate primitive (BQ-7)

- **Technique.** Clip-based, as the shipped `.cv-visually-hidden` (`packages/ui/src/components/controls.css`:16–24: 1 px box, `overflow: hidden`, `clip-path: inset(50%)`): off-screen, never `display:none` or `visibility:hidden` (`05`:173). An optional `focusable` form becomes visible on focus (skip links) with the CMP-039 ring.
- **The rule (T Sec, verbatim intent; R-4).** "Hidden is not absent": `VisuallyHidden` never holds a value the visual layer withholds — a masked key, another account's order, a T3 affordance, a value D07 classes `silent`. The test is: would the value be acceptable on screen to this user? If not, it is not rendered at all.
- **Consumers.** Every canvas surrogate (`05` §6.1), the shell pair's containers (§3.1), the T2 description node in rendering 2b (R32 G-T2.1c).

### 3.3 CMP-247 `MotionVariant` — one resolver, three tiers (BQ-6)

- **Resolver.** One app-level resolver writes D08's three effective tiers — full, canvas calm, reduced — as `data-motion` on the root (D08:123–128); it is the only reader of `prefers-reduced-motion` and of the SCR-117 preferences (the theme runtime: `packages/ui/src/theme/store.ts`:27 and `packages/ui/src/theme/prepaint.ts`:23). `apps/web/src/features/a11y-preferences/PreferencesContext.tsx`:63, :108 are separate `matchMedia` readers: their `prefers-reduced-motion` half is a residual (the motion decision reads the store, :118), deleted with DP-8; their `prefers-contrast: more` half (:64, :109) is the system default of the `increased_contrast` preference (:121) and stays — a contrast input, not motion, its mapping to a theme SCR-117's (D05).
- **JS side.** `useMotionTier(): "full" | "canvas-calm" | "reduced"` reads the resolver's store once per subscription (as `apps/web/src/features/app-shell/motion.ts`:11 already reads `appThemeStore`, which conforms); no component calls `matchMedia`.
- **Canvas calm for CSS.** Canvas calm calms the canvas only (D08:133): a CSS-only consumer sees `data-motion="safe"` and runs its recipes as under full; only reduced changes a stylesheet.
- **CSS side.** The recipe pair `--cv-recipe-<name>-safe` / `-reduce` on `:root[data-motion]` (`16`:207). A component stylesheet's `@media (prefers-reduced-motion: reduce)` block guarded by `:root:not([data-motion])` is the OS fallback before the runtime writes the attribute and stays (BQ-6; e.g. `packages/ui/src/components/dialog.css`:170–172).
- **Constants.** No token is added (D08:310); FR-1 … FR-10 stay named spec constants PROPOSED for `motion.hold.*` (D08-A8, §9).

### 3.4 CMP-248 `NonColorState` — the encoding helper (BQ-7)

- **What it is.** A helper, not a drawing: a component names its encoding and surface (`NonColorState({ encoding: "buy-sell", value: "buy" })`) and receives the channel set D03 §5 assigns — glyph (▲ / ▼, ✓ / ⚠ / ✕), explicit sign (`+` / `−`), pattern (`pattern.hatch`), word — so no component draws its own (D03:303–340).
- **The set.** Keyed to ENC's encodings at the base (`buy-sell`, `bid-ask`, `order-status`, `pnl`, `connection-health`, `demo-live`, `imbalance`, `delta-sign`, `risk-severity`, `estimated`, `gap`, `reduced-detail`) plus the surfaces D03 §5 designs (`profile-levels`, `liquidation`) once D03-A7 … D03-A9 land in ENC (§9).
- **Rule.** A state that changes colour also changes its word or glyph (D03 R-2; `15` §0.3 rule 3); the colour is the theme's, the channel is this helper's.
- **Accessible name.** The state reaches the accessibility tree as text: a glyph beside its word is `aria-hidden`; a glyph alone carries the word as its accessible name (`role="img"` with `aria-label`); a pattern is never the only carrier in the tree (hand-off §C.2; the `GlyphOnly` story).

## 4. CMP-039 FocusRing, final (T Scope; BQ-7; D04-A1, D04-A2, D04-G5, D04-G6)

### 4.1 Geometry and colour

D04 §7.1 as built input (D04:231–239): **normal** 2 px `color.focus.ring` ring with a 1 px `color.surface.canvas` halo on **both** sides at 2 px offset on `:focus-visible`; **inset** the same drawn inside the element (rows, cells); **thick** 3 px ring and 2 px halos under `data-focus-ring="thick"`, PROPOSED `border.focus.thick` (D04-G5, §9). The colour per theme is D03 §3.1's `color.focus.ring` (D03:170–173, measured there); the rule is D04 §7.2's: pair ≥ 3:1 and edge ≥ 3:1 on every measured background. The thick ring is the default in the high-contrast theme (D04:247; D05:131).

### 4.2 Canvas surrogates and panels

The one ring for DOM controls and canvas surrogates alike (D04 §7.4; `15`:464): a surrogate aligned over canvas content takes the normal ring with its halo; the chart draws one ring at its boundary and its keyboard column inside it. A focused panel's frame is CMP-080's, never CMP-039 around the panel (`15`:463).

### 4.3 Forced colours (D04-G6, settled here)

Under `forced-colors: active` a shadow halo is dropped by the browser, so the ring is an `outline` in the system colour `Highlight` at the same width and offset (D03:486), with `forced-color-adjust` left at its default; it never depends on the halo or a `box-shadow` (PROPOSED). The in-app high-contrast theme is a token theme, not forced colours (D04:239). State carried by a fill — a selected row, a focused panel's CMP-080 frame, a T2 badge — also carries a border, outline or glyph in a system colour (`Highlight`, `CanvasText`) under `forced-colors: active`, never the fill alone (R32 R2; PROPOSED). The check is CMP-039's `ForcedColours` story, run with forced-colours emulation in the `vr` job, and QA-4 per entry; forced colours is not a sixth per-entry story.

### 4.4 The two root attributes (BQ-3; D05:131, :135)

`data-focus-ring="thick"` (shipped preference `thick_focus_ring`) selects §4.1's thick variant. `always_show_focus_ring` (D05:135, PROPOSED, D05-G1, D04-G2) adds a root attribute under which the ring shows on `:focus`, not only `:focus-visible` — opt-in only, never the default; CMP-039's stylesheet carries both selectors, so no component changes (R-3). `larger_hit_targets` (D05:136, PROPOSED) is a root attribute raising every interactive CMP's minimum target from R-11's 24 × 24 to 44 × 44 CSS px; its sizes are the components' size tokens, read by their own stylesheets, routed as D10-G4 to the size owners.

### 4.5 API

The as-built `useFocusRing({ inset? })` returning `{ className }` stays the API (`15`:462); thick and always-show are root-level, never props, so no consumer branches.

## 7. Storybook a11y stories and the gate (T AC3, T AC5; BQ-9)

### 7.1 The obligation (one §0.3 rule; D10-A1)

Every interactive entry ships, in addition to its variant stories, five a11y stories: **`Keyboard`** (a play function driving the entry's keyboard table end to end), **`FocusVisible`** (each focusable part focused by keyboard, CMP-039 visible and not covered by a fixed layer: `elementFromPoint` at the ring's centre is the element or a descendant, R-10), **`ReducedMotion`** (rendered under `data-motion="reduce"`; asserts `document.getAnimations()` is empty), **`HighContrast`** (the high-contrast theme, thick ring), and **`LiveRegion`** where the entry announces (the writes captured from CMP-245's test double). A non-interactive entry ships `HighContrast`, and `ReducedMotion` where it animates. Every story is checked by the axe addon (zero serious or critical; its `target-size` rule on, R-11; moderate and minor results reported, not blocking; the colour-contrast rule runs in the browser `storybook` job, never in jsdom) and the `Keyboard` story is the entry's interaction test (`15`:41's baseline, now named per entry). The rule is one item in `15` §0.3 (D10-A1), not 247 per-entry lines; an entry's Storybook bullet lists only its variant stories.

### 7.2 G-STORY: the missing-obligation check (AC5)

Specified for the build (D10-G5): a step in the existing `a11y` check's `storybook` job (JOB:193–303) reads each story file's exports and the entry's contract clause (§2.1); an interactive entry missing one of its obligatory stories fails with `A11Y-STORY <CMP-nnn> missing <StoryName>`; an axe serious or critical result fails with the entry, story and rule id. ## 8. Themes: the matrix, the linter and the seventh theme (T AC4, T Tech; BQ-8)

### 8.1 The matrix, as shipped

The six are **3 colour themes × 2 densities**: dark, light, high contrast (THEMES:3–19) × compact, comfortable (THEMES:20–21), every story against its committed baseline (JOB:13–14; ADR-0019; `16`:768). ### 8.2 The linter over a new theme

The contrast gate (`packages/ui/package.json`:29) evaluates every registered pair in every theme the token build emits. ### 8.3 A missing token fails by name (D03-G4, settled here)

The required-override list per theme (PROPOSED): every colour token that appears in a registered pair of `tools/contrast/pairs.mjs`, as `fg` or `bg`, must be defined by a non-dark theme's own set, not inherited from `semantic-dark` through the overlay (D03:134). ## 11. Security, performance, observability, environment

### 11.1 Security (T Sec)

R-4 and R-5 are the two structural guarantees; the `LiveRegion` type admits no `silent` write, and `VisuallyHidden`'s rule is in its entry (hand-off §C.2). No primitive carries account, credential or order data of its own.

### 11.2 Performance (T Perf; R-3)

One resolver (`data-motion` on the root, one store subscription per consumer, no `matchMedia` listener per instance), one scheduler (the shell pair's queue), one focus-ring stylesheet (`focusring.css`, root-attribute selectors for thick and always-show). A ladder of hundreds of rows adds no observer per row.

### 11.3 Observability (T Obs)

Per design-system release the `a11y` check's report publishes three counts: axe serious + critical violations over all stories, contrast failures (`A11Y-C00x`) per theme, and interactive entries lacking an obligatory story (G-STORY). Release-over-release they are the system's health metric; their location is the existing `reports/storybook-a11y/` artefact (JOB:301–302), a table the build fills (D10-G5).

### 11.4 Environment and versioning (C-2.11; T Tech)

No surface here reads or writes an environment; the primitives carry no account or environment data. The contribution ships as one versioned release of `@candleviewer/ui`; consumers upgrade once.
