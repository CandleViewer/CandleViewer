## 1. Purpose, method, locked inputs and the rules stated once

### 1.1 What this spec fixes

Which token carries each role in each theme and chart palette, how each order-flow meaning survives without hue, what SCR-116 shows and says, and the token rows that close the measured gaps. It re-decides nothing the locked inputs fix; where merged texts disagree a C-row says which reading it takes (§16.1).

### 1.2 Method (honest)

Desk work at the base under the agent-delivery adaptation: no participant, timing or quote exists. The tool resolves every token per `themes.json` (later sets override earlier), measures pairs by the WCAG 2.x formula, simulates dichromacy with the matrices of `color-math.mjs` (MATH:56–92; Brettel / Vienot for deuteranopia and protanopia, Machado 2009 for tritanopia), adds a greyscale projection (relative luminance), and measures CIE76 ΔE against the JND floor of 5.0 (MATH:167). The engine has no render loop yet (S07:19), so the proof pack is computed tables plus boards drawn from the computed hexes, not product screenshots (D03-G3).

### 1.4 Rules stated once (every later row cites "R-n")

- **R-1 One meaning, one token.** A meaning uses the same semantic token on every surface (`16`:198); a retune edits the token, never a component (`16`:470).
- **R-2 Colour reinforces.** Every encoding names at least one channel of `glyph`, `sign`, `text`, `pattern`, `position` (ENC); a state change that changes colour also changes a word or a glyph.
- **R-3 Numbers by script.** Every ratio and ΔE here is the tool's, truncated and never rounded up; a bar is met by the unrounded value.
- **R-4 The overlay model.** `semantic-dark` is the schema; light and high contrast override only what differs (`16`:353–355, :469).
- **R-5 CVD-safe is a chart palette.** It remaps data ink only; chrome, text and the env colours never change with it (J13).
- **R-6 A control's boundary binds `color.border.strong`.** A border that identifies a control meets 3:1 on its surface; `color.border.default` is a decorative divider.
- **R-7 Env salience is never weakened.** No theme, palette, accent or convention touches `color.env.*` or the badge's channels (E10D03:97).
- **R-8 Announcements.** One polite announcement per committed change, coalesced to at most one per second; nothing on load, server apply or match-system flip (J16).
- **R-9 No T2 on SCR-116.** No control is gated: every role, view-as included, changes appearance on this device and a session without `settings:write` skips only the server save (`15`:711; J15 (a), PROPOSED).

### 2.2 One schema: the overlay model and its proof

`semantic-dark` holds 166<!--=COUNT:keys.dark--> entries and is the schema; `semantic-light` overrides 99<!--=COUNT:keys.light--> and `semantic-hc` 14<!--=COUNT:keys.hc-->; every other name resolves to dark's value by design (`16`:354–355; THEMES:3–19). ## 7. The simulation proof pack (computed; AC3)

### 7.1 Method

Each pair is simulated per theme under deuteranopia, protanopia, tritanopia and greyscale, and the ΔE of the two simulated colours is compared with 5.0 (R-3). Where a pair falls below it the Cue column names the channel that carries the meaning; where every value clears it the cue is still drawn and the row says "drawn anyway": ΔE 5.0 is a floor for adjacent patches, not for separated marks, so the default palette is not CVD-safe and its cue is mandatory regardless (R-2). The simulation is full dichromacy only; anomalous trichromacy is not modelled, so W-5's "colour-blind safe" promises no more than these columns.
