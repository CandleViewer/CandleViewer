### 1.4 Rules stated once (every later row cites "R-n")

- **R-1 Visual order.** Tab order and the region ring follow the user's visual panel arrangement: the layout system exposes an ordered region list and the DOM is rebuilt to it, nodes moved and never remounted (T Tech; D15:277).
- **R-2 One stop per composite.** A grid, tree, listbox, toolbar or tablist is one Tab stop with a roving tabindex: one item `tabindex="0"`, the rest `-1`; never `tabindex="0"` per row (`05`:95; `15`:584).
- **R-3 Logical identity.** Focus inside a live composite is keyed by its logical id — price level, bar `(generation, index)`, order id, position key, symbol — never by DOM or row index (T Tech).
- **R-4 Never the body.** Every operation that disables, removes or replaces the focused element names, in the same frame, a destination that exists after it; the document body is never a destination; a busy control stays focusable with `aria-disabled` (D10E09:157, :160; D15:220).
- **R-5 Never stolen.** A data event (a price, a fill, a WS push, a rule fire, a toast) never moves focus; only a user action or an explicit `alertdialog` does, announced first (`05`:96; D15:252).
- **R-6 Safe initial focus.** No dialog, overlay or region opens with focus on a destructive or committing control; a destructive confirm opens on Cancel (T Sec; `15`:525).
- **R-7 Restore to the invoker.** Every close path of a dialog or overlay returns focus to its invoker; if the invoker is gone, to `fallbackFocusRef`, chosen by R-4 (`15`:514; `05`:97).
- **R-8 Moves are announced, by label, at most once a second.** A ring move, a grid entry and every non-user restoration is announced once, politely, by a label (§15); the words are E47-D07's; ≤ 1 Hz per region (T OOS; D15:298).
- **R-9 One ring.** CMP-039 is the only focus indicator for controls and surrogates; per-component rings are prohibited; the panel frame is a separate responsibility (T Tech; `15`:463).
- **R-10 Gated stays, hidden is absent.** A T2 control keeps its role, stays in the order and names its reason; a T3 affordance is absent from the tree — no ghost, no palette hit, no search hit (D09E09:49, :50).
- **R-11 Not obscured.** On focus the element is scrolled into view with an offset equal to every sticky bar or floating panel that overlaps its scroll container, so it is never fully hidden (2.4.11; T a11y).

## 2. The landmark and heading model (T Scope)

**Landmarks.** The shell (SCR-010) has exactly one of each top-level landmark: `banner` = the TopBar; `navigation` = the NavRail (SCR-011, RG-07's tree inside it); `main` = the workspace (SCR-020) or the routed page; `complementary` = the RightRail (SCR-014 when open); `contentinfo` = the StatusBar. Inside `main` on the workspace, each docked panel is a `region` named by E15-D15's rule ("{Kind}, {symbol} {interval spelled}", plus ", {Environment}" for the order-capable kinds; D15:262, :281); the tab strip, toolbar and tray are RG-02 … RG-04. A full page's `main` holds the page's form or tables; its section nav (SCR-110) is a second `navigation` named "Settings" or "Admin". A dialog is not a landmark; while it is open the page is `inert`. The skip-link set (`05`:98) targets `main` and each region by name.

**Headings.** One `h1` per screen: the workspace name on SCR-020 (visually the active tab; the heading is visually hidden), the page title on a full page. Each panel header holds its RG-08 toolbar (D15:269) under a heading: `h2` in the dock, `h3` inside a tab group (`15`:925; D13:726); a panel's sub-sections are one level below its header. A dialog's title is an `h2` inside the dialog and names it. No level is skipped (`05`:235).

## 6. The dense-grid escape hatch (T AC3; T Scope; BQ-4)

### 6.1 One stop

A dense grid is CMP-049 with `role="grid"`: one Tab stop, a roving tabindex, `↑` / `↓` by row, `←` / `→` by cell (`15`:584; R-2). `Tab` from anywhere inside leaves the grid in **one press** to the next stop of its panel (the next panel's header when it is the panel's last stop); `Shift+Tab` leaves to the previous stop (the panel header). It never advances one row. Keys beyond the APG grid set (paging, zoom, order entry) are E47-D09's rows.

### 6.2 Entry and identity

On entry focus lands on the item last focused in that grid by logical id (R-3), else the default (the ladder: best bid; every other grid: the first data row). The grid announces its extent once per entry (R-8): W-2 for the ladder, W-3 as the pattern. Identity per grid: the ladder → price level; SCR-063 positions → position key (account, symbol, side), working orders and SCR-070 → order id, SCR-078 → fill id; SCR-100 and SCR-104 → symbol; SCR-045 → `(generation, index)`. A re-sort moves focus with its logical item and announces nothing unless the item left the visible window (it stays materialised, §12).

### 6.3 `Esc`, in layers

`Esc` closes the innermost transient first — an open menu, then an in-cell edit, then the selection (D04E11:296), then an expansion — and only with nothing open leaves the grid: a panel-hosted grid (the ladder, SCR-063, SCR-070, SCR-078, SCR-100, SCR-104) to its **panel header** (the RG-08 toolbar's last-focused item, else its first; D15:269); SCR-045, which replaced the chart in place, keeps its merged destination, the plot stop (D04E11:167; D04-C2). A bare `Esc` never cancels an order in any grid; a focused order cancels with `Ctrl+Delete` (E29-D01 D9, D01E29:313, :333; E29-D05 A-02, D05E29:654, applied to the `05`:63 cell in this PR; BQ-4; D04-C3).

The halo on **both** sides of the ring is this file's geometry (PROPOSED), extending CMP-039's canvas-surrogate halo (`15`:464) to every control after E06-D03's double ring (D03E06:176), so the ring's only neighbour is the halo whatever lies behind it. Under `forced-colors: active` (Windows High Contrast, which the desktop shell inherits; not the in-app high-contrast theme) a shadow halo is dropped by the browser: the ring falls back to a solid system-colour outline (`Highlight`) at the same width and offset and does not depend on the halo; the technique is E47-D10's to fix (D04-G6).

### 7.2 The two-tone technique (why one colour is not relied on)

The ring and the halo are two tones. The ring is always enclosed by the halo, so the ring's own contrast is the ring–halo pair on every background: 7.05<!--=CONTRAST:pair.dark--> (dark), 6.29<!--=CONTRAST:pair.light--> (light), 18.32<!--=CONTRAST:pair.hc--> (high contrast). The indicator's outer edge against a background X is the better of the two tones against X (the **edge** of §7.6); the rule is **pair ≥ 3:1 and edge ≥ 3:1** on every measured background. The pair is under the 9:1 at which two tones guarantee 3:1 against any colour in dark and light, so the guarantee is per measured background, not universal (D04-G1). The **edge** is this spec's convention, not WCAG's wording: an enclosed ring's outer edge is its halo.

### 7.3 The high-visibility variant (US-SET-007; BQ-8)

US-SET-007 asks that "focus indicators become more prominent" (`11`:5185). The switch already ships: the preference `thick_focus_ring` (MODEL:13) labelled W-7 with W-8 as its help (ASS:113, :114), written as `data-focus-ring="thick"` or `"normal"` on the root (PCX:148). This file specifies the thick geometry (§7.1) and makes it the default in the high-contrast theme. `14`'s SCR-117 also lists "always-show focus ring" (`14`:2471): the ring on `:focus`, not only `:focus-visible`; it is not in the shipped preference model (D04-G2). The control is drawn by E47-D05 (#1304).

### 7.4 The CMP-039 contract (R-9)

CMP-039 is the one ring for DOM controls and canvas surrogates alike (`15`:454; T Tech); a component never draws its own. The chart draws one CMP-039 ring at its boundary and the keyboard column inside it (D05E11:438). A focused panel's frame and header bar are CMP-080's, in `color.focus.ring`, inside the box, and never wrap CMP-039 around the panel (`15`:463; `16`:277).

### 7.5 Not obscured (2.4.11; R-11)

On focus, the element is scrolled into view inside its scroll container with `scroll-padding` equal to the extent of every sticky header, sticky footer and floating panel that overlaps the container, plus the ring's outer extent (offset + halo + ring + halo: 6 px normal, 9 px thick). Where the container cannot scroll that far (a floating order ticket over a short grid), the container adds end padding equal to the overlap, so the scroll always exists and the element is never entirely hidden (the AA minimum); it is fully shown whenever the viewport allows, a behaviour, not a claim of 2.4.12 (AAA, not claimed). The overlap query is the layout system's (D04-G3).

### 9.2 Lifetime, dismissal and restore

- **Trap.** While open, `Tab` and `Shift+Tab` cycle inside the dialog; the page is `inert`; ring keys are inert (§3). A dialog opened from a dialog (step-up from SCR-074) traps in turn and restores into the first.
- **Dismissal.** `Esc` (reserved, `05`:85), Cancel, the close button, and a scrim click on a non-blocking dialog all cancel and restore; on a blocking dialog the scrim does nothing and focus stays inside (A11Y-F-0013).
- **Busy.** While the action runs the focused control stays focusable (`aria-disabled`, `aria-busy`; D10E09:157); focus does not move.
- **Restore.** Every close path ends on the invoker (R-7); if the invoker is gone, on the fallback chosen by R-4.
- **Flatten all (T AC5).** Opened from the TopBar's FLATTEN ALL control (`14`:302) or its hotkey: a CMP-044 `alertdialog`, Cancel initial, trapped for its whole lifetime; `Esc` or Cancel closes it and focus returns to FLATTEN ALL; on completion the dialog closes, focus returns to FLATTEN ALL and the outcome is announced in the assertive region. Opened by its hotkey from a panel, it restores to the element that held focus.
- **Reflow** by R-12.

## 10. RBAC and the accessibility tree (T Sec; BQ-5)

E09-D09 governs (D04-C4): a **T2** control (gated by role, grant, environment, session or state) keeps its native role and full label, `aria-disabled="true"` and never `disabled`, stays in the Tab order, and names its reason through `aria-describedby` (D09E09:49); `Enter` on it changes nothing and re-shows the reason. A **T3** affordance (admin navigation for a session without `admin:read`) is absent: not rendered, not in the tree, not in the palette, not in search (D09E09:50). Nothing is merely dimmed.
