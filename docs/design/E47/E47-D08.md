### 1.4 Rules stated once (every later row cites "R-n")

- **R-1 Both modes.** The flash-rate budget of §4 binds under `safe` and `reduce` alike; `reduce` removes animation, never the budget (T Tech; AC5).
- **R-2 Coalesce, then animate.** A data-rate surface asks for a start at most once per frame on the existing render cadence; the coalescer or the engine admits it; only an admitted start animates. No surface animates per event (T Tech; `06`:67).
- **R-3 One resolution point.** The mode is resolved once, as `data-motion` on the root and `detail.motion` for the engine; no component reads `prefers-reduced-motion` itself (E05D03:83; E11D06:97).
- **R-4 Values always update.** A held carrier delays only its emphasis or its colour change; the value, the digits and the sign are never held (E05D03:105).
- **R-5 Skip, never zero.** A reduced variant does not run its pipeline: no transition, no animation object, no shader decay pass; a zero-duration tween is a defect (T Perf; `14`:2481).
- **R-6 Never stolen.** Pausing, resuming or a mode flip never moves focus; a data event never does (D04:120).
- **R-7 Static safety.** A safety signal is identifiable from its icon and word in every tier and theme; motion is never its carrier (T Sec; E05D03:118).
- **R-8 Wall clock.** Every budget counts wall-clock milliseconds, never replay or virtual time (`06`:39).

### 4.3 The region arbiter (FR-2, FR-3, FR-9; D08-G3)

Requests in one frame are ranked by FR-9; a refused request is dropped, not queued, and the source asks again on its next change. The arbiter runs once per frame on the existing cadence (R-2; FR-4), so the motion layer adds no timer (T Perf). A refused value still updates (R-4).
