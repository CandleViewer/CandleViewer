### 1.4 Rules stated once (every later row cites "K-n")

- **K-1 One grammar.** Every value a pointer drags is reached by select → adjust → commit / cancel, specified once here and reused by the order line, the drawing handles, the profile anchors, the graph nodes and the layout; a surface diverges only by a merged decision recorded as a C-row (T Tech).
- **K-2 Select changes nothing.** The object is selected by focusing its surrogate (`Tab` into its one roving stop, arrows within; D04:219) or by `Enter` on its list twin; selecting moves no value, sends nothing and announces the object with its value.
- **K-3 Adjust by unit.** Arrows move a pending value by one unit (§2.1); `Shift` multiplies by ten; `PageUp` / `PageDown` by a hundred for ticks and bars wherever the surface does not already use them to move between objects. The pending value is drawn on the object and shown in its readout.
- **K-4 Commit through the pointer's own path.** `Enter` commits exactly as the pointer drop would: the same confirm choice, the US-SET-003 policy, the same refusals and the same audit. A local, undoable object (a drawing, a node, a panel) may apply each step at once when its merged twin does, as one undo step per selection.
- **K-5 Cancel restores.** `Esc` before a commit restores the value held at selection, sends nothing and says so (W-2; W-4 for a local object). Moving focus away with a pending value is a cancel. `Esc` never cancels a request already sent (D05E32:272).
- **K-6 The pending value is spoken.** On one polite region under D5's three parameters (§6): the first press at once in full, a held key at most once per window in the short form, the final value within the flush; never one announcement per repeat.
- **K-7 Never per keypress.** An exchange-bound adjustment never sends a request per keypress or per repeat: one commit, one request. Stops tighten only by key (D05E32:264).
- **K-8 The palette lists every command.** Every registered command is reachable in SCR-012 by name, bound or not, pointer-only or not, valid here or not; its current binding, or "unbound", beside it. A command absent from the palette is a defect (T Tech).
- **K-9 The cheatsheet shows what is bound.** SCR-013 lists every command with its current binding, remaps marked, searchable by the action's name or by the key, from anywhere by `Ctrl+/`.
- **K-10 An inert key explains itself.** A binding pressed where it is not valid says once, non-modally and politely, that the action is not available here and where it is; nothing a user presses on purpose is silent (§11).
- **K-11 Gated keeps its keys.** A gated equivalent stays operable as a key and changes nothing: the T2 paragraph of §12 applies to every row of §3 and every palette row.
- **K-12 Single keys are scoped and remappable.** A bare letter or digit binding is active only in its focus context and can be remapped or unbound (SC 2.1.4); a destructive command never takes a bare letter (VAL:177).

## 6. The coalescing window (T Perf; T Tech; BQ-7)

Every adjustment of §2 uses E06-D03 D5's three parameters unchanged (D03E06:105): **`leadDelay` 0 ms** (the first press speaks at once, in full), **`repeatWindow` 500 ms** (a held key speaks at most once per window, the latest value, in the short form — the value alone, W-5), **`trailingFlush` ≤ 250 ms** (the final value is spoken in full within 250 ms of the last key event and never lost). One polite region per surface, last-write-wins; assertive is never used. The pending value lives outside React state: each repeat updates it, the canvas draws it on its own dirty-flag frame, and the readout's state is written at most once per window plus the flush. Nudging a line across 200 ticks therefore issues no 200 renders and no 200 announcements, whatever the platform's repeat rate. The words are E47-D07's (#1306); this file fixes only the cadence and the two forms (hand-off §F).
