## 3. The matrix: a grid, not a list of checkboxes (T §Tech; BQ-06)

**Decision.** SCR-133 is CMP-049 in `grid` mode with the host's `rowWindow` (`15`:591): `role="grid"` with `aria-rowcount` (the symbols plus the two header rows) and an absolute `aria-rowindex` on each drawn row, `aria-colcount` (the accounts plus the symbol column), the symbol as `th scope="row"`, each account as a `columnheader`, and in each cell one CMP-005 checkbox that takes focus in the cell's place (`15`:590). The checkbox is named by `aria-labelledby` pointing at three nodes already in the DOM — the column header's account, the row header's symbol and the cell's own word node — so "sub_001, BTCUSDT, allowed" (`D03B`:410) is assembled by the accessibility tree, never by a string built per cell. `aria-checked` is `true` for allowed only; "blocked" is a word in the name, not a checked state (`D03B`:410).

**Rejected: a set of labelled checkboxes with an off-screen description.** It puts every cell in the Tab order, or needs a roving model the grid already ships; it loses the row and column header announcements; and its description must be computed per cell for the whole matrix.

**The render budget** (`14`:2788, ≤ 600 ms). The name costs nothing until a cell is drawn, and only the window is drawn. At the minimum viewport of 800 px and the compact row height, with an overscan of 10 rows (PROPOSED), the window is <!-- audit:window=264 --> **264 cells** (44 rows × 6 accounts) against **2400** for the whole matrix (400 symbols × 6 accounts, `14`:2788), with three IDREFs each. Whether 264 cells render inside 600 ms is E28-S02's measurement `(heuristic)`; nothing in the naming scales with the 400 symbols.

**Settled with D03.** This is D03's own shape (`D03`:298; `D03`:303); the review adds the IDREF assembly, the window figure and the counts. The `14` line "grid cells are checkboxes with accessible names combining account and symbol" (`14`:2785) is met.

## 18. The audit tool

`docs/design/_tools/e28_d05_a11y_review_audit.py`, stdlib only, offline, run as `python3 -I -B`. Ten gates; each FAIL is led by its letter:

- **[A] cites:** every `KEY`:line resolves at its pin to a non-blank line; a `D03` line also stands verbatim in the #5463 text; the pins file and the cites match both ways, each pin's words on its line.
- **[B] contrast:** §10 equals the tool's measurement; a gated cell below its bar names a High or Critical F row.
- **[C] colour vision:** §11 equals the tool's computation; a channel "none" names a High or Critical F row.
- **[D] findings:** the counts equal the heading and its stamp; each row has a severity, a criterion, a cited line, a fix and one owner; a High or Critical row names an A-row.
- **[E] amendments:** each Old stands exactly once in its target at its pin and on the cited line; no New is there already; each A-row's F row exists; §16.1's per-target counts equal the table.
- **[F] focus order:** six screen tables, each with its FO steps; every modal paragraph names a return.
- **[G] hygiene:** the lane's public-text word list, no local path, host or URL, no hex, the count stamps.
- **[H] live regions:** every LR row has a politeness and a rate; LR-01's rate is at most one per second; LR-04 is assertive.
- **[I] the matrix figure:** §3's window and whole-matrix counts equal the computation from `14`:2788 and the tokens, and its prose names the tool's viewport and overscan.
- **[J] T2:** §7 quotes G-T2.1d and G-T2.6 verbatim from `DS`; every T2 row's Wrapper names CMP-079 and the `lock`; a read-only row carries PROPOSED and the three reason keys.

`--check` exits 1 on any FAIL; `--self-test` applies at least one mutation per gate in memory (fifteen in all) and expects exactly one new FAIL, from that gate; `--tables` prints §10 and §11; `--write-tables` writes them between their markers; `--repin` rewrites the pins file from the cites.
