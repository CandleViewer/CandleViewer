## 1. Purpose, scope, method and locked inputs

### 1.1 What this spec fixes

Every state of the six surfaces #821 names, as text a board can be drawn from without a further decision: SCR-130 (the
profiles list, `/admin/profiles`, R-330), SCR-131 (the editor, `/admin/profiles/:profileId`, R-331), SCR-132 (the
templates modal), SCR-133 (the symbol matrix), SCR-062 (the definition manager, `/admin/trade-groups`, R-352) and the
preview half of SCR-061. Out (BQ-1, BQ-8): SCR-061's send, partial-send, partial-failure, retry and rate-limit states
and its stagger line (E34-D02, #996); SCR-062's execution-group grid and checklist items (E34-D03, #997); SCR-060
(E30); hi-fi, tokens and motion (E28-D03 / D04); SCR-134 and SCR-114 (boundaries only).

### 1.2 Method (honest)

Desk wireframes plus a heuristic evaluation against the memo's findings, the `14` entries, the contract and the
rulings. No participant, timing or quote exists. Every number on a frame is a served field or a fixture from the
stories; no frame computes a cap, verdict, size or readiness (BQ-5).

### 1.3 Locked inputs (built on, not re-decided)

- **C-2.6 / C-4.14** — every position-opening order, every leg included, carries a native exchange stop-loss; no
  flag, environment or mode turns it off (`CON:128-134`, `CON:443-444`). `require_native_sl` is `CHECK = true`
  (`21:1478`, `21:1545`); `require_native_stop` is `const: true` and a `false` is refused as
  `native_stop_mandatory` (`22:3502-3504`).
- **C-2.12 / C-12.4 / C-12.5** — RBAC, risk caps, profile resolution and sizing are server-side; a capped leg is
  refused, never silently clamped; the sizer's own clamp shows in `sizing_explanation` (`22:19911-19915`).
- **#2701 D7, the ceiling** — the default profile is the account's ceiling; alternates, templates, overrides and rules only
  narrow it (`21:1447`). Every account has a default from its creation (`22:3616-3618`).
- **#2701 D8 (L2 row 18)** — group definitions are Owner-only behind the `risk_caps` step-up. **#2701 D11 (L2 row 18)** —
  the loss-bounding caps are bounded on a trading-enabled profile and "all symbols" is an explicit flag.
- **ADR-0040 (L2 row 33, `accepted`)** — Decision 1's ceiling and later-narrows rule; Decision 4's review state.
  **L2 row 46** — the lockout counts realised loss only; the override ceiling is net and fails closed on an unknown
  figure.
- **A18 / A19** — the two owner items, ruled under the delegation (§3 D17, D18).

## 4. Cross-screen patterns (board 10)

### 4.1 "Not yet served" (D11)

`Pattern / not yet served stamp`: a frame-corner stamp in plain text, "not yet served: {route} ({gap})", e.g. "not yet
served: POST /trade-groups/preview (G-9)". The frame draws the contract's state as `22` defines it; nothing on it is
invented, and the built screen hides the control behind a default-off flag until the route mounts (C-4.13). A flag never
gates a safety invariant (C-4.14).

### 4.2 The step-up (D17, D18, BQ-7)

`Pattern / step-up dialog as used here`: SCR-006 composed through CMP-044, class `risk_caps`. Every profile write and
every definition write is Owner-only; without a live step-up the server answers `403 step_up_required` (audited as
`auth.step_up_required`) and nothing is stored. The dialog names what will be saved ("Save sub_001's profile"), keeps
focus inside, returns it to Save, and has no timing trap (AX-7). A Manager never sees it: the write control is not
there (D7, D14).

### 4.3 Readiness and leg words (D5, D25)

`Pattern / readiness and leg words`: status is always a word, never colour alone (AX-8): **ready**, **warn**,
**skipped**, **blocked** on a preview leg (the served `status`); **ready** / **not ready** on a definition member (the
served `ready`). The reason line under a row is the served code's words (§10) or the server's `message`. "N of M ready"
is the served `readiness.ready` of `readiness.total`, or the preview's `accounts_submittable` of `accounts_targeted`;
the client never counts. Unknown reads "unknown", never zero (BQ-5).

  default ("make another profile the default first") and an armed rule covering the account, each rule named.
- **Duplicate** (row menu): opens `SCR-131 / new profile: the empty form` prefilled from the row's profile as a new
  alternate; the save is a `createAccountProfile` behind the step-up. No default move here: the default binding has
  its own operation (`setAccountDefaultProfile`).
- **Changed since** (`14:2629`): each profile's served `version` and `updated_at` ("v3 · changed 2026-10-12 UTC").
- **A non-owner** never reaches this page: `/admin/*` resolves to SCR-155 (`14:43`).
- **States:** loading (CMP-015 rows), empty (no account yet: "No accounts yet. Add one on Accounts."), error
  (CMP-027 with Retry), forbidden (SCR-155 for a non-owner, `14:43`).
- **A11y / performance:** a table with a caption; the row's environment and trading state are text. One call per
  account (`listAccountProfiles`), small dataset.

#### 5.2.1 Sections and fields (AD-5)

The six sections hold every stored field and no control without a column (memo §8): Leverage & margin (`leverage`,
`risk_caps.max_leverage_cap`, `margin_mode`, `position_mode`); Sizing (`sizing.mode` and its one parameter,
`min_leg_notional_usd`, then the order-defaults sub-group `default_time_in_force`, `reduce_only_default`); Brackets
(`stop_loss` unit ticks / percent / ATR with period and multiple, `fallback_pct`, `take_profit`,
`take_profit_ladder`); Risk caps (`max_position_notional_usd`, `max_position_pct_equity`, `max_daily_loss_usd`,
`max_daily_loss_pct`, `max_open_positions`, `max_concurrent_orders`, `max_orders_per_minute`); Symbols
(`all_symbols`, `allowed_symbols`, `blocked_symbols`, with a link to SCR-133); Safety (the fixed statement,
`slippage_tolerance_bps`, `enabled`, `trading_enabled`). The header names the profile, its account, environment,
`version` and trading state. The daily-loss cap carries CD-7 once as its description (D9). Every field has its unit.

#### 5.2.2 The worked example (AD-3, AD-4)

A first-class block directly under the sizing parameter, not a footnote: CD-4, USDT first and R defined in USDT in the
same sentence, every number checkable. On the frames it uses US-PROF-002's numbers (equity 10 000 USDT, risk 0.5 %,
stop distance 120 USDT: "If your stop is hit you lose about 50 USDT (1 R) — 0.5 % of 10 000 USDT. At a 120 USDT stop
that is about 0.41 BTC."); built, it uses the served equity (`wallet`) and the served `sizing_below_min_order`
warning, whose `message` works the example on a write. "About" because the server counts taker fees. The block is labelled
"Example": it illustrates the profile's rule and is never the order size, which only the served preview
(`sizing_explanation`) gives (BQ-5).

#### 5.2.3 Safety (D6)

The Safety section opens with CD-6 as plain text: "Every order carries a stop-loss at the exchange. This cannot be
turned off." It is a sentence, not a field: nothing beside it can be focused, ticked or switched, and a screen reader
reads it as text (AX-6). The stop rule cannot be sent false from this UI, so the `native_stop_mandatory` refusal is
"not reachable from this UI" (§7 row note, §10). The rest of the section is the slippage guard and the two switches
the schema stores (`enabled`, `trading_enabled`), with CD-3 listing the caps still missing when trading is off. The
switches sit under their own sub-heading, "Trading", never on the statement's row or under its label.

#### 5.2.4 Save: two passes, the diff and the step-up (D16)

1. **On blur** — the schema's own shape (type, required member, range and decimal places, as `22` publishes them)
   is mirrored at the field as a convenience (`SCR-131 / first-pass errors on blur`); nothing is sent and nothing is
   judged here. The server's first pass on save (`required`, `not_allowed`, `range`, `precision`, `ladder_sum`,
   `above_leverage_cap`, #2701 D11's trading-caps rule, `22:16511-16513`) is the authority, and its errors replace the mirrored ones. Save
   stays enabled; a submit with errors returns focus to the summary.
2. **Beside Save**, always: "Exchange limits are checked when you save (they can change)."
3. **Review and save** opens the diff summary (`SCR-131 / diff summary: relaxing changes and future orders only`):
   before and after per changed field, every relaxing change marked "relaxing" as the audit record will (AD-7), the
   entries the server will judge against exchange limits listed (an allow entry added, leverage raised, size changed,
   max position lowered), and CD-5 ("Applies to future orders only. Open positions keep the version they were sized
   with.").
4. **Save** takes the step-up once per session (`Pattern / step-up dialog as used here`), then `updateAccountProfile`
   with If-Match.
5. **A second-pass refusal** (`SCR-131 / second-pass refusal against an exchange limit`) returns focus to a summary at
   the top and attaches each error to its field with the symbol and limit served ("SOLUSDT allows at most 20x — your
   25x would be rejected."). `503 instrument_cache_unavailable` shows the served `detail` ("The exchange's limits could not
   be refreshed in time; nothing was saved.") and "Try again in a few seconds." `412 version_conflict` reads "This
   changed since you opened it. Nothing was saved — reload to see the new version." Nothing is ever half-saved.

#### 5.2.5 Read-only view (D14)

A Manager on a granted account sees every field as text with its unit, the Safety statement kept, no Save, no
step-up, no "Edit in matrix" link, in a read-only modal of the trading host (`?modal=` query state, `14:41`), reached
from SCR-061's account cell. It is never an `/admin/*` route, which resolves to SCR-155 for a Manager (`14:43`); the
modal's place is O-3 and A-4. Served:
`getAccountProfile` takes `accounts:read`, which a Manager holds on granted accounts (`24:4941`, `MX:629-634`).

### 5.3 SCR-132 — Profile templates (modal over SCR-130; board 04)

- **Built-in cards (D17).** Three cards — conservative, standard, aggressive — each with its name, a one-line
  description and the placeholder fields "leverage {n}x · risk {p} % per trade · daily loss {d} %", stamped:
  "values set at E28-S02's implementation (orchestrator ruling then), within these constraints: `aggressive` is
  demo-only and never applicable to a LIVE account; conservative ≤ standard ≤ aggressive in every cap; every template
  inside the profile schema's bounds and judged by the server like any save (F-12)". No number is invented.
- **Saved templates.** Their list, rename and delete are "not yet served (G-7: no template storage)", routed to #971 /
  E28-S02 (#972). The frame draws the empty list ("No saved templates") under the stamp.
- **Apply to N accounts.** Pick a template and target accounts (CMP-105). A per-account preview lists, for each
  account, the fields that would change, before and after (the template's placeholders against the served profile).
  Exclusions are only what is known without a call: the aggressive card for a LIVE target (D23). Exchange limits are
  judged at each account's save; the preview says so in the fixed line. **Apply never writes**: it opens SCR-131
  prefilled for the first account, and each account is its own step-up save (W3; "Account 1 of 3: sub_001").
- **LIVE acknowledgement (D17, D23).** Applying any template to a LIVE account shows, before the editor opens: "sub_001
  is LIVE. The template only fills the editor; you review and save each account, and the server judges the save like
  any other." with a required "I understand" checkbox and Continue. The aggressive card is not offered for a LIVE
  target.
- **States:** loading, error and forbidden as SCR-130's.

### 5.4 SCR-133 — Symbol permissions (a view of `/admin/profiles`; board 05)

```
+------------------------- Symbol permissions (default profiles) -------------------------+

|            | Main            | sub_001          | sub_002            | sub_003          |
```

- **Three cell states by glyph and text** (B3, AD-8): "+ allowed", "x blocked" (on the block list, refused even when
  allowed), "- not allowed" (not on the allow list); the column head carries the row-level state ("Allows all
  symbols", "Allows no symbol yet" or "{n} allowed"). An "(all)" suffix marks a cell allowed by the flag; "(pos)" marks
  an open position. Each cell is a checkbox (CMP-005) whose accessible name is "account, symbol, state" ("sub_001,
  ETHUSDT, blocked", AX-1).
- **Grid.** Accounts are columns, symbols rows; both header rows and the symbol column are real table headers and stay
  visible while scrolling (AX-2); rows are virtualised over about 400 symbols (`14:2699`). Search and the account
  filter (CMP-054, CMP-055) narrow the rows; arriving from SCR-130 the account filter is set (D24).
- **Bulk.** A column action ("Block SOLUSDT on all accounts", "Allow all listed on sub_001") and a row action open a

- **Open position (D18).** Narrowing a symbol that an account holds a position in is allowed behind a confirm naming
  the position: "BTCUSDT has an open position on sub_001 — new entries on it will be blocked; closing orders and stop
  changes stay allowed". The position keeps its profile version (`22:3499-3501`). The "(pos)" mark needs a positions
  read that is not mounted (`listPositions`): the frame is stamped "not yet served (G-8)".
- **Save (D18).** "Review changes" lists the unsaved changes per account, each marked relaxing where it widens; Save
  takes one `risk_caps` step-up per session and writes one `updateAccountProfile` per changed account with If-Match.
  The report is per account: "2 of 3 saved; sub_002: version conflict, reload". There is no single server call and no
  `symbol_permission.*` event (C-3, C-4).
- **States:** loading, empty (no symbol matches the search: "No symbol matches"), error and forbidden.

## 6. Annotated flows (board 10 storyboards)

1. **Create a profile.** `SCR-130 / populated: one row per account, default named, alternates nested` → row menu
   Duplicate → `SCR-131 / new profile: the empty form` → `SCR-131 / first-pass errors on blur` →
   `SCR-131 / diff summary: relaxing changes and future orders only` → `Pattern / step-up dialog as used here` →
   saved (or `SCR-131 / second-pass refusal against an exchange limit`).
2. **Apply a template.** `SCR-132 / built-in template cards with placeholder values` →
   `SCR-132 / apply to N accounts: per-account preview and exclusions` → `SCR-132 / live-account acknowledgement` →
   `SCR-132 / apply hands each account to the editor` → per account, flow 1 from the diff summary.
3. **Edit symbol permissions in bulk.** SCR-130's symbol count → `SCR-133 / search and filter, filtered to one
account` → `SCR-133 / bulk column action with its confirmation` → `SCR-133 / narrowing under an open position: the
confirm` → `SCR-133 / unsaved-changes summary and per-account save report`.
4. **Create a group.** `SCR-062 / definitions with readiness` → `SCR-062 / create behind the step-up` → saved, or
   `SCR-062 / refused: no symbol in common` (→ flow 3) or `SCR-062 / refused: Demo and Live mixed`.
5. **Preview a fan-out.** `SCR-062 / Manager: the read-only picker` (or the Owner's list) → `SCR-061 / previewing` →
   `SCR-061 / ready` / `SCR-061 / excluded: skipped and blocked rows with their reasons` → `SCR-061 / refused whole:
not sent` or `SCR-061 / stale-preview` → Send (E34-D02).

## 9. Keyboard, focus and live regions (D26; `05`)

- **Focus order** follows reading order per screen: SCR-130 heading → table (row by row; the row menu is the last
  stop of a row) → page actions. SCR-131 header → sections top to bottom → the fixed line → Cancel → Review and save.
  SCR-133 search → filters → the grid (arrow keys move between cells; Space toggles a cell; the header cells are not
  focusable) → Review changes. SCR-062 list → expander → New definition. SCR-061 intent → table → Preview again →
  Send.
- **Dialogs** (step-up, delete confirm, bulk confirm, open-position confirm, LIVE acknowledgement): `role="dialog"`
  (confirms `alertdialog`), Cancel first, focus returns to the opener; `Esc` cancels; `Enter` never confirms from a
  checkbox.
- **Live regions:** the save summary and the refused-whole summary take focus (no live region needed); the per-account
  save report and the preview's "N of M ready" line are polite, once per result; the review state is a polite
  `role="status"` once per change (AX-4); nothing announces per keystroke.
- **Text resize:** every row's state is text; no fixed-height cell clips the reason line at 200 %.
