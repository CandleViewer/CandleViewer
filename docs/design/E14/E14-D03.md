### 2.3 Grid rules, sizes and the legibility rule

- **Canvas and stroke:** a 16 px square canvas (`size.icon.md`, which `size.icon` aliases), 1.5 px stroke, round caps, strokes on half-pixel centres so a 1.5 px stroke covers two device pixels evenly at 1×; the optical bounding box square-ish for toolbar alignment (`16` §5). `16` §5 names the optical sizes "16/20/24px (`size.icon.sm/md/lg`)" while the primitives resolve `size.icon.sm/md/lg` = **12 / 16 / 20** — the rail draws **`size.icon.md` = 16** and records the contradiction (C5) for `16`'s owner.
- **Buttons and padding (the tool's grid arithmetic):** compact button 24 (`size.control.compact`) − glyph 16 = 8 → **4 px** padding each side; comfortable 32 (`size.control.comfortable`) − 16 = 16 → **8 px**; the pressed / hover fill takes `radius.sm` 4 (= `radius.control`); the inset bar is 2 px (`border.thick`) full height on the button's left edge; the separator block 2 + 1 + 3 = 6 (`border.hairline` for the rule); the column's top and bottom padding `space.1` 4.
- **Badges:** 8 px (half the glyph) with a 1 px `color.surface.raised` halo so a badge never touches the glyph: the T2 lock badge (`lock`, CMP-019 `decorative=false`, name "Not available") at the button's **top-right** (E09-D09 §2.2 rendering 2b), the armed badge (the armed tool's own glyph) at "More tools"' **bottom-right** (Q10, §5.3).
- **Focus ring:** 2 px (`border.focus`) at 2 px offset → a 32 px ring box around a 24 px button, 4 px past each edge of the 24 px column (40 px around the 32 px button); the rail keeps `overflow: visible` so the ring is never clipped (§3.3).
- **The smallest-size rule:** every glyph is designed at 16 px in a 24 px button at 100 % zoom — the smallest rail size that ships — with no feature thinner than the 1.5 px stroke and no two parallel strokes closer than 2 px (the pole caps of the magnets, the four rules of `fib-retracement`, the two inner rules of `trash` are the tightest cases, each at 2 px); a glyph that needs a feature under those limits is redrawn, never thinned `(heuristic)`.
- **200 % and the text scale (`05` §5 item 7; D02 §11 line 494):** 125 / 200 % zoom are CSS-px scales — the 24 px button renders at **30 / 48 px**, the 16 px glyph at 20 / **32 px**, the 1.5 px stroke at 3 px, with the same tokens; nothing is re-drawn at a zoom level, the panel collapses the rail into `[Draw]` once it is under 1280 CSS px wide (§5.4), targets stay CSS px (WCAG 2.5.8). The in-app text scale grows the tooltip, the menu labels and second lines, the deferred tags and the chip's text with the type tokens; the 24 / 32 px buttons, the 16 px glyph, the 8 px badges and the 2 px bar stay CSS px (the rail is not text). The CMP-044 confirm at 200 % fills the viewport width, keeps Cancel and Delete 497 on one sticky row and scrolls its body if the copy wraps past the height (`05` §5 item 7). Board 09 shows both scaled specimens.

## 12. Security, performance, observability

### 12.1 Security

Delete-all is a UX hazard, not a STRIDE row: it destroys server-persisted drawings on every pane of the symbol (ticket Security notes), so §7 keeps it apart, distinct and behind CMP-044 with one undo; the rail itself has no row in `docs/security/threat-models/E14-drawings.md` — DR38 (line 158) covers the Viewer: `workspaces:write` is required and a Viewer gets 403 before the store is touched, whatever the rail shows. No credential, account or key data appears on the rail; the only account word is the status row's env badge (cited). The rail is never an access control (§1.2).

### 12.2 Performance — the layer card

Hover, pressed, focus and T2 feedback are DOM / CSS token swaps (a fill, a border, a badge) that dirty no canvas layer and run no per-frame layout; the rail never re-renders on chart frames (D02 §13.2; ticket Performance: ≥58 fps dragging with 200 drawings, SCR-037). The icons ship as **inline SVG `<symbol>`s referenced by `IconName`** (PROPOSED for E14-D08; the ticket's "a sprite or inline SVG set" — C8): one `<svg>` sprite inlined once per document, each glyph a `<use href="#icon-trendline">`, so theming is `currentColor` (the `color.text.*` token of the state), no image request, no layout per frame and no raster to re-cut per theme or zoom. Every board's "Layer:" strip line restates the card.
