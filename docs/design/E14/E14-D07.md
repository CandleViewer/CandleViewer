## 8. Selection coupling and undo (D7, D8; Q9, Q10)

### 8.1 Both directions, the off-screen object and the two routes

**Row → canvas:** focusing or selecting a row highlights the object (the selected state's outline on the canvas; no handles unless the plot has focus — D02 §5.1) and **never moves the viewport**: focus is never silently stolen and the chart never jumps under the user (`05` §3.4 item 3). When the object's **rendered extent** — its anchors and, for a horizontal line, ray, extended line or anchored VWAP, the extension the engine draws past them — does not intersect the viewport in time **and** price (the engine's test over its object index, `26` §3.9, evaluated on a viewport change, batched, never per frame — PROPOSED; the client sees `geometry.points` only, `22` `Drawing`: `21` §3.8.3's `anchor_start` / `anchor_end` are server index columns that never reach it, G-12) the row shows the **"off-screen"** tag + glyph (§4) — so a horizontal line is never tagged while its level is on screen (its time is irrelevant, §2.2) and a level priced outside the visible range is tagged although its anchor bar is in view — and the row menu's **Reveal on chart** — or the tag itself, a button with the same command (a pointer target, `tabindex="-1"`; the menu item is its key twin), name "Off-screen — reveal on chart" — brings that extent into view (the time axis to the first anchor of a time-bounded object, the price axis to the level of a horizontal line) and moves the data cursor there (`ChartApi.setCursor(…, "table")`, E06-D03 D10 — the `table` origin announces like a keyboard move), announcing once "Revealed horizontal line at 64,120.5." (PROPOSED). Reveal is the same menu command for an on-screen row (E13-D02 D26); no chord is added. **Canvas → row:** selecting an object on the canvas **reveals** its row — expands its sub-group, scrolls the virtualised list so the row is in view, sets `aria-selected` — and **moves focus to the row only if focus is already inside the tree**; otherwise the row is selected and revealed without a focus move, and the tree's roving stop lands on it at the next `Tab` into the tree. A hidden drawing cannot be selected on the canvas (D02 §5.1: its row is the only way to it), so this direction never fires for it. The Select-area marquee (D02 §5.5) reveals and selects every matching row and the bulk bar shows the count. **Two routes, two orders:** the canvas surrogate (E11-D02 D18's "overlay handles" stop; D02 §9.4 — time, then price, "item X of Y") and the tree row are two routes to one object with one accessible name; each names its own position in its own set, and neither route changes the other's order.

### 8.2 Undo and redo surfacing (US-DRAW-008; AD-8; Q10)

(a) **Delete → the toast** of §7.3. (b) **Undo** (`Ctrl+Z` or the toast's Undo) → **the row returns** at its z-order position — a new id at the old `z_index` (D02 AD-8; nothing in the UI depends on id stability) — `aria-selected="true"`, **focused only if focus was in the tree**, with the **"restored"** tag for 10 s and one decorative flash: the fill from `color.surface.selected` to the row's resting fill over `motion.duration.normal` (200 ms) with `motion.easing.standard`; the announcement **"Undone: trendline removed. Restored on 2 panes."** (PROPOSED, ≤ 10 words — D02 §12's "Undone: {op} {type}." extended with the pane count, because memo §4's prediction (c) is a user expecting one pane to come back: the words say every pane did; "… Restored on this pane." for a pane-local drawing, PROPOSED). (c) **Reduced motion** (`05` §7; the resolved `motion: reduce` mode of `16` §4): no flash — the row appears in its resting state with the tag; the tag is the carrier, the motion the decoration. (d) **Redo** (`Ctrl+Y`, D02 C12 / memo AM-12 — US-DRAW-008's `Ctrl+Shift+Z` is C-9) mirrors (b) with "Redone: …". (e) **Bulk undo:** a bulk action is one undo entry (D02 §5.3) — the toast counts ("9 drawings hidden." / "9 drawings shown." / "9 drawings locked." / "9 drawings unlocked." + **Undo**, PROPOSED; "7 drawings deleted. 2 locked drawings kept." + **Undo** — the worked example throughout is 9 selected, 2 of them locked), the undo restores every row with the tag on each and one announcement. E14-D09 owns the curve and the timing beyond the token pair named here (§16.6); a restored row that was off-screen keeps its off-screen tag after the "restored" tag's 10 s (the priority order of §4).

## 13. Security, performance, observability

**Plain text and text nodes (ticket Security notes; DR6 / DR7):** §2.6 — the row name, the tooltip and the filter are text; `label` and `text` are sanitised on write by `22` and never HTML-encoded, so the sink is the safety (DR6); names are set through DOM property / attribute APIs with a text node, never concatenated markup (DR7; E14-Q07 verifies). **Owner-scoped rows (DR12 / DR20):** the tree lists the caller's drawings only; nothing on the branch implies another user's objects. **Destructive placement:** §7.1's gaps and glyph; every destructive bulk action is behind the `alertdialog` naming the count and the multi-pane effect; a single delete has its undo toast (§7.3). **Analytics, never audit (DR17):** drawings are explicitly outside the C-2.9 append-only audit scope; the events below carry ids and counts only (D02 DR26 — no label text, no price), no sink until one is specified (D02 OQ-6); a T2 press emits nothing. **RBAC (C-12.4; DR38):** the server refuses a Viewer's or a view-as write regardless of what the tree shows (§1.3). **Performance (ticket Performance notes; `14` §0.5 item 7; D02 §13.2):** row values update on commit (the 500 ms drag debounce, `22` 8812), never per frame; a drag or a rubber band dirties the drawings layer only — never price or footprint; the branch is virtualised above 200 rows and collapses its sub-groups by default above 200 rows (one threshold, E13-D02 G-1); the off-screen test runs on a viewport change over the engine's object index (`26` §3.9), batched, never per frame (§8.1); its updates are batched; the filter is a text match over the loaded rows; the 500-row frame is the proof; SCR-037's ≥ 58 fps drag with 200 drawings and the shell's 60 fps scroll bar are the budgets protected. `listDrawings` pages at ≤ 500 per call (`22` 8695), so a branch of 500 or more is at least one full page — E14-T02's load story, G-7.
