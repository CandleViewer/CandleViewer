### 1.2 What the popover touches (normative; the Safety framing)

The popover **styles and edits drawings; it never trades.** Every write it makes is a `/drawings*` write — `updateDrawing` (`22:8887`, a full replacement with `If-Match`), `batchUpsertDrawings` (`22:8809`, one transaction, ≤200 operations, `if_match` per op — the multi-select's bulk apply), `deleteDrawing` (`22:8923`, soft delete) — or a template / default write whose resource does not exist yet (G-T1; the shape is engineering's, ticket Out of scope). No control calls an order, position, account or key endpoint. The one trading-adjacent control, the position tool's **Send to ticket**, is D06's: this spec draws the slot as D02 §7.2 words it (D06's branch is not on origin) and changes nothing about it — a pre-fill of SCR-060 that calls no operation, stays T1 for a Viewer and under view-as (E09-D09 §2.3), and leads to no order outside the ticket's own validation, arming and native stop-loss (C-2.6; sizing and caps server-side, C-2.12). No order word appears in the popover apart from that row. RBAC is enforced server-side (C-12.4; `14` §0.5 item 5; DR38): the popover is never an access control — a Viewer opens it and reads every value; the server refuses a Viewer's write before the store is touched. Statecharts record, synchronous code enforces (C-2.21).

### 1.3 **Four kinds of "no"**, never confused (the standing gates' clarification; E09-D09 §9.1; E30-D02 D3 / D16)

1. **T2** — a role, grant, view-as or **registered state** gate (the Viewer, view-as, the locked drawing under Q10's default, the future alert quota): the CMP-019 `lock` glyph leading the full label, `aria-disabled` (never `disabled`), the reason in the DOM at mount and linked by `aria-describedby`, the fill `color.surface.raised` with a `color.border.default` hairline, the label and glyph `color.text.tertiary`, the reason `color.text.secondary`, CMP-079 RbacGate on the role legs; never `color.text.disabled`, never `opacity.disabled`; a press stages nothing and re-shows the reason once, politely; it emits nothing. §8.1 states the rule once.
2. **Form validity** — an out-of-range width, an empty or duplicate template name, a duplicate or out-of-range Fibonacci level, a bad anchor price: the field in E30-D02 D16's look (`color.text.primary` message text + a `color.status.danger.strong` glyph + a 2 px `color.status.danger.default` field boundary; `aria-invalid`, `aria-describedby` → the message), the dependent save / apply action in E30-D02 D3's look — its own fill and full label at `opacity.disabled` (0.45), the reason as full-opacity `color.text.secondary` text under it (layer `validity-reason`), `aria-disabled` so it stays focusable and a press re-shows the message once; **no lock glyph, no CMP-079, never called T2** (E09-D09 §9.1; the [LANE-53] / [LANE-55] rider).
3. **An availability marker** — the alert toggle today (D02 §7.1): `aria-disabled` + the description "Coming in a later release." in `color.text.secondary`; no lock glyph, no CMP-079; a deferred capability is an absence, never a T2 lock (the orchestrator, 2026-10-23).
4. **An outcome** — "Saved" is a status line with a check glyph that fades, never a disabled control; "Saving…" is CMP-038's loading state (`aria-busy` on nothing: the field stays live, the line says it).

Every §8 row names its kind; the tool's string gate checks that no T2 row carries `opacity.disabled` and no validity row carries "T2" or a lock glyph.

### 1.4 Optimistic, never silent (ticket Technical notes 66–67, AC 2; `26` §3.10 line 262)

A property change paints on the drawings layer at once and **persists on commit**: a swatch pick, a toggle, a slider release, a stepper step, a field's `Enter` or blur (the note textarea: blur or 500 ms idle, PROPOSED — the batch debounce's cadence, `22:8812`). The **status line** under the title always answers "did this save?": **"Saving…"** (CMP-038, `role="status"`) → **"Saved"** with a `color.status.success.default` check glyph (an outcome; fades after `motion.duration.slow`, reduce → stays until the next change) → or **"Couldn't save — Retry"** (CMP-027 `warning`, `role="status"`, polite; the glyph `color.status.warning.strong`) with **the local value kept**: the canvas keeps the edited look, the drawing carries D02's "changes not saved" tag (§5.1), Retry re-sends the same body with the same `If-Match`. A `403` is refused at the point of action with no Retry and the control re-renders from the fresh session (D02 §7.2's forms, §8 row `access-changed`); a `412 version_conflict` on the single PUT (`22:8893`) is D02's conflict state — "Trendline changed elsewhere."; re-applying the local version is one undoable command (D02 §11 line 484 names the batch's `409`; both codes are one state, C6); `503` / offline is transport: "Not saved — offline. Retrying when connected." (PROPOSED), the drawing tagged, no Retry button while offline (the retry is automatic on reconnect, E17-D01's states). **A multi-select bulk apply is one `/drawings/batch` call in one transaction: the first failure rolls the whole batch back** (`22:8819–8820`) — the status line says **"Nothing changed — 7 drawings kept their style. Retry"**, never a partial result (§7).

### 9.3 Focus return and the no-trap rule

The chart region's stops run toolbar → chips → rail → legend → gutter → plot → handles (E11-D02 D18; D02 §9.4), and the popover opens from the handles stop. The popover never traps: `Tab` past Delete leaves to the surrogate (D02 Table 2) and `Shift+Tab` from the first field returns to it; `Esc` returns to whatever opened it — the surrogate (the handles stop), the context menu's trigger surrogate, or the tree row whose menu said Properties (D02 §8.2). The two CMP-043 dialogs trap (`05` §3.4 item 4) and return focus to the button that opened them. A save result, a retry, a `403` or a conflict **never moves focus** (`05` §3.4 item 3; E30-D02 361); only Delete (the popover closes) and Clone (the popover follows the clone) move it, each stated above. The ring is CMP-039's on every stop (§2.2).
