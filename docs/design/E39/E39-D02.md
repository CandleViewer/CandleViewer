## 1. Purpose, scope and the safety framing

The two _monitoring_ surfaces of E39 — **SCR-071** the risk dashboard (R-150 `/risk`, the owner's supervision page; R-151 `/risk/:accountId`, the manager's "what are my limits" page) and **SCR-073** the lockout notice (the interruption a manager sees when the server locks their account, B20) — plus the two components they contribute, **CMP-117 RiskLockoutBanner** and **CMP-138 RiskCapMeter**, taken from E39-D01's wireframes (its 7 `SCR-071 / *` and 9 `SCR-073 / *` boards) to hi-fi, with the a11y review and the handoff package E39-S04 consumes. **The UI mirrors server truth and server enforcement:** the server enforces risk and RBAC (C-2.12), statecharts record while synchronous code enforces (C-2.21; the client never computes `until`). **A lockout notice never implies that closing or reducing is blocked when it is not:** under a B20 lockout reduce-only closes stay available everywhere (D10 :317; `14` SCR-073 :1544 "Read-only access to everything else remains"; every §8.2 row "closing and reducing still work"; §9.1 :563), and only the **frozen** (B18) manager banner promises nothing beyond "ask the owner" (OD-11 :687, §8.1 :488). **Native-SL protection (C-2.6) is never implied removed:** R4 widened to lockouts (SR-E39-06 :244) — a lockout cancels only exposure-adding working orders, position TP / SL and reduce-only stops are never cancelled;
