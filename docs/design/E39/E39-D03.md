## 1. Purpose, scope and the safety framing

The two _action_ surfaces of E39 — **SCR-072** the kill-switch / freeze confirmation (`role="alertdialog"`, the only place a human engages B18) and **SCR-134** the global risk policy (`/admin/risk-policy`, R-353) — plus the **CMP-211 PanicButtons** cluster and the **global hotkey** treatment, taken from E39-D01's wireframes (its boards `SCR-072 / *` and `SCR-134 / *`) to hi-fi, with the a11y review and the handoff package E39-S05 (#1012) consumes. The UI **mirrors server truth and server enforcement**: the server enforces risk and RBAC (C-2.12), statecharts record while synchronous code enforces (C-2.21), and native stop-loss protection is never implied removed (C-2.6). A FREEZE halts order acceptance server-side in one call (the `14` SCR-072 performance note: "within 200 ms"; INV-B18-a/b: the block takes effect before the event that records it is processed) and per-account completion streams in after it, cancel-all paced at 1 req/s per UID (`04` §9.3) — **the UI never appears blocked**. Open positions are NOT closed unless "also flatten positions" is ticked (E39-D01 D1, §8.1); flatten implies cancel (E39-D01 §0.1, D2). **R4 in one paragraph:** a freeze blocks NEW orders; cancel-all cancels the working entry / exit orders that add risk (`CancelAllRequest.intents`, `exclude_reduce_only`); flatten closes positions reduce-only at market; SL / TP and reduce-only stops on the positions that stay open are never cancelled (SR-E39-06, threat model :244); `engaged` is reported only after an exchange read confirms the requested actions and `positions_without_native_stop == 0` (E39-D01 §7.1). No key, fingerprint or balance detail beyond SCR-071 is rendered anywhere here: the modal shows per-account counts of working orders, open positions and armed rules, and the positions it would close as symbol · side · size · uPnL. LIVE vs DEMO is never colour-only (`14` §0.5 item 1; D-3 / D11). Step-up (SR-025) is a **drawn** step for release (SR-E39-08), for the SCR-134 save (`14` SCR-134 audit line) and for any override (D-4) — never for engage (D2; AC-RK-21).

**Out of scope:** SCR-071, SCR-073, CMP-117, CMP-138's anatomy → E39-D02 (#878; cited, never redrawn); the flatten-all runbook → E39-T03 (#957); the feature-flag console that also exposes a kill-switch-class flag → E42 (E42-D02 D13: the console never labels a flag "kill switch" and never offers the emergency engage). **The bar** `(heuristic)`: a professional terminal's emergency controls (E39-D01 §6 fetched Sierra Chart, TradingView, Bookmap, Quantower and IBKR's conventions — cited, not refetched): the stop is two keystrokes away from anywhere and impossible to trigger by accident, the consequence is readable in one glance under stress, nothing lies about what was and was not done, and release is deliberately slower than stop.
