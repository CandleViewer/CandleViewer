## §E Test hooks

- `data-motion` (`safe | reduce`) on `document.documentElement`, the only mode a component reads (spec §9).
- `data-state` on the rail (`collapsed | expanded`), the drawer (`open | closed`) and each banner row (`shown | cleared`).
- Under `data-motion="reduce"` every transition computes `transition-duration: 0.01ms` (CSS:63).
- "No layout during frames": no forced style and layout recalculation of the WorkspaceCanvas subtree between frame 0 and the last frame of T-01 to T-04 and T-17 to T-19 (spec §5, §8.2; E10-Q04).
- The safety rows (spec S-01 to S-07): under `data-motion="safe"`, CMP-074, the StatusBar's CMP-075, CMP-215 and the FROZEN and lockout slots compute `transition-duration: 0s` on every property (R-4).
- Frame 0: after T-04, T-11, T-16 and T-19, `document.activeElement` is the row's named target and `aria-expanded` holds its end value in the first frame after the trigger (R-4, R-5); a held `Ctrl+/` opens SCR-013 once (spec G-07).
- The keyboard route, verbatim, for E10-Q03: SkipLink → TopBar → NavRail → banner slot → WorkspaceCanvas → RightRail → StatusBar (D02:254); then each `Esc` row of spec §13.2; an informational banner's Dismiss or Later moves focus to the next banner's first control, else the search trigger (T-19, PROPOSED).
