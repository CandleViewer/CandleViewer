## 1. Purpose, method and the rules stated once

### 1.1 What this spec settles

How a trader recovers from a preset applied by accident, sees and resolves "modified from preset", and names presets without silent loss; how a profile range is made, adjusted, opened forward and removed with the pointer and with the keyboard alone; what a profile attached to an E14 drawing does when the drawing moves, locks, hides, is deleted or is shared; and which of the chart, the drawing tools, the profile and chart trading owns each pointer input, with the cursor that says so.

### 1.2 Method (honest)

Desk work at the base under the agent-delivery adaptation: no participant, prototype or engineer session exists; every judgement is heuristic (§13.1). The audit tool checks every cite at its pinned revision, the six scenario names, the preset operations, the matrix (no undecided cell), the keyboard rows, the delete outcomes, the event payloads, the states ↔ boards reconcile and the board cap.

### 1.3 Rules stated once (every later row cites "R-n")

- **R-1 C-2.11, a hard constraint.** The profile is environment-neutral (D02:97): a preset, a range, an anchor and a drawing link carry no environment, and nothing in these flows reads, mixes or switches one (CONSTITUTION C-2.11). The gesture matrix (§5) is identical in DEMO and LIVE; arming chart trading is E31's and its own environment rules are E31's; no flow here adds a DEMO / LIVE badge, an environment control or an account context.
- **R-2 Words carry meaning.** "Modified" is a word on the menu button and in the dialog header, never a dot alone (T A11y); the drawing link is a glyph plus the words of W-33; a range is its two times in words in the legend; colour never carries a state alone; no motion carries meaning alone.
- **R-3 Announcements ≤ 1 Hz.** Polite, once per outcome, through the panel's one polite region (D02:100; `05`:168): range created, anchor set, anchor removed, preset applied, settings restored; never per drag frame, per key repeat (K-6) or per recompute; a toast's sentence is written once into that region (`15`:533). If two outcomes land together, one string is spoken: the latest, or the combined form the deck names (W-17's armed form); nothing queues.
- **R-4 No field invented.** No `22` / `23` / `24` change: a missing contract is a G-row to an existing ticket (§12.2), the control drawn with its gap named.
- **R-5 Motion: none here.** Every change these flows add is a cut (`motion.duration.instant`); the choreography is E19-D05's. `prefers-reduced-motion` (`05`:231) is the hard gate for anything E19-D05 adds; with nothing animated here, no state depends on motion. The shipped CMP-041 menu, CMP-043 / CMP-044 dialogs and CMP-045 toast keep their own entrances and their own reduced-motion variants. The Visible-range catch-up (§3.5) is a data redraw at ≤ 10 Hz with no fade or blink, the same under `prefers-reduced-motion`; nothing flashes more than three times a second and nothing moves for more than 5 s, so no pause control is needed.
- **R-7 Times in words (PROPOSED).** Every {time}, {start} and {end} reads `YYYY-MM-DD HH:MM` UTC ("2026-11-02 14:00 UTC"; seconds added on a sub-minute timeframe), the same in the legend, the announcements and `aria-valuetext`.
- **R-6 In-flight bases (R32:79).** D02 and D03 are quoted exactly; every D02 / D03 cite holds if #5487 / #5517 merges as is and re-pins at its merge.

## 2. Presets (US-VP-009; boards 01–03, 10)

### 2.1 What a preset holds, and where it travels (BQ-3)

### 2.3 Save as new and the name conflict (AC "A preset name collides")

`Save as new…` opens a CMP-043 dialog (`15`:505), size `sm`: title "Save as new", the field "Preset name" (W-12) with the helper W-11, footer `Cancel` · `Save`. Initial focus is the field; `Enter` in it submits; `Esc` and `Cancel` close and return focus to the menu button. A name is 1 to 80 characters after trimming (W-15 when outside it); uniqueness is per user and case-insensitive, as indicator presets are (`22`:10802–10803; D08E08:243). On `Save` with a name already used, the dialog stays open and shows the conflict inline under the field, never a silent replace: W-13 with two buttons, `Overwrite` and `Rename`; the field keeps `aria-invalid="true"` and `aria-describedby` on W-13, which is announced once. `Overwrite` replaces the named preset's values (one explicit action) and closes; `Rename` returns focus to the field with its text selected. A name equal to the built-in's, in any case, shows W-14 with `Rename` only: the built-in is never overwritten. A successful save announces W-21 once and the new preset becomes the applied one.

### 2.4 Modified (AC "Modified-from-preset is visible")

After any change to a held key while a preset is applied, the menu button reads W-9 ("{name} · Modified") and SCR-039's header shows the same words; the word W-8 is text in the accessible name, never a dot, a colour or an icon alone (R-2). It is announced once on entering the state, never per change (R-3). From a Modified user preset the menu offers both `Save changes to {name}` (overwrite) and `Save as new…`; from the Modified built-in only `Save as new…` and `Reset to {name}` (D04-C2). Changes to keys a preset does not hold (the input, the table switch) never set Modified.

### 2.5 Rename, delete and the empty state

- **Rename:** the save dialog titled "Rename preset", the field pre-filled and selected; the same name rules and the same inline conflict (W-13 or W-14); success announces W-21's rename form.
- **Delete:** CMP-044 (`15`:516), `role="alertdialog"`, W-16's title and message, `Cancel` focused (`15`:525) and `Delete`; profiles using the preset keep their current values, which become unnamed; success announces W-21's delete form and focus returns to the menu button. There is no undo after the confirm.
- **Empty:** the menu shows `Session value`, the row W-10 and `Save as new…` (board 01).

### 2.6 Undo after an accidental apply (AC "A preset apply is recoverable"; BQ-5)

Applying a preset changes every held key at once (`11`:1851–1853) and shows a CMP-045 toast "Applied {preset}" with the action `Undo` (W-17): a toast with an action is persistent by default (`15`:531), so it stays until dismissed or until the next settings change on that instance, which ends the affordance. For exactly the same lifetime the menu offers `Restore previous settings` (W-18), the discoverable twin when the toast is gone from view. Either restores the values held before the apply, announces W-19 once, and ends the affordance. One level, per instance, session-only: a second apply replaces the saved state; a reload loses it. It is never on the drawings `Ctrl+Z` stack (`26`:329; D04-C7). Applying with no preset change (the same values) still shows the toast, so the outcome is always announced. The toast never takes focus (`15`:533), so Undo is never reachable only through it: `Restore previous settings` in the Presets menu is the keyboard path for the whole lifetime, and the toast sits in CMP-045's stack, never over the plot stop, the handles or the Presets button.

## 3. Period anchoring (US-VP-002; boards 04, 05, 10)

### 3.1 The Profile range mode: making a fixed range (BQ-6)

Choosing Fixed range (the Period menu or SCR-039's radio, D02:314) or Anchored arms the **Profile range** mode on the bound chart's plot (the docked panel's chart, or the overlay's own pane). It is an armed tool like E14's: the armed-tool chip in the status row reads W-22 (E14's slot, D02E14:153), arming from the Period menu or SCR-039 moves focus to the plot stop (D02E14:153, :388), and the hint W-23 replaces D02's Shift-drag hint (D02 W-30, D02:379; D04-C1), announced once; arming caused by a preset apply moves no focus (§2.1). The chip is E14's `role="status"` node, read on demand and never re-announced (D02E14:153). While armed, a **plain drag** on the plot selects the range (cursor `crosshair`): the band shows `color.surface.selected` with `color.focus.ring` edges (D03:336), and the legend reads the two times in words as the drag moves (no announcement until release). Release commits: the profile recomputes once for exactly that window and stays pinned to those timestamps (`11`:1719–1721); W-26 is announced once; the mode disarms (as E14's tools revert after a commit, D02E14:80). Without a drag (SC 2.5.7, `05`:101): a plain click sets the start and a second click sets the end and commits, as E14 places with clicks (D02E14:472); `Esc` between the clicks leaves the mode and keeps the previous period. `Esc`, before release, leaves the mode and keeps the previous period; `Space` + drag pans without leaving the mode (§5). One armed tool at a time: arming the Profile range mode disarms an armed drawing tool and the reverse (§5). The same commit through the keyboard is §6.

### 3.2 Adjusting: the two edge handles

A committed range shows two edge handles at its start and end, vertical bars the full plot height with a 24 × 24 CSS px pointer target (`size.target.min`) and E14's handle glyph language (D02E14:84, :287); hover and drag show `ew-resize`. A handle drag moves that edge by whole bars; the profile keeps its last state during the drag and recomputes once on release (as a drawing drag never re-renders the price layers, `14`:978); W-26 once. `Esc` mid-drag restores the edge. Start never passes end (the dragged edge stops one bar from the other; W-41 once). Without a drag (SC 2.5.7, `05`:101): a click on a handle selects that edge and moves focus to its thumb on the profile range stop (§6); a click on a bar then moves the selected edge there and commits, or the arrows nudge it; `Esc` restores.

### 3.3 Converting to an anchored profile, and Anchored itself

The range's context menu and the Period menu offer **Keep open-ended** (W-27): the start stays, the end is released, and the profile accumulates forward and extends with new bars indefinitely (`11`:1725–1727); W-28 once. Choosing Anchored directly arms the same mode for one point: a click on a bar places the anchor (D02 W-31's hint, here W-24; D02:315, :380); the anchor marker is `color.text.primary` (D03:337). Anchored has no contract kind: `24`'s `ProfilePeriod.kind` lists `session`, `fixed_range`, `visible_range`, `composite`, `bar` and `rolling` (`24`:970); it is drawn and annotated "contract pending A-1" (MEMO:260; D02:215), never wired to an invented field (R-4; D04-C3, D04-G3).

### 3.4 Removing an anchor

**Remove anchor** (W-29) in the range's context menu and in the Period menu ends a Fixed range or Anchored profile: the period returns to the host default (docked Session, overlay Visible range; D02's PD-7 defaults) and W-30 is announced once. Remove is not destructive (the range is one choice away), so it has no confirm and no restore item of its own: the range is re-made by a drag, two clicks or §6's keys (BQ-6 adds no undo here; BQ-5's one undo is the preset apply's).

### 3.5 Visible range during a pan, and a stalled feed (BQ-7)

During a pan or zoom in Visible range the last computed profile stays drawn at full ink: **no dim, no skeleton, no busy bar**. It catches up at most 10 times a second while the gesture runs and once more after the pan-end debounce (`11`:1730; D02:317, :319), so a profile visibly lagging a fast pan is correct and says nothing. A stalled feed is shown only by E17's vocabulary: the feed chip ("Stale 7s", W-39, D02E17:65) and its shade, with D02's stale state (D02 W-18) on the panel; never by the profile's own ink. A trader tells the two apart because a lagging profile moves when the pan stops, and a stale one carries E17's word. `SCR-038/visible-pan-dark` and `SCR-038/visible-stale-dark` draw the pair side by side.

## 4. Drawing anchors (boards 06, 07)

### 4.4 Deleting the drawing (AC "A deleted drawing does not orphan a profile"; BQ-9)

The profile is **converted**, never removed and never blocked by a confirmation:

### 4.5 A shared drawing and a clone

A drawing has one stable `id` (`26`:328) and is shared symbol-wide within the layout, by every pane showing the symbol, not by sync group (D07E14:260; sync-group scoping is E14's open G-2). A profile instance lives in one pane: when it is attached to a shared drawing, a move made in any pane that shows the drawing moves that instance's range. A "this pane only" drawing (D02E14:372) drives only its own pane's profile instance; a profile instance in another pane is never attached by a shared drawing's move unless the user attached it there. A **Clone** is a new object with a new id (D02E14:295): it carries no link, and the profile stays on the source drawing (D04-C4, the reading of T's "cloned into a sync group").

No profile capability is pointer-only (`05`:35, `05`:101).
