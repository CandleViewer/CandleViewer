## 1. Purpose, method and the rules stated once

### 1.1 What this spec settles

How a trader recovers from a preset applied by accident, sees and resolves "modified from preset", and names presets without silent loss; how a profile range is made, adjusted, opened forward and removed with the pointer and with the keyboard alone; what a profile attached to an E14 drawing does when the drawing moves, locks, hides, is deleted or is shared; and which of the chart, the drawing tools, the profile and chart trading owns each pointer input, with the cursor that says so.

### 1.2 Method (honest)

Desk work at the base under the agent-delivery adaptation: no participant, prototype or engineer session exists; every judgement is heuristic (§13.1). The audit tool checks every cite at its pinned revision, the six scenario names, the preset operations, the matrix (no undecided cell), the keyboard rows, the delete outcomes, the event payloads, the states ↔ boards reconcile and the board cap.

### 1.3 Rules stated once (every later row cites "R-n")

## 2. Presets (US-VP-009; boards 01–03, 10)

### 2.1 What a preset holds, and where it travels (BQ-3)

A preset applies to every profile instance for any symbol (`11`:1854–1856), so it holds only what reads the same on any symbol and any chart:

| Held (the five keys of `11`:1851–1853, plus relative period parameters)                                                                                              | Never held                                                                                             |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |

| the session anchor (UTC day / funding 8 h / HH:MM), a fixed duration in minutes, a composite look-back in sessions, the VWAP anchor as `anchorMode` only (`15`:1689) | a drawing id or a drawing link; a symbol; an account, key, position or order; an environment           |

A preset whose period type is Fixed range or Anchored holds no times, and an apply never silently turns a plain drag from pan into select (R-8). On an instance that already has a range or an anchor, the apply keeps the instance's own times and changes the other held keys only; no mode is entered. On an instance with no range, the apply changes the other held keys and enters the Profile range mode (§3.1) visibly: E14's tool-chip slot shows W-22 and the one string spoken is W-17's range-mode form (R-3), the stored duration, if any, filling the duration field; the profile keeps its previous period until a range is committed, and focus stays with the menu (it returns to the Presets button). `Esc` leaves the mode with the previous period kept (§3.1), and Undo or `Restore previous settings` leaves the mode too and restores every value held before the apply (§2.6). A preset whose `anchorMode` is `custom-bar` holds no bar time: the instance keeps its own custom bar, or, with none, its VWAP anchor stays as it was until a bar is chosen (§7). The built-in "Session value" (W-2; D02:302) is listed first and is immutable: no Save, Rename or Delete is offered on it. **The export surface** (T Security): presets travel per user in the workspace export (`11`:1862); `22`'s `WorkspaceBundle` carries indicator presets only (`22`:24595) and nothing for profiles, so the field and its import validation are D04-G1 (E19-S09, E15-S07). ### 2.3 Save as new and the name conflict (AC "A preset name collides")

### 2.6 Undo after an accidental apply (AC "A preset apply is recoverable"; BQ-5)

Applying a preset changes every held key at once (`11`:1851–1853) and shows a CMP-045 toast "Applied {preset}" with the action `Undo` (W-17): a toast with an action is persistent by default (`15`:531), so it stays until dismissed or until the next settings change on that instance, which ends the affordance. For exactly the same lifetime the menu offers `Restore previous settings` (W-18), the discoverable twin when the toast is gone from view. Either restores the values held before the apply, announces W-19 once, and ends the affordance. One level, per instance, session-only: a second apply replaces the saved state; a reload loses it. It is never on the drawings `Ctrl+Z` stack (`26`:329; D04-C7). Applying with no preset change (the same values) still shows the toast, so the outcome is always announced. The toast never takes focus (`15`:533), so Undo is never reachable only through it: `Restore previous settings` in the Presets menu is the keyboard path for the whole lifetime, and the toast sits in CMP-045's stack, never over the plot stop, the handles or the Presets button.

### 2.7 One undo model and the three recovery verbs (ruling, cross-BQ rider 4)

## 3. Period anchoring (US-VP-002; boards 04, 05, 10)

### 3.1 The Profile range mode: making a fixed range (BQ-6)

Choosing Fixed range (the Period menu or SCR-039's radio, D02:314) or Anchored enters the **Profile range** mode on the bound chart's plot (the docked panel's chart, or the overlay's own pane). It behaves as one of E14's tools (R-8): E14's tool-chip slot in the status row reads W-22 (D02E14:153; the label an A-row, D04-A11), entering from the Period menu or SCR-039 moves focus to the plot stop (D02E14:153, :388), and the hint W-23 replaces D02's Shift-drag hint (D02 W-30, D02:379; D04-C1), announced once; entering through a preset apply moves no focus (§2.1). The chip is E14's `role="status"` node, read on demand and never re-announced (D02E14:153). In the mode, a **plain drag** on the plot selects the range (cursor `crosshair`): the band shows `color.surface.selected` with `color.focus.ring` edges (D03:336), and the legend reads the two times in words as the drag moves (no announcement until release). Release commits: the profile recomputes once for exactly that window and stays pinned to those timestamps (`11`:1719–1721); W-26 is announced once; the mode ends (as E14's tools revert after a commit, D02E14:80). Without a drag (SC 2.5.7, `05`:101): a plain click sets the start and a second click sets the end and commits, as E14 places with clicks (D02E14:472); `Esc` between the clicks leaves the mode and keeps the previous period. `Esc`, before release, leaves the mode and keeps the previous period, one step of E14's `Esc` ladder (D02E14:81; D04-A12); `Space` + drag pans without leaving the mode (§5). One active tool at a time: entering the Profile range mode cancels an armed drawing tool, and arming a drawing tool leaves the mode (§5). The same commit through the keyboard is §6.

### 3.2 Adjusting: the two edge handles

A committed range shows two edge handles at its start and end, vertical bars the full plot height with a 24 × 24 CSS px pointer target (`size.target.min`) and E14's handle glyph language (D02E14:84, :287); hover and drag show `ew-resize`. A handle drag moves that edge by whole bars; the profile keeps its last state during the drag and recomputes once on release (as a drawing drag never re-renders the price layers, `14`:978); W-26 once. `Esc` mid-drag restores the edge. Start never passes end (the dragged edge stops one bar from the other; W-41 once). Without a drag (SC 2.5.7, `05`:101): a click on a handle selects that edge and moves focus to its thumb on the profile range stop (§6); a click on a bar then moves the selected edge there and commits, or the arrows nudge it; `Esc` restores.

### 3.3 Converting to an anchored profile, and Anchored itself

The range's context menu and the Period menu offer **Keep open-ended** (W-27): the start stays, the end is released, and the profile accumulates forward and extends with new bars indefinitely (`11`:1725–1727); W-28 once. Choosing Anchored directly enters the same mode for one point: a click on a bar places the anchor (D02 W-31's hint, here W-24; D02:315, :380); the anchor marker is `color.text.primary` (D03:337). Anchored has no contract kind: `24`'s `ProfilePeriod.kind` lists `session`, `fixed_range`, `visible_range`, `composite`, `bar` and `rolling` (`24`:970); it is drawn and annotated "contract pending A-1" (MEMO:260; D02:215), never wired to an invented field (R-4; D04-C3, D04-G3).

### 3.4 Removing an anchor

**Remove anchor** (W-29) in the range's context menu and in the Period menu ends a Fixed range or Anchored profile: the period returns to the host default (docked Session, overlay Visible range; D02's PD-7 defaults) and W-30 is announced once. Remove is not destructive (the range is one choice away), so it has no confirm and no restore item of its own: the range is re-made by a drag, two clicks or §6's keys (BQ-6 adds no undo here; BQ-5's one undo is the preset apply's).

### 3.5 Visible range during a pan, and a stalled feed (BQ-7)

During a pan or zoom in Visible range the last computed profile stays drawn at full ink: **no dim, no skeleton, no busy bar**. It catches up at most 10 times a second while the gesture runs and once more after the pan-end debounce (`11`:1730; D02:317, :319), so a profile visibly lagging a fast pan is correct and says nothing. A stalled feed is shown only by E17's vocabulary: the feed chip ("Stale 7s", W-39, D02E17:65) and its shade, with D02's stale state (D02 W-18) on the panel; never by the profile's own ink. A trader tells the two apart because a lagging profile moves when the pan stops, and a stale one carries E17's word. `SCR-038/visible-pan-dark` and `SCR-038/visible-stale-dark` draw the pair side by side.

### 4.5 A shared drawing and a clone

A drawing has one stable `id` (`26`:328) and is shared symbol-wide within the layout, by every pane showing the symbol, not by sync group (D07E14:260; sync-group scoping is E14's open G-2). ## 5. The gesture-conflict matrix (AC "Gestures do not collide silently"; BQ-10; board 08)

Rows are every pointer input on the chart canvas (`26`:335–347; E14-D02's register, D02E14:466–492; KM:263–280). Columns are the four modes; **one active tool at a time** (the Profile range mode and an armed drawing tool are never on together), and chart trading's arm is orthogonal: with trading armed and the Profile range mode on, the Profile column governs plain inputs and the Trading column governs the chords. Each cell names **exactly one owner** (Chart = pan / zoom / cursor, `26` §3.11; Drawing = E14; Profile = this spec; Trading = chart trading, E31 and `13` §6) and **one cursor** (a CSS cursor keyword). No cell is undecided. The profile mode takes plain drag and plain click only; no modifier is a profile gesture; the trading chords stay trading's in every column (D02E14:469–471). The matrix is **identical in DEMO and LIVE** and no cell reads, mixes or switches an environment (R-1, C-2.11). ## 6. Keyboard paths (AC "Every gesture has a keyboard path"; BQ-11; board 09)

No profile capability is pointer-only (`05`:35, `05`:101). The grammar is `05`'s K-1 … K-12 (`05`:122–133) and DE-08's row (D09E47:168): the range mode on the plot stop uses E14's creation grammar (D02E14:388), and a committed range is adjusted through its own stop, the **profile range stop**, placed after the overlay handles stop (D02E14:428): two slider thumbs, W-25, each `role="slider"`, `aria-orientation="horizontal"`, `aria-valuemin` / `aria-valuemax` the first / last loaded bar, `aria-valuetext` "{time} UTC" in R-7's form (PROPOSED; D04-C6); a thumb stopped by the other speaks W-41 once. The focused thumb carries an offset ring and its value text beside it (§11), so it never reads as an unfocused edge. Context menus open with `Shift+F10` or the Menu key, as on E14's surrogates (D02E14:321). Units are D09E47:137's for a time: `←/→` one bar, `Shift` ×10, `PageUp` / `PageDown` ×100, `Home` / `End` the first / last loaded bar. On the profile range stop `PageUp` / `PageDown` are ×100 and never move between its two edges (`Tab` does): K-3 gives ×100 where the keys do not move between objects (`05`:124), and D09-C6's drawing-surrogate exception (D09E47:137) does not apply to this stop. The pending value is spoken politely, coalesced while a key is held (K-6); `Enter` commits (K-4); `Esc`, or focus leaving the stop, restores the value at selection (K-5). Every command is also in the command palette, unbound (K-8; no bare-letter binding, K-12).
