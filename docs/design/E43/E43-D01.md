## 1. Locked inputs (built on, never re-decided)

1. **Server truth (C-2.12, C-12.4).** Every value on these surfaces is the server's: the posture, the findings, the gate's state and items, the session's legs. The UI computes no check, no severity and no eligibility. RBAC is enforced server-side; the UI presents. The server enforces the fix-only refusal (SEC-12), the owner-only admin link (SW-01) and the attestation writes (§6.2) (C-12.4). Contract first (C-6.1): `22` serves only `getSecuritySummary` here, so the gate's state, the attester, a finding's id and a dismissal are drawn PROPOSED and listed as G-rows for the E43 / E44 contract tickets (§11).
2. **Synchronous enforcement (C-2.21).** The live gate (B17, `28`:7177) **records and orchestrates; it does not enforce** (INV-B17-a, `28`:7361). Live order entry is refused by a synchronous check before any interpreter (`28`:7361; the `trading_disabled` refusal, `22`:444, :6607). No copy on these surfaces says the screen enforces anything: the screen reports the gate's state and sends the Owner's requests.
3. **Demo / live isolation (C-2.11).** Enabling live makes LIVE **selectable**; it switches no session. Each session still switches through SCR-074 with its own typed `LIVE` and its own code (`E38D02`:116). Demo state never moves.
4. **No secret material.** Every field drawn exists in `SecuritySummary` (`22`:25554) or is a G-row (§11); key ids appear only masked, `...` plus four characters (`22`:25554's `key_id_masked`), never an API secret, a signature, a session token, an allowlisted address or an evidence link's query.
5. **The gate (B17).** Three states, `locked`, `eligible` and `enabled` (`28`:7323–7330). Enabling needs the Owner, a fresh elevation and evidence still valid (INV-B17-b, `28`:7362); an invalidated item demotes the gate at once (INV-B17-c, `28`:7363); **`EMERGENCY_DISABLE` needs no elevation and always succeeds** (INV-B17-d, `28`:7364); every enable, denial and turn-off is audited with the actor and the evidence set (INV-B17-e, `28`:7365), the enablement as high severity (`11`:5010). **The gate rows are B17's four evidence keys** (`28`:7206–7211): `pentest_passed`, `key_audit_passed`, `env_separation_verified` and `runbooks_signed`. `07` §6's four items (`07`:164) are their PRR mapping: the pen-test (`07`:168), the key-permission audit (`07`:169), the kill-switch test (`07`:170) and the Owner's written sign-off (`07`:171); two pairs differ by name, and A-7 asks to align them.
6. **Step-up per D8 (ruled).** D8 is ruled for per-action step-up (`14`:43, :3069; `15`:990): entering SCR-137 asks for nothing, and there is no entry gate, no admin window and no countdown. The threat model's D8 and SR-E42-12 still read open (`TM`:749, `TM`:1045); that reading is stale (C-2). **The enable press is D8-invariant**: it always asks a fresh code, because writing `true` to `trading.live_enabled` needs `live_enablement` whatever is stored, no-grace and single use (`22`:12535). Copy says "Confirm it's you", never "step-up" or "re-authentication" (`E42D02`:58).
7. **T2** (`E09D09`:49; `14`:85): a control the session may not use is disabled with a visible reason, programmatically associated (CMP-079, `15`:893). Reasons are E09-D09 §3.1's keys, verbatim (`E09D09`:83); a new reason is a PROPOSED key with its owner named. Each T2 control keeps its native role and full label, and its state row names its rendering (G-T2.1c): 2a, the reason inline, the label led by the CMP-019 `lock` glyph ("Not available"; G-T2.1d); 2b, the CMP-016 Tooltip echo, for icon-only controls, the `lock` the badge on the icon; or the sentence form, where there is no control and no `lock`. G-T2.1b, verbatim (`DS`:28–29): `aria-disabled="true"`, never the `disabled` attribute — it stays in the Tab order and a menu item stays arrow-reachable. G-T2.2, verbatim (`DS`:40–42): hi-fi label `color.text.tertiary`, reason `color.text.secondary`; for primary / buy / sell actions the fill becomes `color.surface.raised` with a `color.border.default` hairline; never `color.text.disabled`, never `opacity.disabled` on the label, glyph or reason (the label pair is §10.1 P-03). G-T2.3, verbatim (`DS`:47–48): `Enter`, `Space` or a bound hotkey on a T2 control changes nothing and re-shows the reason inline with one polite announcement.
8. **The ladder.** AD-11 (`E42D02`:56) and D3's one anatomy per rung (`E42D02`:129): enabling live is **rung 4** (`live_enablement`, no grace) with a typed token; dismissing a finding and recording gate evidence are **rung 1**; turning live off is B17's `EMERGENCY_DISABLE`, never gated and on no rung: CMP-044 `standard`, no word, no code, no hold, with CMP-093's audit marker (INV-B17-e; C-6). ### 5.2 The finding anatomy (AC-2)

A list (`<ul>`), one item per finding, most severe first; each item is a CMP-050 card whose heading (`h3`) reads the severity word, the category and the object: "Critical: Withdrawal permission detected — key ...a1B2 on sub_001".

- **Severity:** the word first, then the glyph, CMP-178's shapes: Critical and Error the octagon, Warning the triangle, Info the ring. Greyscale reads the same: word, shape, then tone.
- **Risk:** one plain sentence, e.g. "This key holds a permission that can move funds off the exchange; it must not (C-2.8)."
- **Evidence line:** "Last evaluated 14:02 UTC · Source: key verification".
- **Actions:** the remediation button, then **Dismiss…** (rung 1), each with D5's marker where audited (`E42D02`:131).
- **The heading line** of the section counts by severity, words only: "Findings: 1 critical, 2 errors, 3 warnings" (`14`:2872).

## 9. Accessibility (`05`)

- **Headings and landmarks:** one `h1`; the three `h2`s in the ticket's order; each finding an `h3`; the skip link "Skip to live gate" in the top-of-page skip-link set; the gate a named region.
- **Focus order (R3):** the skip links → header (Scan now) → Posture (its remediation links, Acknowledge…) → Findings (per card: remediation, Dismiss…) → the gate (Turn off when shown, the rows' Record… and review buttons, then Enable). Tables are static: `Tab` moves between controls; no arrow grid.
- **T2:** every T2 control keeps its role and label, `aria-disabled="true"`, and points by `aria-describedby` at its reason node, mounted with it; Enable also points at the status line and the table caption (§6.3).
- **Dialogs:** each traps focus, is labelled by its title, starts on Cancel (the typed and reason fields are the next stop), and returns focus to the control that opened it; `Enter` in a typed or reason field never confirms; `Esc` is Cancel. SCR-006's success returns focus to the gate's status line.
- **Announcements:** scan start and finish, a dismissal, and turning off, polite and once; an invalidation, `role="alert"` once; the age texts never live; no per-check live region.
- **Text resize (R1):** at 200 % zoom and the 150 % text scale, at 1280 × 800, the posture and gate tables reflow to stacked rows (label over value, CMP-036 `stacked`), the dialogs fill the viewport with the body scrolling between fixed header and footer, and the popover's reason wraps under the action.
- **Forced colours (R2):** severity and result keep their word and glyph shape (system `CanvasText`); the attested and machine-checked tags keep their outline style (dashed vs solid, `ButtonText`); the T2 `lock` stays a glyph with its name; the CMP-028 tones keep their glyph and title.
- **Motion:** none added; dialogs per CMP-043; state changes are cuts; severity escalation never animates; `prefers-reduced-motion` changes nothing because nothing moves (the busy indicator is a static glyph under reduced motion).
- **Greyscale:** every carrier is a word first, then a shape, then a tone (§5.2, §6.2).
