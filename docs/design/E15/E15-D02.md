## 1. Purpose, scope and method

### 1.1 What this spec fixes

The structure of the whole E15 surface as one model, in greyscale, before any hi-fi: the chrome budget (§3); the layout tree that design, FE and the contract share (§4); every screen of the ticket at both reference widths with its states (§5, §6); the docking and keyboard-move storyboards with the pointer and keyboard parity audit (§5.3, §5.4); the sync model (§5.8); the save, preset, conflict and restore rules (§5.1, §5.6, §5.7); the layout hotkey map against the global table (§7); the structural accessibility contract (§8); and what each consumer takes (§18). It does not decide colour, type, elevation, iconography or final spacing (E15-D03..D12), motion timing (E15-D14), hosted panel internals (their own epics), the design-system components themselves (E15-D13) or the Electron window implementation (E15-S02, E10).

### 1.2 Method (honest)

Desk design under the agent-delivery adaptation: no participant, no session, no prototype run, no owner walkthrough yet. The contract, the keymap and the merged specs were read at the `main` sha above; the keymap lint was run on copies with the proposed rows (§7); the trees of §4 were checked against `22` `LayoutGridSpec`'s documented rules by a scratch script (not the server validator). Competitor patterns come from E15-D01 §10 and its review record (PR #4079 comment 6335301876, a web check of 2026-10-22); the delivery network refused the vendor pages again on 2026-10-22, so nothing was re-read. The ticket's validation round becomes the protocol of §16, ready for the owner to run; its 5-of-6 sync bar is a pre-registered rule, not a result.

### 1.3 Locked inputs (built on, not re-decided)

- **AM-1, ruled:** five dock zones; float becomes a desktop command ("Pop out" in the panel menu, re-docked by the window's button, CMP-215), never a sixth drop target; the browser hides float with an explanation instead of a maximised overlay; hide = minimise to a tab; drag docking is demoted while the mandatory keyboard move mode (CMP-214) stays the protected path (WCAG 2.1.1, 2.5.7). OQ-3 is closed; the other E15-D01 questions keep their defaults until the owner's sessions.
- **E15-D01's locked list:** no function by hover or drag alone (`05` §3.1 item 6); the native stop-loss and server-side RBAC and risk are untouched by any layout choice (C-2.6, C-2.12, C-12.4); the DEMO/LIVE badge is never hideable, in the shell or any floating window; a chart is an opaque rectangle; layout events are analytics, never audit; a Viewer cannot save workspaces or layouts (`21` §10.1, owner decision #1778); `Esc` and `Ctrl+K` are reserved (`05` §3.3 item 3); exports carry no credentials or account bindings (US-LAY-007).
- **The shell (E10-D02, SCR-010):** TopBar 48 px with the ENV badge, NavRail 240 px expanded or 64 collapsed, RightRail 240 px, StatusBar 48 px repeating the ENV badge, the SCR-153 banner below TopBar; E10-D02's SCR-011 and SCR-027 text. Its PNGs are not an anatomy reference: most are blank fills.
- **Chart chrome (E11-D02 §2, §8):** the CMP-221 toolbar row, the status row that carries the env badge, the time strip, 24 px compact and 32 px comfortable each; splitters with a 24 px hit band; `Shift` coarse steps.
- **The reason vocabulary (E09-D09 §3, `14` §0.5 rule 5):** a control the session may not use is disabled with a visible reason, never hidden (except `/admin/*`); for workspaces the reason is "Your role can't save workspaces."
- **The contract:** `22` `listWorkspaces`, `createWorkspace`, `getWorkspace`, `updateWorkspace`, `deleteWorkspace`, `listLayouts`, `createLayout`, `getLayout`, `updateLayout`, `deleteLayout`, `listLayoutPresets`, `exportWorkspace` (specified, not served: `openapi_pending`); the schemas `WorkspaceInput`, `LayoutInput`, `LayoutGridSpec`, `LayoutGridPreset`, `PaneKind`, `PaneConfig`, `WorkspaceBundle`; `21` §3.8.1.
- **The keys:** `apps/web/src/keymap/keymap.json` (71 commands, the single source of default hotkeys) and `apps/web/src/keymap/reserved-keys.json` (27 entries).

## 8. The structural accessibility contract (`05` §3, §6.2, §7; WCAG 2.2 AA)

- **Regions and names.** Each panel is a `role="region"` named by kind, symbol and interval ("Chart, BTCUSDT 1m"), described by its sync state and environment; the tab strip is a manual-activation `tablist`, the rail a `tree`, the minimised tray a `toolbar`, a dock tab group a `tablist` with automatic activation, the move-mode bar a `status`.
- **Order.** The region ring (`Ctrl+\`, and `F6` in the desktop app) runs TopBar, NavRail, tab strip, the panels in reading order, the minimised tray, RightRail, StatusBar (E10-D02's landmark order with the workspace inside). After any move the DOM order is rebuilt to the visual order, because CMP-081's `aria-owns` fallback does not change the Tab order. The rebuild moves nodes and never remounts a panel: each pane renders once into a persistent host element that the dock moves between slots as a DOM node (`Element.moveBefore` in current Chromium keeps focus and state; `insertBefore` otherwise, focus restored after it), so React keeps the instance, the canvas and its WebGL context (§10 item 2); where a move cannot keep the node, the DOM order stays stable and a roving `tabindex` with `aria-owns` gives the reading order instead (E15-T02). Inside a panel, Tab follows the header, then the body, then the splitter that follows it.
- **Focus.** Never moved by a sync change, a restore, a crash notice or a background event (`05` §3.4 item 3). A dialog returns focus to its trigger. After a drop focus stays on the moved panel's header; after a close it goes to the panel that took the space, announced. The focused panel is marked by weight and a bar, never by hue (AD-7); controls carry the 2 px ring.
- **Announcements**, polite and once per committed change unless marked:

| Event                                    | Politeness | Text                                                                                           |
| ---------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------- |
| Layout switched or preset applied        | polite     | "Layout changed to Order-flow, 4 panels." (CMP-081's "Layout changed to 2 by 2")               |
| A move dropped, or undone                | polite     | "Positions moved below Chart." / "Move undone."                                                |
| Move mode entered, each step, cancelled  | polite     | "Move mode. Positions. Choose a panel." / "Below Chart." / "Move cancelled. Layout unchanged." |
| Panel added, closed, minimised, restored | polite     | "CVD added to the right of Chart." / "Tape closed." / "Tape minimised."                        |
| Sync membership changed                  | polite     | "Chart 15m joined sync group A." / "… left sync group A. It keeps BTCUSDT 15m."                |
| Symbol set by sync on an order panel     | polite     | "DOM now shows ETHUSDT, set by sync group A."                                                  |
| An armed panel disarmed by sync          | assertive  | "{Kind} disarmed: sync group A changed its symbol to ETHUSDT. Arm again to trade ETHUSDT."     |
| An armed panel entering the compact view | polite     | "{Kind} disarmed: panel too small to trade. Maximise to trade."                                |
| Restore at launch; partial restore       | polite     | "Restored your layout from 14:02. Not saved." / "1 panel couldn't load: Chart, ABCUSDT."       |
| Splitter at its minimum                  | polite     | "Minimum size."                                                                                |

- **Targets** are at least 24×24 px in compact (`05` §3.4 item 7): header buttons, tray tabs, the splitter's 24 px hit band.
- **Colour is never the signal:** sync by letter and words, environment by word and shape, focus by weight and bar, an invalid zone by hatch and words, an active tab by weight and underline.
- **Reduced motion:** the ghost, the zones and the tray appear and leave without animation; no state is carried by motion (timings are E15-D14's).
- **Zoom:** at 125 % OS scaling a 1280×800 screen is 1024×640 CSS px, so the tabbed collapse applies (§5.15, OQ-12's default). At 150 % a 1920×1080 screen is 1280×720 CSS px: wide enough for the arrangement and 80 px short of 800, so the short-window rule applies (§5.15, OQ-T).

## 10. Structure that protects performance (ticket Performance notes)

1. **Lazy mount:** the loading and skeleton frames show frames, never data; a panel mounts on first visibility, a hidden dock tab when shown, and hidden tabs and panels behind a maximise unsubscribe after 30 s (SCR-020).
2. **Re-parenting, never re-creation:** every tree operation of §4 moves the existing panel instance, so a layout change never remounts a WebGL context; the focus-order rebuild of §8 is the same node move, never a React remount; a preset reuses panels by kind (SCR-022's ≤300 ms rebuild); maximise and the narrow-window collapse are display transforms of the same tree.
3. **The ghost is one translucent rectangle drawn with transforms,** never a live panel, and a drop commits exactly one mutation (SCR-021).
4. **The measured-cost confirm and the 16-panel cap** keep a layout inside the budgets of US-LAY-001 (four order-flow panes) and US-LAY-002 (a four-panel restore); the values themselves live only in `CONSTITUTION.md` §14 (C-14.2), and the per-kind cost model is E15-K01's.
5. **Floating windows** each own a renderer and GL context; the fifth GPU-heavy window asks first (SCR-027, SCR-046).
