## Decisions at a glance

Plain statements of the six heuristic decisions; evidence in §Findings, paste-ready form in the protocol §10, owner calls in §Open questions. Board 3 carries this list.

1. **D1 Pan/zoom:** the wheel zooms time around the bar under the pointer; Shift+wheel pans; one modifier+wheel zooms price (Alt proposed, Ctrl if trackpad handling proves clean — owner call O3); double-click resets the axis you click; no drag-region zoom in v1.
2. **D2 Autoscale:** dragging the price axis switches autoscale off and shows a text badge "Price scale locked" that is itself the way back — never silently, never a prompt, never a hidden preference; the lock is forgotten on reload.
3. **D3 Crosshair:** the readout crosshair snaps to the bar horizontally and is free vertically by default; snapping to open/high/low/close is an option; the drawing magnet is a separate E14 decision.
4. **D4 Keyboard:** arrow keys move a data cursor, not the view; the view follows when the cursor reaches an edge; the vocabulary is bar, price level, extreme, page; End returns to live.
5. **D5 Data table:** a working surface, not a read-only copy: bar rows that expand to price levels, actions on every row, seven primary columns that fit at 200 % zoom, the rest one click away.
6. **D6 Aggregation:** a text chip states that columns merge bars, the ratio, what stays exact and how to get back, whenever more than one bar shares a column; it is never worded as a confidence or staleness claim.

Owner calls with dates: O2 prototypes (2026-10-22), O3 price-zoom modifier and its slip guard (2026-10-22), O4 footprint readout unit (2026-10-20), O5 column volume, L1 wicks and cause-neutral chip copy (2026-11-06).

## Method note

- **Frame:** Nielsen's 10 plus the trading-specific heuristics in `05` — keyboard-first as speed (§1), single hotkey layer (§3.1), no hover-/drag-only interaction (§3.1 item 6), colour never alone (§4), equal-status canvas alternatives (§6), reduced motion (§7).
- **Evidence, cited per finding:** (a) plan text (`26` §3.11/§12, `05`, `11`, `14`, `15`, `E11.json`, the shipped `apps/web/src/keymap/keymap.json`, `docs/generated/default-keymap.md`); (b) corpus 01, 02, 04, 05, 07, 09, 20 and `docs/research/findings/E12-bar-modes.md`; (c) public pages opened 2026-10-19 (TradingView, Lightweight Charts, DeepCharts, Bookmap, W3C, MDN, Highcharts, accessible-chart literature), cited by URL at first use; (d) the prior draft (branch `design/e11-d01-chart-nav-research`, 2026-10-14), reused only where re-verified — the list of its claims retired by the audit is in the PR description, not here.
- **State of the product:** no chart UI is shipped (`packages/chart-engine/src` is scaffold; no chart feature in `apps/web/src/features`), so every CandleViewer statement is about _planned_ behaviour; shipped are the keymap — one chart-navigation binding, `chart.zoom_price` = Shift+wheel; the other nine Chart-context bindings are footprint, interval, order and drawing commands (`default-keymap.md` Chart rows) — and the SCR-117 accessibility settings screen. **No interactive surface exists:** the E06 spike is a throwaway Node bench scene with modelled GPU cost and no GPU context (`docs/plan/spikes/E06-K02.md` summary and "Why modelled GPU cost"; `packages/chart-engine/bench/scenes/README.md`; its only "wheel" is a scripted sweep in `bench/driver.mjs`), no wheel or pointer handler exists in `packages/chart-engine` or `apps/web/src`, and E06-T01 #220 / E06-T02 #221 are open. ## Findings: navigation, scale and crosshair (Q1–Q3)

### Q1 — Pan/zoom gesture bindings and muscle memory (→ E11-S04; decision D1)

**Planned.** `26` §3.11 gesture table: drag plot = pan time (and price if unlocked) with momentum; wheel = zoom time at cursor; `Shift+wheel` = horizontal
pan; `Ctrl+wheel` = zoom price; double-click price axis = auto, plot = auto-scale + latest bar; pinch (touch/trackpad) = zoom at centroid; §3.5
cursor-anchored zoom, τ = 120 ms; §12 reduced motion disables momentum. E11-S04 Scope repeats the table (+ `Ctrl+Home` reset, `+/-` zoom about the cursor
bar, `Space` pan-drag modifier, kinetic scroll on touch). Against it: SCR-030 Interactions "`Shift+wheel` = zoom price", the shipped keymap
`chart.zoom_price` = `Shift+wheel` (`apps/web/src/keymap/keymap.json`; `docs/generated/default-keymap.md`), and US-CHART-006 "Pan and zoom" ("When I drag
horizontally or scroll" / "Then the view pans/zooms") with the wheel undefined — #239's "highest-cost" ambiguity. No plan source gives CandleViewer a
drag-region zoom.

**Reference products.** TV Advanced Charts Shortcuts (https://www.tradingview.com/charting-library-docs/latest/configuration/Shortcuts/): "Move chart to the
left/right = Shift + Mouse wheel", "Zoom in focused area = Ctrl + Mouse wheel", "Zoom in / Zoom out = Ctrl + ↑ / ↓", Alt+G go to date, Alt+R reset chart,
Alt+Z "Start keyboard navigation", **no unmodified-wheel row**; the Supercharts list (URL in §Method) has the same two wheel rows ("Focused zoom" = Ctrl +
wheel) and no plain wheel; neither page names the axis a focused zoom acts on. TV Featuresets (https://www.tradingview.com/charting-library-docs/latest/customization/Featuresets/
— Advanced Charts library defaults): `mouse_wheel_scale` "series scaling with a mouse wheel" on (axis unstated), `mouse_wheel_scroll` "a horizontal mouse
wheel" on, `right_bar_stays_on_scroll` on — "the bar under the mouse cursor stays in the same place if this feature is disabled"; that the right edge stays
put when it is enabled is this report's inference. Third-party pages split on tradingview.com's plain wheel: one says it pans and `Ctrl+wheel` "zooms toward
the cursor position" (https://www.financialtechwiz.com/post/how-to-zoom-out-on-tradingview/); corpus 01 §6.4 (TradingCode.net) lists "Zoom in: scroll up /
Zoom out: scroll down" — low either way. DeepCharts: "Scroll mouse wheel anywhere on the chart: Zooms X-axis (time scale)", "Hold Alt + scroll mouse wheel:
Zooms Y-axis", "use an external mouse instead of a trackpad" (https://helpdesk.deepcharts.com/portal/en/kb/articles/chart-zoom-in-and-out-not-working); its
price-chart page says the cogwheel _shifts_ the X-axis, double-click returns to the latest bar, and lists "Zoom Range" (click the start, click the end),
"Zoom Out" (reset) and "Hand" tools — inconsistent on the wheel, low (https://helpdesk.deepcharts.com/portal/en/kb/articles/price-chart). Bookmap
(https://bookmap.com/knowledgebase/docs/KB-SettingUpAndOperating-HeatmapSupportingFeatures): "Scroll using the mouse wheel over the heatmap or price axis"
(no axis named); in Drag Mode the wheel zoom keeps "the chart centered on the cursor location"; "Zoom by Drag" with `Ctrl+Z` to zoom back out. LWC:
double-click resets the time and price axes by default (https://tradingview.github.io/lightweight-charts/docs/api/interfaces/AxisDoubleClickOptions).

**Findings.**

- (heuristic, medium) Wheel = zoom time is the plan (`26` §3.11, E11-S04 Scope), supported by DeepCharts' chart-zoom page and one third-party TV row; Bookmap's wheel zooms but names no axis; the TV library featureset does not say which axis it scales; "scroll" appears on DeepCharts' price-chart page and the other third-party TV page. Keep zoom as the default; the owner's habit is untested until T1.
- (heuristic, high — contradiction verified in each source) **Contradiction Q1-a.** `Shift+wheel`: TV and `26`/E11-S04 = pan; SCR-030 and the keymap = zoom price. A trader trained on TradingView presses `Shift+wheel` to pan. Under SCR-030 and the keymap that zooms the price axis, which silently rescales it and (Q2) locks it — Nielsen #4, #5. Pan is supported by TV only, so the recommended side is medium. The keymap change belongs to E11-S04 #385 (with the regenerated `default-keymap.md`), not to a design ticket.
- (heuristic, medium) **Contradiction Q1-b — modifier.** `Ctrl+wheel` = zoom price (`26` §3.11) collides with trackpad zoom: "Zooming actions using the wheel or trackpad also fire wheel events (with ctrlKey set to true)" (https://developer.mozilla.org/en-US/docs/Web/API/Element/wheel_event; "pinch" is this report's reading of that sentence), so E11-S04 must disambiguate and `preventDefault()` page zoom; and with TV habit, whose `Ctrl+wheel` is a focused zoom (axis not documented; "time" is an inference, low). CMP-189 A11y's "`Ctrl+scroll` equivalent via keyboard modifiers" is a third, ambiguously worded `Ctrl+wheel` meaning. `Alt+wheel` is DeepCharts' price-zoom precedent and free in the keymap. **Slip risk:** `Alt+click` is the arm-gated market order (SCR-030 Interactions; keymap); a held `Alt` followed by a click while chart trading is armed is a Nielsen #5 hazard on a surface that moves money — the owner picks a guard in O3 (price-zoom wheel only while the pointer is over the price axis, or ignore a click within ~300 ms of an `Alt+wheel`); T1 observes "Alt held, then click, armed". Two chart-trading modifier sets exist — SCR-030 Interactions / keymap (`Ctrl+drag` axis = limit, `Alt+click` = market, arm-gated) vs `13` §6 / `17` §7 (`Ctrl+Click` = market, `Shift+Click` = limit); keymap and SCR-030 are the tie-break, the `13`/`17` split goes to E11-D07.
- (heuristic, medium) **Contradiction Q1-e — zoom anchor.** `26` §3.5 and E11-S04 (cursor-anchored) vs the TV Advanced Charts library default `right_bar_stays_on_scroll` (right edge stays put — inferred from the featureset text); Bookmap, in Drag Mode, keeps the chart centred on the cursor (low; centring, not an anchor statement). Keep the cursor anchor — the plan, and the only anchor that works on a bar in mid-history; T1 records which bar stayed put and, on the participant's own TV, which bar stays put and what `Ctrl+wheel` moves; right-edge-while-live is the alternative.
- (heuristic, medium) **Q1-d — double-click.** Plot = back to live (`26` §3.11) matches TV Alt+R and DeepCharts; SCR-030 and US-CHART-006 name only the axis; the time axis is undefined in the plan — LWC resets it on double-click by default (URL above) and corpus 01 §6.4 "reset bar spacing" (third-party) agrees.
- (heuristic, medium) **Gap Q1-g — region zoom.** All three reference products have a drag-region zoom (TV "Zoom-in cursor", corpus 01 §2.10; DeepCharts "Zoom Range"; Bookmap "Zoom by Drag" + `Ctrl+Z`); `26` §3.11 and E11-S04 have none, and one would need a keyboard equivalent (`05` §3.1 item 6). Recommend **not in v1** — wheel plus `+/-` cover the need — recorded for E11-S04/E11-D02 as a deliberate omission; T1 watches for a drag that expects a zoom.
- (heuristic, medium) **Contradiction Q1-c.** Reduced-motion precedence: `16` §4 (in-app override wins both ways) vs E11-S04 Scope (any "reduce" wins). Momentum feel, τ and this rule → E11-D06 (Sprint 04).
- (heuristic, high — plan sources checked directly) **Contradiction Q1-f — no interactive build.** #239 Technical notes (E06 spike build, real inertia), E11-D06 Context and AC/DoD (tested "against the E06 build on the reference machine with the owner"), E11-D02 Test plan ("Prototype review against the E06 spike build") and E11-D07 Test plan (a screen-reader "prototype walkthrough") vs `docs/plan/spikes/E06-K02.md`: a Node bench scene, modelled GPU cost, no GPU context, no pointer input. One throwaway prototype would serve four tickets — owner decision O2; E11-D06 proceeds on τ = 120 ms (`26` §3.5), deferral recorded.
- (heuristic, high — plan sources checked directly) Keyboard equivalents (US-CHART-006 NFR) carry four arrow semantics (`05` §3.1 item 7 vs §3.2 Chart rows; `26` §3.11; SCR-030 A11y; CMP-189) → Q4. Go-to-date (SCR-044) has no hotkey; TV's Alt+G is already Rules "Switch to graph mode" (`default-keymap.md`) → E11-D03 picks a free chord via the registry check (`05` §3.1).

### Q2 — Autoscale when the price axis is dragged (→ E11-S05, US-CHART-006 lock badge; decision D2)

**Planned.** US-CHART-006 "Manual lock" scenario (`11`, Must): "Given I drag the price axis Then autoscale disengages, a lock badge appears, and
double-clicking the axis restores auto-fit". E11-S05 Scope: `lock` orthogonal to mode, "a lock badge appears on the axis", only the _mode_ persisted; its AC
gives the badge the accessible name "Price scale locked"; E11-D03 AC requires "a text label, not an icon alone" and designs the badge. SCR-043 (`14`): the
Type line lists auto / log / percent / indexed, invert, **lock**, merge, reset without defining lock; the A11y line says "Lock to bar". `26` §3.5 defines no
disengage rule or state ("unlocked", "resets to auto" in §3.11); `viewportChanged` (§8) omits lock. CMP-188 A11y / E11-S06 keyboard rescale (Up/Down; Home
restores) — badge engagement unstated. SCR-030's time-axis strip draws "[ auto | fit | > ]", which E11-D02 Scope calls "the auto/fit control cluster"; the
strip's three controls are not mapped to behaviours anywhere (SCR-043 lists a time-scale "auto-fit" item and US-CHART-001 says "zoom to fit", neither tied
to the strip).

**Reference products.** TV "How to enable Autoscale": "enable the Auto button located on the price scale", nothing on when Auto turns off
(https://www.tradingview.com/support/solutions/43000762826-how-to-enable-autoscale/); Supercharts settings: "Reset price scale … turns on the Auto mode", a
separate "price to bar ratio lock" (https://www.tradingview.com/support/solutions/43000748166-how-to-configure-your-supercharts/); the Advanced Charts
price-scale page offers "Reset price scale" only "when it is in a non-default state" (https://www.tradingview.com/charting-library-docs/latest/ui_elements/Price-Scale/).
LWC: `autoScale` default true, silent on drag (https://tradingview.github.io/lightweight-charts/docs/api/interfaces/PriceScaleOptions); on issue #1759 a
contributor calls keeping the manual range "the expected behaviour", restore by API — silent disengagement, and a confused user filed the issue
(https://github.com/tradingview/lightweight-charts/issues/1759). Bookmap documents the one setting-based answer: "'Recenter in Drag Mode' Checkbox —
Enabled: Retains the selected re-centering preference during dragging. Disabled: Switches to the 'None' setting, enabling manual vertical adjustments"
(URL above) — a silent, badge-less disengage controlled by a preference; DeepCharts Y-axis "Auto Scroll" and Bookmap re-centring are _follow_ models, not
_fit_. Corpus 01 §4: TV auto vs lock, nothing on drag, no badge.

**Findings.**

- (heuristic, high) Disengage **with a badge** is the only option meeting Nielsen #1 and #3: silent is LWC's default and produced #1759; "ask" would interrupt a drag mid-gesture and no reviewed product documents it; Bookmap's preference neither supports nor contradicts the badge — it hides the state behind a setting, which is why a setting is not the primary answer (Could, E11-D03, only if T2 shows demand). The Must story already says so.
- (heuristic, medium) Make the badge the _restore control_: focusable, Enter/Space restores — a keyboard path beside E11-S06's `Home`, as `05` §3.1 item 6 (no drag-only interaction) requires, with no extra UI. (Inference: TV's Auto button doubles as indicator and switch; its page documents only "enable".)
