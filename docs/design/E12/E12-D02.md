## 2. SCR-030 anatomy: what stays mounted

```text

| [BTCUSDT v] [Vol 50 BTC v] [Candles|Bars|Hollow|Line|Area|Baseline|HA] [FP] [...]  | toolbar CMP-221
| DEMO  last <price>   bar close 0:41   (non-time: Vol 37 / 50 BTC)                 | header row

| legend CMP-199                                                                      |
|      :                                                                    |forming|  |
|  (B) : "Recorded prints from 2026-10-18 08:00 UTC"     price area         | bar   |y |
|      :                                                                    | (F)   |  |
| (K) Loading older bars...                                                           |
| [Bar order · not time] [Aggregated · about 8 bars per pixel] <open times> [auto|fit]| time axis CMP-189
+------------------------------------------------------------------------------------+
```

The toolbar, both axes, the drawings layer and the trading-overlay layer stay mounted through every E12 state;
only the series data swaps, in one frame (`setData`, 26 §9). Values in every sketch are illustrative. This is a
requirement for engineering (E12-S11), not an aesthetic: it is what makes ≤200 ms possible and what prevents the
flash of an empty chart. The strip (S) is a reserved row of fixed height in the header band, empty when idle: a
message never moves the legend or the plot, and no price content, order line, position line or label is drawn under
it. It costs one text row of plot height, accepted over a legend that jumps or an auto-scaled high or stop-loss line
hidden during a build. Drawings keep their timestamps on every axis (E14 owns the mechanics). On a non-time axis open
times repeat (one print can close several bars), so a drawing anchored at time t lands on the first bar whose open
time is at or after t, equal open times share one axis label, and the data cursor names the bar's position ("brick
3 of 5 opened 10:22:11.412"). Indicator overlays re-prime on the new series (23 §6.1) and are E13's state. Order and
position lines belong to another epic, stay live through every E12 state and are never shed (06 §4.4). No control
on any E12 surface places an order.

**Semantics (CMP-220 contract, E12-D01 §8).** The trigger is a menu button (`aria-haspopup="menu"`) named
"Interval: 15 minutes" or "Bar mode: Volume, 50 BTC per bar". The menu (`role="menu"`) holds three `role="group"`
sections separated by `role="separator"`: "Favourites", "Time", and "Bar modes: the x-axis is not time". Entries
are `menuitemradio` with `aria-checked` on the active one. A mode's one-line description (E12-D01 §3), its current
parameter and any "needs recorded prints" reason are its accessible description, never visual-only text. A menu
may hold only items, groups and separators, so each parameter editor is rendered inside the same popover but
outside the menu subtree: a `role="group"` named "Volume per bar" holding a `spinbutton` whose label carries the
unit ("Volume per bar, BTC") and whose message is linked by `aria-describedby` and `aria-invalid`.

**Keyboard path.** With the chart focused: `Alt+I` (new, OQ-4) or `Tab` to the toolbar, roving to the
interval button, `Enter`. In the menu: `↓`/`↑` move across all groups, `Home`/`End` jump, `1..9` choose a
favourite, `Enter`/`Space` commit an entry with its shown parameter, `→` opens the parameter editor (focus in the
field, value selected); `Esc` closes without change and returns focus to the trigger, and `Tab` closes without
change and moves on, as the ARIA menu pattern does. In the editor: type, or `↑`/`↓` to step, `PageUp`/`PageDown`
for ten steps; `Enter` commits mode and parameter and closes the menu; an invalid `Enter` keeps focus in the field
and announces the message once; `Esc` or `←` returns to the mode row. Committing returns focus to the trigger when
the menu was opened from it, and to the chart region when it was opened by hotkey (same rule as SCR-041, E12-S11);
never to the page body. A build that starts then follows D-11.

**Parameter fields.** Units from the 22 `/market/bars` table; bounds from `bars/limits.py` and `bars/spec.py`.
Defaults on first use are E12-D01 §3's designed values; afterwards the last value used for that mode.

| Mode   | Field label (API unit)                    | Bound the client checks                                                    | Message shown below the field                                            |
| ------ | ----------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Tick   | Trades per bar                            | 100 to 1 000 000                                                           | "Enter 100 to 1 000 000 trades."                                         |
| Volume | Volume per bar, in the base asset (`BTC`) | Whole numbers (shipped parser), at least the floor max(10 × `qty_step`, 1) | "Whole BTC only in this release; at least 1 BTC per bar."                |
| Range  | Range per bar, ticks                      | 2 to 100 000                                                               | "Enter 2 to 100 000 ticks."                                              |
| Delta  | Delta per bar (±), base asset (`BTC`)     | as Volume, on the absolute cumulative signed volume                        | "Whole BTC only in this release; at least 1 BTC of delta per bar."       |
| Renko  | Brick size, ticks                         | 2 to 100 000; `atr:` refused                                               | "ATR bricks are not available yet. Enter a brick size in ticks."         |
| Custom | Interval, number plus `s`/`m`/`h`/`d`/`w` | the served ladder until OQ-1                                               | "Use a number and a unit: s, m, h, d or w." / "7m is not available yet." |

The volume and delta floor renders per symbol from the instrument catalogue's `qty_step` (BTCUSDT: 1 BTC while only
whole numbers parse); once OQ-9 admits fractions, the visible floor becomes 10 × `qty_step` (0.01 BTC), the
server's own bound. The estimate line under the message names the build window and its size before commit (D-13).

**Favourites.** The default ladder is time-only and ascending so a higher digit means a longer bar: `1` 1m, `2` 3m,
`3` 5m, `4` 15m, `5` 30m, `6` 1h, `7` 4h, `8` 12h, `9` 1D (proposed, confirm in E12-D04; 1W waits on G-1a). Any
slot may hold a non-time entry such as `volume:50`, because `PaneIntervalCode` spells every bar type. The editor:
`↑`/`↓` move between slots, `Enter` assigns from the menu groups, `Alt+↑`/`Alt+↓` reorder (inside the editor
only), `Del` clears, "Add current" fills the focused slot; `Enter` saves and `Esc` discards.

**States.** Symbol with no recorded prints: non-time rows and (after OQ-1) sub-minute rows are disabled with "Needs
recorded prints: none yet". Shallow recording keeps them enabled and F-BAR-5 marks the boundary. Flags off: rows
absent, never offered and then failed (E12-S12).

**Keyboard path.** With the chart focused, the existing symbol-search key `/` (05 §3.2) opens SCR-041 for that
chart; the toolbar's symbol button opens it too. No new key is proposed (OQ-4). Focus lands in the input with the
current symbol selected. Typing filters and the result count is announced politely (debounced, CMP-048); `↓`/`↑`
move the active option; `Enter` commits the symbol and keeps the interval. To change both, `Tab` from the input to
the interval row (a radio group: `←`/`→`, `Home`/`End`), then `Enter` commits both; "More..." opens SCR-042 in
place; for the owner, `Record this symbol` follows the interval row in the `Tab` order. `Esc` restores the previous
symbol and interval. After a commit, focus returns to the chart region when the switcher was opened by hotkey
(E12-S11) and to the symbol button when opened from it; it never falls to the page body. Not-recorded symbols stay
selectable: live topics work for any symbol, and while auto-record is on, recording starts once the chart has been
open for the dwell (60 s by default; ADR-0015, 23 §12.6).
