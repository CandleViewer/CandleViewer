## 6. Precision and numbers on this tab (RULED BQ-9)

- **Display only** (R-5). Precision formats axis labels, pills and the tooltip (E11-D03:253); it never changes a stored or sent value: bars are integer ticks in the store (`26`:163); drawings and order prefill keep Decimal strings at tick precision (E14-D06:191). No `Number`, `toFixed` or float arithmetic touches a contract value (E08-D06:209).
- **Auto** = the instrument's tick decimals (`22`:17908, which `InstrumentDetail` extends at `22`:17935), shown in minimal exact form, "Auto (tick 0.1<!--=FIX:btc.tick-->)" for BTCUSDT's "0.10" (E08-D06:220). `price_scale` is never used (`22`:17909; E08-D06:222). A tick-size epoch change re-resolves Auto: an inference, since `14`:760 states only that the series restarts.
- More decimals than the tick: pad with zeros (E30-D02:201). Fewer decimals than the tick: round half-even in decimal arithmetic, display only — **PROPOSED**: the docs are silent for prices, and this borrows E08-D06's statistics rule (E08-D06:230–231).
- **Heikin-Ashi values** are off the tick grid (D06:169): shown at display precision, labelled "(derived)" in the mirror (D06:353), never offered as an order or drawing anchor (D06:120).
- **Parameters** are whole trades, ticks or base units (D03:58), so precision never applies to them.
- **Mirror and SCR-045** use the panel's display precision, so the two agree (`05`:233 asks parity between the DOM mirror and View as table) — **PROPOSED**: the docs are silent.
