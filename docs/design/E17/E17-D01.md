## 1. Purpose and scope

Fix the **vocabulary, thresholds, per-panel treatment, order-entry gating and announcement policy** for the six
feed states, so that E17-D02 (SCR-152 connection-state components, #325) can wireframe them without
re-deciding. Out of scope, per ticket: any visual design (greyscale wireframes begin in E17-D02), the recorder
"history starts at" state (E16) and the ingestion-lag half of CMP-092 (E04).

The safety framing is `CONSTITUTION` C-2.12 (server-side authority; UI renders server truth) and C-2.21 (statecharts
record, synchronous code enforces): **the UI treatment informs the trader, the server/OMS enforces**. Every
order-entry gate below is a UX mirror of a synchronous server check, never the only control. The stale-UI-mirror
threat is `docs/security/threat-models/E17-ws-gateway.md` WS-E06 and AC-26: the client treats a stale or
disconnected `system` stream as *unknown*, not as "not killed".

## 3. Findings (each cited; all heuristic)

| # | Finding | Source |
|---|---|---|
| F1 | The protocol has **three distinct non-live modes plus a read-only family**: stale (topic silent), degraded cadence (`connection_quality` `lagging`/`saturated`, data correct but less frequent), resync/disconnect. | `23-ws-protocol.md` §8.3, §7.4, §9.2, §4.4; ticket Context |
| F2 | Degraded cadence has **no data loss in final state** (coalescing keeps last-write-wins state; throttling "No loss of information"), but `trades`/`liquidations` are append-batched, `orders`/`executions` are never throttled. So "reduced rate" is honest and must **not** look like "broken". | `23-ws-protocol.md` §8.1, §8.2 |
| F3 | `saturated` additionally drops `heatmap`/`profile` to 1 000 ms and the frame names `degraded_topics`, so the treatment can be **per-panel, not global**. | `23-ws-protocol.md` §8.3 (`applied.degraded_topics`), §12.7 |
| F4 | `coalesced_count` is specified as the driver of a "feed compressed" indicator on the tape-speed widget; without it tape speed **silently under-reports** activity. | `23-ws-protocol.md` §8.2 last paragraph; `24-internal-schemas.md` (`tape_speed`) |
| F5 | **Threshold inconsistency.** The UI catalogue says stale after 2 s for every panel; the backend watchdog uses book 2 s, trades 10 s, ticker 5 s; `degraded_data` is "upstream stale beyond SLO". | F6 | **Order-entry rules conflict across docs.** SCR-152 says trading controls hard-disabled while offline; arch §6.3 says order entry is *allowed* when only the public WS is down (positions still need managing), and "allowed but forces REST confirm" when private WS is down; the E08-D03 `degraded` variant keeps trading enabled; WS §9.4 disables the ticket on `shutdown_notice`; kill-switch frame disables every order-entry affordance on the frame alone. | `14-screens-catalogue.md` SCR-152; `20-architecture.md` §6.3; `23-ws-protocol.md` §9.4, §12.5; E08-D03 §3 |
| F7 | `resync` is a **book-level** event that can happen on a healthy connection, and must not be a global banner (E08-D02 correction #2); resync reasons include `backpressure`, which is *caused* by degraded cadence. | F8 | Silence is read as "fine": desk evidence from E08's internal recognition work says a frozen panel is trusted until a secondary signal contradicts it, and hue-only dimming was misread as "live, quieter theme". | F9 | Reconnect cadence is mandated: 0.5 s, 1, 2, 5, 10, 30 s with full jitter; heartbeat 15 s client ping, 45 s timeout; close codes decide whether to retry (`1002/4400/4403` never). | F11 | Native exchange stops survive client/backend disconnect; emulated rules do not (they "can silently fail on stale snapshot"). ## 4. The six states, ranked

Severity rank 1 = worst. Precedence among states on the **same surface** keeps the E08 rule (one state per
surface, highest wins). Labels are proposed plain-English labels; the Owner has not confirmed them (§9).

| Rank | State | Label (chip) | Trigger (source signal) | Enter after | Exit after |
|---|---|---|---|---|---|
| 1 | **Disconnected** | "Disconnected" / "Reconnecting (3)" | transport closed or no traffic 45 s (§9.1); `bye`; `exchange_unavailable`; incl. `slow_consumer` 4429 close | immediate on close; or heartbeat timeout; or 2 missed pongs | `auth_ok` **and** private snapshots reconciled |
| 2 | **Read-only** | "Read-only — <reason>" | `shutdown_notice`; kill switch engaged; clock drift; viewer role; unknown `system` state; private feed down | immediate on frame | reason cleared + one fresh `system` snapshot |
| 3 | **Stale** | "Stale 7s" | per-topic age > threshold (T1 below) with transport up | threshold crossed | first fresh frame for that topic |
| 4 | **Resyncing** | "Resyncing book…" | `exchange_state: resyncing`; `snap` with `reason` ≠ `initial`; client `resync` sent | immediate | fresh `snap` applied **and** min display 1 s |
| 5 | **Delayed** | "Reduced rate ×4" (saturated) | `connection_quality` `saturated` (queue 60–90 % or RTT > 500 ms) | 2 consecutive classifications (≈4 s) | 2 consecutive `healthy` (≈4 s) and min display 5 s |
| 6 | **Live** | none (ambient) | none of the above | — | — |

`lagging` (queue 25–60 % / RTT 150–500 ms) is **not** a state: no chip, no announcement; it is shown only in the
connection chip tooltip ("Connection quality: fair"). Rationale: F2 (no loss) + F8 (false alarms teach the trader
to ignore chips). **Read-only ranks above Stale** because it blocks action regardless of data age; **Stale ranks
above Resyncing** because a silent topic's last value is more dangerous than a book being actively rebuilt.
Rank 4 vs 5 (resync vs delayed) is an ordering judgement to be validated in the owner walkthrough (§9.3 Q3).

### 4.1 Thresholds (T1–T5)

| ID | Threshold | Value | Rationale |
|---|---|---|---|
| T1 | Stale chip, per topic | book **2 s**, ticker **5 s**, trades **10 s**, private (orders/positions) **5 s**, `system` **15 s** | matches backend `STALENESS_S` (F5); trades use 10 s so quiet symbols do not false-alarm; `system` stale means kill-switch state is *unknown* (WS-E06) |
| T2 | Stale escalation ("Stale — do not trade on this price") | 3× T1, minimum 6 s for book | second, stronger step so a long freeze is more prominent than a short one |
| T3 | Delayed enter/exit | 2 consecutive classes (≈4 s) in, 2 healthy out, min display 5 s | classification runs every 2 s (§8.3); stops chip flapping and respects ≤3 flashes/s |
| T4 | Disconnected escalation | at 30 s, banner gains "Last data 00:30 ago" in warning→danger; at 5 min "escalated" (as E08-D03 `long-outage`) | long outages need a changed, not just longer, signal |
| T5 | Flap collapse | ≥3 state changes in 5 s → one "Connection unstable" announcement | already in E08-D01 §4 |

Hysteresis: all exits use the *exit* column of §4; entering is immediate for transport loss and Read-only (safety
direction), debounced for Delayed (information direction). Principle: **fast to warn about danger, slow to clear it.**

## 5. What each panel shows

Surfaces: chart (SCR-030), DOM/heatmap (SCR-050), tape (SCR-053), tape-speed widget, order ticket (SCR-060),
positions/orders grid (SCR-063), watchlist (SCR-100), global chrome (CMP-076 chip, SCR-152 banner).
Cell = authoritative treatment. "Last-good" = timestamp text always shown (F5, §0.5.4).

| State | Global chrome | Chart / DOM / heatmap | Tape + speed widget | Watchlist | Positions / orders |
|---|---|---|---|---|---|
| Live | chip "Live" (quiet) | none | none | none | none |
| Delayed | chip "Reduced rate ×4" (info colour + icon + text); **no banner** | only panels in `degraded_topics` (heatmap/profile): small corner tag "1 s refresh"; others unchanged | speed widget tag "Feed compressed ×N" from `coalesced_count`; tape rows still list every print | none | none (orders never throttled) |
| Stale | chip "Stale" with oldest-topic age | panel dim 15 % + chip "Stale 7s" + last-good time; value text kept | chip "Stale 12s" on tape header; speed widget shows "—" not 0 | row chip "Stale 4s" (E08-D02) | stale-priced P&L shown with "Mark 8s old" |
| Resyncing | chip unchanged unless >5 resyncs/60 s | ladder/heatmap scrim "Resyncing book…" (grid frozen underneath); chart price unaffected | gap marker persists after backfill (E08-D01 §4) | none | none |
| Read-only | banner "Order entry off — <reason>" (not alarming red unless disconnected) | data live, no dim | none | none | grid readable, action buttons disabled-with-reason (CMP-079) |
| Disconnected | banner (SCR-152) + chip; scrim on every public panel | frozen last-good + "Disconnected — last data 00:12" | frozen; speed widget "—" | all rows "Disconnected" (not per-row stale) | frozen + "Positions as of 00:12 ago — exchange stops still protect (native SL only)" |

The positions grid is **never hidden or blanked** (SCR-152 checklist). Resync does not stack with Stale/Disconnected
on the same surface (precedence).

## 6. Order entry by state

UX mirror of server enforcement (C-2.12/C-2.21). "New risk" = any order that can open or increase a position.
"Risk-reducing" = cancel, reduce-only close, flatten, kill switch, SL/TP edit that tightens.

| State | New risk | Risk-reducing | Notes |
|---|---|---|---|
| Live | enabled | enabled | — |
| Delayed | enabled; ticket shows "Prices may lag ~Xs" | enabled | orders/executions are not throttled (§8.1) |
| Stale (< T2) | market, one-click, chart-click orders **disabled** for the stale symbol; typed-price limit allowed with explicit confirm showing "price data 7s old" | enabled | blocks the "hit a price that no longer exists" failure (ticket Context) |
| Stale (≥ T2) | **all new-risk disabled** for the symbol, reason "Price feed stale 14s" | enabled | |
| Resyncing | DOM-click/ladder orders disabled while scrim shown; ticket orders allowed | enabled | the ladder is the unsafe surface |
| Read-only | **disabled**, reason shown | enabled unless reason is kill switch/shutdown (then follows server) | shutdown: whole ticket disabled incl. risk-reducing, per §9.4 double-send note |
| Disconnected | **disabled** | enabled **only if** a REST path is reachable, with a forced REST confirm read; otherwise disabled with "Cannot reach server" | see amendment A1 |

Disabled controls follow §0.5.5: disabled-with-reason, not hidden; refused attempts recorded as
`order.blocked_offline`.

## 7. Announcement policy

Matches `05-accessibility-standard.md` §6.2 and CMP-076; one live-region pair pre-rendered empty at load.

| Event | Region | When | Text pattern |
|---|---|---|---|
| Entering Disconnected / Read-only | `role="alert"` (assertive) | once on entry | "Disconnected. Trading is off. Exchange-side stop-losses still apply." |
| Entering Stale ≥ T2 | assertive | once per symbol per episode | "BTCUSDT price feed stale 14 seconds. New orders off." |
| Entering Stale < T2, Resyncing, Delayed | `role="status"` (polite) | once on entry, once on exit | "Heatmap refresh slowed to 1 second." |
| Reconnect attempt counter, countdown ticks, age counters | none | never re-announced | visual only; the countdown is not announced per tick |
| Recovery | polite | once | "Reconnected. 1 order filled while offline." (assertive only if an order state changed) |
| Flapping | polite | once | "Connection unstable." |

Rules: no state is conveyed by colour alone (icon + text + colour); no pulsing, blinking or looping animation
(state change is a single flip; ≤3 flashes/s, `prefers-reduced-motion` honoured; motion detail owned by E08-D11).
Stale-age text updates at ≤1 Hz visually and is not in a live region.

## 8. Decisions (adopted, each testable)

| ID | Decision (testable statement) | Finding(s) |
|---|---|---|
| D1 | A surface is in exactly one of the six states; a wireframe stacking two chips on one surface violates this. | F13 |
| D2 | Severity order is Disconnected > Read-only > Stale > Resyncing > Delayed > Live; the labels and chip text are those in §4. | F1, F6, F7 |
| D3 | Stale thresholds are per topic (T1) and escalate at 3× (T2); a wireframe using one blanket 2 s violates it. | F5 |
| D4 | **Degraded cadence is an in-panel tag plus a connection-chip state, never a banner and never a modal.** A banner for `saturated` violates D4. Banner is reserved for Disconnected and Read-only. | F2, F3, F14 |
| D5 | `coalesced_count` drives a visible "Feed compressed ×N" tag on the tape-speed widget; the widget must not show a plain trades/s number without it while coalescing is active. | F4 |
| D6 | Every non-live treatment carries text + icon + last-good time (or age); opacity alone never signals state. | F8, F12 |
| D7 | Stale price on the order's symbol disables market/one-click/chart-click entry (T1) and all new risk at T2; risk-reducing actions stay enabled. | F5, F6, F11 |
| D8 | Disconnected/Read-only disable new risk; the positions grid stays visible and readable; the native-SL reassurance is shown with "exchange stops only — rules paused". | F6, F11 |
| D9 | Announcements follow §7; countdowns and counters are never announced per tick. | F9, F12 |
| D10 | Warn fast, clear slow: entry/exit hysteresis per §4 and T3; no chip may flash >3/s. | F12, F7 |
| D11 | `system` stream stale ⇒ kill-switch and gating state shown as **unknown** ("Status unknown") and new risk disabled; never "not killed". | WS-E06 |

## 9. Amendment proposals, open items, validation plan

### 9.1 Amendment proposals (raised, not silently designed around)

- **A1 → `20-architecture.md` §6.3 + `14-screens-catalogue.md` SCR-152:** the docs disagree on order entry while
  offline (F6). Proposed single rule: new risk is disabled in every non-live transport state; risk-reducing actions
  remain available via REST with forced confirm. Owner/architect decision required (money-path).
- **A2 → `14-screens-catalogue.md` §0.5.4 / SCR-030:** replace "after 2 s without an expected update" with the
  per-topic T1 table (F5).
- **A3 → `23-ws-protocol.md` §10.3:** the "Transient, self-healing" row says `degraded_data` → badge + chip, no
  modal; add that `connection_quality: saturated` is a distinct fifth treatment (in-panel tag, no banner), and
  that `slow_consumer` is Capacity-class but presents as Disconnected with a reason.
- **A4 → `15-component-catalogue.md` CMP-076:** props `connected|reconnecting|degraded|offline` cannot express
  six states; E17-D02 to extend (Delayed, Stale, Resyncing, Read-only).
