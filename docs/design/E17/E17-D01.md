## 1. Purpose and scope

Fix the **vocabulary, thresholds, per-panel treatment, order-entry gating and announcement policy** for the six
feed states, so that E17-D02 (SCR-152 connection-state components, #325) can wireframe them without
re-deciding. Out of scope, per ticket: any visual design (greyscale wireframes begin in E17-D02), the recorder
"history starts at" state (E16) and the ingestion-lag half of CMP-092 (E04).

The safety framing is `CONSTITUTION` C-2.12 (server-side authority; UI renders server truth) and C-2.21 (statecharts
record, synchronous code enforces): **the UI treatment informs the trader, the server/OMS enforces**. Every
order-entry gate below is a UX mirror of a synchronous server check, never the only control. The stale-UI-mirror
threat is `docs/security/threat-models/E17-ws-gateway.md` WS-E06 and AC-26: the client treats a stale or
disconnected `system` stream as _unknown_, not as "not killed".

## 4. The six states, ranked

Severity rank 1 = worst. Precedence among states on the **same surface** keeps the E08 rule (one state per
surface, highest wins). Labels are proposed plain-English labels; the Owner has not confirmed them (§9). **Architect ruling (#249 comment 6163908535, A4):** the chip carries five values (`live|delayed|stale|reconnecting|offline`). **Read-only is a permission overlay, not a CMP-076 chip state** (rendered by SCR-010 chrome, CMP-117 and the SCR-152 Read-only banner; it always displays alongside the feed state). **Resyncing is panel-only on the chip**: it is per-book, and the chip shows only the detail "resync storm" at >5 resyncs/60 s. Feed precedence: Disconnected > Stale > Resyncing > Delayed > Live; Read-only is orthogonal.

| Rank    | State                                                                                                                                     | Label (chip)                                         | Trigger (source signal)                                                                                                                               | Enter after                                                 | Exit after                                         |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------- |
| 1       | **Disconnected**                                                                                                                          | "Disconnected" / "Reconnecting (3)"                  | transport closed or no traffic 45 s (§9.1); `system` unknown after heartbeat failure; `bye`; `exchange_unavailable`; incl. `slow_consumer` 4429 close | immediate on close; or heartbeat timeout; or 2 missed pongs | `auth_ok` **and** private snapshots reconciled     |
| overlay | **Read-only** (permission overlay, not a CMP-076 chip state; ranks above Stale in effect because it blocks action regardless of data age) | "Read-only — <reason>" (banner/chrome, not the chip) | `shutdown_notice`; kill switch engaged; clock drift; viewer role; unknown `system` state; private feed down                                           | immediate on frame                                          | reason cleared + one fresh `system` snapshot       |
| 3       | **Stale**                                                                                                                                 | "Stale 7s"                                           | per-topic age > threshold (T1 below) with transport up                                                                                                | threshold crossed                                           | first fresh frame for that topic                   |
| 4       | **Resyncing** (panel-only; chip shows only "resync storm" at >5/60 s)                                                                     | "Resyncing book…" (in-panel scrim)                   | `exchange_state: resyncing`; `snap` with `reason` ≠ `initial`; client `resync` sent                                                                   | immediate                                                   | fresh `snap` applied **and** min display 1 s       |
| 5       | **Delayed**                                                                                                                               | "Reduced rate ×4" (saturated)                        | `connection_quality` `saturated` (queue 60–90 % or RTT > 500 ms)                                                                                      | 2 consecutive classifications (≈4 s)                        | 2 consecutive `healthy` (≈4 s) and min display 5 s |
| 6       | **Live**                                                                                                                                  | none (ambient)                                       | none of the above                                                                                                                                     | —                                                           | —                                                  |

`lagging` (queue 25–60 % / RTT 150–500 ms) is **not** a state: no chip, no announcement; it is shown only in the
connection chip tooltip ("Connection quality: fair"). Rationale: F2 (no loss) + F8 (false alarms teach the trader
to ignore chips). **Read-only ranks above Stale** because it blocks action regardless of data age; **Stale ranks
above Resyncing** because a silent topic's last value is more dangerous than a book being actively rebuilt.
Rank 4 vs 5 (resync vs delayed) is an ordering judgement to be validated in the owner walkthrough (§9.3 Q3).

### 4.1 Thresholds (T1–T5)

| ID  | Threshold                                               | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | Rationale                                                                                                                                                                     |
| --- | ------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1  | Stale chip, per topic                                   | book **2 s**, ticker **5 s**, trades **10 s** (T2 at 3×: book 6 s, ticker 15 s, trades 30 s). Private topics and `system` have **no silence threshold** (they emit on change; silence is normal). Derived: private topics are stale iff the transport heartbeat is unhealthy (ping after 20 s idle, pong within 10 s, 45 s timeout) or the server reports `exchange.private_ws != connected`; `system` is _unknown_ iff no `system` snapshot has arrived since the last (re)connect or the heartbeat is unhealthy (WS-E06, D11). | T3  | Delayed enter/exit                                      | 2 consecutive classes (≈4 s) in, 2 healthy out, min display 5 s                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | classification runs every 2 s (§8.3); stops chip flapping and respects ≤3 flashes/s                                                                                           |

Hysteresis: all exits use the _exit_ column of §4; entering is immediate for transport loss and Read-only (safety

## 6. Order entry by state

Architect ruling R1 (#249 comment 6163908535). UX mirror of server enforcement (C-2.12/C-2.21): every gate has a server twin wherever the server can observe the condition; the client enforces only its own transport state and displayed-data age (UX gate with audit record). New risk is blocked whenever the price the trader would act on is untrustworthy; risk-reducing actions are never blocked by feed state alone.

**Action classes.** _New risk_: any entry order (market, limit, conditional), one-click/hotkey, chart-click and ladder-click entries, trade-group fan-out, algo starts, **risk-increasing amends** (qty up, entry price change, SL loosen/removal) and **cancelling a protective exit** (TP/SL). _Amend (reducing)_: qty down, SL tighten, TP edit on a reduce-only exit (treated as risk-reducing). _Cancel_: one working entry order; cancel-all with `exclude_reduce_only`. _Reduce-only / close / flatten_. _Kill switch (engage)_.

Legend: **A** allowed; **G** gated (one CMP-044 `standard` confirm naming the data age and consequence; Esc cancels); **B** blocked (disabled-with-reason, §0.5.5). **[S]** server enforces; **[C]** only the client can. T1/T2 per §4.1.

**Server twin (R1-S1/S2).** _R1-S1:_ with `age_S` the server's own age of the last applied ticker/mark for symbol S: `age_S ≥ T1_ticker` (5 s) refuses every mark-dependent new-risk order (market, one-click, conditional/trigger, relative-SL-offset entries) with `degraded_data` 503; `age_S ≥ T2_ticker` (15 s) refuses all new risk and risk-increasing amends for S; unknown age counts as stale (fail closed); cancel, reduce-only, flatten and kill switch are never refused for staleness. _R1-S2:_ private feed down > 10 s refuses new risk and risk-increasing amends with `risk_state_unavailable` 503 (cause added by E39-S01); the OMS REST confirm read follows every accepted risk-reducing submit. No server rule keys on client transport state. Client refusals are audited: `order.blocked_offline` and the new `order.blocked_stale {symbol, topic, ageMs, orderClass}`. When client and server gates differ, both apply and the worse one blocks.

Reassurance copy in Disconnected and Read-only: "Exchange-side stop-losses still protect open positions (native stops only; app-managed rules are paused)".

Disabled controls follow §0.5.5: disabled-with-reason, not hidden; refused attempts recorded as
`order.blocked_offline` / `order.blocked_stale`.

## 7. Announcement policy

Matches `05-accessibility-standard.md` §6.2 and CMP-076; one live-region pair pre-rendered empty at load.

| Event                                                    | Region                     | When                        | Text pattern                                                                            |
| -------------------------------------------------------- | -------------------------- | --------------------------- | --------------------------------------------------------------------------------------- |
| Entering Disconnected / Read-only                        | `role="alert"` (assertive) | once on entry               | "Disconnected. Trading is off. Exchange-side stop-losses still apply."                  |
| Entering Stale ≥ T2                                      | assertive                  | once per symbol per episode | "BTCUSDT price feed stale 14 seconds. New orders off."                                  |
| Entering Stale < T2, Resyncing, Delayed                  | `role="status"` (polite)   | once on entry, once on exit | "Heatmap refresh slowed to 1 second."                                                   |
| Reconnect attempt counter, countdown ticks, age counters | none                       | never re-announced          | visual only; the countdown is not announced per tick                                    |
| Recovery                                                 | polite                     | once                        | "Reconnected. 1 order filled while offline." (assertive only if an order state changed) |
| Flapping                                                 | polite                     | once                        | "Connection unstable."                                                                  |

Rules: no state is conveyed by colour alone (icon + text + colour); no pulsing, blinking or looping animation
(state change is a single flip; ≤3 flashes/s, `prefers-reduced-motion` honoured; motion detail owned by E08-D11).
Stale-age text updates at ≤1 Hz visually and is not in a live region.
