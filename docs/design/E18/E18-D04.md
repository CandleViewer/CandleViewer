### 1.3 Rules stated once (every later row cites "R-n")

- **R-1 Tokens only, in the frame loop.** Every duration is `motion.duration.instant` / `.fast` / `.normal` / `.slow`, 0 / 100 / 200 / 400 ms (TOK:454–468), and every curve `motion.easing.standard` / `.decelerate` / `.accelerate` (TOK:470–480). For the implementer: every chart row runs in the engine's frame loop, never CSS, timed in ms of real `dt`, the curve a cubic Bézier evaluated from the token's four numbers (the tokens are code-only, `16`:401). Violated if a row names a literal duration, or a canvas moment is a CSS transition (G-MOTION, G-TOKENS; M-6, M-9).
- **R-2 Skip, never zero.** A reduced variant is an instant state change: no transition object, no tween, no shader pass (E47D08:118). Violated if a Reduce cell reads anything but `instant` (G-MOTION; M-7).
- **R-3 One draw.** A fade is an alpha uniform on the draw that already exists; nothing adds a second pass or a second batched draw (T Perf; `26`:286). Violated if a row asks for one (G-LOD; M-13).
- **R-4 Values never wait.** The number, the sign and the glyph swap in the frame the coalesced update lands; only a marker's visibility and a fill's emphasis are held (E47D08:117). Violated if a hold delays a value.
- **R-5 Hold, latest wins.** A marker's state change is held ≥ 200 ms after the last one, and at the hold's end the latest state applies; nothing queues (§3).
- **R-6 Re-target, never restart.** A fade or fill ease that is running when a new target arrives starts from the value on screen, never from its old start.
- **R-7 Announcements never wait for motion**, no transition moves focus, and nothing is announced per forming update (§7.3; D02:749–750). A key pressed during a fade acts at once: `Esc` never waits for a close transition.
- **R-8 One resolved mode.** The engine reads the `16` §4 resolved mode and maps it onto E47-S07's `RenderFlags` (E11D06:372; `26`:801); no footprint code reads `prefers-reduced-motion` itself (§6).
- **R-9 The T2 rule.** The gated controls this review touches, the cell menu items, the SCR-032 controls and the SCR-056 row menu, keep D03 §1.4's renderings and gain no motion: native role and full label (G-T2.1a); `aria-disabled="true"`, never `disabled`, in the Tab order, a menu item arrow-reachable (G-T2.1b); the reason node in the DOM at mount, linked by `aria-describedby` (G-T2.1c); CMP-079 RbacGate wraps it and the CMP-019 `lock` glyph leads the label (G-T2.1d); label `color.text.tertiary`, reason `color.text.secondary`, never `color.text.disabled`, never `opacity.disabled` (G-T2.2); a press re-announces its reason once (G-T2.3); the reason strings stay D03's W-n, a state string one sentence of at most 60 characters (G-T2.4); no transition delays the reason (this review's timing rule, not a G-T2 item); a read-only surface carries one notice (G-T2.5). ## 3. The flicker policy (BQ-5; G-HOLD)

**The rule.** No marker (the imbalance outline, the POC rail, the VA ticks, the stack bracket, the unfinished-auction ledge, the forming cap) may change state sooner than 200 ms after its last change. A change that arrives inside the hold is not queued: at the hold's end the latest state applies (latest wins), whatever happened in between, so a value that oscillates is held until the window closes (T Scope). Appearance fades over `fast` (M-03, M-05, M-09), never scale or bounce, and never a slide; disappearance is a cut. The hold is one constant, 200 ms, PROPOSED into E08-D11's `motion.hold.*` group with no token added (OQ-1).

**In numbers.** The tool drives one marker whose wanted state toggles at every coalesced rate from 1 to 10 Hz for 10 s at 60 frames per second and counts the changes in any half-open 1 000 ms window, in whole frames so float spacing adds none (WCAG 2.3.1 counts a flash as a pair of opposing changes; E47-D08 FR-7 fails at ≥ 3, E47D08:195):

| Case   | Worst 1 000 ms window |
| ------ | --------------------- |
| unheld | 10 changes, 5 flashes |
| held   | 5 changes, 2 flashes  |
| cycles | 2.5                   |

So a held marker stays at ≤ 2.5 cycles per second, under `05`:252's 3, at any data rate.

## 4. The forming bar: cadence, the fill and the flash audit (BQ-4; G-FLASH)

**Cadence.** Cells and markers coalesce to ≤ 10 Hz, one admitted update per 100 ms (`11`:1666; D02:310). D02:398's "250 ms cadence" is C-4: the design holds at either rate, and E18-K01 #583 measures which one ships. **The fill** eases over `motion.duration.fast`, so at 10 Hz it settles in the frame the next update arrives; a new target re-targets from the colour on screen (R-6). **The number** swaps in one frame (M-01).

**The flash audit.** For each theme, and again for its cvd-safe twins (`color.cvd.*`, D03 §2.5), the tool takes every fill a forming cell can reach (the canvas for an empty side, then `ramp.delta`'s four inked stops) at full ink, finds the pair with the largest relative-luminance step through `cvd_simulate.relative_luminance`, tests it against WCAG 2.3.1's general-flash pair (a step ≥ 0.1 with the darker below 0.80), then drives a cell that alternates between that pair on every 10 Hz update and counts flashes in the worst 1 000 ms window, unheld and under the fill hold:

| Theme                   | The pair (darker → lighter)                        | Step  | Darker | A flash pair | Flashes, unheld | Flashes, held (FR-6) |

## 5. LOD text: the crossfade on the dead band (AC 3; BQ-3; G-LOD)

**The rule.** When the cell height crosses a text threshold of `LOD_PROFILE_M0` (L0 → L1 below 10.2 px, back at 12 px; L1 → L2 below 8.5 px, back at 10 px; E06D01:59, :61), only the cell **text** fades: one alpha uniform on the single glyph draw, never a second pass, over `fast` / `decelerate`, starting on the frame of the crossing. Fills, outlines, brackets and the L2 ↔ L3 step stay E11-D06 D14's one frame (E11D06:232), so the two specs agree once split: D14's "no crossfade" holds for fills, whose blend would need two draws and a colour that is neither, and A-4 and A-8 narrow its wording and its table row 22 (E11D06:324) to fills, outlines and the L2 / L3 collapse (BQ-3, RULED). Under reduce and canvas calm the text change is a hard cut, which the dead band makes safe (T Scope).

**The simulation (AC 3).** A 10 s zoom sweep at 60 frames per second from 20 px to 2 px of cell height and back, geometric in time, with a 3 Hz multiplicative wobble standing in for an unsteady hand. The gated wobbles stay inside the band (±7 %: a 1.15 ratio from trough to peak, below the band's 1 / 0.85); ±10 % is reported, not gated. "Text crossings" counts the two text thresholds the sweep passes; "text changes" the text-tier changes the user sees; "layer changes" every level change, L2 ↔ L3 included:

| Sweep | Wobble | Text crossings | Text changes | Layer changes |
| ----- | ------ | -------------- | ------------ | ------------- |
| down  | ±0 %   | 2              | 2            | 3             |
| down  | ±7 %   | 2              | 2            | 7             |
| down  | ±10 %  | 2              | 2            | 7             |
| up    | ±0 %   | 2              | 2            | 3             |
| up    | ±7 %   | 2              | 2            | 5             |
| up    | ±10 %  | 2              | 2            | 7             |

Every text crossing makes exactly one visible text transition, and the clean round trip makes 6 level changes, gate B2's ceiling (K02:56). The crossfade cannot add a transition: a reversal inside its 100 ms re-targets the alpha (R-6), and the band keeps a gated wobble from reversing at all. **The layer changes are a finding:** L2 ↔ L3 switches at 6 px with no dead band (E06D01:71; `26`:238), so a wobble at that height flips the whole layer in one-frame steps, which neither AC 3 (text only) nor D14 covers (F-1).
