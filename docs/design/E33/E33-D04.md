## 1. Purpose, method, locked inputs and the rules stated once

### 1.1 What this spec fixes

The entries the epic's patterns need in the design system, each defined exactly once, and the motion each may carry. It decides no behaviour: every state, string and carrier comes from merged D02 / D03; where this spec picks between merged texts that disagree, it says which and why (§1.4, §8).

### 1.2 Method (honest)

Desk work at the base: the tool extracts every backticked token name from D02, D03 and H03 at their merged text, resolves it in dark, light and high contrast through `themes.json`, re-measures every contrast pair by the WCAG 2.x formula (the one `contrast_check.contrast_ratio` implements), and simulates protanopia, deuteranopia and tritanopia with a verbatim port of the Brettel / Viénot projection in `docs/research/_tools/cvd_simulate.py` (its constants re-read from that file at the base by the gate G-CVD-PORT), distances as CIE76 ΔE and the floor from the E11-D05 tool. The greyscale and deuteranopia PNG strips of board 02 are rendered with `docs/design/_tools/cvd_sim.py` at the boards step. No prototype was run and no participant exists; findings labelled `(heuristic)` are the writer's (§12). Motion values are tokens or cited constants, not measured kinematics.

### 1.5 Rules stated once (every later row cites "R-n")

- **R-1 Never colour alone.** Every algo state renders glyph + word + fill; the word leads the accessible name; the glyph is `aria-hidden` (`16`:160; `05`:105–117; `15`:37). Each glyph is used with exactly one fill, so two states whose fills differ always differ in glyph and word (§3.1).
- **R-2 State transitions are instant.** Word, glyph, fill and control availability change at frame 0 in both modes, `motion.duration.instant` (0 ms<!--=MOTION:duration.instant-->), no easing (RULED BQ-11; §7.4).
- **R-3 Cadence.** Algo values render at most at 2<!--=MOTION:cadence.render-max-hz--> Hz on the client, whatever the transport does (§7.1).
- **R-4 Exits are never gated.** Close, `Esc` and Acknowledge are T1 in every treatment and frame; nothing here locks them.
- **R-5 No T2 is introduced.** AlgoStateLabel specifies the status look only; control locking stays in the host entries and cites D02 / D03's merged rulings, their `algo.*` keys PROPOSED (D03-A12, D03:319). No frame of §9.2 draws a lock.
- **R-6 Reduced motion has one source** (§7.5).
- **R-7 The emulation is never hidden.** The three-part affordance (§2) on every builder; the tag on every card and every host of a row (§4.3).

## 7. The motion spec

### 7.1 Cadence and "no implied sub-second precision" (RULED BQ-10)

The client renders algo values at most 2<!--=MOTION:cadence.render-max-hz--> Hz, coalesced client-side, whatever the transport does (`14`:1551, :1613 vs `23`:824 "never throttled": D03-C3, D04-C10). Text and `aria-valuetext` swap at frame 0 on each rendered sample. "No easing that implies sub-second precision" is three rules, gated row by row:

1. **No transition is longer than the sample interval** it animates between (a move ends before the next sample can arrive).
2. **No tweened numbers** — the digits, prices, sizes and countdowns never interpolate; only a bar's fill moves.
3. **No continuous motion between samples** — once a value has rendered, nothing loops, pulses or drifts while waiting for the next sample. The one bounded exception is Mo-7's first-load skeleton, which runs before any value exists and is stopped at 5<!--=MOTION:skeleton.stop-s--> s (D04-C14).
