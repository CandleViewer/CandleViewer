- **M-1 (A26).** One step. While waiting, "Verify and save" shows row 7's busy state with D18's in-flight label, and

  carrier (`E05-D03`:75) on M-1. When the answer arrives, every check row appears in the same
  frame. The result card pushes the form down as a cut, because heights never animate (`D03`:1196). A fabricated
  stagger is forbidden: T says "a fabricated progress animation is a lie about system state".
- **M-2.** Each stage change is a cut, with focus on the new stage's heading and `aria-current="step"` moving in the
  same frame (AX-1). A refusal at stage 3 cuts to "Nothing changed — the old key ...e5f6 is still active." and is
  announced assertively once. "No verdict" is the same cut, announced once by D03's one CMP-027 `role="alert"` (`D03`:1342; C-5). The stage meta "Verify · 2.4 s" is real
  elapsed time, shown as text and never as a progress bar. A rollback is never drawn as backward motion.
- **M-3.** No motion. The time left counts on server-corrected time and steps once per second as text, with no tween.
  The stage advances on the server's `state`, never when the timer reaches 0. When it does and the wizard is open,
  the end is announced politely once and then focus moves to stage 5's heading (`D03`:791, :1344; §4, C-4). Reduce mode is identical, since the text
  is information, not motion. A text change once a second is a one-shot state change, not a flash under MR-1, and MR-2
  does not apply because nothing animates.
- **M-8 (A25, A25a).** The entrance is row 2a: the card is a cut, complete and focused at frame 0, and only the scrim
  fades (A25). **A destructive confirmation's loading state is motion-free in both modes.** Every SCR-129 dialog opens

  list, the confirm control and the polite first sentence land in one frame, and focus stays on Cancel throughout
  (`D03`:1514). The ruling is #2701 ledger addendum A row A25a (a precision of A25); A25 stands unchanged.
- **M-4 and M-5.** Each is applied only when the server answers. Row 3's value flash names CMP-036, but it is not

- **M-7.** The banner, the verdict's failed form and the row's danger treatment appear in the frame the state is
  known, with no fade, pulse, shake or repeat, in both modes. The check list's failed row is never animated, and the

## 3. The anti-motion rules

**T's words, quoted byte for byte from `E27.json`:416.**

- Q-1 (§Scope / Deliverables): "destructive confirmations (SCR-129, revoke, mark-compromised) appear without decorative animation; the withdrawal-detected state does not fade in gently; nothing about a blocking error is soft."
- Q-2 (§Security notes): "The specification explicitly forbids fading in the withdrawal-detected banner, animating the destructive confirmation entrance, or using motion to draw attention away from a failed check."
- Q-3 (§Scope / Deliverables): "numeric balances never tween between values, because an intermediate frame of a balance is a number that was never true"
- Q-4 (§Technical notes / design): "a fabricated progress animation is a lie about system state"
- Q-5 (AC 5's Gherkin, one word bracketed): "each completed check is [shown] as it completes rather than all at once at the end"

Q-5 replaces one word of the Gherkin with "[shown]", as the BQ list did (BQ-06), because the original word is on the
lane's public-text list. The tool restores the word before it compares the quote with `E27.json`:416.

**The danger-zone rules.** Each is a checkable statement. The tool pins the bold sentence of each.

- **DZ-1. Nothing else on the screen starts motion in the frame a blocking error or a failed check appears.** No
  toast, skeleton restart or drawer starts in that frame. The rows of a check list land together, so the failed row is
  never the last thing to land; it is never animated, and the passed rows are never emphasised. CP-5's refusal string
  is cited by id and never restyled. Motion never draws attention away from a failed check (Q-2).
- **DZ-2. Nothing about the countdown suggests more urgency than its copy.** The 900 s countdown is plain text, with no
  colour change, pulse, ring, bar or scale at any threshold (M-3). "Open orders stay open" is the copy it must not
  outrun.
- **DZ-3. Balances never tween.** A balance changes in one frame (Q-3). Row 3's value flash is not applied to SCR-079
  balances (M-5), and a stale balance keeps full contrast.

**BQ-04: the confirmation's scrim. RULED (orchestrator, 2026-10-29, #2701 ledger addendum A row A25).** Row 2a's
`motion.duration.normal` scrim fade is not "animating the destructive confirmation entrance" (Q-2). The confirmation is
the card, and row 2a makes the card a cut: complete, and focused on Cancel, at frame 0. The scrim marks the modal
boundary, which is functional, not decorative. No per-dialog scrim variant is requested.

**A25a: the confirmation's loading state. RULED (orchestrator, 2026-10-29), #2701 ledger addendum A row A25a (a
precision of A25).** A destructive confirmation's loading state is motion-free in both modes: the skeleton lines take
their reduce rendering (static), the polite "Reading what … holds…" sentence is the only signal, and loading → ready
is a cut with focus on Cancel throughout (M-8). A25 stands unchanged: the card is static from frame 0, and only the
scrim fades.

**How the rules meet Q-1 and Q-2.** The destructive confirmations (M-8) take row 2a, whose card is a cut. The
withdrawal-detected state (M-7) is a cut in both modes and never fades in. Every blocking error (M-6, M-7, a failed
check in M-1 and M-4) is a cut under DZ-1.

## 4. Reduced motion, focus and announcements

- **The reduce column.** Rows 2a, 2b, 6 and 7 take E05-D03's reduce cells: `none`, the end state at frame 0, and for
  row 7 the static glyph with its in-flight label (`E05-D03`:81-94). Every cut row reads "identical (a cut)".
  Row 6's reduce cell, the static fill, is also what SCR-129's loading skeleton shows in normal mode (M-8, C-3).
- **One mechanism.** Reduce is driven by `data-motion` only, never by a per-row OS query (`E05-D03`:221-226). A mode
  flip mid-transition completes on its own clock (`E05-D03`:93).
- **No flash anywhere.** No row starts a flash, so HS-1 and HS-1b (`E05-D03`:105-112) are cited as not applicable, and
  MR-1 holds with no flash counted. MR-2 holds through rows 6 and 7 as E05-D03 rules them (`E05-D03`:113-116).
- **Announcements never wait on a transition.** A state is announced in the frame it is applied, inside row 2a and 2b
  entrances too (`16`:228-229).
- **Focus moves only on a user action, with the one carve-out below.** Dialogs focus Cancel at frame 0 (the step-up its password field). The
  compromise card's `h2` takes focus after the press. The stepper focuses the stage heading: D02's AX-1 (`D02`:665) governs over `16`:220's "first control".
- **The one server-driven focus move.** The stage 4 to 5 change (M-3) arrives from the server, not from a user
  action. With the wizard open, it is announced politely once, and only then does focus move to stage 5's heading
  (`D03`:791, :1344; `05`:96). It is not a danger state (C-4).
- **Danger from the server never moves focus.** A withdrawal-detected, KEK or down state that arrives from the
  self-check or WS never moves focus (`05`:96). It is announced assertively once, with one assertive voice per episode
  (`05`:148; `D03`:2018).
- **Motion never carries a danger state alone.** Each already has words, a glyph and a role (`alert` or
  `alertdialog`), and nothing flashes (`05`:202-210).

## 9. The audit tool

`python3 -I -B docs/design/_tools/e27_d04_motion_audit.py --check` (also `--json` and `--self-test`). Stdlib only and
offline; it reads every cite at `29fe3d5b2e` with `git show`, and the token names from the token JSON there. Seven
gates:

- G1-TABLE: §2 holds M-1 to M-11, every cell filled and no Carrier or motion-reduce cell a dash; each row's recipe
  is the ruled one (M-1 a cut with row 7, M-2 a cut with row 2a, M-3 to M-7 and M-9 cuts, M-8 row 2a, M-10 row 2b,
  M-11 rows 6 and 7), the row ids exist in E05-D03 §2 at the base, a cut is written as the instant triple, and a
  recipe row's reduce cell names that row's reduce cell.
- G2-TOKEN: every dotted name in backticks anywhere in the spec is a token in the token JSON at the base (the one
  state key, `keys.kek_unavailable`, excepted). In the table, the cells other than Transition and Surfaces name no
  `motion.*` token except `motion.duration.instant`, so no easing or recipe duration is restated, and every Stagger
  cell is `motion.duration.instant`. The check does not inspect animated properties: that rests on every animated row
  being an E05-D03 recipe, which E05-D03's own tool gates (G2-PROPERTY there).
- G3-QUOTES: Q-1 to Q-5 byte for byte against `E27.json`:416.
- G4-DANGER: DZ-1 to DZ-3 with their pinned sentences, applied on M-7, M-3 and M-5; A25, A25a, A26 and A27 stamped RULED, and A25a's loading-state sentence present.
- G5-CITE: every cite in range at the base, the load-bearing ones pinned to their words, and E05-D03 identical at
  `bca5f0f1` when readable.
- G6-HYGIENE: the public-text list (in this file and the tool), local paths, hosts, closing keywords and any wording
  that leaves a ruled sign-off open.
- G7-BOARDS: §7's seven dark boards, no twins, PENDING.

`--self-test` applies one mutation per gate, plus a probe that moves M-7 onto row 2a consistently, and passes only
when each adds exactly one new FAIL from its gate and no file on disk changes.
