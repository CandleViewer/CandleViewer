## 1. Purpose, scope, method, inputs

### 1.1 What this spec fixes

E13-D03 designed the indicator surfaces and their visual language and routed every design-system consequence here (`E13-D03.md` §20 :618). This spec **publishes** them — the eight-slot palette as a token set with its assignment function, the identity ladders as design-system variants, the five-key style vocabulary as the closed list `indicator_presets.style` validates against, and the CMP-199 / CMP-224 variant additions — and **specifies** the motion the three surfaces and the indicator panes carry: the SCR-034 / 035 / 036 open and close, the sub-pane create and collapse, the series re-compute transition, the legend row add and remove and the count chip, each with its reduced-motion twin. It consolidates the copy deck (AC 4). It re-decides nothing of E13-D02 (layouts, dimensions, states, keys, strings — ruling 6) or E13-D03 (slots, function, ladders, vocabulary, row states — BQ-5): where this spec's tool reproduces a number, the number is quoted from this run and the decision from its owner; where a number differed it would be a C-row, never a silent override (none differs: `--check` drift 0). Out of scope (ticket :25–:27): implementing the tokens in code (E13-S01 / S02 / T01 and E05's pipeline); motion for drawings (E14) or layouts (E15) — the splitter animation is E11-D06's and the persisted pane ratios are E15's (named in §21, not specified); CMP-197's and CMP-226's rows and the chassis motion (E11-D06's, inherited by reference); the a11y review of these twins (E13-D05's, in flight, not cited).

### 1.2 Method

A desk **design-system and motion spec** `(heuristic)` on the merged E13-D02 and E13-D03: every slot, tier, state, key and string is cited by its D-id or § and never redrawn; contrast, ΔE, CVD and the alpha are **re-computed by this spec's tool through E13-D03's tool** over the token JSON at the base and compared with that tool's own output (drift 0); the motion numbers (frame counts, first-frame fractions, the alpha curve, the draw-call transient, the ratio arithmetic) are computed by the tool, never typed. No participants, no bench (BQ-8: a desk spec in E11-D06 §11's form, with the owner's walkthrough in §14); owner approval pending. Prose is short; the tables carry the content; every number names the tool section it came from.

### 2.4 The exclusion rule, the ordering rule and the assignment function (cited; the pseudocode verbatim)

The exclusion rule (E13-D03 §3.2 :124), the ordering rule (§3.3 :128) and the assignment function (§3.4 :132–:146, Q-6 RULED on #314: the hue-first assignment stays the default) stand as written; the function is reproduced here verbatim because the ticket asks for it "documented alongside" the set (:19):

```text
on add(instance, pane):
  pairs    = { (slot(i), tier(i)) for i in pane.instances }          # per pane, never per chart
  hues     = { slot(i) for i in pane.instances }
  siblings = { i in pane.instances if i.indicator == instance.indicator }
  tier     = min(t in 0..5 if t not in { tier(i) for i in siblings }) ?? 0
                                                                      # D4: the lowest tier no sibling uses
  slot     = instance.preset.style.color if that hue has a free tier  # a saved preset's token wins (RULED; SR-E13-08)
          ?? min(s in 1..8 if s not in hues)                           # else the lowest hue not on the pane (AC 3)
          ?? the lowest (s, t) not in pairs, t searched from tier on   # all eight hues in use: the lowest free pair
  while (slot, tier) in pairs: tier = (tier + 1) mod 6                 # a winning preset hue: bump its tier until free
  instance.slot, instance.tier = slot, tier
on remove(instance): its pair is freed; undo re-takes the same pair if it is still free, else re-assigns as an add
on move-to-pane: the instance is re-assigned on the target pane as an add
```

Identity is the (slot, tier) pair; E13-D03's tool proves no two instances on a pane share one over 80,015 add / remove / undo / preset checks (§3.4 :148); the ten-indicator frame's assignment is `(1, 0) (2, 1) (3, 0) (4, 0) (5, 0)` on the price pane and `(1, 0) (2, 0)` / `(1, 0) (2, 0) (3, 0)` on the sub-panes (every sub-pane starts at slot 1).
