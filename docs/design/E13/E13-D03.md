### 3.3 The ordering rule

The order **alternates hue family and lightness** so adjacent slots differ in hue **and** in greyscale luminance: teal (light) → purple (dark) → orange (light) → blue (dark) → purple (light) → teal (dark) → blue (light) → orange (dark); the same family recurs only three slots later and at the other lightness (1 / 6 teal, 2 / 5 purple, 3 / 8 orange, 4 / 7 blue). The light theme keeps the families and the alternation with the darker steps of each family. Slot 1 is the brightest common line (9.05:1 on the dark canvas, 3.53:1 on the light), because it is the one the first indicator on every pane takes. The owner may reorder (Q-2); the function below is order-agnostic.

### 3.4 The assignment function (the engine assigns at add-time; stated as pseudocode, never as swatches alone)

```text
on add(instance, pane):
  used      = { slot(i) for i in pane.instances }            # per pane, never per chart
  slot      = min(s in 1..8 if s not in used)                 # the lowest free slot
            ?? ((count(pane.instances) mod 8) + 1)            # all eight in use: wrap to 1, 2, …
  tier      = floor(count(pane.instances) / 8)               # the identity tier bumps once per wrap (BQ-1 ladder, §4)
  siblings  = { i in pane.instances if i.indicator == instance.indicator }
  if siblings: tier = (max(tier(i) for i in siblings) + 1) mod 6   # D4: a second instance of the same indicator
                                                             #     takes the next free slot AND the next non-colour marker
  if instance.preset.style.color: slot = instance.preset.style.color   # a saved preset's token wins (SR-E13-08 value set, §9)
  instance.slot, instance.tier = slot, tier
on remove(instance): its slot is freed; undo re-takes the same slot and tier
on move-to-pane: the instance is re-assigned on the target pane as an add
```

"No series colour repeats within a pane" (AC 3) holds for up to eight instances on a pane; the ninth wraps to slot 1 at tier 1 (a 1 px solid line beside the 2 px one) — 8 × 6 = 48 identities ≥ the 20-instance cap (SR-E13-02). A multi-output instance takes **one slot** and spreads its outputs over tiers of that hue (§5: the primary output at tier 0, the signal at tier 3, a histogram as the slot hue, bands as 1 px edges with the fill between them). Hidden instances keep their slot (they still count against the caps, E13-D02 D5 / OQ-E).

## 4. The identity ladder (BQ-1, RULED: weight first, dash second, the reserved geometries never)

Identity is a pair (slot, tier): the slot carries the hue, the tier carries the non-colour marker. ### 4.5 Greyscale statement and the pointer to E25-D01 §9.5

With hue removed, a series is told apart by its tier (weight, then a long dash, then dash-dot; a bar's width; a marker's shape) and by its label; the tool measures what luminance alone adds: adjacent slots differ by ≥ 9.2 L\* in every theme, while the slots of one lightness tier (1 / 3 / 7 and 2 / 4 / 8) differ by less than 5 L\* (22 of the 84 pair-theme rows, §10.3). So a second instance of the same indicator (D4: next slot **and** next tier) and every instance past the eighth on a pane (the wrap) always differ in geometry; two unrelated indicators at the same tier on one pane (EMA 21 in slot 1 and a Bollinger middle line in slot 3) differ in luminance by 2.1 L\* and are told apart by their shape (a band is three lines and a fill) and by their legend label — recorded as the AC 1 residual with the per-instance-tier variant PROPOSED for the owner (C-26, Q-6). **C-17 (a pointer, never a second proposal):** E25-D01 §9.5 PROPOSES for `16` §6 "hollow, dashed or hatched = estimated or absent, never a side or direction"; this ladder complies — no dash, hollow or hatch carries a side or a direction; the identity dashes are long (≥ 8 px) and distinct from the 4 / 3 estimated dash; the warm-up zone is hatched (absent coverage) and the provisional leg dashed (unconfirmed), both with their word; the one residual is H2's outlined bar, kept last and flagged (Q-7).
