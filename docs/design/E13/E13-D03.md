### 3.3 The ordering rule

The order **alternates hue family and lightness** so adjacent slots differ in hue **and** in greyscale luminance. In dark (and high-contrast): teal (light) → cyan (dark) → teal (light) → purple (dark) → amber (light) → teal (dark) → purple (light) → cyan (dark) — adjacent L\* differences 20.9 / 13.9 / 25.1 / 18.6 / 5.8 / 9.8 / 17.9 / 27.4 (the wrap 8 → 1 included); the same family never sits beside itself and recurs at the other lightness. In light the strong line is the dark step, so the roles flip: teal (dark) → blue (mid) → cyan (dark) → purple (mid) → amber (dark) → teal (mid) → purple (dark) → blue (mid), adjacent differences ≥ 26.0 L\*; slots 1, 4, 5, 6 and 7 keep their dark-theme family, slots 2, 3 and 8 take the family the light search leaves (blue, cyan, blue), so the swatch's accessible name says the family of the active theme (§13). Slot 1 is the strongest common line in every theme (9.05:1 on the dark canvas, 11.35:1 on the light), because it is the one the first indicator on every pane takes. The owner may reorder (Q-2); the function below is order-agnostic.

### 3.4 The assignment function (the engine assigns at add-time; stated as pseudocode, never as swatches alone)

```text
on add(instance, pane):
  pairs    = { (slot(i), tier(i)) for i in pane.instances }          # per pane, never per chart
  hues     = { slot(i) for i in pane.instances }
  siblings = { i in pane.instances if i.indicator == instance.indicator }
  tier     = min(t in 0..5 if t not in { tier(i) for i in siblings }) ?? 0
                                                                      # D4: the lowest tier no sibling uses
  slot     = instance.preset.style.color if that hue has a free tier  # a saved preset's token wins (RULED; SR-E13-08)
          ?? min(s in 1..8 if s not in hues)                           # else the lowest hue not on the pane (AC 3)
          ?? the lowest (s, t) not in pairs, t searched from tier on   # all eight hues in use: the lowest free pair
  while (slot, tier) in pairs: tier = (tier + 1) mod 6                 # a winning preset hue: bump its tier until free
  instance.slot, instance.tier = slot, tier
on remove(instance): its pair is freed; undo re-takes the same pair if it is still free, else re-assigns as an add
on move-to-pane: the instance is re-assigned on the target pane as an add
```

Identity is the **pair**, and no two instances on a pane ever share one: the tool simulates the three failure cases the round-1 lens found in the first, wrap-by-count function (a removal before a wrap handing out a pair already in use; nine and twelve instances of one indicator; a preset's colour beside the same slot) and 2,000 seeded add / remove / undo / preset sequences up to the 20-instance cap — 80,015 checks, no duplicate pair (its section 1e). "No series colour repeats within a pane" (AC 3) holds with **two stated exceptions**: the ninth instance on a pane (eight hues; it takes the lowest free pair at the next tier — a 1 px solid line beside the 2 px one) and a saved preset whose colour is already on the pane (the preset wins its hue and takes the next free tier of it; a seventh preset in one hue yields to the function — six tiers). 8 × 6 = 48 pairs ≥ the 20-instance cap (SR-E13-02). D4 ("the next non-colour marker") holds for up to six instances of one indicator on a pane; the seventh shares a tier with a sibling and differs by hue. A multi-output instance takes **one slot** and spreads its outputs over tiers of that hue (§5: the primary output at tier 0, the signal at tier 3, a histogram as the slot hue, bands as 1 px edges with the fill between them). Hidden instances keep their pair (they still count against the caps, E13-D02 D5 / OQ-E).

## 4. The identity ladder (BQ-1, RULED: weight first, dash second, the reserved geometries never)

Identity is a pair (slot, tier): the slot carries the hue, the tier carries the non-colour marker. Dashes mark **identity**, never a side, a direction or a status; the only dashed-with-a-word state is the provisional Zig Zag leg (§5), and the one output pair that is a direction — ADX's +DI / −DI — carries its sign by a word on the plot and by weight, never by a dash (§5). Widths are CSS px, device-snapped per E11-D02 §4.4 (`max(1, floor(dpr))` hairlines, dashes scaled alike). ## 10. Themes and densities: the measured matrix, the resolved values, the CVD table, the band-fill alpha and the design-system change requests
