## 1. Purpose, scope and method

### 1.1 What this spec fixes

The low-fidelity structure of the three E13 surfaces so engineering (E13-S01, S02, S08) can estimate against it and E13-D03 can theme it without re-deciding layout: SCR-034 Indicator library (landing, search, categories, entry anatomy, caps, in-flight add, the `Ctrl+K` palette entry), SCR-035 Indicator settings (five tabs, schema-driven controls, validation, live preview, save-as-default and reset, multi-output and multi-series, the OQ-6 re-tune guard), SCR-036 Indicator manager (the tree, per-item controls, multi-select and bulk actions, the empty state, blocked removal, the full keyboard contract), and the legend and chip states they drive (CMP-199, CMP-224, including insufficient history). Out of scope, per #246: colour, type, iconography, elevation (E13-D03); motion (E13-D04); order-flow indicator entries beyond the category existing (E18/E19/E23/E24); the alert editor's internals (SCR-091, E40).

### 1.2 Method (honest)

Desk design and heuristic evaluation under the agent-delivery adaptation (owner decision 2026-09-25): no participants, no sessions, no prototype. The bar is the indicator library, settings and manager of the professional terminals the personas already know (TradingView, Sierra Chart, ATAS, Quantower, Bookmap, Jigsaw, Exocharts): their patterns are cited only at the level of general interaction patterns recalled from familiarity, not re-verified against live builds, and every such statement is `(heuristic)`. Contrast is computed programmatically (§13), never eyeballed. Frame: Nielsen's ten heuristics plus the trading heuristics of `05` (keyboard-first as speed §3.1; one hotkey layer §3.1/§3.3; no hover-only or drag-only interaction §3.1 item 6; colour never alone §4; equal-status canvas alternatives §6; reduced motion §7).

## 4. SCR-034 Indicator library (D1–D8)

The catalogue is `GET /api/v1/indicators` (`listIndicators`): 28 v1 descriptors (`orderflow/indicators/catalogue.py`, ADR-0034's table order), nine of them `compute: server` (`sma`, `ema`, `rsi`, `atr`, `adx`, `vwap`, `cvd`, `volume`, `zigzag`) and the rest `client_worker`. Favourites and the "On chart" tags come from `GET /api/v1/indicator-presets` (`is_favourite`) and the chart's own instance list; Recents has no backing store (D7). Order-flow entries exist as a category with their names only (their content is E18/E19/E23/E24).

### 4.1 Landing (D1)

The dialog opens with the **search field focused** and the **All** tab active; with an empty query the list body is the landing: a **Favourites** group (the user's `is_favourite` presets, each a parameterised entry such as "EMA 21" or "ATR 14") and a **Recents** group (the last eight indicators added, most recent first, "store pending" until CG-3 lands). Below them the full catalogue follows, grouped by category in `IndicatorDescriptor.category` order (trend, momentum, volatility, volume, orderflow), so the browse fallback is one scroll away and nothing is hidden behind a tab. The tabs (CMP-042, one roving stop) filter by **pane target**, which is what a trader reasons about when adding (`pane: price` → Overlay, `pane: sub` → Sub-pane, `pane: both` appears in both, `category: orderflow` → Order-flow); a non-empty query searches inside the active tab. **Empty Favourites** is a designed state (CMP-026 `no-data`): "No favourites yet. Star an indicator to keep it here." — Recents and search stay usable; a seeded "house" list is **not** drawn (E13-D01 OQ-5 → §18 OQ-D). _(heuristic: first-time "find ATR" is won by search, repeats by favourites and recents, browse by the tabs — E13-D01's findability answer; TradingView's dialog lands the same way.)_

### 4.2 Entry anatomy (D2)

One option (`role="option"` inside the `role="listbox"`, SCR-034 A11y) is a two-line row: the **thumbnail slot** (CMP-228 with a proposed `kind: "indicator"`, §20 A-5; `aria-hidden`, since the name and description carry the meaning) · the **name** (`IndicatorDescriptor.name`, matched substrings in `<mark>` plus weight — the highlighting comes from CMP-213's `matchRanges` over text nodes, never from injected markup) · a one-line **sub-label** — the category and the pane target ("Momentum · Sub-pane"); the descriptor carries no description or alias field, so the description line SCR-034's checklist asks for is drawn as a labelled empty slot and recorded as contract gap CG-6 (owner E13-T02) · **tags** (CMP-011): "Requires recorded history" for every `compute: server` descriptor (the server kernel computes from tape-built bars, `22` `IndicatorDescriptor.compute`), "(estimated)" when `estimated: true` (`14` §0.5 rule 2, CMP-227 wording), "On chart ×N" when N instances exist (D4). The option's accessible name reads them in order: "ATR — Average true range, volatility, sub-pane, requires recorded history". The **footer action bar** is bound to the active option and holds the interactive controls an option cannot contain: a **star** toggle (CMP-002, "Favourite ATR", `aria-pressed`), a **pane-target** segmented control (CMP-003 "Overlay | Sub-pane", only for `pane: both`), and the primary **Add to chart** button (CMP-001). `Enter` on the option is the same as Add to chart. The dialog **stays open** after an add (E13-D01 R1) so a second indicator costs one more `Enter`; `Esc` closes and returns focus to the invoker.

### 4.3 Search and no results (D3)

CMP-054 SearchBox (`role="searchbox"`, "Clear search" button) feeds CMP-213 FuzzyList over `name`, `id` and the alias list the catalogue will carry (CG-6: no alias field exists; until then name and id). Results are grouped by category with `role="group"` headers; the count is announced politely ("3 indicators match 'atr'"). Typo-tolerant match is the point of CMP-213 (E13-D01 board 2: "search wins only if the match is typo-tolerant"). **No results** echoes the query: "No indicator matches 'xyz'." with the "Clear search" action and the hint "Try a category tab."; the tabs stay enabled. A query inside the Order-flow tab that matches an indicator in another tab shows "2 matches in other categories — show all" so the tab filter never hides a hit silently _(heuristic, H5 error prevention)_.

### 4.4 Already present (D4)

An indicator already on the chart keeps its row; the tag "On chart ×1" is added and the primary action reads **Add second instance**. The second instance is auto-labelled with its parameters ("EMA 21 (2)" until a parameter differs, then "EMA 34") and takes the **next non-colour marker** of the ladder E13-D03 publishes (dash pattern for lines, fill pattern for histograms and areas, glyph shape for marker series — E13-D01 AD-2), so two instances never look alike without colour. The legend row's menu offers the same "Add second instance" (§2).

### 4.5 Caps and refusals (D5)

- **20 instances or 6 sub-panes reached (SR-E13-02):** the add action is disabled-with-reason (CMP-001 `disabledReason`, the reason tooltip reachable on focus): "This chart has the maximum of 20 indicators. Remove one to add another." / "This chart has the maximum of 6 sub-panes. Remove a sub-pane indicator to add another." A hidden instance still counts (E13-D01 §5a; OQ-E), so **hiding is never suggested**.
- **Server caps (SR-E13-03):** a `compute: server` add refused by the per-user cap shows the refused state inline under the entry (CMP-027 `warning`, polite): "You have the maximum of 8 server-computed indicators. Remove one to add another." The per-symbol and process-wide caps are not user-actionable and name no other user: "Server-computed indicators are at capacity for this symbol." / "Server-computed indicators are at capacity. Try again later." with a **Retry** button — never a spinner (SR-E13-04 refuses, never queues).
- **Full recompute refused (SR-E13-04):** "History for this indicator can't be computed right now. Retry" — the instance is added, its legend row says "history unavailable · Retry" and the series draws from the bars the store holds.

### 4.6 In-flight add (D6)

Budget: ≤250 ms to mount and compute the first visible window for a 100 k-bar series in a worker (SCR-034 Performance). The design never assumes it is synchronous: on Add, (1) the legend row for the new instance appears at once with value "—" and the word **computing…** (CMP-199 computing state, D27), (2) the entry's action shows CMP-038 "Adding…" and is disabled for the duration, (3) the dialog stays open and every other control stays live, (4) on completion the polite announcement "EMA 21 added to price pane" fires once (never per bar), the legend value fills and the action reads "Add second instance" with the tag updated. Past 250 ms nothing changes visually except that the "computing…" word remains until the first value lands; a worker add draws the **visible window first** and backfills off-screen ranges afterwards (SCR-035 Performance, applied to adds too). A `compute: server` add shows "Subscribing…" instead of "Adding…" and resolves to the value, the refused state (D5) or "history unavailable". **Bounded end:** the word never lasts forever — after **2 s** without a first value the row reads **still computing…** (no announcement; the same 2 s `14` §0.5 rule 4 uses for a missing update), and on a worker or WS error, or at **5 s** (`RECOMPUTE_TIMEOUT_S`, `limits.py`), it becomes **history unavailable · Retry** (D5) or the errored row (D27) with one polite announcement. `Esc` or Close on the dialog never cancels an add in flight: the row persists, and Retry and Remove live on its menu. Reduced motion: no fade-in on the legend row (E13-D04).

### 4.7 Favourites and Recents stores (D7)

**Favourites** map exactly onto the presets contract: a starred entry is a user-owned `IndicatorPreset` with `is_favourite: true`. The star on a **catalogue entry** calls `createIndicatorPreset` with `name` = the entry's name, `indicator_code` = its `id`, `params` = the descriptor `defaults` written out, `style: {}`, `pane_target` from `pane` (`both` → the segmented control's value), `is_favourite: true`; the star on a **built-in preset** (`is_builtin: true`, `owner_user_id: null`) saves a user-owned copy the same way (`22`: "a built-in is starred by saving a copy"); un-starring sets `is_favourite: false` via `updateIndicatorPreset` (a full replacement; the preset is kept, not deleted). A favourite therefore carries parameters and adds with them. The 500-live-presets cap (`409 limit_reached`) surfaces as "You have the maximum of 500 saved presets. Delete one to star another." **Recents** has no store (`indicator_presets` has no recency column; `Settings` has no recents leaf — E13-D01 OQ-7): the group is drawn with the "store pending" annotation and the proposed `Settings` leaf is contract gap CG-3; until it lands, Recents is session-local (in-memory) and the frame says so.

### 4.8 The `Ctrl+K` palette entry (D8)

No new binding: `Ctrl+K` is the reserved global palette (`05` §3.3 rule 3; `keymap.json` `global.palette`). The indicator feature registers commands in CMP-059's `commands` prop under the **`action`** group (SCR-012's grouping navigate / panel / symbol / action / setting): one **"Add indicator: <Name>"** per catalogue entry (28 commands, fuzzy over name and id; the hint column shows the pane target and "requires recorded history" when it applies), one **"Add favourite: <preset name>"** per `is_favourite` preset, **"Add indicator…"** (opens SCR-034 with search focused) and **"Manage indicators"** (opens SCR-036). `Enter` on an add command adds the indicator with its `defaults` (or the preset's `params`) to the **focused chart pane** (the pane whose plot or legend last had focus; the price pane when none), the palette closes, **focus returns to the element that had it before `Ctrl+K`**, and the polite announcement "EMA 21 added to price pane" fires (E13-D01 R1). An add that would hit a cap shows the SCR-012 RBAC-style greyed entry with the D5 reason as its hint and runs nothing. `Ctrl+Enter` is not used (SCR-012 reserves it). The palette's recency (`PATCH /api/v1/me/preferences`, SCR-012) orders repeated adds first, which is why Recents inside SCR-034 can wait for CG-3 without losing the fast path _(heuristic)_.

## 5. SCR-035 Indicator settings (D9–D19)

One dialog per instance (CMP-043, `aria-labelledby` = the header). The form is generated from the descriptor's `params_schema` (`22`: "the settings form renders from this"), so adding an indicator never needs a frontend release; the renderer is the closed subset of D10 and nothing else (SR-E13-09).

### 5.1 Anatomy (D9)

Header: the instance label ("EMA 21 · price pane · 5m"), an **edited** marker (a dot glyph plus the word "edited") when any value differs from the descriptor `defaults` (or from the user's default preset when one exists, D14), and a **"Used by N armed rules"** tag (CMP-011, count only — names appear only in the blocking list, D17) when the instance is rule- or alert-referenced. Tabs (CMP-042): **Inputs · Style · Visibility · Scale · Alerts**. The form column (CMP-065 FormSection groups, CMP-040 FormField rows) sits left; the **preview region** (CMP-228, `role="img"` named "Preview: EMA 21 over the last 200 bars, display-only") sits right at both sizes, with a caption line under it stating the window and the display-only rule; footer: **Reset ▾** (split button, CMP-057), **Save as default for this indicator**, **Cancel**, **Apply**. The dialog is sized in §2; the preview never hides a field (it is beside the form, not under it).

### 5.2 Schema-driven controls (D10)

The descriptor's `params_schema` is JSON Schema with one property per parameter carrying `type`, `title`, `default`, `minimum`, `maximum`, `multipleOf` and `enum` (`catalogue.py` docstring). The renderer maps:

| `params_schema` shape                                | Control                                                                                                                                                                                                                  | Help text under the field |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------- |
| `integer` with `minimum`/`maximum` (period-style)    | CMP-008 NumericStepperInput, `step` 1, `role="spinbutton"` with `aria-valuemin/max`                                                                                                                                      | "1–5000 bars"             |
| `number` with `minimum`/`maximum`/`multipleOf`       | CMP-008 with `step` = `multipleOf`, decimal step check (a binary64 division refuses 0.3 for 0.1 — `24` §7.4)                                                                                                             | "0.1–10, step 0.1"        |
| `string` with `enum` (e.g. VWAP `anchor`)            | CMP-009 Select                                                                                                                                                                                                           | the enum's titles         |
| `boolean`                                            | CMP-004 Toggle (label right)                                                                                                                                                                                             | —                         |
| the applied-price `source` (E13-S02)                 | CMP-009 Select restricted to the series available on this chart (SCR-035 Validation: "source field restricted to available series")                                                                                      | —                         |
| a style colour (Style tab)                           | CMP-031 ColorSwatch / ThemeChip over the **closed token set** of E13-D04 (SR-E13-08); the set is empty today, so the control is disabled with the reason "Style tokens arrive with E13-D04"                              | token name, never a hex   |
| anything else (`string` without `enum`, `object`, …) | a read-only row "Unsupported parameter type — this parameter can't be edited here" (CMP-036 KeyValueRow; the raw default is rendered as escaped plain text, truncated at 80 characters with the full value in a tooltip) | —                         |

There is **no free-text, HTML or markdown field** anywhere in the dialog (ticket Security note): the one text input in E13 is the preset name on Save as default (D14), rendered as plain text and sanitised server-side (`IndicatorPresetInput.name` rules). Field order is the descriptor's property order; labels come from `title`.

### 5.3 Validation (D11)

Reject, never clamp (SR-E13-01, E13-D01 AD-4). A value outside its bound keeps the previous committed value in the model; the field shows the typed value with `aria-invalid="true"`, an error glyph (text-carrier, never colour-only) and the message under it, linked by `aria-describedby`: **"Period must be between 1 and 5000."** for every period-style parameter (the numbers are the descriptor's `minimum`/`maximum`, which `limits.py` fixes at 1 and 5000 — the UI renders what the schema says and never hard-codes them), **"Standard deviations must be a multiple of 0.1."** for a `multipleOf` breach, **"Standard deviations must be between 0.1 and 10."** for a fractional bound, and **"Choose a source available on this chart."** for the source select. The stepper's arrow keys stay inside the bound; typing past it is what triggers the message. **Apply is disabled with the reason "Fix the highlighted field first."** while any field is invalid; `Enter` in an invalid field re-announces the message (polite `role="status"`; assertive is reserved by `05` §6.2) and does not commit. The server re-validates on commit and refuses with `422` naming the bound (IR-07); its text names the parameter **key**, not its title (`validate_params`: "n must be between 1 and 5000.", "mult must be a multiple of 0.1."), so the UI **never echoes the server string**: it maps the error's `pointer` (`/n`), its `rule` (`minimum` | `maximum` | `multipleOf` | `enum` | `type`) and the descriptor's `title` and bounds to the §12 message and shows it inline on the field — never a toast only. §21 proposes that `InvalidParamsError` build its message from `spec.title` so the two read alike (additive).

### 5.4 Live preview and the commit model (D12)

The preview tile recomputes **the visible window** (last 200 bars by default) within **≤100 ms** of a change and draws the new output over sample bars; it is **display-only**: it publishes no metric, registers no server instance and never changes the instance key (E13-D01 R2-A). For a `client_worker` instance that **no rule or alert references**, the chart behind the dialog previews the change too (display-only, visible window), so the dialog does not hide the thing being tuned _(heuristic, H1 visibility; TradingView and ATAS both preview on the chart)_; **Apply** or `Enter` commits (re-keys the instance, publishes the metric), **Cancel** or `Esc` reverts the chart to the committed values, and **blur never commits**. For a **referenced** instance the chart behind does not change at all — only the tile does — and Apply opens the guard (D17). For a `compute: server` instance a per-keystroke preview would be a server registration each time (SR-E13-03), so the tile shows the committed curve with the caption **"Preview on Apply — this indicator is computed on the server."** and the chart changes only on Apply.

### 5.5 In-flight edit (D13)

Budget ≤100 ms over the visible window, then off-screen backfill (SCR-035 Performance; `06` §4.3 indicator pane redraw ≤2 ms per frame). Nothing blocks: the fields stay editable, the tile keeps the previous curve and gains the caption word **"Updating…"** only once 100 ms have passed, and drops it when the new curve lands; on Apply, the Apply button shows CMP-038 "Applying…" only past 100 ms and the dialog stays open until the commit returns (a server `422` lands as D11, a cap refusal as D5). The chart's off-screen ranges keep backfilling after the dialog closes; the legend row shows "computing…" meanwhile (D27). Reduced motion: the preview never animates between curves (instant redraw).

### 5.6 Save as default, Reset, the edited marker (D14)

**Save as default for this indicator** maps onto `/indicator-presets` exactly: it opens an inline row (not a second dialog) with a plain-text **name** (prefilled with the instance label, "EMA 34"; ≤80 characters, `string_too_long` / `string_too_short` surfaced inline) and a **Favourite** checkbox, and calls `createIndicatorPreset` with `indicator_code`, the **full canonical `params`** (every parameter written out, so a later change of a catalogue default never alters it — `22`), `style: {}` (until E13-D04), `pane_target`, `is_favourite`; a name clash (`409 name_taken`) offers **Replace** (`updateIndicatorPreset` on the clashing preset) or a new name. **What the contract cannot express is "default on add"** — no `IndicatorPreset` field marks one preset per `indicator_code` as the one the picker and the palette use instead of the descriptor `defaults` — so that semantic is **contract gap CG-1** (§17) and the control's saved preset behaves, until CG-1 lands, as a favourite that adds with its params (D7). **Reset ▾** restores the descriptor `defaults` ("Reset to catalogue defaults"); when the user holds a default preset (post-CG-1) the primary action reads "Reset to my default" and the catalogue reset moves into the split menu. The **edited marker** (dot glyph + "edited") sits on every field whose value differs from the reference and on the header; Reset clears it. Both actions are keyboard-reachable in the footer order (§11). While the save row is open, `Enter` in its name field **saves the preset** (not Apply); `Esc` closes the row first and reverts nothing else; a second `Esc` cancels the dialog.

### 5.7 Multi-output and multi-series (D15, D16)

**MACD** (`macd`: `fast` 12, `slow` 26, `signal` 9; outputs `macd` "MACD line", `signal` "Signal line", `histogram` "Histogram"; `compute: client_worker`): one instance, one Inputs tab; the **Style** tab has one collapsible CMP-065 section per output, each with a **Show** toggle, the marker (line solid / line dashed / histogram fill — the non-colour carrier), width and, after E13-D04, the colour token; the legend shows **one row** "MACD 12 26 9" with the three values in output order, each labelled for screen readers by `IndicatorOutput.name` ("MACD line 12.4, Signal line 9.8, Histogram 2.6"), and three mini swatches (D28). **MA ribbon of five lengths** (US-IND-002 "Ribbon", E13-S02): the v1 catalogue holds **no ribbon descriptor** (`catalogue.py` has the 28 ADR-0034 entries), so this spec draws it as E13-S02 will add it — one instance with five period fields (`n1`…`n5`, each 1..5000) — and records the missing descriptor as CG-5. Its legend entry is **one expandable row** ("MA ribbon 10 · 20 · 50 · 100 · 200", a disclosure chevron, five sub-rows each with its own value and eye toggle); its Style tab has one section per length. Both count as **one row** against the legend overflow (D28), and both appear in SCR-036 as one item with children (D21).

### 5.8 The re-tune guard (D17 — OQ-6 drawn as _block_)

An instance's identity is `spec_hash(indicator, canonical params, bar spec, source)` (`24` §7.4), and that key is also the metric a rule or alert references (`RuleMetricRef {metric, params, timeframe}`; US-IND-008). Changing a **parameter or the source** of a referenced instance therefore re-keys it, so: (1) on **Apply** the dialog opens the **same blocking list as removal** (D24, as an `alertdialog` over the settings dialog) titled "Can't change EMA 21 yet", listing the user's own referencing rules and alerts with Disarm / Disable and Edit, and other users' objects as a count; (2) the dialog's footer carries the explicit branch **"Apply as new instance"** — it commits the new values as a second instance (counting against the 20 cap) and leaves the original key, its rules and its alerts untouched; (3) **no commit on blur** anywhere in the dialog, and the legend quick-edit of the primary parameter (E13-D01 R2, pending OQ-B) shares the guard: `Enter` opens the same list, blur reverts with the inline note "Not applied — this indicator is used by 2 armed rules"; (4) the **preview is display-only** (D12). Changing **Style, Visibility or Scale** does not re-key the instance and is never guarded. The other two OQ-6 policies (_new instance_ by default; _confirm_ with the rules losing their metric) are annotated on board 10 and not drawn. Disarm's target mode is `disabled` (OQ-H).

### 5.9 Alerts, Scale and Visibility tabs (D18, D19)

**Alerts** (US-IND-008): read-only CMP-036 rows — **Metric key** (the stable key, e.g. `ema(21, 5m)` as the alert and rule editors list it, with each output's key for multi-output), **Current value** (from the WS instance point; "—" before warmup with the reason from `nullable_when`), **Availability** ("Available" / "Requires recorded history for BTCUSDT — recording is on" / the fail-closed "Unavailable: <reason>" when `resolve()` returns `unavailable`), **Used by** (own rules and alerts by name with Open links; "2 other objects" as a count); the primary action **Create alert from this indicator** opens SCR-091 (E40 owns it) with the metric prefilled; a note states "Stop sizing uses the account profile's ATR period and multiple, not this instance" (SR-E13-11; the UI never offers a client-side ATR source). **Scale:** a CMP-006 RadioGroup — Own scale (a left gutter per E11-D02 §7.1), Merge with price scale, Pinned right (a third scale merges or goes without, E11-D02 §7.1), No scale — plus "Invert" and "Log" toggles where the output unit allows. **Visibility:** a CMP-005 checkbox list of the chart's intervals ("Show on 1m · 5m · 15m · 1h · 4h · 1D") and a CMP-008 "Hide below N px per bar" (the LOD floor the chart passes to the plugin), with the hint that hiding never frees a cap (D5).

## 6. SCR-036 Indicator manager (D20–D26)

The drawer is the a11y-complete alternative to manipulating canvas objects by mouse (`14` SCR-036; persona theme T9): everything attached to the chart — indicators, drawings, alerts — is reachable, named and editable here by keyboard. Its operations are O(1) against the render list (SCR-036 Performance): reorder, hide and delete never rebuild the chart.

### 6.1 Drawer anatomy (D20)

CMP-046 Drawer, right side, **non-modal** (`modal=false`) and **docked, never overlaid**: while it is open the chart panel reflows to `panel width − drawer width`, so the price gutter, the legend, the plot and every right-edge Tab stop of E11-D02 D18 (right gutter → lock badge → splitter) stay visible and unobscured (WCAG 2.2 SC 2.4.11 Focus Not Obscured; `05` §3.4 item 6: a focused element is never hidden behind a sticky panel); the chart stays interactive and the drawer coexists with the legend and the crosshair; width per §2 (fixed 320 / 360 px), full height of the chart panel. _(heuristic: TradingView docks its Object Tree; Sierra's Studies window is a separate window; an overlay would have to drop the obscured stops from the Tab order while open — the worse option.)_ **Chart binding — one drawer per workspace:** the drawer is bound to the chart that opened it and its header names that chart; the palette's "Manage indicators" targets the focused chart (D8's rule: the pane whose plot or legend last had focus, the first chart when none); focus moving to another chart does **not** retarget it; activating another chart's count chip, or its legend's "Manage all…", swaps the content to that chart and announces "Objects on ETHUSDT 5m" once (polite). Header: the title **"Objects on BTCUSDT 1m"** (symbol and interval from the bound chart; the header is the drawer's accessible name), a close button (CMP-002 "Close objects"). A CMP-054 filter box ("Filter objects") appears when the tree holds more than 20 items and filters by label without changing the tree's structure (matching items keep their group header). The tree (`role="tree"`, `aria-multiselectable="true"`, one roving stop) has four top-level groups in a fixed order with counts: **Overlays (3) · Sub-panes (2) · Drawings (7) · Alerts (2)**; sub-pane items nest their indicators one level down (a sub-pane row is a group with a collapse chevron; removing its last indicator collapses the pane, US-IND-003). Footer: **Add indicator** (CMP-001 secondary, opens SCR-034 for the bound chart). Loading: CMP-015 skeleton rows under the group headers, `aria-busy` on the tree, no per-row announcement.

### 6.2 Item row (D21)

- **Row anatomy**, left to right: the disclosure chevron (groups, sub-panes, ribbons only; `aria-expanded`), a **drag handle** glyph (grip, `aria-hidden` — the keyboard equivalent is `Alt+↑/↓`, `05` §3.4 item 8), the **shape swatch** (8×8, the same marker as the legend row: line / dashed line / bar / glyph, never colour alone), the **label** with its parameters ("EMA 21", "Anchored VWAP 12:00", "Trendline #3"), a **lock** glyph when locked, a rule glyph when referenced.
- **Controls**: three icon-only controls, each a named CMP-002 button of its own (never one ambiguous row click): **eye** ("EMA 21 visible", `aria-pressed`, the stable name of E11-D02 D12), **lock** ("Lock EMA 21", `aria-pressed`), **menu** ("More actions for EMA 21", opens CMP-041 with Settings · Rename · Select / Deselect · Add second instance · Reveal on chart · Move up · Move down · Move to new sub-pane · Duplicate · Remove; Select / Deselect are the pointer and AT fallback for selection, D22).
- **Rename**: CMP-058 InlineEdit in place (`F2` or double-click; `Enter` saves, `Esc` cancels); a renamed indicator keeps its metric key (US-IND-008 NFR: identity is the key, not the display name) and the legend shows the custom label with the parameters kept in the accessible name.
- **Delete**: `Del` on the focused item or the menu's Remove — the item leaves at once and a CMP-045 toast "EMA 21 removed. Undo" (10 s, pauses on hover and focus) offers the undo (US-IND-001 "undo available"); a referenced item is blocked instead (D24).
- **Hidden and locked**: hidden items stay in the tree with the eye-off glyph and "hidden" in their name; locked items refuse reorder and delete with the reason "Unlock to move or remove" (disabled-with-reason, `14` §0.5 rule 5 pattern).

### 6.3 Multi-select and bulk actions (D22)

Selection is a declared **hybrid of APG's two multi-select tree models** (the modifier-free model's `Shift+arrows` extension with the selection-follows-focus model's `Ctrl+Space` toggle, because `Space` is the ticket's visibility key and arrows must not select): `Ctrl+click` or `Ctrl+Space` toggles the focused item, `Shift+↑/↓` extends from the anchor, `Shift+Space` and `Shift+click` select a range, `Ctrl+A` selects every item of the focused group (mirrors `rules.select_all`), the row menu's Select / Deselect are the pointer and AT fallback, `Esc` clears the selection before it closes the drawer; `Ctrl+Space` carries a Windows IME caveat (OQ-G). Selected rows carry `aria-selected="true"`, the selection fill and a check glyph (the fill alone is decorative, §13). A selection shows the **bulk-action bar** (proposed CMP-243, §10 G-4) under the header: "**3 selected** · Hide · Show · Lock · Unlock · Delete · Clear selection", each a CMP-001 button; the bar is in the Tab order after the tree. **Bulk delete** with at least one rule-referenced item is **blocked whole**: the D24 dialog lists the referenced ones and nothing is removed until they are resolved (all-or-nothing, OQ-I) — a partial removal would silently change the stack while the user resolves the rest _(heuristic, H5)_. Bulk hide and lock never block.

### 6.4 Empty state (D23)

With nothing attached, the tree body is CMP-026 (`variant="no-data"`): heading **"Nothing on this chart yet"**, body "Indicators, drawings and alerts you add appear here.", CTA **Add indicator** (opens SCR-034; the footer button is hidden while the empty state shows so there is one CTA). Each empty group keeps a one-line row ("No drawings") so the four groups are learnable before they are used; the filter box is hidden until 20 items exist. The before-history and recorder states do not belong to this drawer (they are the legend's, D27).

### 6.5 Blocked removal (D24)

- **Trigger**: `Del`, the menu's Remove, a bulk Delete, or the legend row's Remove, on an instance an **armed rule or an enabled alert references** (US-IND-008 "Removed indicator in use"; the server-authoritative referential guard is E13-S08's, IR-16 — the UI renders the server's answer and never decides it).
- **Dialog**: CMP-043 with `role="alertdialog"`, titled **"Can't remove EMA 21 yet"**, body "2 armed rules and 1 alert use ema(21, 5m). Disarm or edit them first."; focus lands on the first row's Disarm.
- **Own referencing rules**: one row each (a plain `role="list"`, not CMP-049): the rule name, a mode badge ("Armed", word + glyph), its scope ("BTCUSDT · Main"), and two actions — **Disarm** (CMP-001 secondary → `PUT /rules/{id}/mode { mode: "disabled", reason }`; the row updates to "Disabled" with a check glyph and announces "Rule 'ATR breakout' disarmed") and **Edit** (CMP-001 ghost → the rule editor SCR-081 / SCR-082 for that rule; the alertdialog closes, focus goes to the editor, and returning lands on the tree item).
- **The audited `reason`** (`setRuleMode` is audited and broadcast, so the text is durable and must describe what is happening, never a removal that has not happened): "disarmed from the indicator manager: ema(21, 5m) is being removed" (removal) or "disarmed from the indicator settings: ema(21, 5m) is being changed" (re-tune, D17), ≤280 characters. The later removal or apply emits its own event; a Done without removal leaves the rule disabled by the user's explicit, announced action — nothing is silently reverted.
- **Own referencing alerts**: the same row with **Disable** (`PUT /alerts/{id}/enabled { enabled: false }`; announces "Alert 'ATR spike' disabled") and **Edit** (SCR-091).
- **Other users' objects**: one count-only row — "2 other objects (not yours)" — with no names and no actions (IR-23, AC-16; the Owner role sees names per E09 RBAC), so a Manager is told why removal is blocked without learning another user's rules. A rule the Manager lacks `rules:write` on appears in the own-objects list only if it is theirs; otherwise it is in the count.
- **Only other users' objects** (the Manager's own list is empty): the body reads "Only other users' objects use ema(21, 5m). An Owner can disarm or edit them; nothing you own blocks this.", followed by the count row, Done, and Remove disabled with the reason "Resolve every reference first — an Owner must do this." E13-D01 §5a asked this variant to offer a way forward; for removal there is none by design (never "remove anyway"; the names stay hidden), so the dialog names the resolver instead.
- **Footer**: **Done** (closes, nothing removed) and **Remove EMA 21**, disabled with the reason "Resolve every reference first" until the list is clear, then enabled; there is **no "remove anyway"**.
- **Re-tune variant** (D17): the same dialog titled "Can't change EMA 21 yet", its footer adding **Apply as new instance**.
- **Reduced motion**: the dialog opens instantly.

### 6.7 The tree and the DOM mirror (D26)

### 7.2 Multi-output and ribbon entries, overflow (D28)

A **multi-output** instance is **one row**: label with params, then its outputs' values in kernel order, each with its own 8×8 swatch shape and its `IndicatorOutput.name` in the accessible name ("MACD 12 26 9: MACD line 12.4, Signal line 9.8, Histogram 2.6"); hiding one output is a Style-tab toggle (D15), not a legend control, so the row keeps one eye. A **ribbon** is **one expandable row**: the parent shows the five lengths and a disclosure chevron; expanded, five sub-rows each with value and eye; `←/→` collapse and expand it inside the legend's roving stop (E11-D02 D12's `↑/↓` rows, `←/→` controls — the chevron is the first control). The **overflow at 12** is E11-D02 D12's rule unchanged — visible rows ≤ ⌊0.3 × pane height / row height⌋, minimum 3, the rest behind "+N more" — and **counts rows, not series**: 12 indicators of which one is MACD and one a ribbon are 12 rows (plus the price row), so a 600 px compact pane shows 7 and "+6 more"; the popover lists the hidden rows with the same states and ends with "Manage all…" (opens SCR-036).

### 7.3 CMP-224 as the count chip (D29)

Per E11-D02 A-14 (one home for indicator toggles), CMP-224 is the toolbar's **indicator entry**, not a row of per-indicator chips: a CMP-011-class pill reading **`Ind 4`** (the count of indicator instances), with a suffix when a state needs surfacing — `Ind 4 · 1 hidden`, `Ind 4 · 1 error`, `Ind 4 · 1 computing` (one suffix, error first) — and `Ind 0` when none. The ticket's "normal, hidden, errored" chip states are therefore drawn on the **legend rows** (D27) and summarised on the chip; the contradiction with #246's scope wording is C-1 (§17), with the owner confirming A-14.

## 11. Keyboard and a11y (WCAG 2.2 AA, `05`)

### 11.1 Tab order per frame

- **SCR-034 (board 01/02/03):** on open, focus lands in the **search field** (`initialFocusRef`). `Tab`: search → category tabs (one roving stop; `←/→` switch, `aria-selected`) → results listbox (one roving stop; `↑/↓` move `aria-activedescendant`, type-ahead, `Enter` adds, `Home/End`) → Favourite toggle → pane-target segmented control (only when shown) → Add to chart → Close. `Esc` closes and returns focus to the invoker (the toolbar button, the palette's invoker, the tree's footer button or the legend menu). The thumbnail is `aria-hidden`; the tags are part of the option's name.
- **SCR-012 palette (board 04):** `Ctrl+K` → the combobox input → `↑/↓` in the listbox → `Enter` runs; the palette closes and focus returns to the element that had it before `Ctrl+K` (SCR-012; E13-D01 R1); `Esc` closes without running.
- **SCR-035 (boards 05–10):** on open, focus lands on the **active tab** (Inputs) so the dialog's name and the tab list are heard first; `Tab`: tabs (roving) → the tab panel's fields in descriptor order (each CMP-040: label, control, help / error) → the preview is **not** a stop (`role="img"`, named) → Reset ▾ → Save as default (then, when its row is open: name, Favourite, Save, Cancel) → Cancel → Apply → Close. `Enter` in a valid field = Apply; in an invalid field it re-announces the message; while the save-as-default row is open, `Enter` in its name field saves the preset and `Esc` closes the row first; `Esc` = Cancel (reverts any chart preview) and returns focus to the invoker. The blocking `alertdialog` (D17) takes focus on its first action and returns it to Apply when closed with Done.
- **SCR-036 (boards 11–14):** on open (toolbar chip, palette, "+N more" popover link), focus lands on the **first tree item** (the drawer is non-modal and docked: the chart reflows by its width, so no chart stop is behind it); `Tab`: Close → Filter (when shown) → tree (one roving stop, §6.6) → bulk-action bar (only with a selection) → Add indicator. `Esc` from the tree clears the selection, then closes the drawer and returns focus to the invoker. The blocked-removal `alertdialog` takes focus on its first row's Disarm and returns it to the tree item (or to the bulk bar's Delete) on Done; Edit leaves for the rule editor and the drawer stays open.
- **Chart region (E11-D02 D18, unchanged):** toolbar → status chips → per pane: legend (one roving stop; the indicator rows of §7 live here) → plot → … ; CMP-224 is on the toolbar stop.

### 11.2 Dialog focus and return

CMP-043 / CMP-046 contracts (`05` §3.4 item 4): focus is trapped in the two modals and in the blocking `alertdialog`; the drawer is non-modal and traps nothing. Every close path (Close, `Esc`, Cancel, Apply, Done) returns focus to the invoking element; when the invoker is gone (an indicator removed from the tree) focus goes to the next tree item, else the group header, else the Add indicator button. A `role="alertdialog"` is announced by its label on open; a live update is not sent as well (no double announcement). Opening SCR-035 from SCR-036 stacks the modal over the drawer; closing it returns to the tree item.

## 14. CVD note

Greyscale needs no hue check, so no colour-vision simulation is run for this spec (E11-D02 §11.3 covers the chassis hues D03 inherits). What this spec guarantees instead is that **every state has a text or shape encoding**, so E13-D03's colours stay redundant (`05` §4; `16` §6 rule 1): the instance marker is a dash pattern, fill pattern or glyph shape (E13-D01 AD-2); hidden = eye-off glyph + "hidden" + `text.tertiary`; computing = the word; insufficient history = the count and the first-valid-bar start; errored = glyph + "error"; provisional = dashed + the word; used-by-rules = glyph + the words; selected = check glyph + `aria-selected`; the edited marker = dot + "edited"; the validation error = glyph + the message; the count chip's suffix is text. **States D03 must keep non-colour** (it may add hue, never replace these carriers): hidden, errored, insufficient history, before-history, provisional, computing, used by rules, selected / multi-selected, locked, the edited marker, invalid field, disabled-with-reason, the "On chart ×N" and "Requires recorded history" tags, the mode badge in the blocking list ("Armed" / "Disabled" words), and the second-instance marker. D03 runs the `docs/research/_tools/cvd_simulate.py` projection over the indicator palette it introduces (its own DoD, `05` §4 item 2).
