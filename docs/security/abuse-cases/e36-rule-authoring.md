# E36-X02 — Abuse-case catalogue: the rule authoring surface

- Ticket: E36-X02. Threat source: `docs/security/threat-models/e36-rule-form-editor.md` (E36-X01, #948), its §3
  rows (RA-S01 to RA-E06) and its §9 requirements (SR-E36-01 to SR-E36-23). The E35 suite
  (`docs/security/e35/abuse-case-suite.md`, cases a to o) is referenced, not repeated.
- Handoff state: written by E36-X01 for E36-X02 to automate. One seed per model claim that needs a test; a claim
  with no test here is not an accepted mitigation (#948 test plan).
- Method: white-box. Server cases use a raw HTTP client through `create_app()` that ignores every client rule, so
  the server is what refuses; client cases run in Vitest over `packages/rule-editor-core` and the rules slice, and in
  Playwright for the cross-screen legs. No network, no live account, no real key; fixture account ids only (C-13.5).
- Paths: server tests under `services/api/tests/` (new cases in `tests/security/rules/`); client tests under
  `packages/rule-editor-core/test/`, `apps/web/src/features/rules/` and `apps/web/e2e/rules/`; Semgrep rules
  under `.semgrep/`, each with a fixture that fails on a deliberate violation.
- Actors: **O** the Owner; **M** a Manager granted account A only, holding `orders:write` on A and no
  `rules:arm_live`; **V** a Viewer. B is an account M is not granted.
- Depth: counted in levels of objects and arrays with the root as level 1, as the model's §5.1 does; `ir` may hold
  65 levels and a bundle file, whose wrapper adds one, 66. The server counts a scalar leaf as a level
  (`common.py:50-53`), so the at-limit `ir` fixture is 64 nested non-empty containers holding a scalar, or 65
  whose innermost is empty; 66 openers are refused by both.
- Verdict key: **COVERED** an existing test on `main` holds it, cited; **NEW** E36-X02 writes it against code on
  `main`; **WAITING** the code is not on `main` yet, and the row names the ticket that builds it. Never skipped.
