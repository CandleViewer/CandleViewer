# E17-X02 — Abuse-case catalogue: the client WS gateway

- Ticket: E17-X02 (#415). Threat source: `docs/security/threat-models/E17-ws-gateway.md` (E17-X01), its §3
  rows (WS-S01 to WS-E06) and its §7 seeds (AC-01 to AC-31). Review record and findings:
  `docs/security/reviews/e17-ws-review.md`.
- Method: white-box. The cases run over a raw protocol client (`services/api/tests/security/ws/_raw.py`)
  that shares no code with `apps/web`, only the generated types, and ignores every client-side rule, so
  the server is what refuses. In process they run on the E17-Q01 conformance gateway (fake clock, no
  sleeps); on real sockets, on the E17-Q02 chaos rig's uvicorn server on 127.0.0.1 with the production WS
  settings. No network beyond loopback, no live account, no real key.
- Every case runs under both subprotocols (`cv.v1.json` and `cv.v1.msgpack`) unless its row names one.
  Test paths are under `services/api/`; `apps/`, `packages/`, `.semgrep/` and the fuzz corpus
  `tests/fuzz/ws-frames/` are at the repository root.
- Lanes: `tests/security/ws` and the other unit and contract suites run in the PR `py` lanes; `perf`
  cases, the timing leg of AC-05 among them (as E09-X02's AC-ENUM-03, #4521), in `py-perf`; `fuzz`
  targets in `fuzz-nightly.yml`. `cv_ws_errors_total{code}` is in process only (#2747), so
  the suites read it in process.
- The metric and audit row columns name each refusal's signal as the model's §8 names it; the
  `tests/security/ws` cases assert theirs, and an empty cell says that none is written.
- Verdict key: DEFENDED (the refusal holds as documented) · DEFENDED, leg NOT RUN (the row names the leg
  with no observed result; the NOT RUN table says why) · NOT RUN.
- Escalation result: no executed case reached another account's data, another user's identity or an
  action over the WS.
