# E21-X02 — Abuse-case catalogue: the DOM ladder and the liquidity heatmap

- Ticket: E21-X02 (#652). Threat source: `docs/security/threat-models/e21-dom-heatmap.md` (E21-X01), its
  §3 rows (HM-S01 to HM-E05) and its §7 seeds (AC-HM-01 to AC-HM-19).
- Method: white-box. The WS cases run over the E17-X02 raw protocol client
  (`services/api/tests/security/ws/_raw.py`) on the real `/ws` router with real sessions, under both
  subprotocols, with the heatmap producer's leases wired (`tests/security/marketdata/conftest.py`); the
  REST cases run on the real `GET /market/heatmap` router over the real cold tier, a temporary archive
  root and a spy on the hot tier. Fake clocks, no sleeps, no network, no live account and no real key.
  Test paths are under `services/api/` unless they start with `packages/` or `infra/`.
- Fixtures (C-13.5): the WS and REST cases need no exchange payload: they send the gateway's own frames
  and the route's own parameters. No depth-500 payload is synthesised: a depth-500 leg runs at depth 200
  on the recorded capture, and its depth-500 half is a carry to E21-K01 (#603) and E21-Q03 (#698).
- Lanes: `tests/security/marketdata` and the unit suites run in the PR `py` lanes; the `perf` case in
  `py-perf`; the promtool cases in the `py-checks` job.
- Verdict key: DEFENDED (the refusal or bound holds as the contract states it) · DEFENDED, leg NOT RUN
  (the NOT RUN table names the leg, its reason and its owner) · NOT RUN.
