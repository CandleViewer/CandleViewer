# E37-X02 — Abuse-case catalogue: the node-graph editor

- Ticket: E37-X02 (#1125). Threat source: `docs/security/threat-models/e37-rule-graph-editor.md` (E37-X01, #1073),
  its §3 rows (RG-S01 to RG-E05) and its §9 requirements (SR-E37-01 to SR-E37-16). The E35 suite
  (`docs/security/e35/abuse-case-suite.md`) and the E36 catalogue (`docs/security/abuse-cases/e36-rule-authoring.md`,
  AC-RA-01 to AC-RA-24) are referenced, not repeated.
- Handoff state: written by E37-X01 for E37-X02 to automate. One seed per model claim that needs a test; a claim with
  no test here is not an accepted mitigation (#1073 test plan).
- Method: white-box. Server cases use a raw HTTP client through `create_app()` that ignores every client rule, so the
  server is what refuses; client cases run in Vitest over `apps/web/src/features/rule-builder-graph/` and
  `packages/rule-graph`, and in Playwright for the cross-screen legs. No network, no live account, no real key; fixture
  account ids only (C-13.5).
- Paths: server tests under `services/api/tests/security/rules/`; client tests under
  `apps/web/test/features/rule-builder-graph/` and `apps/web/e2e/rules/`.
- Actors: **O** the Owner; **M** a Manager granted account A only, holding `orders:write` on A and no `rules:arm_live`;
  **V** a Viewer. B is an account M is not granted.
- Verdict key: **COVERED** an existing test on `main` holds it, cited; **NEW** written against code on `main` (by
  E37-X01 where it says so, else by E37-X02); **WAITING** the code is not on `main` yet, and the row names the ticket
  that builds it. Never skipped.
